> 只记跨会话有长期价值的东西：体例约定、可复用的校验手段、反复踩过的坑。
> 逐日流水记在 `YYYY-MM-DD.md`。

## 一、专题笔记体例（硬约定）

每个专题目录 = **MOC 导航页 + 大观正文** 两件套（`高数大观/{一元积分,函数极限,多元微分,微分方程}/`、
`线代大观/`）。**新增或重构专题一律照抄这个骨架，不要自创。**

| 文件 | 骨架 |
|---|---|
| `<专题> MOC.md` | `# <专题> MOC` → `> [!info] 来源`（含逐次更新的日期行）→ `## 知识结构总览`(mermaid) → `## 专题导航`/`## xx速查`(表) → `## 核心考点速查` → `## 相关链接` |
| `<专题>大观.md` | `# <专题>大观` → `> [!info] 整理说明` → `## 总览`(主线 + 知识地图 mermaid + 解题总顺序) → `## 一、…`～`## 六、…` → `## 相关链接` |

- H2 用「中文序号、」，H3 用「阿拉伯 x.y」，再深一层 `####`。
- **不用 YAML frontmatter**（provenance 写在 `> [!info] 来源` callout 里）；全库唯一例外是
  `微分方程大观.md`，它保留了带 aliases 的 frontmatter 以便旧链接不失效。
- 结尾 `## 相关链接` 三件套：指回自己的 MOC、指孪生的教材级笔记（`[[🌲N.xxx及其应用]]`）、
  指同库其他 `[[… MOC]]`（各专题 MOC 之间要形成闭环）。
- callout 用法约定：`[!info] 补充说明` 标"为闭合知识链条而补、非原文逐字转录"的内容；
  `[!warning]` 易错点；`[!tip]` 判型提示；`[!summary]` 口诀；`[!question]` + 嵌套 `[!success]-` 做自测。

## 二、公式与排版（与用户级记忆互补，这里只记本库独有的）

- 多步推导用 `$$` + `aligned`（见用户级技能 `math-derivation-style`）。
- **绝对值写 `\lvert y\rvert`**：表格单元格里绝不能出现裸 `|`（会破格）；
  `\lvert` 后必须紧跟空格，否则吞掉下一个字母。
- 表格里写 wikilink 别名要转义：`[[#3.1 标题\|3.1]]`——**只用于 wikilink**，别和 MathJax 的 `\|` 混。
- 锚点要**完整抄标题**，含括号：`### 4.7 差分方程（数学三）` → `[[#4.7 差分方程（数学三）]]`。

## 三、重构/整理既有笔记的标准动作

已固化为技能 **`obsidian-daguan-restructure`**（`~/.workbuddy/skills/`），含两个脚本：
`check_note_structure.py`（静态体检）与 `coverage_diff.py`（覆盖度核对）。要点：

1. **先核对行数**：`Read` 默认只读 2000 行，长笔记必须先 `git show … | wc -l`。
2. 建「旧节 → 新板块」映射表，再动手。
3. 结构病四类判据：平铺（同级标题 > 15）、重复（**同一事实完整写两遍以上**）、
   散落（同一主题信息 ≥3 处）、断链（下游依赖的上游相隔 > 10 节）。
4. 改完必跑：结构体检 → 覆盖度核对 → 逐条判读剩余项是"真丢失"还是"改写"。
5. 改名一律 `git mv`，旧名进 aliases。
6. **同一文件的多处编辑必须串行**——一次消息里并行 Edit 同一文件，后写者以旧快照回写，前一处静默丢失。
7. macOS 自带 grep 不支持 `\|` 交替，`grep "a\|b"` 会静默无输出，别误判成文件损坏。
