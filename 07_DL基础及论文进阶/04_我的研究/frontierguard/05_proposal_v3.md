## 1. 定位、投稿目标与一句话

**一句话（v3）**：并行 RL 在大 N 下"跑得多、学得少"，根因之一是**经验被投给了错误的配置**；FrontierGuard-RL（FG）用"**归一化学习进度的导数 × 估计量不确定性**"在线分配并行环境的 reset 预算，并给出"**何时 success-rate 启发式已经足够、何时必须看趋势与噪声**"的可证伪判据——全部在 **¥5,000 租卡 + 一台消费级 4070 Ti Super + 2 台 SO-101** 的可及预算内完成。

**ICRA 叙事顺序（v3 修订，O2）**：先讲**机器人**，再讲 **scaling**。
1. **可及性事实**：SO-101（~¥3k/台）+ 一张消费级显卡 + 5,000 元租卡，已足以跑 N=1,024–16,384 的并行训练；小实验室的真实瓶颈从"买不到算力"变成"**同样预算下，经验怎么分**"。
2. **现象**：N 增大以后，uniform 采样把大量 env-step 花在已掌握（p≈1）或学不会（a_g≈0）的配置上；success-rate 启发式（SGS，CoRL 2026）缓解了这一点，但当**单配置结果本身随机**时，它会把噪声误判为进步。
3. **我们的问题**：把"success-band 何时足够"变成**两个可测的不等式**（§4.4），并用**域内自然噪声审计**（§5.8）而非仅合成注入来验证。
4. **贡献**：机制（LP 导数 + 估计量不确定性 + 三重 guard）× 可证伪判据与 8 条预测 × fixed-K 主协议的同预算 head-to-head × 真机零样本证据 × 全开源。

**投稿目标（按优先级，概率为 judge 的估计，非承诺）**：
| 会议 | 预计截止 | 我方窗口 | 匹配度 | 单投估计 |
|---|---|---|---|---|
| **ICRA 2028** | ~2027-09-15（待核实） | W41 = 2027-08-09 投稿，留 5.2 周 | 中（须机器人优先） | **40%（80% CI 29–51%）；v3.1 修复后 ≈43%** |
| RA-L | 滚动 | W34 后可投 | **最高**（篇幅容纳理论+全消融+完整真机） | 38–44%（judge 估计） |
| CoRL 2027 | ~2027-06（待核实） | 仅当 W24 进度**超前 ≥3 周**才启动 | 高（边界/分析型贡献更受认可） | 25–30%（条件期权） |

**v3 的赌注（诚实版）**：judge 的核心判断是「novelty 不能靠论证获得，只能靠效应量获得」——唯一可能翻盘的是 **H4（域内自然噪声）** 与 **H8（真机效应量）**。因此 v3 把省下的预算/时间**刻意押在这两处**：域内噪声审计（§5.8，20 GPU-h + 日志分析）、真机前置 pilot 门控（§5.10，90 trials）与第 3 任务条件项。若这两处都不出效应，v3 也预注册了**转向 RA-L 分析型论文**的路线（§11.3），而不是硬投。

### 1.6 与 SGS 的关系（三句话，v3 修订）

1. **我们不声称 SGS 是 FG 的特例。** SGS 用三档 success band 加权 reset，本质是 a_g 的**分段常数近似**；FG 用归一化 LP 的导数 × 估计量不确定性门控。二者只在"success 与 LP 单调、每桶结果噪声小、桶结构相近"时**近似重合**（精确条件与不覆盖项见 §4.6）。
2. **我们不覆盖 SGS 的阈值（cut-point）、重采样比与调度**；这些在 FG 中由 bandit 与 guard 隐式决定，不保证与 SGS 等价或更优。
3. **我们要回答 SGS 没回答的问题**：何时 success-band 已经足够（判据 (i)(ii)），以及在 fixed-K 的同一 N 下，差异是否来自分配而非"更多更新"（§2.1）。

## 2. 研究问题与假设（预注册版本）

### 2.1 主终点为什么从"固定步数"移到"固定更新数"（v3 核心修订）

v2 把协议 A（固定 env-step 预算 B）当主结果，把协议 B（固定更新次数 K）当"决定性控制"，两者自相矛盾：**B 固定时，N 越大每轮 PPO 更新看到的经验越少**——N=2,048、B=15M、L=50 时一个策略只得到 `K = B/(N·L) = 146` 次更新，此时"大 N 更差"可能纯粹是**更新饥饿**，与"分配是否合理"无关。这正是 R3 审稿人会一眼看穿的点。

v3 规定：
- **主协议 = fixed-K（协议 B）**：Tier-2 `K = 1,172 = 15M/(256×50)`，Tier-1 `K ≈ 2,930`；所有方法在同一 K、同一 N、同一 episode 长度 L 下比较，N 翻倍则 B 翻倍（交互预算）。此时"分配收益"与"更新饥饿"在统计上可分离：**同一 N 下差异只可能来自经验分配**。
- **主格 = T2-Bmain（192 runs）**：4 任务 × N{256,1024} × 3 方法（uniform/SGS-band/FG）× 8 seeds；N=256 的 96 runs 在本地（B=15M = K·N·L，2.83 h/run，271.7 h），N=1,024 的 96 runs 租卡（B=60M，5.61 h/run，538.6 h，¥1,346）。**其他 Tier-2 行若用 B=15M 固定步数，一律标"协议 A"，不得再称 fixed-K。**
- **次协议 = fixed-B（协议 A，原主终点）**：回答"给定 15M/150M 步预算，应该开多大 N"——这是**部署区制**问题，结论按"区制"陈述而非普适主张。
- **协议 C = fixed-wall-clock**：只做描述性报告（成本-性能），不做假设检验。

这一修订使 Tier-2 租卡较 v3 的 fixed-B 计价增 ¥403（¥2,018→¥2,421；见 §6.2），对叙事的影响是**把"大 N 的 scaling"从"我们观察到"降级为"在什么区制下成立"**，反而更符合 ICRA 的实验评价口径。

### 2.2 RQ1：机制归因——增益真的来自"分配"吗？

**RQ1**：在同等更新次数（fixed-K）下，FG 的收益是来自**更好的经验分配**，还是来自隐式的探索增强、更大的有效 batch、或更长的训练？

**H1（主假设，fixed-K 排序）**：在 Tier-2 的 4 个 SO-101 任务上，fixed-K 最终成功率满足 `FG > SGS-band > uniform`，且 FG 相对 uniform 的平均提升 ≥3 pp（4 个任务中 ≥3 个方向一致）；在 Tier-1 的 4 个族中 ≥3 个方向一致。
- 判定：分层 Holm 校正后的单侧检验 + 效应量 CI；跨任务用混合效应模型（任务/seed 随机截距）。
- 杀死条件：若 fixed-K 下 FG 与 uniform 差 <1 pp 且 CI 跨 0 → H1 失败，直接进入 N1（§2.6）。

**H2（等价性，回应"只是 SGS 换个信号"）**：在 fixed-K 下，`N × method` 交互项在等价界 **Δ = 2.5 pp** 内不显著——即 FG 的收益不随 N 单调放大，增益主要来自"同等 N 下更好的分配"，而不是"越大 N 越占便宜"。
- 统计：**TOST**（two one-sided tests，α=0.05，等价界 ±2.5 pp，预注册），对 logit 尺度上的交互项；同时报告点估计与 90% CI。
- 设计意图：若等价成立 → 论文的贡献是"在任何 N 都更好"，这比"只在大 N 更好"更难被质疑为噪声；若等价不成立（交互显著为正）→ 支持 H3/H9 的 scaling 叙事，按预注册的 N3 分支写。

### 2.3 RQ2：scaling——大 N 什么时候不再划算？

**RQ2**：在固定交互预算（协议 A）下，uniform 的 `J(N)` 是否呈倒 U？FG 是否把峰值 `N*` 推得更大？更新饥饿是否是主因？

**H3（协议 A 倒 U）**：Tier-2 上 uniform 的 final success 在 N∈{64,256,1024,2048} 上出现倒 U（峰值 N*≤1024）；FG 的 N* 更大（差 ≥1 个档位）或在高 N 处下降更缓（斜率差 ≥0.5 pp/档）。
- 判定：二次项回归 + 按 N 分档的配对比较；同时对"每策略更新次数 K"做协变量分析（把 K 作为解释变量，看 N 效应是否被 K 吸收）。
- 注意：H3 是**次终点**，即使成立也不单独构成本文主张（v2 曾把它当主结果，是过度承诺）。

**H9（K-sweep 直接检验更新饥饿）**：在 1 个 Tier-2 任务上扫描 `K∈{146,293,586,1172}`（N 固定 1,024，B=K·N·L），uniform 与 FG 的差距在 `K ≤ 293` 时最大，随 K 增大而收窄（差距(K=146) − 差距(K=1172) ≥ 3 pp）；饥饿阈值 `K*` 估计落在 300–600。
- 判定：交互回归 + 分段线性；若差距不随 K 变化（|斜率| < 0.5 pp/倍）→ H9 失败，说明固定 K 的选择对结论不敏感，反而简化叙事（在论文中如实写）。
- 成本：24 runs，63.7 GPU-h，¥159（§6.2 T2-K 行）。

### 2.4 RQ3：边界——success-band 什么时候已经够用？

**RQ3**：SGS 的 success-band 启发式在什么条件下与"学习进度 × 不确定性"等价/足够？我们的两个判据（§4.4）能否被**域内自然噪声**证实，而不只是合成注入？

**H4a（域内自然噪声，v3 新增，最高 ROI）**：在 Tier-2 的 4 个 SO-101 任务的**现有日志**中，至少 1 个任务/配置组满足 `σ_a ≥ Δ_min/2`（即单配置结果的固有随机性已超过相邻难度桶的可行差异）——这意味着 success-band 在该组上从原理上不可分辨（判据 ii 被自然违反），**不需要我们人为注入噪声**。
- 判定：从所有 Tier-2 main 运行的 episode 日志估计 per-config 的 beta-binomial 方差 σ_a；与由相邻配置成功率差估计的 Δ_min 比较；bootstrap CI 跨"≥Δ_min/2"线。
- 成本：日志分析（0 GPU-h）+ 20 GPU-h 定向重跑（同配置重复，分离 within/between 方差）+ 图 1 张（§5.8）。

**H4b（受控验证，注入 p_slip）**：在 Tier-1 的 1–2 个族上注入 `p_slip∈{0, 0.05, 0.10, 0.20, 0.30}`（动作以 p_slip 概率被替换为随机动作），SGS-band 相对 FG 的 regret 随 p_slip 上升（斜率 >0），且在 p_slip=0 时两者差 <1 pp（TOST 证明"无噪声时 success-band 足够"）。
- 判定：混合效应回归（p_slip × method），斜率检验 + 零点等价。
- 设计意图：H4b 是**受控**证据，H4a 是**域内**证据；两者互为补充。若只有 H4b 成立而 H4a 不成立，论文诚实写"SGS 在无噪声时够用，我们的增益需要噪声前提，而 SO-101 任务的域内噪声未越过阈值"——这会显著降低评分，但仍是可发表的负结果（N2）。

**H5（guard 的必要性与分工）**：三个 guard 中，**噪声 guard**（§3.5 G1）在 σ_a 高的设置上贡献主要收益（去掉后 FG 与 SGS-band 的差距缩小 ≥50%）；分布塌缩 guard（G2）与置信度门控（G3）主要影响稳定性指标（跨 seed 方差、最小任务成功率），对均值影响 <1.5 pp。
- 判定：A5–A7 消融 + 交互项；预注册"若 G1 无贡献则诚实写 guard 多余"。

### 2.5 RQ4：泛化与真机——能否离开 MuJoCo？

**RQ4**：在视觉操作（SO-101）与真机上，fixed-K 下的结论是否保持？真机上 FG 相对 uniform 的提升是否 >0（单侧）且效应量在预注册区间内？

**H6（SO-101 广度）**：Tier-2 4 个任务中 ≥3 个 FG > uniform（≥2 pp）；8 任务广度（T2-f，可选）中 ≥6/8 方向一致。
**H7（MT10 附录，任务级分配）**：在 MetaWorld MT10（task ID 在 obs 中）上，任务级 FG（两级=任务级 + 任务内配置级）相对 uniform 与 DRATS 适配版不劣（差 ≥−1 pp，且 ≥2 个任务上 >+2 pp）。
**H8（真机，v3 修订）**：`FG − uniform > 0` 的**单侧**检验在 α=0.05 下显著（池化 2 个任务 × 45 个配对场景 × 2 轮 = 90 个配对），且效应量 CI 下界 >0；**20 pp 只是期望量级，不是门槛**。预注册的次要目标是"效应量 ≥8 pp"（由 W22–W23 pilot 估计后锁定，见 §5.10）。
- 判定：配对 McNemar 单侧 + 效应量（差值比例）95% CI；同时报告每条件 Wilson CI（用于读者直觉，不做检验）。
- 杀死条件：若 pilot 点估计 <8 pp → 按 M6 降级为"非劣/定性"叙事；若主实验 CI 跨 0 → H8 失败，写负结果（N2）。

## 3. 方法

### 3.0 总览与"部件 → 失效模式 → 消融"对应表

FG 是一个**外挂在任意 on-policy 并行 RL 之上的配置分配器**：它不改变 PPO 的目标，只在每个 rollout 轮次决定"下一轮 N 个并行环境里，每个配置桶分几个 env"。

| # | 部件 | 目标失效模式（不加会怎样） | 对应消融 |
|---|---|---|---|
| P1 | 归一化 LP（双 EMA + 组内 z-score） | 不同组的成功率尺度不可比，直接比较会把"简单但没学好"的组误判为前沿 | A1（去归一化） |
| P2 | LP 的**导数**项 Δℓ | 只用 LP 水平 = 追逐已经高的组（贪心），在"高原但仍在进步"的组上停得太早 | A2（去导数，κ=0） |
| P3 | 估计量不确定性门控（bootstrap EMA 离散度，不声称 model epistemic） | 小样本组的高方差被误当“在进步”，噪声追逐 | A3（去不确定性） |
| P4 | guard-1 noise（σ̂_est 大 → 冻结权重） | 同上，但作为硬保护；与 P3 互补 | A4 |
| P5 | guard-2 starvation（w_min + n_min warm-up） | 某组被永久饿死，最终 min-group 成功率塌陷 | A5（去 w_min）/ A5b（去 warm-up） |
| P6 | guard-3 信任域（ρ 平滑 + 单轮变化上限） | 分配在相邻轮次抖动，PPO 的 advantage 归一化被打乱 | A6 |
| P7 | Hedge（full-information）而非 EXP3-IX | 每组每轮都有 env、都能观测到 reward → 是 full-information 设定，用 EXP3 的 importance weight 是错配且方差更大 | A7 |

**审稿人友好条款**：若 A1–A3 显示"只用 LP 水平"或"只用不确定性"即可解释全部收益，则 v2 的最终方法简化为对应单信号版本，并在论文中如实报告（方法可被自己的消融证伪）。

### 3.1 形式化：单任务配置级 MDP 族

**基本设定**：一个任务 𝒯 定义 MDP ℳ=(𝒮,𝒜,P,r,γ,ρ₀)，其**配置空间** 𝒞 由环境参数 c 张成（初始状态、物体位姿、目标区域、物理参数、光照）。采样 c∼p(c) 得到**配置实例** ℳ_c。策略 π_θ(a|s) 对所有 c **共享**（这是合法的：reward 与成功判定相同，只有初始条件/参数不同）。

> **关键合法性条件（v1 在此出错）**：共享策略要求所有配置实例属于**同一个 MDP 的初始分布扰动**，而不是**不同 reward 函数的任务**。因此 v2 的主实验**固定单个任务**，绝不把多个 SO-101 任务塞进同一个 PPO（C9）。跨任务只出现在 MetaWorld 附录，且那里 **task ID 进入观测**。

**分组**：把 𝒞 划分为 M 个互斥桶 G₁…G_M（构造见 §3.2）。第 t 轮（每轮 L 个 env step）中，组 g 分到 n_g 个 env，权重 w_g=n_g/N，Σ_g w_g=1。

**优化目标**（论文中明确写出，回应"你们到底在优化什么"）：

  J(θ, w) = E_{c∼p_w(c)}[ J_c(θ) ]，  p_w(c) = Σ_g w_g · p(c | c∈G_g)

注意：**w 不改变最优策略**（p_w 与 p 同支撑时 argmax_θ J 相同），w 只改变**有限预算下的学习速度**。这是本文方法的合法性基础，也是审稿人最可能问的第一问——必须显式写出这一句。

### 3.2 分组构造（统一 M 的语义）

> **v1 的错误**：Tier-1 的 M=8 是"任务内初始状态桶"，Tier-2 的 M=4 是"任务"；两种粒度混用同一个 g。v2 全篇只保留一个定义：**group = 同一任务内的一个配置桶**。

#### Tier-1（MuJoCo Playground，本地，N≤16,384）：构造族 A/B/C/D

| 族 | 任务（合法 env 名） | 分组方式 | M | 真 LP 是否已知 | 用途 |
|---|---|---|---|---|---|
| **A** | `PandaPickCube` | 目标区域 4 × 物体质量/摩擦 2 | 8 | **是**（解析可达性/成功概率） | 主族：含真 LP，验证"FG 能否逼近 oracle-LP" |
| **B** | `CheetahRun` | 初始速度 4 档 × 动作噪声 2 档 | 8 | 部分（速度档可解析） | 异质性 + **aleatoric 噪声注入**（H4） |
| **C** | `HumanoidRun` | 初始姿态扰动 4 档 × 地形粗糙度 2 档 | 8 | 否 | 高维、难学性差异大，检验泛化 |
| **D** | `Go1JoystickFlatTerrain` | 目标速度指令 8 档 | 8 | 部分 | 指令条件化、接近真机部署形态 |

- 统一 M=8，便于跨族比较；**H1 要求 ≥3/4 族排序一致**。
- **族 B 的噪声注入**是 H4 的核心：在部分配置上以 p_slip∈{0, 0.3, 0.6} 随机让 episode 提前终止（"滑倒"），制造**与可学性无关的 aleatoric 噪声**。σ_a=0 的族 A/C 是"无差异"预测的对照组。
- **构造性保证异质性**：v1 假设"Cheetah 的初速度桶天然有难度差"，这不成立（δ≈0，各桶几乎同样难）。v2 用**显式构造**：族 A 的目标距离从"机械臂可达半径的 40%→95%"取 4 档，保证成功概率从 ~0.9 单调降到 ~0.1（pilot 校准）；族 D 的速度指令从 0.5→3.0 m/s 取 8 档。**"真 LP 已知"来自解析/半解析计算，不是拟合**。

#### Tier-2（Squint SO-101 视觉操作，租卡 N=1024/2048，本地 N=256）

- **主实验任务（4 个）**：`SO101LiftCube-v1`、`SO101StackCube-v1`、`SO101PlaceCan-v1`、`SO101ReachCan-v1`（env_id 以 Squint 仓库为准，**`-v1` 不是 `-v0`**；W1 核对）。

- 方法：uniform / DRATS（任务级）/ FG（任务级）/ FG 两级（任务级 × 配置级）。
- **只作泛化性证据**，明确写"不作 N-scaling 主证据"。

### 3.3 学习进度（LP）估计：双 EMA + 组内归一化 + 导数

对每个组 g，维护成功率的双 EMA：

  p̄_g^{fast} ← (1−α_f)·p̄_g^{fast} + α_f·p̂_g^{(t)}，  α_f = 1/H_ep^fast，H_ep^fast=20 episodes
  p̄_g^{slow} ← (1−α_s)·p̄_g^{slow} + α_s·p̂_g^{(t)}，  α_s = 1/H_ep^slow，H_ep^slow=100 episodes

- **LP 水平**：ℓ_g = p̄_g^{fast} − p̄_g^{slow}（正值 = 近期进步快于长期平均，即"正在爬升"）。
- **LP 导数**：Δℓ_g = ℓ_g^{(t)} − ℓ_g^{(t−1)}（用 3 轮移动平均去噪）。
- **组内归一化**（M7 修正）：u_g^{raw} = (ℓ_g + κ·Δℓ_g) / (σ̂_g + ε₀)，其中 σ̂_g 是该组最近 20 轮 ℓ 的样本标准差，ε₀=0.05，κ=1.0。归一化保证跨组可比（不同任务/桶的成功率尺度不同）。

> **为什么用导数而不只是水平**：只看 ℓ_g 水平等于"追高 LP 组"，在"LP 高但已进入平台"的组上会持续投入（v1 的贪心问题）。导数项识别"仍在上升"的组。A2 消融（κ=0）直接检验这一项是否必要。

### 3.4 估计量不确定性：E=3 bootstrap EMA 离散度（v3 修订，M4）

**术语修正**：v2 把这一项叫 σ̂_est（epistemic uncertainty），这是**错误命名**——审稿人会直接指出"你测的是采样方差，不是模型认知不确定性"。v3 改称 **估计量不确定性 σ̂_est**，并在论文中显式声明：**我们不声称识别或估计 model epistemic uncertainty**；σ̂_est 只度量"小样本下进度估计的稳定性"，作为门控信号。

- **实现**：E=3 条 bootstrap 重采样的 EMA 估计器——每 20 轮从最近 H_ep=100 个 episode 中有放回重采样，更新三条独立快速 EMA；`σ̂_est,g = sd(p̄_g^{(e)}, e=1..3) / (p̄_g + ε₀)`（相对离散度，便于跨组比较）。**不重训策略**，额外开销 = 3× O(M) 在线统计，≈0.1% wall-clock。
- **方差分解（仅作诊断，不作识别声明）**：组内二项方差（aleatoric proxy）与 bootstrap 离散度（估计量不确定性）并列报告；我们不把两者当作可识别的"真 aleatoric / 真 epistemic"。
- **校准诊断（预注册，A3 的一部分）**：把 σ̂_est 分 5 箱，比较每箱名义 90% bootstrap 区间对**留出重复**（同配置重跑）的覆盖率；目标覆盖率 0.85–0.95。若 <0.70 → σ̂_est 判为不可信，G-1 退化为固定阈值，并在论文中报告（失败模式不隐藏）。
- **为什么仍然需要**：n_g 小（大 N、小 w_g）时 LP 方差 ∝ 1/n_g 会让 u_g^{raw} 爆炸；σ̂_est 是"该不该信这轮估计"的唯一在线信号。A3 消融（σ̂_est≡0）检验其必要性。

### 3.5 分配器：full-information Hedge + 三重 guard

**为什么不是 EXP3-IX（C6 修正）**：每个组每一轮都分到至少 1 个 env、都能观测到自己的 p̂_g，因此这是 **full-information** 设定，不是 bandit。EXP3 的 importance weighting 在这里只会放大方差。v2 主分配器为 **Hedge**（乘性权重），EXP3-IX 降为 A7 消融（用于证明"full-information 假设是对的"）。

**Hedge 更新**（每轮）：

  w̃_g ← w_g · exp(η · û_g)，  η=0.05，û_g = clip(u_g^{raw}, −1, 1)
  w ← ProjectToSimplex(w̃) 受约束：w_g ≥ w_min = 0.5/M，Σ w_g = 1
  w ← (1−ρ)·w_old + ρ·w，  ρ=0.2（信任域平滑）
  单轮硬约束：|w_g − w_g^{old}| ≤ 0.10

**三重 guard**：

| guard | 规则 | 默认参数 | 作用 |
|---|---|---|---|
| G-1 noise | 若 σ̂_est,g > β_noise · \|u_g^{raw}\|，则本轮的 w_g 冻结在上轮值 | β_noise=0.5 | 估计不可信时不改分配 |
| G-2 starvation | w_g ≥ w_min；每组累计 episode < n_min=30 时强制 uniform（warm-up） | w_min=0.5/M, n_min=30 | 防止饿死；n_min 由 §4.2 的 SNR 推出 |
| G-3 信任域 | ρ=0.2 平滑 + 单轮 ≤0.10 | ρ=0.2, Δ_max=0.10 | 防止分配抖动破坏 PPO 的 advantage 归一化 |

> **n_min=30 的推导**（不是拍的）：二项比例在 p=0.5 时 sd=0.5/√n；要求 sd ≤0.09（足以区分 0.4 vs 0.5 的 10 pp 差），n≥30.9 → **n_min=30**。

### 3.6 权重 → env 配额的整数映射

  n_g = max(1, round(w_g · N))，剩余名额按最大余数法分配，保证 Σ n_g = N。

N=256, M=8 时每组的可能配额为 1–64；w_min=1/16 → 至少 16 个 env，满足 n_min 需要每轮每组 ≥30 个 episode——注意 episode 数 ≠ env 数：每轮 L=50 步、episode 长 H=50 步（Squint 全部任务 `max_episode_steps=50`，已核实），则每 env 每轮约 1 个 episode，**16 env × 1 = 16 < 30**。因此 warm-up 在 N=256 时需 **2 轮**，在 N=1024 时需 **1 轮**。这一条必须写进论文（否则 n_min 与 N 的关系会被质疑）。

### 3.7 算法伪代码与 PPO 集成

```
输入: N, M, 分组函数 g(c), PPO 超参, FG 超参(η, κ, β_noise, w_min, ρ, n_min)
初始化: w_g = 1/M, 双 EMA 未就绪 → warm-up 阶段用 uniform
for t = 1..K:                       # K = B/(N·L)
    n_g = IntAlloc(w, N)            # §3.6
    并行 rollout: 每个 env 按 n_g 采样配置 c ~ p(·|G_g)，跑 L 步
    收集 {s,a,r,s'}，更新 PPO（标准实现，UTD=1）
    对每组 g: 统计 p̂_g（本轮 episode 成功率）
    更新双 EMA → ℓ_g, Δℓ_g → u_g^{raw}
    更新 3 条 bootstrap EMA → σ̂_est,g
    û_g = clip(u_g^{raw}, −1, 1)
    w ← Hedge(û, η) → 投影(w_min) → 平滑(ρ) → 变化上限(0.10)   # §3.5
    记录: w, p̂_g, σ̂_est,g, ℓ_g, 每轮 wall-clock
```

- **PPO 不变**：FG 只在 rollout 采样层作用，不改变 loss、GAE、clipping。这一点让"FG 可直接用于任何并行 RL 代码库"成为卖点（也是审稿人喜欢的"plug-in"定位）。
- **异步版本（可选，附录）**：若 Squint 的 ManiSkill3 实现是同步向量化（默认），无需改；若改为异步（IMPALA 式），分配器需按完成 episode 事件触发而非固定轮次——v2 **不做**，仅在 Limitations 提一句。

### 3.9 计算与内存开销（审稿人必问）

- 分配器本身：O(M) 的标量运算 + 3 个轻量 MLP 前向（每轮一次）→ **<1% 的 step 时间**。
- 额外内存：每组 ~20 轮的统计量 + 3 个 MLP（<1 MB）→ 可忽略。
- **不额外跑 rollout**（与"用 ensemble 估不确定性"的重方法不同）：这是 FG 相对 ensemble-RL 方法的成本优势，必须在论文里明确写。

## 4. 理论：一个可检验的"可学性混合"模型

> **诚实声明（写进论文）**：本节不是关于 PPO 收敛性的定理，而是一个**风格化模型（stylized model）**：它把"配置分配是否重要"压缩成可解析的形式，并给出 8 条可证伪预测。论文中必须用这段原话，不能包装成定理。

### 4.1 假设

- **A1（可学性）**：组 g 的成功率按分配到的环境步数 s 演化：p_g(s) = 1 − exp(−a_g·s)，a_g ≥ 0 为**可学性系数**（a_g=0 ⇔ 不可学/纯噪声组）。
- **A2（共享策略）**：所有组共享同一 π_θ，且 a_g 与 θ 无关（在关注的中期尺度上近似成立）。
- **A3（估计）**：p̂_g = p_g + ε_g，ε_g ~ 近似 N(0, p_g(1−p_g)/m_g)，m_g = 每轮该组完成的 episode 数。
- **A4（预算）**：总环境步 B = K·N·L 固定（协议 A），或总更新数 K 固定（协议 B）。

> **A1 的局限必须在 Limitations 写明**：真实 PPO 的 p_g(s) 不是指数曲线（有平台、有遗忘、有课程耦合）。A1 只用于推出**方向性预测**，不用于拟合实验曲线。

> **A1 在哪些任务上近似成立（v3 新增）**：我们**不**假设 A1 普遍成立。可检验的近似度排序（写作时按此讨论）：`PandaPickCube`（目标距离开采驱动，成功率随步数单调上升，近似较好）> `CheetahRun` 速度桶（部分成立，快速饱和）> `Go1JoystickFlatTerrain` 指令桶（部分成立，欠驱动耦合）> `HumanoidRun`（近似差：平台、遗忘、高维）。因此 §4.3 的"水填充"只用于解释**权重排序的方向**（w_g 随 â_g 增、随 σ̂_est 减），不给出可直接套用的最优权重公式；若 HumanoidRun 结果与预测方向相反，按预注册的"模型局限"披露，**不改理论**。

### 4.2 单轮噪声与 EMA 滞后（C8 修正）

- **每组每轮的 episode 数**：m_g = w_g·N·L/H（H = episode 长度）。
- **单轮估计噪声**：sd(p̂_g) = √(p_g(1−p_g)/m_g)。
- **LP 的估计噪声**（ℓ_g 为两个 EMA 之差）：sd(ℓ_g) ≈ √(2·p_g(1−p_g)/(m_g·H_ep))，其中 EMA 窗按 **episode 数** H_ep 定义（H_ep^fast=20、H_ep^slow=100）。

由此得到两个**不同**的量（v1 把它们混为一谈，是 C8 的根源）：

1. **单轮精度**：SNR_ℓ = Δp / sd(ℓ_g) ∝ **√(w_g·N·L·H_ep/H)** → **∝ √N**。这是 P1 要检验的量（协议 B 下对 log N 回归，期望斜率 0.5）。
2. **响应滞后**（以"轮"计）：τ_g = H_ep·H/(w_g·N·L) → **∝ 1/(w_g·N)**，即 N 越大，同样的 episode 窗在更少的轮次内填满 → **墙钟响应更快**。

两者不矛盾：一个是"一轮内的精度"，一个是"积累窗口所需的时间"。

### 4.3 分配收益的解析形式

在 A1 下，固定权重 w 的终局目标为

  J(w) = 1 − (1/M) Σ_g exp(−a_g·w_g·B)

- **uniform**：w_g=1/M。
- **oracle**（已知 a_g）：解 a_g·exp(−a_g w_g B)=λ，得 w*_g = (1/(a_g B))·ln(a_g B/λ)（水填充），s.t. Σw*=1。
- **FG**：用估计的 â_g 代替 a_g，误差 ~1/√(m_g·H_ep)。

**三条直接可读出的结论**：
1. **收益随异质性增长**：ΔJ(FG−uniform) 随 {a_g} 的离散度（如 CV(a_g) 或 max/mean）单调增；a_g 全相等时 ΔJ=0。→ **P1**。
2. **收益随 B 增长而衰减**：B→∞ 时所有 learnable 组饱和，ΔJ→(不可学组占比)；因此**收益是"中期限"现象**，论文必须报告"何时收益消失"，而不是只报终点。→ **P2**。
3. **FG 与 oracle 的差距 ∝ 1/√N**：估计精度随 N 提升，但 **FG 与 uniform 的差距（领先项）与 N 无关** → **N×method 交互不显著**。→ **P3**（这就是 H2）。

### 4.4 核心判据：success-band 何时足够？（两个可测不等式）

SGS 的 success-band 把组分成三档（never-solved / improving / mastered），等价于用**分段常数**函数近似 a_g。它足够的条件是**两个不等式同时成立**：

**(i) 可分辨条件**：观测噪声必须小于相邻组的真实可学性差
  σ_obs < Δ_min/2，其中 σ_obs = sd(p̂_g)，由每轮组内 episode 数 m_g = w_g·N·L/H 决定；Δ_min = 相邻配置在 p 空间的最小真实差（pilot/oracle 估计）。

**(ii) 无 aleatoric 混淆条件**：配置级随机性不得把"随机成功"误判为"正在进步"
  σ_a < Δ_min/2，其中 σ_a = 同一配置**重复运行**的固有成功率标准差（物体初始位姿敏感性、相机噪声、p_slip、接触随机性）。

**当 (i) 被破坏**（N 大、w_g 小 → m_g 小 → σ_obs 大）：success-band 的 "improving" 判据被噪声触发，分配退化为"追逐噪声组"。**关键推论：(i) 的破坏随 N 增大而加剧**——这是"大 N 反而更需要好信号"的定量理由，也是 fixed-K 下 H1 的机制来源（P1 的 SNR ∝ √N 给出对照）。
**当 (ii) 被破坏**（任务本身随机）：success-rate 的任何单调变换都无法区分"配置难"与"配置随机"；必须用**跨 episode 趋势**（LP 导数）与**方差门控**。**(ii) 是否被自然破坏不由我们说了算——由 §5.8 的域内噪声审计判定（H4a）**；合成注入（H4b）只作受控验证。

> **写作纪律**：论文里"success-band 何时失效"必须是**判据 + 测量**，不能是断言。§4.6 给出权重映射与 success-band 关系的严格表述与"不声称"清单。

### 4.6 与 success-band 的关系：三档单调近似（不是特例）

v2 写过"SGS 是 FG 的特例"，这是**过度声称**（judge 已标为硬伤）。v3 的准确表述：

**命题（近似关系，非算法等价）**：在以下五条同时成立的极限下，FG 的权重分配退化为"按 band 加权 + 周期性重分配"，与任一 success-band 三段式分配器**按构造单调相容**：
1. κ=0（关掉 LP 导数项）；
2. σ̂_est≡0 且 β_noise→∞（关掉不确定性门控）；
3. 去掉 G-2/G-3（w_min=0、无平滑、无变化上限）；
4. û_g 量化为三档（阈值固定为 band 定义：never=0 / improving=1 / mastered=0）；
5. η→0 且 band 不变期间不更新分配。

**但不覆盖**：SGS 的阈值（具体 cut-point）、重采样比、调度（何时重采样）、per-env 配置固定策略、success 历史 buffer 的长度与衰减。因此：
- 我们**不声称** SGS 是 FG 的特例，也不声称"FG 在所有设置上严格更优"；
- 我们声称：**判据 (i)(ii) 给出 success-band 足够/不足的边界**，且 FG 在 (i) 或 (ii) 被破坏时有可测优势——由 H1/H4a/H4b 检验；
- 附录 C 给出五条条件的逐条对照，以及"任一条不满足时预期差异"的定性说明（不做定量承诺）。

### 5.6 统计规范（预注册）

| 项 | 规定（v3 修订） |
|---|---|
| 主终点 | **协议 B（fixed-K）** 的 final success rate（最后 10% 更新窗口均值） |
| 次终点 | 协议 A（fixed-B）final success；协议 C 描述性 |
| seeds | **T2-Bmain（主格）8**；T2 N=2,048 确认格 5；T2 breadth 3；T1-A **4**（M10 修订）；消融 3 |
| 模型 | 线性混合效应：J ~ method + log₂N + method×log₂N + (1\|task) + (1\|seed)；主终点单独报告 method 主效应 |
| 多重比较 | 预注册 5 个主比较（H1 族）× 分层 Holm：family 1 = Tier-2，family 2 = Tier-1；其余标 exploratory |
| **等价性** | H2/P3 用 **TOST**：等价界 **Δ=±2.5 pp**（logit 尺度上的交互项），α=0.05 单侧；同时报 90% CI |
| 效应量 | Cohen's d、Cliff's δ、差值比例的 95% bootstrap CI（10,000 次） |
| 功效 | **T2-Bmain 每个 N 档 n=32 对（4 任务×8 seeds）**、pairwise；按 seed 间 σ≈5 pp → 可检 **≈2.5 pp**；T1-A 4 seeds（16 对）→ 可检 **≈3.5 pp**（Tier-1 只按"方向一致"判） |

| 数据 | 全部 run 进 artifact（含失败/崩溃 run），报告失败率；不做 cherry-picking |

### 5.7 机制指标（回答"为什么有效"，而不只是"更好"）

| 指标 | 定义 | 对应假设 |
|---|---|---|
| **分配 regret** | R_t = Σ_g \|w_g^{(t)} − w*_g\|（w* 为 oracle 水填充） | P3/H1 |
| **浪费率** | 投在 a_g=0 或 p_g>0.95 的组的样本占比 | P2/H4 |
| **饥饿事件** | 任意组连续 >5 轮 w_g=w_min 的次数 | P5 |
| **抖动** | mean_t Σ_g \|w_g^{(t)}−w_g^{(t−1)}\| | P6 |
| **响应滞后** | 人为改变分布后 w 恢复到新最优 90% 所需轮数 | P6 |
| **min-group 成功率** | 最差组终点成功率（公平性/不放弃） | P5 |
| **σ̂_est 校准** | 名义 90% 区间覆盖率（分 5 箱），目标 0.85–0.95 | A3/M4 |
| **分配熵** | H(w) = −Σ w_g log w_g，与 uniform 的偏离 | H1（机制） |
| **墙钟效率** | 协议 C 下 J(T) 与 N 的关系 | ICRA 工程相关性 |

### 5.8 域内自然噪声审计（v3 新增，M7，judge ROI 最高项）

**目的**：把"success-band 在随机任务上失效"从**合成注入的主张**升级为**域内自然成立的测量**（H4a/P7）。这是 v3 相对 v2 最可能翻盘的一处。

**步骤**：
1. **日志聚合**（0 GPU-h）：对 T2-L2（协议 A）与 T2-Bmain（fixed-K）的全部 run，按 (任务, bucket, 轮) 抽出 per-config 的 episode 结果序列。
2. **σ_a 估计**：对每个 (任务, bucket)，用 beta-binomial / bootstrap 分离 (a) 同一配置内重复运行的固有方差 σ_a 与 (b) 不同配置间差异；σ_a 取组内方差的池化估计（含 DR 位姿随机性——Squint 的 DR 本身就是域内噪声源）。
3. **Δ_min 估计**：由相邻 bucket 的成功率差（pilot 的 N=1,024 long run）估计 p 空间最小真实差；报告 bootstrap CI。
4. **判据检查**：对每个 (任务, bucket) 计算 `σ_a / (Δ_min/2)`；≥1 即"判据 (ii) 被自然违反"。
5. **定向重跑**（20 GPU-h）：从 2 个任务各取 4 个 bucket，固定配置重复 5 次 × 3 seeds = **15 runs**（N=1,024、B=15M，1.44 h/run ≈ 21.6 h），把 (a) 从"日志推断"变为"直接测量"。

**预注册判定规则**：
- ≥1 个 (任务,bucket) 的 σ_a ≥ Δ_min/2 且 CI 下界 >0 → **H4a 成立**（论文主图 Fig.5：σ_a vs Δ_min/2 散点 + 判据线）。
- 全部 <Δ_min/2 → H4a 失败，按 N2 分支诚实报告"SGS 在 SO-101 域内足够"，并把不确定性门控降级为"针对 (i) 的机制"。
- 临界（CI 跨线）→ 报告"不确定"，不据此下结论。

**成本**：20 GPU-h 租卡 + 日志分析 ≈ ¥50（§6.2 T2-N 行）。**为什么不放在真机之后**：它决定主叙事，必须 W18–W20 完成（早于 W24 决策）。

### 5.9 K-sweep pilot（v3 新增，M1/M2）

**目的**：验证"固定 B 下的大 N 变差是更新饥饿"这一前提（G-S3），并校准主协议 B 的 K=1,172。

**设计**：任务 `SO101LiftCube-v1`；N=1,024；L=50；方法 {uniform, FG}；K∈{146,293,586,1172}（对应 B=7.48M/15M/30M/60M）；3 seeds → **24 runs**；周 = W9（租 4090，63.7 GPU-h ≈ ¥159）。

**输出与判据**：
- 曲线：final success vs K（2 方法 × 4 K）；若 uniform 在 K=146 比 K=586 低 ≥5 pp → **饥饿存在（G-S3 通过）**；
- 差距 Δ(K)=J_FG−J_uniform 的斜率：若 Δ 随 K 减小而增大（H9/P8）→ 支持"大 N 需要更好分配"；若 |斜率|<0.5 pp/倍 → 记"K 选择不敏感"，H3/H9 降级为描述性；
- 估计 K*（uniform 曲线的拐点）并检查 K=1,172 是否落在平台段（若是，主协议 K 的选择有依据）。

### 5.10 真机协议（2× SO-101，v3 修订）

**硬件与场景**：2 台 SO-101 + LeRobot；**3D 打印物体**（bin 白 / can 蓝 / cube 红 / large_cube 蓝，STL 在 `deploy_utils/blender_stls`）；黑色桌面背景 overlay（`envs/black_overlay.png`）；相机与关节对齐调参、电机标定。**这些前提条件 v1 未计工程量，v3 计入 W20–W22 的显式任务（3D 打印 2 人日、deploy 改造 3–5 人日）**。

**设计细节**：
- 任务：**LiftCube**、**PlaceCan**（sim 训练成本最低、真机复现最稳；与 §5.2 的 bucket 定义一致）。
- 方法：**uniform / SGS-band / FG**，各用 1 个训练 seed 的 N=1,024 checkpoint，**零样本 RGB 迁移**。
- **配对设计**：同一组 45 个场景布局（物体位姿/目标区域记录）在三方法间复用 → McNemar；2 轮独立训练 seed → 合并 90 个配对（每任务），两任务共 **180 对**。

- 评分协议：成功 = 物体被抬起 ≥5 cm 并（Place 任务）落入目标区域，60 s 内完成；**双人盲评**（视频随机编号、方法隐藏），Cohen's κ ≥0.8，分歧由第三人裁定。
- 随机化与漂移控制：方法顺序按 block 随机化；每 10 trials 复位/校准；记录温度与光照为协变量。
- 硬件故障：预注册"可排除但必须报告"；排除率 >20% 则整轮作废。
- **人工预算（v3 修正，judge F）**：pilot 90 trials ≈ 4 h 执行 → 1.5 人日；主实验 540 trials ≈ 27 h 纯执行 + 复位/校准 ≈ **35 h → 6 人日**；打印 2 人日；deploy 改造 3–5 人日；retry/标定 2 人日 → **合计 ≈12–14 人日**（v2 写 5–6 人日偏乐观，已修正）。
- **功效（真机）**：pilot n=90 配对，15 pp 差 power≈0.8、10 pp≈0.2（**不可测**）；主实验 n=180 配对，15 pp≈0.8、10 pp≈0.45–0.5（仍不主张）。故论文只主张"方向 + 效应量 CI"，Limitations 写 "underpowered for 10 pp differences"。

### 11.3 Rebuttal bank（10 条预写，含审稿人原话）

1. **"SGS with a different allocation signal… what is genuinely new?"** → 本文与 SGS 是**三档单调近似**（不是特例，见 §1.6/§4.6，不覆盖阈值/调度/重采样比，近似条件已写明）；判据 (i)(ii) 解析地说明何时 success-band 失效；fixed-K 控制证明增益不是"更多更新"；TOST 给出等价边界；同层 head-to-head 直接对比（Table 2/Fig.3）。
2. **"SGS is a special case is asserted, not proven"** → v3 **删掉该断言**，改为"三档单调近似"（§4.6），给五个成立条件与不覆盖项（阈值/调度/重采样比），并明确不声称包含 SGS。
3. **"2^11–2^14 vs 2^20 scale mismatch"** → 承认；我们的贡献是"信号设计 + 判据"，不声称规模；在 Limitations 明写，并把 2^20 列为 future work（SGS 的 2^20 需要 GPU 集群，1 人 45 周不可及）。
4. **"σ_epi is sampling variance, not model epistemic uncertainty"** → v3 已改名"估计量不确定性 σ̂_est"，给出 bootstrap-EMA 定义与校准诊断（5 箱覆盖率），不声称 model epistemic。
5. **"N=2048 gives only 146 PPO updates, methods are update-starved"** → 这正是 fixed-K 主终点的动机；K-sweep 直接测（T2-K）；协议 A 作为部署区制附录。
6. **"Noise injection constructed so baseline fails / no natural noise evidence"** → v3 加**域内自然噪声审计**（Fig.5，从现有日志估计 σ_a vs Δ_min/2），注入实验降级为"受控验证"。
7. **"Two tasks 45 trials CI ±10pp, no power analysis"** → pilot 90 trials + 门控；主实验 180 配对（15 pp power≈0.8）；10 pp 时明确写"功效不足，只报方向与 CI"。
8. **"Theory paper + benchmark paper + robot paper compressed into six pages"** → 6 页重排（Method 1.2/Theory 0.4/Exp 2.3），理论只留判据与 P 表，MT10 与推导进附录。
9. **"Training efficiency, not a new robot capability"** → 真机零样本迁移 + 部署视频；同时把"可及性"（单卡、200 行钩子、2 台 SO-101）做成第一类贡献（§1）。
10. **"Budget/feasibility unrealistic"** → 逐行可审计预算（附录 D 脚本）+ 峰值占空比 52% + 最坏情景 L1/L2 削减规则。

### 11.4 写作纪律

- 每个数字都能追溯到 run ID 或日志路径；**不写"我们已得到"**，只写"预期/将检验"。
- 负结果与边界写进 Abstract 最后一句（"we also characterize when…"），降低被攻击面。

## 附录 D：预算审计脚本（v3.1 版，可直接运行并复算）

```python
# -*- coding: utf-8 -*-
# v3.1 预算复核：fixed-K 行按 B=K*N*L（h/run 取表中 2 位小数）；逐行 -> ¥
THRU = {64: 600., 256: 1500., 1024: 3000., 2048: 3800.}   # steps/s（假设，W2 实测替换）
PRICE = {"local": 0.0, "4090": 2.5, "A100": 8.0}
L = 50.0
KB = 1172.0

def hours(B, N, ov=0.05):
    return B / THRU[N] / 3600.0 + ov

# (name, runs, B, N, platform, fixed_hours)  —— fixed_hours 非空时用该值（显存测试/调试）
rent = [
    ("T2-00b",     0,  0,     0,    "A100", 3.0),
    ("T2-Bmain-R", 96, KB*1024*L, 1024, "4090", None),   # fixed-K 主格
    ("T2-R2",      60, 15e6,  2048, "4090", None),        # protocol A
    ("T2-R3",      48, 15e6,  1024, "4090", None),        # protocol A
    ("T2-R4",      24, 15e6,  1024, "4090", None),        # protocol A
    ("T2-R5",      36, 15e6,  1024, "4090", None),        # protocol A
    ("T2-R6",      18, 30e6,  1024, "4090", None),        # protocol A
    ("T2-N",       15, 15e6,  1024, "4090", None),        # protocol A
    ("T2-S",       0,  0,     0,    "4090", 60.0),
]
# T2-K: fixed-K sweep: N=1024, 2 methods x 3 seeds x K in {146,293,586,1172}
k_h = sum(6 * hours(k*1024*L, 1024) for k in (146, 293, 586, 1172))
rent.append(("T2-K", 24, 0, 0, "4090", None))

local = [
    ("T2-00a",     36, 3e6,  256, "local", None),   # protocol A
    ("T2-L1",       5, 15e6, 64,  "local", None),   # protocol A
    ("T2-L2",     192, 15e6, 256, "local", None),   # protocol A（fixed-B 对照）
    ("T2-Bmain-L", 96, KB*256*L, 256, "local", None),  # fixed-K 主格
]
# 表中 h/run 取 2 位小数（5.61 / 2.83），与 §6.2 一致
BMAIN = {"T2-Bmain-R": 5.61, "T2-Bmain-L": 2.83}

tot = rent_h = local_h = 0.0
for name, runs, B, N, plat, fh in rent:
    if name == "T2-K":
        h = k_h
    elif name in BMAIN:
        h = runs * BMAIN[name]
    elif fh:
        h = fh
    else:
        h = runs * hours(B, N)
    cost = round(h * PRICE[plat])
    print(f"{name:11s} {runs:4d} runs {h:8.1f} GPU-h  ¥{cost:5d}")
    tot += cost; rent_h += h
for name, runs, B, N, plat, fh in local:
    h = runs * BMAIN[name] if name in BMAIN else runs * hours(B, N)
    print(f"{name:11s} {runs:4d} runs {h:8.1f} GPU-h  (本地)")
    local_h += h

totals = round(tot * 1.12)
print(f"\n租卡小计 ¥{tot:.0f}（{rent_h:.1f} GPU-h，{sum(r[1] for r in rent)} runs）")
print(f"含 12% 缓冲 ¥{totals}（+{totals-tot}）")
print(f"+电费/杂项 ¥285 → ¥{totals+285}")
print(f"本地 Tier-2 {local_h:.1f} GPU-h（{sum(r[1] for r in local)} runs）")
print("期望：租卡小计 ¥2421（962.0 GPU-h，321 runs）；含缓冲 ¥2712；总计 ¥2997；本地 871.4（doc 871.5，逐行取整差 0.1）")
```

复算结果：**租卡 ¥2,421（962.0 GPU-h / 321 runs）→ 含 12% 缓冲 ¥2,712 → +电费/杂项 ¥285 = ¥2,997**；本地 Tier-2 **871.4 GPU-h / 329 runs**。逐行进位使「GPU-h×单价」与逐行取整合计差 **¥16**（962.0×2.5=2,405 vs 2,421），偏保守。
