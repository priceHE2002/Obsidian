# 最终研究方案：DexWeaver
## 通过执行驱动练习，学习可由 LLM Agent 组合的灵巧操作技能

**英文工作标题：** *DexWeaver: Learning Agent-Composable Dexterous Skills through Execution-Grounded Practice*

**版本：** v1.0 · 研究方向重置版  
**制定日期：** 2026-11-02  
**文档性质：** 可执行的研究与实验方案；不是已完成论文，不含虚构结果、已证定理或精确录用概率。  
**替代范围：** 替代 `99C_FINAL_DEXTEROUS_PLAN.md` 与 `26_synthesis_v3.md` 的论文定位、核心贡献、实验矩阵、预算及投稿路线；旧文仅保留工程经验，不再作为理论主线。[U1][U2]

> **最终目标：让 Sharpa 灵巧手通过 GPU 并行强化学习，获得可复用、可恢复、可组合的物理操作技能，再由 LLM Agent 根据指令和执行反馈组织这些技能，完成未见的长程装配任务。**
>
> **主要贡献必须发生在“技能如何学得更好”上，而不是“如何给现有技能测成功率、算证书或证明接口测量复杂度”上。**

## 0. 一页决策摘要

### 0.1 本次明确保留的用户目标

- **平台：** Sharpa 五指灵巧手 + KUKA 机械臂；以 Play2Perfect 官方代码和公开 play 预训练模型为工程起点。
- **任务：** AlphaNIST 同款 NIST ATB1 装配问题；迁移到上述灵巧手平台，不冒称原论文原样复现。
- **技术主体：** GPU 并行强化学习、物理技能学习、多任务迁移、长程技能组合。
- **Agent：** LLM 负责理解任务、选择技能、传参、验证结果和重规划；不逐帧产生关节控制。
- **阶段：** 先仿真，不把采购真机、触觉硬件、sim-to-real 或从零训练大模型设为前置条件。
- **现有算力：** 按已有 RTX 4070 Ti Super 16GB 用于开发、小规模训练与评测；大并行实验使用经过实测的同型号租赁 GPU。
- **预算：** 先沿用旧方案约人民币 5,000 元总上限进行可行性核算；该数字是项目约束，不是已验证足够完成所有实验的报价。

### 0.2 最终选择的研究问题

**在同样的总体仿真与训练成本下，如何选择下一批练习，让学到的灵巧技能更有利于完成未见的长程任务？**

不是再问“哪个初始状态成功率约 50%”，也不是只问“哪个任务失败最多”，而是问：

> **练习这一类操作之后，整个技能库在其他操作和组合任务上的能力，是否真的提高？这种提高是否值得练习和验证的成本？**

### 0.3 唯一主要算法改动

提出待验证方法 **执行驱动练习（Execution-Grounded Practice，EGP）**：

1. 从实际训练任务执行中收集可恢复的物理状态与目标，不只使用人工整理的理想起点。
2. 将可练习场景组织为少量“技能 × 物体/接触情境”练习桶。
3. 从同一个策略检查点做短程、等成本的候选练习与参考练习。
4. 在独立的**训练用途探测任务集**上比较完整任务收益，估计“练什么更有用”。
5. 用该收益分配后续大批量并行 RL；LLM 执行产生经验，但不凭语言判断决定奖励或宣称技能已经掌握。

**新意不是“用了 LLM”“用了 PPO”“用了迁移收益”或“用了失败回放”。这些都有前作。** 拟贡献是：面向高自由度、接触丰富的技能学习，把**实际长任务收益、可复用练习状态、等成本参考更新与全成本核算**连成可复现训练闭环，并证明它优于廉价的难度、学习进度、失败回放和梯度迁移基线。[S3][S6][S7][S8][S9]

### 0.4 不能预支的结论

目前不能保证该算法优于 SGS、TAC 或经验迁移调度，也不能保证 5,000 元能完成投稿级实验。以下均为实验假设，而不是既成事实。

**提高投稿竞争力的路径：一个清晰训练贡献 + 强近邻对照 + 连续执行泛化 + 全成本公平性 + 可复现代码。**

本方案不再给出“41%”“55%”“65%”之类未经校准的中稿率；也不承诺“修完一定录用”。

## 2. 已核实的技术基础与最近邻：哪些事已经有人做过

本节是截至 2026-11-02 的公开资料核查。其余算法、阈值、任务划分和预算算例是本方案设计，不是文献结论。

### 2.1 工程基础

**Play2Perfect。** 官方代码公开了 Isaac Sim/Isaac Lab 训练流程、play 预训练与装配微调、检查点下载和评测入口；论文机器人为 22-DoF Sharpa 手与 7-DoF KUKA iiwa 14。本文优先复用其基础设施。其论文也明确把任务顺序、对象选择等留给外部系统，因此存在完整任务执行层面的拓展空间；但“接一个规划器”本身不构成充分创新。[S1][S2]

**AlphaNIST。** 已研究共享策略在 NIST ATB1 全部 20 类装配任务上的训练，以及独立训练的十零件连续装配策略。因此本研究不能以“首次多任务装配”或“首次长程装配”为卖点。其公开论文仍描述后续发布代码的计划，本方案不等待未核实的官方训练代码，不把第三方实现当官方复现。[S4]

**SGS。** 已通过配置成功率的 beta 型权重分配训练经验，且研究了并行规模。因此“难度适中采样 + 更多并行环境”不是本文创新。官方项目页查询时仍写 code coming soon；实现状态以实际获得的代码版本为准。[S3]

**NIST 资产。** 官方提供任务板与部件的 CAD/STL 等资源。几何资产可用不等于已经有适配 Sharpa 的高保真接触环境；碰撞、尺度、惯量、关节/螺纹与成功判定仍需工程验证。[S5]

### 2.2 必须正面比较的相关工作

| 近邻 | 已有能力 | 本研究不能重复声称 | 本研究要额外证明 |
|---|---|---|---|
| Play2Perfect / ADEPT | 灵巧预训练与下游操作学习 | “先学通用操作再装配”是首次提出 | 训练分配提高未见任务组合，而非只提高孤立装配 |
| AlphaNIST / SGS | 多任务、状态覆盖、成功引导的规模化 RL | “共享策略 + 采样”本身新颖 | 相同成本下，收益导向练习优于难度导向练习 |
| HAFER | 技能转换、失败经验回放 | 把失败留下重练是新机制 | 胜过失败回放，而不是仅利用更多失败数据 |
| ReSYNC | 从失败中学恢复技能与规划概念 | “失败→学习→重新规划”首次提出 | 聚焦灵巧运动能力增长与跨组合迁移，而不是符号概念学习 |
| TAC | 用梯度迁移关系进行课程调度 | 迁移收益感知课程首次提出 | 在物理长任务中，实测收益是否足以抵偿额外探测成本 |
| Omni-Thinker | 以实际准确率迁移指导调度 | “先训练再看其他任务提升”是首次提出 | 等成本参考更新、执行状态分布和组合目标的增量价值 |
| SayCan | LLM 与低层技能结合执行 | LLM 调用技能即为新贡献 | 新训练策略带来能力增量，而非只更换高层提示词 |
| PLR | 依据学习潜力回放任务实例 | 优先重放难任务/高误差任务首次提出 | 超越已有学习潜力调度 |

来源：[S3][S4][S6]–[S12]。

### 2.3 新颖性判据

必须同时满足以下条件，才把论文写成“新的技能学习方法”：

- 相对于 SGS/PLR，增益不是仅因获得了更丰富的状态库。
- 相对于 FER，增益不是仅因重练失败。
- 相对于 TAC 和 BWT 调度，增益不是仅因加入“迁移”这个词。
- 在相同高层规划器下仍有增益，排除 LLM 提示词变化。
- 将探测、验证和状态生成成本全部算入后，仍有实际优势。
- 最终成功发生于未参与训练调度的连续任务，而不是训练探测集。

如果这些条件不满足，不能通过更换标题、增加未经证明的定理或隐藏基线维持强算法主张。

**最强的新颖性风险：** “实际练习 + 迁移探测”本身也不是全新范式。本方案提出的是需要实证验证的具体改进，不因机器人应用不同就自动成立。若参考分支、组合目标与执行经验相对于 BWT/TAC 没有明确增量，应删除多余机制、保留最佳简单方法，并把结果如实定位；不能宣称必然具备顶会新颖性。

## 3. 论文核心：一条因果链，三项可验证主张

### 3.1 核心假设

**只按当前任务成功率分配练习，未必能最大化最终可组合操作能力；以实际跨任务收益校正练习分配，可能让有限仿真预算产生更可复用的灵巧技能。**

“可能”必须由实验确认。

### 3.2 三项拟贡献

**C1 — 训练方法。** 一个以实际执行经验为练习来源、以等成本参考更新为对照、以跨任务完成收益为调度信号的 GPU 并行强化学习方法。

**C2 — 能力证据。** 在独立技能、扰动恢复和未见连续组合上，测出技能学习带来的能力增长；并在同总成本下比较强课程学习基线。

**C3 — 完整系统与可复现任务协议。** 让固定 LLM Agent 调用冻结技能库完成新指令，公开任务、划分、动作约束、预算和日志，使“真的学会”与“规划更会说”可以区分。

C2、C3 是支持 C1 的证据，不再另起两套数学故事。

### 3.3 论文不主张什么

不主张首次把 RL、灵巧手与 LLM 结合；不主张无监督技能发现；不主张无任务奖励预训练；不主张最优课程；不主张理论 scaling law；不主张安全认证；不主张 state-based 仿真已经解决真实视觉与触觉。

本版与用户曾考虑的“迁移收益感知目标生成”保留思想联系，但**当前使用任务/技能成功标签，不包装成完全自监督预训练**。Self-Evolving Reflexes 可作为后续研究，不再同时塞入本篇。

## 4. 机器人、物理任务与技能库

### 4.1 平台冻结

**主平台：Sharpa + KUKA，Play2Perfect 官方 Isaac Sim 路径。**

不同时移植 Isaac Lab、MuJoCo、Newton 三套引擎。开发阶段先锁定官方仓库一个可运行 commit、环境版本、资产与 checkpoint hash。若公开检查点与当前代码不兼容，首先修复版本匹配；不假定下载成功就能直接训练。

工程复现可以使用公开装配检查点检查物理和控制；**正式算法比较统一从同一个公开 Stage-1 play checkpoint 起步**，不得让某个方法额外使用已针对测试任务微调的模型。

### 4.2 技能的定义

技能是受目标条件控制的闭环物理策略，不是 LLM 生成的文本步骤，也不是手写关节轨迹。

建议固定以下六类语义操作。它们是本研究设计的学习目标，不是声称从零自动发现的六种技能。

| 技能 ID | 人话解释 | 主要目标条件 | 成功判定原则 |
|---|---|---|---|
| `pick_lift` | 抓住并抬起物体 | 对象、目标高度、工作区 | 物体抬升且持续受控，非短暂弹起 |
| `reorient` | 在手中/允许的支撑接触下改变姿态 | 对象、目标姿态 | 姿态误差与持稳时间达标 |
| `place_release` | 放到指定位置并释放 | 对象、目标区域/姿态 | 放置稳定、手已退出，不扰动已完成组件 |
| `insert` | 对准并完成插接 | 对象、配合件、完成位姿/深度 | 完成几何关系、稳定且无穿模 |
| `turn_fastening` | 旋转、锁合或旋拧 | 对象、轴/螺纹几何、目标进度 | 真实接触运动达到终态，不把角度变化直接算装配 |
| `recover` | 脱离卡滞、重新获得可控状态 | 恢复目标：自由零件/稳定抓持/安全退离 | 达到预定义可继续操作条件，而不是靠重置场景 |

`recover` 的运动同样由 RL 学习。其语义目标可以细分，但不能把手写脱困轨迹伪装成策略能力。

六类技能可共享一个条件策略；不必训练六个完全独立的大网络。对象型号、姿态和指令措辞不是新的“技能数量”。

### 4.3 ATB1 任务选择与范围

按 AlphaNIST 公开示例与 NIST 资产，主套件优先纳入下列 **8 个装配实例目标**：

1. 8 mm rod；
2. 8 mm peg；
3. M12 nut；
4. M16 nut；
5. medium gear；
6. waterproof connector；
7. D-sub connector；
8. USB-A connector。

这些任务名称与部件类型有公开来源；具体 Sharpa 版本、合法技能组合、碰撞参数与成功阈值是待实现内容。[S4][S5]

**启动子集只用三类：杆/销插接、齿轮放置、较大螺母旋拧。** 通过基本学习 gate 后才扩大到八实例。小型螺纹、柔性件、需要第二只手的自由配合件不作为首轮依赖。

若某任务无法在原尺寸下稳定模拟，应明确作为未完成任务报告，或在训练冻结前按公开工程原因替换；不得看完最终方法排名后再删掉不利任务。

### 4.4 灵巧性必须实证，而不是由手的自由度代言

建立三种独立诊断：

- **手内重定向：** 限制腕部可完成的姿态变化，观察手指相对运动与物体在掌中的运动。
- **受限抓持插接：** 初始抓持并非直接可插，是否能通过重抓/手内调整完成。
- **接触扰动恢复：** 训练与测试扰动区间分离，观察滑移后恢复、卡滞后退离重试。

必须同时报告机械臂/手指的控制贡献。至少对诊断任务加入冻结手指或固定抓持的对照；不宣称这个对照能完全隔离所有动力学因素。

不能仅凭“换成五指手完成普通抓取放置”证明获得了高水平灵巧操作。

### 4.5 两个层次的任务

**低层练习任务：** 某技能在某物体与接触情境下达到可验证目标。

**完整程序任务：** LLM 根据指令调用多个技能，在同一连续 episode 内完成多对象目标。

首版完整任务按计划预算分为 **4、8、12 次技能调用**，不是固定要求每个任务必须正好走该步数。报告实际调用数、物理时长和重试数，防止方法通过冗长重复获得不公平优势。

示例：
“先把杆件放入指定孔，再装配齿轮；保持已经完成的部件不被碰倒。若连接器卡住，先恢复到可控状态，再继续装配。”

正式任务图必须有真实顺序、目标选择或遮挡约束，而不只是把独立的装配视频拼接起来。

## 5. 系统架构与训练初始化

```text
用户指令 + 当前可观测场景
            |
            v
固定 LLM Agent
任务分解 / 选择技能 / 传参 / 执行结果反馈 / 重规划
            |
            v
类型检查与执行器
合法技能、对象、目标、超时、重试和关节限制
            |
            v
共享的目标条件灵巧策略
pick / reorient / place / insert / turn / recover
            |
            v
Sharpa + KUKA 连续物理仿真
            |
            +----> 任务结果与可恢复状态 --> 训练专用练习库
                                             |
                                             v
                                EGP：收益驱动练习分配
                                             |
                                             v
                                     GPU 并行 RL 更新
```

### 5.1 策略形式

\[
a_t \sim \pi_\theta(a_t\mid o_t,h_t,z,g)
\]

- \(o_t\)：关节状态、物体相对位姿、目标与所需场景特征。
- \(h_t\)：循环网络历史。
- \(z\)：六类技能之一。
- \(g\)：目标对象、目标位姿/配合件、恢复目标等结构化参数。
- \(a_t\)：沿用已验证的机械臂/手部控制接口，不让 LLM 直接输出控制量。

以公开 play 网络为起点，优先添加小型条件模块与必要的价值头；新增条件模块用尽量不破坏旧策略的初始化。所有算法使用相同结构、输入、初始化和可训练参数。

**共享参数是“练习一个场景可能迁移到其他技能”的载体。** 独立策略无共享时也可研究调度，但不得假装存在同样的参数迁移。

### 5.2 算法选择

训练内环沿用官方代码已经工作的 PPO/SAPG 路径，整个对照矩阵保持一致。初期不要同时改变优化器、网络、奖励和课程。Play2Perfect 实际采用的训练框架包含 SAPG，不能不加说明地把所有结果归因于普通 PPO。[S1][S2]

不承诺某个并行环境数一定适配 16GB 显存。开发目标从 64–512 环境实测；租卡训练拟测 512、2,048、8,192 三档，8,192 若无法运行，就冻结为可稳定运行的三个档位并准确报告。不能把 8K 结果包装成 million-scale。

### 5.3 观测边界

主研究首先是 **state-based simulation**：

- actor 可使用仿真提供的位姿等状态，但必须清楚标注；
- critic 的额外信息单独列出；
- 不宣称已经具备 RGB-only、触觉闭环或真实世界感知；
- LLM 得到的是同一观测管线产生的结构化场景，不是未来状态或测试答案；
- 可增加小规模噪声/缺失观测压力测试，但不再启动完整视觉学生训练作为必做项。

## 6. 核心方法 EGP：选择真正提高整体操作能力的练习

### 6.1 为什么不是“再加一个失败缓存”

训练数据来源固定为三类：

1. **通用覆盖池：** 随机起点、稳定抓持、接近目标等合法状态。
2. **执行经验池：** 训练指令执行时出现的状态，包括成功、中间进度和失败前状态。
3. **能力保持池：** 已掌握任务的代表样本，防止只练短板而遗忘。

失败池不是唯一来源；不可恢复终态不反复当成“最难任务”过采样。回放的是**起始状态与目标**，随后重新采集当前策略轨迹；不是把旧动作轨迹直接塞进 on-policy PPO。

### 6.2 练习桶，不建立技能对接口矩阵

令 \(b\in\mathcal B\) 表示练习桶，例如：

- 长杆抓取后姿态调整；
- 斜抓连接器的对准插接；
- 受侧向约束的螺母旋拧；
- 部件滑移后的重新抓持；
- 近配合位姿下的退出与再次接近。

初期固定 **12–24 个桶**，由技能目标、物体几何/接触情境划分；不是任意增大桶数。每桶具有合法性检查、目标谓词和状态生成/恢复记录。

这里的研究对象是**练习对策略参数的影响**，不是统计两个技能的配合成功率。

### 6.3 数据划分：训练探测集不是测试集

必须在训练前固化：

| 集合 | 用途 | 是否允许影响参数/采样 |
|---|---|---|
| `train_rollout` | 普通 RL 和 Agent 训练任务 | 是 |
| `train_probe` | 估计练习收益、指导采样 | 是；它属于训练信息 |
| `dev` | 选择超参数、冻结方法 | 可用于开发选择，不进入最终分数 |
| `test` | 最终泛化评测 | 否 |

建议任务程序数量：24 个训练程序模板、12 个训练探测模板、12 个开发模板、24 个最终测试模板；具体可实现程序在工程 gate 后冻结。

不能把 `train_probe` 写成“从未用于训练的泛化测试”。它虽然不直接求策略梯度，仍参与训练决策。

测试集需要在对象布局、任务图组合、干扰种类和数值参数上与前三者分离。语言同义改写不是唯一泛化来源。

### 6.4 等成本短程更新

每隔一个大训练区间，在同一检查点 \(\theta_t\) 上挑选两个候选桶 \(b_1,b_2\)，并建立一个参考分支。

\[
\theta^{(b)} =
\operatorname{Update}(\theta_t,\mathcal D_b,c),\qquad
\theta^{(\mathrm{ref})} =
\operatorname{Update}(\theta_t,\mathcal D_{\mathrm{ref}},c).
\]

其中 \(c\) 是相同原始交互步数与同一更新规则下的练习预算；参考分布使用冻结的 SGS 混合规则。

**必须复制的不只是模型参数：** optimizer 状态、观测/价值归一化器、RNG 起点和影响更新的配置也要一致。每个分支用自己的新轨迹，不能复用另一个分支的 off-policy PPO rollout。

所有分支串行运行也可以，不要求 16GB 显存同时容纳三套仿真。

### 6.5 收益定义

在相同的训练探测任务初始条件上，分别执行候选分支和参考分支。固定高层任务逻辑，不让不同 LLM 随机输出污染差分。

设 \(Y_j(\theta)\) 是探测任务 \(j\) 的最终成功指示变量，则：

\[
\widehat u_b
=
\frac{1}{n}\sum_{j=1}^{n}
\left[Y_j(\theta^{(b)})-Y_j(\theta^{(\mathrm{ref})})\right].
\]

这是**一个短更新、一个参考分布、一个探测集合上的经验相对收益**，不是完整因果价值函数，也不是有一致性保证的最优收益估计。

为了避免只提高长任务却遗忘基础能力，探测评分采用预注册组合：

\[
\widehat u_b^{\mathrm{mix}}
=
0.75\,\widehat u_b^{\mathrm{program}}
+
0.25\,\widehat u_b^{\mathrm{primitive}}.
\]

权重是设计默认值，不是推导出的最优常数；仅允许在 dev 阶段对少量候选作同预算选择。

若候选与参考成本存在差异，记录两者实际 GPU 时间与交互步数；不通过把分母选得有利来夸大收益。主比较最终仍按整个方法的总成本评测。

### 6.6 从收益到采样

对每个桶维护有衰减的经验收益 \(\bar u_b\)。未观测桶初始值为零，长期未更新的分数逐步回到零。

\[
P_t(b)=
\eta\frac{1}{|\mathcal B|}
+
(1-\eta)
\frac{\exp(\bar u_b/T)}
{\sum_{b'}\exp(\bar u_{b'}/T)}.
\]

初始建议 \(\eta=0.2\)，温度根据 dev 集冻结。桶内仍可使用 SGS 选择具体配置；因此贡献是“全局练习价值分配”，不是再发明一次 beta 采样。

不给经验收益套统计认证措辞。稀疏信号、随机更新和非平稳性都可能使收益不可靠，必须通过消融与额外独立短更新验证其预测性。

### 6.7 探测频率与开销

初始工程配置：

- 每约 8M 个主训练交互步，更新一次练习价值；
- 两个候选分支和一个参考分支；
- 每分支 1–4 个 PPO/SAPG 训练迭代，具体由单步样本数决定；
- 训练探测任务与基础技能各有固定、轮换的评测小批次；
- 总探测与决策开销以 **不超过整体 GPU 时间约 15%** 为设计目标，而不是已经达到的结果。

这组参数要通过小实验校准。若短更新没有可辨别信号，不允许默默把噪声当迁移收益；需要增加单次练习长度、降低探测频率并重新核算成本。

**如果在可接受开销内仍无法获得有用信号，EGP 的核心算法假设未通过。** 保留已完成的技能系统，但不能继续声称提出了有效的收益调度方法，也不能退回接口测量论文来填空。

### 6.8 分支如何并回主训练

最清晰的首版协议：探测分支全部丢弃，只更新桶权重；主策略从原检查点按新采样规则继续 on-policy 学习。

优点是避免“选择最幸运的短更新并接续”引入额外选择偏差，也便于和 TAC/BWT 比较。缺点是探测成本真实存在，必须计入。

后续“复用探测分支”只能作为独立优化/消融，不能在主实验中悄悄使用。

### 6.10 两条必须验证的机制预测

**P-A：** 经验练习收益应能预测下一次独立练习对其他任务的影响，至少应比“本桶当前成功率”具有额外预测力。

**P-B：** 当收益调度有效时，提升不应只集中在该桶自己的单技能测试，也应出现在没有用于估计收益的任务组合中。

两条均为经验预测，不叫定理。若 P-A 不成立但整体表现略升，需要考虑额外探索、计算量或状态分布带来的替代解释。

## 7. 奖励、状态恢复与训练阶段

### 7.1 奖励设计原则

低层采用统一结构：

\[
r_t =
\mathbf 1[\text{本技能目标首次达成}]
-\lambda_a\|a_t\|^2
-\lambda_\Delta\|a_t-a_{t-1}\|^2
-\lambda_v\mathbf 1[\text{预定义物理违规}].
\]

具体控制代价和训练实现以能复现的官方路径为起点，在开发集一次性冻结；不是声称上述符号式直接替换源代码即可收敛。

技能成功可由仿真几何/接触规则判断；完整任务成功由最终物理谓词判断。**LLM 不生成每次奖励，也不裁定自己的动作已经成功。**

必须如实说明：本方法使用公开 play 预训练、人工定义技能目标及成功谓词。它比 AlphaNIST 的单一完整任务目标提供了更多结构性监督，因此不能声称在相同监督下击败其“从零纯稀疏 RL”。[S4]

所有主算法使用相同奖励、初始状态来源、终止条件和动作接口。奖励塑形不能只给新方法。

### 7.2 成功判定不能被物理漏洞利用

所有成功判定需同时满足：

- 几何达成；
- 持续稳定窗口；
- 不存在严重穿透、瞬间弹射或非法对象绑定；
- 已完成的其他装配没有被破坏；
- 必要时手部脱离后装配仍成立。

旋拧任务必须检查实际装配进度与轴向变化；若采用理想化螺旋约束，应明确“理想化关节模型”，不能把它等同于真实螺纹接触。

优先使用尺寸归一化、预先定义的阈值；不能为新方法单独放宽成功标准。

### 7.3 Snapshot 恢复协议

训练用 snapshot 至少包括：

- 机器人关节位置/速度；
- 物体、配合件、桌面/任务板的状态；
- 物理参数、随机种子、已完成装配标志；
- 当前技能目标；
- 恢复所需的短历史或统一 burn-in 规则；
- 来源策略版本、原任务、状态生成与恢复成本。

循环网络的旧 hidden state 不能不加校验地给更新后的策略使用。优先使用短历史重建当前网络 hidden state；或者统一 warm-up，并把其物理交互计入预算。

检查恢复前后短时自由演化是否一致，检查接触/约束是否产生数值爆炸。无法一致恢复的状态剔除并记录，不能通过手工移动对象“修好”后冒充真实失败状态。

**测试过程中禁止恢复 snapshot、瞬移物体或重置机械臂。** 唯一重置发生于完整 episode 结束后。

### 7.4 三阶段训练

**A：工程复现与可控起步。** 复现官方 play/assembly 评测，证明机器人、资产、控制频率、成功判定都可工作。此阶段结果不作为新方法贡献。

**B：基础技能可用。** 用统一 play prior 和基础练习池形成可调用的六类目标条件能力。共同前置训练成本单列；所有方法继承同一个基座。主结论是“在共同基座上的能力增长”，不是从零学习。

**C：并行技能提升与 Agent 执行闭环。** 同等预算下运行 EGP 与各基线，周期性采集训练程序执行经验。最终冻结低层策略和 Agent，进行连续任务测试。

不得把基座训练、状态库生成或恢复策略训练隐藏在“免费预处理”里。公共模型的外部预训练成本不重复向每个方法收费，但必须披露该依赖。

## 8. LLM Agent：真正参与任务组合，但不抢走算法主线

### 8.1 模型与可复现性

主实验固定 **Qwen2.5-7B-Instruct** 的一个具体公开权重版本与推理配置。该模型选择是为了本地复现与成本控制，不代表它是当前最强模型。[S13]

- temperature、最大 token、system prompt、工具 schema、seed/确定性设置全部记录；
- 量化与非量化结果不能混用；
- 16GB 卡上的实际显存占用先测，训练与 LLM 推理必要时分时运行；
- 第二个 LLM 只做小规模稳健性实验，不另起大模型训练线；
- 不依赖不可复现的持续变化 API 主结果。

### 8.2 Agent 输入

输入包括用户指令、合法技能说明、当前场景对象及状态、上次执行结果。

允许：对象身份/类型、可观察位置、当前抓持状态、已完成组件、失败检测信号。

禁止：直接提供正确完整计划、未来成功率、测试任务的隐藏最优答案、从测试回报倒推的最优动作。

目标位姿由已知装配几何或任务配置提供，明确是机器人任务先验；不伪装成 LLM 自己从像素推理出来。

### 8.3 工具调用协议示例

下面是待实现的 schema 示例，不是已上线工具：

```json
{
  "skill": "insert",
  "object_id": "rod_8mm_01",
  "target_id": "board_hole_03",
  "goal_id": "mate_rod8_hole3",
  "max_control_steps": 600
}
```

执行器返回：

```json
{
  "status": "timeout",
  "goal_satisfied": false,
  "object_controlled": true,
  "failure_category": "stalled_near_target",
  "completed_components_preserved": true,
  "control_steps_used": 600
}
```

执行器验证对象与目标类型、关节/动作限制和 episode 剩余预算，但不偷偷选择正确物理动作。Skill controller 自己完成接触操作。

### 8.4 重规划与恢复

一个 episode 内允许有限次数重规划与物理恢复：

- 默认每个子目标最多两次恢复/再次尝试；
- 总物理控制步数统一；
- 总技能调用数、LLM token 和延迟全部报告；
- 失败不从分母中删除；
- 超时、预算耗尽、物体掉出工作区均按预定义规则处理。

Agent 根据反馈选择 `recover`、更换顺序或终止。不能通过无限重试获得更高成功率。

### 8.5 必须证明 LLM 层不是摆设

建立四种高层对照，低层策略保持相同：

1. 固定脚本/预定顺序；
2. 符号规划器或明确标注的 oracle 高层计划；
3. LLM 开环计划；
4. LLM 闭环执行与重规划。

测试需包含对象指代变化、不同有效顺序、已完成/缺失部件、实际执行失败后改变动作等情境。

**不要求 LLM 必须击败知道完整模型的符号规划器。** 若符号规划器更强，应报告它作为高层上界；LLM 的角色是自然语言目标的灵活组合，不是凭空证明语言模型优于一切规划。

### 8.6 训练贡献与规划贡献分离

先用固定、可复现的高层程序比较 RL 训练方法，再把最终几种技能库放入同一个冻结 LLM Agent。

如果换成同样的高层后训练方法收益消失，不能把提升归因于学到了更好的技能。

最终测试默认不在线更新参数。测试时自学习是另一研究问题，不与冻结泛化结果混报。

## 9. 基准划分：技能、对象、程序、语言四条轴

### 9.1 四个评测套件

| 套件 | 主要问题 | 核心设置 |
|---|---|---|
| Skill | 基础物理技能是否真的提高 | 六类技能的合法对象组合，完整可达起点 |
| Recovery | 能否从接触扰动恢复 | 与训练不同幅度/方向的滑移、卡滞与偏置 |
| Composition | 已知技能能否完成未见程序 | 未见顺序/目标组合，连续 4/8/12 调用预算 |
| Generalization | 是否只记住特定资产和语言 | 保留对象/尺寸、布局、程序图与指令变化 |

所有汇总按任务族先做宏平均，防止大量容易的插接变体淹没困难旋拧。

### 9.2 数据泄漏防线

必须对以下内容做独立版本与 hash：

- 资产与几何参数；
- 训练/探测/开发/测试程序图；
- 初始状态生成 seed；
- 扰动采样区间；
- 指令模板及人工审核结果；
- 成功谓词。

程序图的划分不能只是同一序列换个 seed。应保留某些目标组合或依赖结构，只在测试出现。

使用公共 play 模型时，不宣称其从未接触过类似几何；只能说明当前下游训练与调度没有使用本研究测试实例。官方已微调装配 checkpoint 不作为正式测试初始化。

### 9.3 原尺寸与精度

主 NIST 子集优先采用实际尺寸。为了启动学习，可以有训练用的放大间隙或近目标 reset，但要：

1. 所有方法同样使用；
2. 训练后在冻结的目标尺寸/间隙评测；
3. 分别报告训练辅助条件与目标条件；
4. 不能只展示宽松间隙版本却称完成精密 NIST 装配。

### 9.4 最低投稿证据，不再“四个技能跑一下就够”

目标证据是六类语义技能、八个装配实例、多个未见程序和第二任务族；**数量不是充分条件，物理难度与统计可信度更重要。**

若只有三类技能跑通，应把它当原型而不是强行上调质量评分。若六类中只有抓取放置有效，也不能用“六技能 API”掩盖能力不足。

## 10. 实验矩阵：优先回答最容易被拒稿的问题

### 10.1 主训练比较：七种方法，五个独立微调种子

所有方法继承相同基座，固定网络、奖励、动作、任务池获取权限、可用训练探测分布与总成本边界。

| ID | 方法 | 核心作用 |
|---|---|---|
| M0 | Uniform | 全桶均匀采样的必要基线 |
| M1 | SGS-style | 成功率难度前沿 |
| M2 | PLR-style | TD/学习潜力与陈旧度驱动的配置回放 |
| M3 | FER + SGS | 失败经验优先的强实用基线 |
| M4 | TAC-style | 梯度迁移关系 + 可学性调度 |
| M5 | BWT-style | 短练习前后实际跨任务收益调度，无等成本参考分支校正 |
| M6 | EGP（本文） | 执行经验 + 组合收益 + 同检查点等成本参考更新 |

SGS/PLR/TAC/BWT 的跨领域适配要写明“重实现/适配”，不能称官方机器人复现。所有方法都要先在开发任务检验数值正确与合理表现。[S3][S8][S9][S12]

局部学习进度采样可作为 pilot 对照；不能用它替代最直接的 TAC/BWT 近邻。

### 10.2 两种公平性协议，避免“数据更多所以更好”

**协议 A：固定共享状态库。** 从共同基座的训练执行生成相同状态池，固定后比较七种训练调度。用途是隔离“如何分配练习”的影响。

**协议 B：完整闭环。** 所有方法都有同样的采集时间点、状态保存规则和预算权限，各自执行训练程序产生新状态。策略不同导致数据不同是闭环方法的一部分，不能再宣称状态数据完全一致。

正文必须区分两种协议。**七方法 × 五种子的主实验使用协议 B；协议 A 另外比较 SGS、BWT、EGP，三种子、半主预算，单独计费。** 固定库实验不能替代完整闭环；完整闭环结果也不能代替干净的调度消融。

### 10.3 核心消融

三个必做消融，各至少三个训练种子：

- **A1 无执行经验：** 只用基础 reset 池，保留其余方法。检验真实执行分布的价值。
- **A2 无组合收益：** 用基础技能成功率代替完整程序收益。检验究竟是“技能刷分”还是组合能力增长。
- **A3 无覆盖/保持机制：** 去掉覆盖下限与保持池中的指定一项，避免同时改两个组件；先在 dev 决定具体去掉哪项并冻结。检验遗忘与探索不足。

“无参考分支”的消融已由 M5 承担，不重复计算成独立贡献。若 M5 与 M6无差异，应删除参考分支并承认它没有提供增量价值。

### 10.4 额外结构对照

**直接长程 RL。** 在同平台上训练一个直接接收完整目标的共享策略，预算和输入信息明确对齐。它可以使用相同合法 reset、基础模型与目标谓词，但不能被故意限制成完全从零、毫无辅助的弱基线。

如果主方法使用子目标标签而直接策略不使用，必须披露这个监督差别。结果用于回答层级结构的实用取舍，不证明同信息条件的理论优势。

**手部贡献诊断。** 在精心定义的诊断任务上比较完整手部控制与固定抓持；只用于解释灵巧性，不把它作为主要算法胜负基线。

### 10.5 并行规模与训练量

“规模化”分两条轴，不混用：

1. **同总交互量，不同并行度：** 检验高并行是否使采样/优化退化。
2. **同 GPU 时间，不同并行度：** 检验真实吞吐和最终能力。
3. **固定并行度，增加总训练预算：** 检验方法是否仍持续收益。

核心比较选择最强非 EGP 基线与 EGP，三档并行度、至少三个种子。不能只把 throughput 曲线当学习能力 scaling，也不能从三档拟合一个“定律”。

短预算规模实验只支持短预算结论。若没有全预算大并行结果，标题不写“mega-scale”。

### 10.6 第二任务族

使用 Play2Perfect 的 beam assembly 或另一组公开非 NIST 精密装配任务，沿用阶段一 prior、相同方法与基本超参数，比较 SGS、最强迁移基线、EGP，至少三个种子。[S2]

这里不能直接拿已针对该任务微调的公开 checkpoint 当本方法起点。允许任务几何的必要定义，不允许重新大规模调参后称“零调参迁移”。

### 10.7 主指标与成本

**预注册主终点：** 在共同总 GPU 训练预算下，最终冻结策略在未见连续程序上的任务族宏平均成功率。全体方法的探测、状态采集、恢复 warm-up、训练内评测等都计入该预算。

**必须同时报告：**

- 总物理交互步数，包括被丢弃的探测分支；
- GPU 小时与训练 wall-clock；
- 完整成功率对总成本的学习曲线；
- 独立技能成功率、恢复成功率；
- 已完成组件被破坏率；
- 平均/分位数物理时长、技能调用与重试次数；
- LLM 规划正确性、执行成功率、token 与延迟分开统计；
- 探测开销占比和每桶训练分配。

公共预训练算力单列为外部依赖。若本地与租卡混用，主算法比较在同型号卡上进行；不能把不同 GPU 的一小时直接当等价算力。

### 10.8 必须画出的六张主图

1. 完整任务成功率对**全成本**曲线；
2. 已知技能与未见程序上的表现对照；
3. 强基线与 EGP 的训练分配变化及独立迁移验证；
4. 连续任务长度/扰动下的性能；
5. 并行规模与训练预算二维结果；
6. 固定脚本、符号规划、开环 LLM、闭环 LLM 的分解对照。

视频必须包含固定抽样的成功与失败样例，并标注是否含测试扰动、是否使用恢复，不用剪辑代替定量结果。

## 11. 统计设计与结果判读

### 11.1 独立性单位

训练随机种子是算法比较的重要独立单位；同一个 checkpoint 上运行上千条 episode 不能替代多个独立训练种子。

初始目标为主比较五种子、消融/规模/第二套件至少三种子。预算不够时须降低结论强度，不宣称“很多评测 episode 已经补足训练不确定性”。少样本 RL 结果应报告区间与完整任务分布。[S14]

### 11.2 测试次数

初始评测设计为每个冻结 checkpoint、每个最终程序约 50–100 个独立物理初始条件，具体由 pilot 方差和实际评测成本冻结。主结果不在看完方法差异后决定增加哪一组样本。

同时报告逐 seed 结果、任务族宏平均和分层/配对置信区间。配对仅在相同任务和随机初始条件确实可对齐时使用。

### 11.3 哪个基线是“最强基线”

在 dev 集和预注册预算下选择最强非 EGP 方法，最终 test 上主比较 EGP 与这个冻结基线。其他基线完整报告。

不能在 test 上挑最弱者作为主结论，也不能忽略 TAC/BWT 优于 SGS 的情况。

### 11.4 实用效应与显著性

开发阶段可以将“完整任务宏平均提高约 8 个百分点”或“达到同成功率的总成本降低约 20%”作为继续投入的**工程目标**，但它们不是录用阈值，也不是保证会观察到的收益。

正式结论要求：

- 报告实际效应与区间；
- 主要效果不是一两个任务或一个幸运 seed 驱动；
- 没有通过更多重试、宽松成功阈值或额外训练预算获得；
- 第二套件方向一致，或对不一致有明确分析；
- 不把“没有显著差异”写成方法等价或假设成立。

不复用旧文件未经实测方差支持的 MDE 数字。

### 11.5 三类可能结果

**方法成功：** 全成本下优于强基线，迁移机制预测有效，未见组合也提升。可以主张 EGP 提高可组合技能学习。

**系统成功、算法无增益：** 机器人能完成丰富任务，但 EGP 不优于 SGS/TAC/BWT。可以继续开放系统和任务，不能维持算法型 headline；是否构成基准/系统论文取决于实际资产与评测贡献，不自动保证发表。

**基础技能或物理不成立：** 优先修复模型、控制和奖励，不投入大量 LLM 或论文评分。失败不再转写为接口测量理论。

## 12. 算力与预算：用实测吞吐决定规模，不用反推数字美化方案

### 12.1 先承认真实工程成本

Play2Perfect 论文报告的单卡预训练与单任务微调并非几分钟级作业；公开模型和代码因此是重要资源，但不会让新任务训练自动免费。[S1]

本方案的成本优势来自复用共同 play prior、共享条件策略、先完成小型验证，以及不同时建设视觉、触觉、真机和大模型训练系统。不能根据其他论文吞吐直接保证本项目每次训练只需几小时。

### 12.2 统一预算变量

- \(t\)：主比较中**一次共享多技能/多任务训练 run**的实测 GPU 小时，包括该方法自己的探测与训练内评测；用最慢方法的可执行上限估计经费。
- \(p\)：同一实际租赁 GPU 的到手单价，需下单时核验。
- \(H_{\mathrm{fixed}}\)：共同基座适配、开发对照、最终评测、状态生成等单列 GPU 小时。
- \(C_{\mathrm{other}}\)：存储、电费、少量 API/数据搬运等。
- \(C_{\mathrm{reserve}}\)：全项目应急金，包含在总上限里，不在硬顶外再加一笔。

**一次 run 是共享整个任务套件，不是“每技能各跑一次”后漏乘技能数。** 若实际实现改为独立技能训练，必须全部重算。

### 12.3 投稿级目标矩阵的训练量

| 模块 | 目标运行数 | 单 run 预算 | 折算主 run 数 |
|---|---:|---:|---:|
| 七种主方法 × 五种子（动态闭环） | 35 | \(t\) | 35 |
| 固定共享状态库：三方法 × 三种子 | 9 | \(0.5t\) | 4.5 |
| 三项消融 × 三种子 | 9 | \(0.5t\) | 4.5 |
| 两方法 × 两个额外并行档 × 三种子 | 12 | \(0.25t\) | 3 |
| 第二任务族三方法 × 三种子 | 9 | \(0.5t\) | 4.5 |
| 直接长程 RL 结构对照 × 三种子 | 3 | \(t\) | 3 |
| 合计 | 77 次不同预算运行 | — | **\(54.5t\)** |

说明：

- 最大并行档的对应主方法结果复用主实验，不重复计费。
- 消融、第二任务族和规模实验的预算短于主实验，必须明确报告；不能据此宣称全预算结论。
- \(0.25t\)、\(0.5t\) 是规划占位，不代表不同任务耗时必然线性；实际以交互量和实测计算时间核算。
- 如果第二套件无法在半预算中进入有信息的学习区间，就必须追加预算或缩小论文主张，不把所有方法都接近零的表格当作泛化证据。
- 最终确认阶段必须保存完整实验 manifest，所有 run 和 checkpoint 可追溯。

### 12.4 5,000 元以内何时可行

仅作算例，**不是现行市场报价**：

\[
C_{\mathrm{total}}
=
p(54.5t+H_{\mathrm{fixed}})
+C_{\mathrm{other}}
+C_{\mathrm{reserve}}.
\]

暂取 \(p=7\) 元/小时、\(H_{\mathrm{fixed}}=80\) 小时、其他开支 600 元、应急金 1,000 元：

| 实测主 run 耗时 \(t\) | 总 GPU 小时 | 含其他开支与应急金 |
|---:|---:|---:|
| 6 h | 407 h | **4,449 元** |
| 8 h | 516 h | **5,212 元** |
| 12 h | 734 h | **6,738 元** |
| 24 h | 1,388 h | **11,316 元** |

因此，按上述算例，完整目标矩阵要在 5,000 元内完成，需要：

\[
t\le
\frac{(5000-600-1000)/7-80}{54.5}
\approx 7.44\text{小时}.
\]

这不是对训练速度的预测，而是**必须通过 pilot 验证的可行性边界**。80 小时固定成本同样需要测量；它不够时必须加上差额。

若单价增加 50%，同样 \(t=8\) 的矩阵总额为 7,018 元，而不是仍然声称“预算闭合”。

### 12.5 分阶段拨款

**阶段 P0：不超过 600 元的验证性支出。** 在使用已有本地算力的基础上，完成公开代码复现、三类技能起步、同成本 SGS/EGP 短实验和吞吐测量。此笔支出计入总预算，不另加。

**阶段 P1：累计支出不超过 1,500 元。** 确认迁移信号不是纯噪声、探测开销受控、连续任务表现不为零，完成最直接近邻的 pilot。

**阶段 P2：主要确认实验。** 仅在 P1 通过且剩余预算能覆盖最终测试时启动。常规计划支出上限 4,000 元，应急金 1,000 元在统一总顶内管理。

实际调价或重跑需要重新生成余款与完成成本预测，不能因为已经花钱就继续沉没成本式训练。

### 12.6 超预算时的正确删减顺序

先删第二个 LLM、大量语言改写、额外渲染视频、非必要感知扩展；再缩小未进入主论点的任务范围。

不要首先删：

- 最直接的 TAC/BWT/FER 基线；
- 主实验独立训练种子；
- 全成本核算；
- 连续执行测试；
- 成功判定与数据泄漏审计。

可以在冻结前统一降低所有方法主训练预算，但必须保证已经进入可比较的学习区间；不能只给新方法足够收敛时间。

**如果 5,000 元下无法支撑确认实验，本方案交付的是完整可执行原型与初步证据，而不是已经被预算保证的顶会论文。** 不要求用户现在采购真机或自动增加预算。

## 16. 投稿定位：怎样提高竞争力，而不是伪造概率

### 16.1 首选 CoRL 风格

本题首先是机器人学习问题。强稿应展示：

- 灵巧物理能力，不只抽象环境或语言规划；
- 明确的训练算法增量；
- 持续接触与不重置的组合；
- 接触模型、状态信息与资源限制透明；
- 强且公平的近邻比较。

当前 CoRL 官方站点仍为 2026 周期；本次未从官方核验到 2027 正式截止安排。不能继续沿用旧文“六月投、八月出结果”的推算。[S15]

**仿真优先完全保留。** 不把真机写成录用的硬性条件，也不否认缺少真机证据会限制物理泛化主张。用更严格的物理检查、不同对象/任务族、模型扰动和可复现环境弥补，而不是声称仿真等同真机。

### 16.2 ICLR 的额外要求

只有当收益调度具有跨任务族的稳定效果、机制证据清楚，而且增量不是机器人系统拼装时，再按 ICLR 方法论文组织。

ICLR 2027 正式论文截止为 2026-09-25，已过去；不能把当前项目安排成赶上该轮。未来周期以正式 CFP 为准，不预填 ICLR 2028 日期。[S16]

### 16.3 TMLR 作为后续路线，而非“50% 兜底”

TMLR 官方强调技术正确性、滚动投稿及灵活评审，但没有因此保证本稿 50% 被接收。严谨的经验研究可考虑这一出口，仍须满足其实际评审标准。[S17]

提交策略只能写成条件树：

```text
证据完成
  ├─ 机器人学习贡献突出且符合当轮时间 → CoRL
  ├─ 通用学习方法贡献充分且符合当轮时间 → ICLR
  └─ 需要滚动修改/完整经验报告 → TMLR

当前投稿作出决定，或按规定正式退出审稿后，
再选择下一出口；不要预排互相重叠的“顺序投稿”。
```

### 16.4 最大化竞争力的取舍顺序

**第一优先：** 强近邻、同成本、连续执行、独立种子、未见组合。

**第二优先：** 清楚证明手指操作、恢复和迁移机制。

**第三优先：** 第二任务族和并行规模。

**最后才做：** 第二个大模型、大量提示工程、更多花哨演示和复杂理论。

如果收益并不显著，不通过堆论文术语或转移成“接口论文”挽救故事。保留原目标，以实际学到的机器人能力和可重复结果决定下一步。

## 18. 论文写作骨架

### 18.1 摘要应回答的四句话

1. **问题：** 高自由度灵巧策略需要大量练习，但单技能可学性与长任务可用性不完全相同。
2. **方法：** 用实际执行经验构造练习池，并用等成本短更新在训练用途组合任务上验证收益，调度后续并行 RL。
3. **证据：** 在 Sharpa + KUKA 的多任务装配和未见连续组合中，进行近邻、开销、恢复和泛化比较。
4. **结果：** 仅在实验完成后填入真实提升及区间；目前不预填数字。

不要在 proposal 中写“实验表明我们大幅超越全部基线”。

### 18.2 正文结构

1. Introduction：从练习分配到可组合物理能力；
2. Related Work：dexterous pretraining、curriculum/transfer、skill composition；
3. Setup：技能与程序、共享策略、可观测信息、全成本预算；
4. EGP：状态来源、配对练习、收益估计、采样与开销；
5. Experiments：同成本主表、未见组合、机制、并行与第二套件；
6. Limitations：公共预训练、state-based 仿真、探测噪声、有限任务族；
7. Conclusion：按实际证据写，不扩大到通用自主智能或最优训练律。

### 18.3 标题何时需要改

工作标题使用 *Learning Agent-Composable Dexterous Skills through Execution-Grounded Practice*。

只有得到足够规模证据，才添加 *Scalable Reinforcement Learning*。不要添加 *Optimal*、*Certified*、*Universal*、*Foundation* 或 *Self-Evolving*，除非各自确有对应证据。
