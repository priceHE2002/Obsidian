# 快速幂

在模运算（以及广义的计算代数）中，常常需要将一个数提升到 $n$ 次幂——用于 [[模运算.md#费马定理|模除法]]、执行 [[模运算.md#剩余|素性测试]]，或计算某些组合值——而通常你希望计算它所用的操作少于 $\Theta(n)$ 次。

*快速幂*（binary exponentiation，又称平方求幂 exponentiation by squaring）是一种借助如下观察、用 $O(\log n)$ 次乘法计算 $n$ 次幂的方法：

$$
\begin{aligned}
    a^{2k}       &= (a^k)^2
\\  a^{2k + 1}   &= (a^k)^2 \cdot a
\end{aligned}
$$

要计算 $a^n$，我们可以递归地计算 $a^{\lfloor n / 2 \rfloor}$，将其平方，若 $n$ 为奇数再乘以 $a$，对应如下递推式：

$$
a^n = f(a, n) = \begin{cases}
   1,               && n = 0
\\ f(a, \frac{n}{2})^2,     && 2 \mid n
\\ f(a, n - 1) \cdot a, && 2 \nmid n
\end{cases}
$$

由于每两次递归转移后 $n$ 至少减半，该递推的深度与总乘法次数至多为 $O(\log n)$。

### 递归实现

既然已经有了递推式，将该算法实现为一个模式匹配的递归函数是很自然的事：

```c++
const int M = 1e9 + 7; // modulo
typedef unsigned long long u64;

u64 binpow(u64 a, u64 n) {
    if (n == 0)
        return 1;
    if (n % 2 == 1)
        return binpow(a, n - 1) * a % M;
    else {
        u64 b = binpow(a, n / 2);
        return b * b % M;
    }
}
```

在我们的基准测试中，使用 $n = m - 2$，以便计算 $a$ 模 $m$ 的 [[模运算.md#费马定理|乘法逆元]]：

```c++
u64 inverse(u64 a) {
    return binpow(a, M - 2);
}
```

我们使用 $m = 10^9+7$，这是竞赛编程中常用于组合问题校验和的模数——因为它是素数（可通过快速幂求逆）、足够大、做加法时不会溢出 `int`、做乘法时不会溢出 `long long`，而且易于输入为 `1e9 + 7`。

由于我们在代码中将其作为编译期常量使用，编译器可以通过 [[整数除法.md|替换为乘法]] 来优化取模（即使它不是编译期常量，手动预计算一次"魔法常数"并用于快速约简仍然更廉价）。

执行路径——进而运行时间——取决于 $n$ 的值。对于这个特定的 $n$，基准实现每次调用约需 330ns。由于递归会带来一些 [[函数与递归.md|额外开销]]，将该实现展开为迭代过程是有意义的。

### 迭代实现

$a^n$ 的结果可以表示为 $a$ 的若干个 2 的幂次的乘积——这些幂次对应 $n$ 的二进制表示中的 1。例如，若 $n = 42 = 32 + 8 + 2$，则

$$
a^{42} = a^{32+8+2} = a^{32} \cdot a^8 \cdot a^2
$$

要计算该乘积，我们可以遍历 $n$ 的二进制位，同时维护两个变量：$a^{2^k}$ 的值，以及考虑 $n$ 最低 $k$ 位后的当前乘积。在每一步中，若 $n$ 的第 $k$ 位为 1，则将当前乘积乘以 $a^{2^k}$；无论何种情况，都将 $a^k$ 平方得到 $a^{2^k \cdot 2} = a^{2^{k+1}}$，供下一次迭代使用。

```c++
u64 binpow(u64 a, u64 n) {
    u64 r = 1;
    
    while (n) {
        if (n & 1)
            r = res * a % M;
        a = a * a % M;
        n >>= 1;
    }
    
    return r;
}
```

迭代实现每次调用约需 180ns。繁重的计算相同；改进主要来自依赖链的缩短：`a = a * a % M` 必须在循环继续前完成，而现在它可与 `r = res * a % M` 并发执行。

性能还受益于 $n$ 是一个常量，[[分支的代价.md|使所有分支都可预测]]，并让调度器提前知道需要执行什么。然而，编译器并未利用这一点，也没有展开 `while(n) n >>= 1` 循环。我们可以将其改写为执行固定 30 次迭代的 `for` 循环：

```c++
u64 inverse(u64 a) {
    u64 r = 1;
    
    #pragma GCC unroll(30)
    for (int l = 0; l < 30; l++) {
        if ( (M - 2) >> l & 1 )
            r = r * a % M;
        a = a * a % M;
    }

    return r;
}
```

这会强制编译器只生成我们所需的指令，再省下 10ns，使总运行时间约为 170ns。

注意，性能不仅取决于 $n$ 的二进制长度，还取决于其中二进制 1 的个数。若 $n$ 为 $2^{30}$，由于无需执行任何"偏离主路径"的乘法，耗时约减少 20ns。
