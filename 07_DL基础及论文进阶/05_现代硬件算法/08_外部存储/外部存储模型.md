# 外部存储模型

为了思考访存受限算法的性能，我们需要建立一个对昂贵的块 I/O 操作更敏感、又不至于过于严苛而失去实用价值的代价模型。

### 缓存感知模型

在[[复杂性模型.md|标准 RAM 模型]]中，我们忽略了原语操作完成时间不相等这一事实。其中最重要的，是它不区分不同类型内存上的操作，把一次从 RAM 读取（实时约 50ns）与一次从 HDD 读取（约 5ms，大约相当于 $10^5$ 倍）等同看待。

在精神上与这类似，在*外部存储模型*中，我们干脆忽略一切非 I/O 的操作。更具体地说，我们只考虑缓存层次中的一层，并对硬件和问题做如下假设：

- 数据集大小为 $N$，且全部存储在*外部*内存中，我们可以在单元时间内以大小为 $B$ 的块对其进行读写（读取一整块和读取单个元素耗时相同）。
- 我们可以在*内部*内存中存储 $M$ 个元素，也就是说，我们最多能存放 $\left \lfloor \frac{M}{B} \right \rfloor$ 个块。
- 我们只关心 I/O 操作：在读与写之间所做的任何计算都是免费的。
- 我们额外假设 $N \gg M \gg B$。

在此模型中，我们从算法的高层 *I/O 操作*（或称 *IOPS*）角度来衡量其性能——即在执行期间读入或写出外部存储的块的总数。

我们将主要聚焦于内部内存为 RAM、外部内存为 SSD 或 HDD 的情形，不过我们即将开发的底层分析技术适用于缓存层次中的任意一层。在这些设定下，合理的块大小 $B$ 约为 1MB，内部内存大小 $M$ 通常为几 GB，而 $N$ 可达几 TB。

### 数组扫描

<!-- The external memory model can be used very efficiently without sacrificing simplicity. -->

作为一个简单的例子，当我们通过逐元素迭代来计算一个数组的和时，我们隐式地以 $O(B)$ 个元素为一组将其载入，而在外部存储模型的语境下，就是逐组处理这些块：

$$
\underbrace{a_1, a_2, a_3,} _ {B_1}
\underbrace{a_4, a_5, a_6,} _ {B_2}
\ldots
\underbrace{a_{n-3}, a_{n-2}, a_{n-1}} _ {B_{m-1}}
$$

因此，在外部存储模型中，求和及其他线性数组扫描的复杂度为

$$
SCAN(N) \stackrel{\text{def}}{=} O\left(\left \lceil \frac{N}{B} \right \rceil \right) \; \text{IOPS}
$$

你可以像下面这样显式地实现外部数组扫描：

```c++
FILE *input = fopen("input.bin", "rb");

const int M = 1024;
int buffer[M], sum = 0;

// while the file is not fully processed
while (true) {
    // read up to M of 4-byte elements from the input stream
    int n = fread(buffer, 4, M, input);
    //  ^ the number of elements that were actually read

    // if we can't read any more elements, finish
    if (n == 0)
        break;
    
    // sum elements in-memory
    for (int i = 0; i < n; i++)
        sum += buffer[i];
}

fclose(input);
printf("%d\n", sum);
```

请注意，在大多数情况下，操作系统会自动完成这种缓冲。即便数据只是从一个普通文件重定向到标准输入，操作系统也会缓冲其流，并默认以约 4KB 的块进行读取。
