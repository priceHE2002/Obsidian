# 外部存储

把两个数相加需要多长时间？作为最常用的指令之一，`add` 本身只需一个周期即可执行。因此，如果数据已经载入寄存器，它只需一个周期。

但在一般情况下（`*c = *a + *b`），我们需要先从其内存中取出操作数：

```nasm
mov eax, DWORD PTR [rsi]
add eax, DWORD PTR [rdi]
mov DWORD PTR [rdx], eax
```

从内存中取出任何数据时，数据到达之前总会有一定的延迟。此外，请求并不会直接发往其最终的存储位置，而是首先经过一套复杂的地址转换单元与缓存层系统，这套系统既能辅助内存管理，又能降低延迟。

因此，关于这个问题的唯一正确答案是"视情况而定"——主要取决于操作数存储的位置：

- 如果数据存储在主存（RAM）中，取出它大约需要 100ns，即约 200 个周期，再写回又需要约 200 个周期。
- 如果它最近被访问过，那么很可能已被*缓存*，取出的时间会更短，具体取决于上一次访问距今多久——最慢的缓存层可能约 50 个周期，最快的约 4–5 个周期。
- 但它也可能存储在某种*外部存储*（如硬盘）上，在这种情况下，访问它大约需要 5ms，即大致 $10^7$ 个周期（！）。

内存性能如此之大的差异，源于内存硬件并不像 CPU 芯片那样遵循同样的[[现代硬件.md|硅缩放定律]]。内存仍通过其他手段在进步，但如果在 50 年前内存时序与指令延迟大致处于同一量级，如今则远远落后。

![](img/memory-vs-compute.png)

为了减少这种限制因素的影响，现代内存系统正变得越来越[[存储层次.md|分层化]]，其中较高的层级会以牺牲一部分容量为代价来降低延迟。由于这些特性在各层之间可能存在数量级上的差异——尤其是外部存储类型——对于许多访存密集的算法而言，优先优化其 I/O 操作变得至关重要。

这促使了一种新的代价模型的诞生，称为*外部存储模型*，其唯一的原语操作是块的读与写，只要只涉及存储在有限大小本地内存中的数据，其他一切操作的成本都为零。它催生了一个激动人心的新领域——*外部存储算法*，我们将在本章中研究它。
