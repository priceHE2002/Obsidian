# 插桩

<!-- pv in Linux, pipes -->

*插桩（Instrumentation）* 是一个过于复杂的术语，意思是向程序中插入计时器和其他跟踪代码。最简单的例子是在类 Unix 系统中使用 `time` 工具来测量整个程序的执行时长。

更一般地说，我们想知道程序的*哪些部分*需要优化。编译器和 IDE 自带一些能自动为指定函数计时的工具，但更稳妥的做法是用语言提供的任何与时间交互的方法手动完成：

```cpp
clock_t start = clock();
do_something();
float seconds = float(clock() - start) / CLOCKS_PER_SEC;
printf("do_something() took %.4f", seconds);
```

这里的一个微妙之处在于，你无法用这种方式测量特别快的函数执行时间，因为 `clock` 函数返回的是微秒级（$10^{-6}$）的当前时间戳，且它本身完成也要花费几百纳秒。所有其他与时间相关的工具同样至少具有微秒级粒度，而在底层优化的世界里，这已是永恒般的漫长。

为了获得更高精度，你可以在循环中反复调用该函数，一次性为整个过程计时，然后将总时间除以迭代次数：

```cpp
#include <stdio.h>
#include <time.h>

const int N = 1e6;

int main() {
    clock_t start = clock();

    for (int i = 0; i < N; i++)
        clock(); // 对 clock 函数本身做基准测试

    float duration = float(clock() - start) / CLOCKS_PER_SEC;
    printf("%.2fns per iteration\n", 1e9 * duration / N);

    return 0;
}
```

你还需要确保没有任何东西被缓存、被编译器优化掉，或受到类似副作用的影响。这是一个独立且极其复杂的主题，我们将在 [[基准测试.md|本章末尾]] 更详细地讨论。

### 事件采样

插桩也可用于收集其他类型的信息，这些信息能让你对特定算法的性能获得有益的洞见。例如：

- 对于哈希函数，我们关注其输入的平均长度；
- 对于二叉树，我们关心其大小与高度；
- 对于排序算法，我们想知道它做了多少次比较。

类似地，我们可以在代码中插入计数器，用于计算这些算法特定的统计信息。

添加计数器有引入开销的缺点，不过你可以通过只在很小比例的调用中随机地这样做，几乎完全消除它：

```c++
void query() {
    if (rand() % 100 == 0) {
        // 更新统计信息
    }
    // 主逻辑
}
```

如果采样率足够小，每次调用仅剩的开销将是随机数生成和一次条件检查。有趣的是，我们可以用一些统计技巧再优化一点。

从数学上讲，我们此处所做的，是反复从 [伯努利分布（Bernoulli distribution）](https://en.wikipedia.org/wiki/Bernoulli_distribution)（其中 $p$ 等于采样率）中采样，直到得到一个成功。还有另一种分布告诉我们，在首次出现成功之前需要进行多少次伯努利采样，称为 [几何分布（Geometric distribution）](https://en.wikipedia.org/wiki/Geometric_distribution)。我们可以做的是直接从中采样，并将该值用作一个递减计数器：

```c++
void query() {
    static next_sample = geometric_distribution(sample_rate);
    if (next_sample--) {
        next_sample = geometric_distribution(sample_rate);
        // ...
    }
    // ...
}
```

这样，我们免去了每次调用都采样一个新随机数的需要，只在选择计算统计信息时重置计数器。

此类技术常被大型项目内部的库算法开发者使用，以在不对最终程序性能造成太大影响的情况下收集剖析数据。
