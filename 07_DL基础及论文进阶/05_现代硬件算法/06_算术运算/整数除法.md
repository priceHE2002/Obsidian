# 整数除法

与其他算术运算相比，除法在 x86 乃至一般计算机上的表现都非常糟糕。无论是浮点除法还是整数除法，在硬件上都 notoriously 难以实现。相关电路在 ALU 中占用大量面积，计算过程包含许多级流水，因此 `div` 及其同类指令完成一次运算通常需要 10–20 个周期，且数据类型的位宽越小，延迟略低一些。

### x86 中的除法与取模

既然没有人愿意为单独的取模操作重复这一整套繁琐机制，`div` 指令便同时承担了两种功能。要执行一次 32 位整数除法，你需要将被除数*专门*放入 `eax` 寄存器，并以除数作为唯一操作数调用 `div`。此后，商将存入 `eax`，余数将存入 `edx`。

唯一的注意事项在于，被除数实际上需要存放在*两个*寄存器 `eax` 和 `edx` 中：这一机制使得 64 除以 32 甚至 128 除以 64 的除法成为可能，其原理与 [[整数.md|128 位乘法]] 类似。在执行常规的 32 乘 32 有符号除法时，我们需要将 `eax` 符号扩展（sign-extend）到 64 位，并将其高位部分存入 `edx`：

```nasm
div(int, int):
    mov  eax, edi
    cdq
    idiv esi
    ret
```

对于无符号除法，你只需将 `edx` 置零以免其干扰：

```nasm
div(unsigned, unsigned):
    mov  eax, edi
    xor  edx, edx
    div  esi
    ret
```

在上述两种情况下，除了 `eax` 中的商之外，你还可以将 `edx` 作为余数访问：

```nasm
mod(unsigned, unsigned):
    mov  eax, edi
    xor  edx, edx 
    div  esi
    mov  eax, edx
    ret
```

你也可以将一个 128 位整数（存于 `rdx:rax`）除以一个 64 位整数：

```nasm
div(u128, u64):
    ; a = rdi + rsi, b = rdx
    mov  rcx, rdx
    mov  rax, rdi
    mov  rdx, rsi
    div  edx 
    ret
```

被除数的高位必须小于除数，否则会发生溢出。受此约束，编译器很难[自行生成](https://danlark.org/2020/06/14/128-bit-division/)这样的代码：如果你将一个 [[整数.md|128 位整数类型]] 除以一个 64 位整数，编译器会用额外的检查将它层层包裹，而这些检查实际上可能并无必要。

### 除以常量

即便完全由硬件实现，整数除法也慢得令人痛苦，但如果除数是常量，在某些情况下就可以避免除法。一个众所周知的例子是除以 2 的幂，它可以用一个单周期二进制移位来替代：[[二进制 GCD.md|二进制 GCD 算法]] 就是运用此技巧的一个绝佳范例。

在一般情况下，有若干巧妙的技巧可以用一次乘法外加少量预计算来替代除法。所有这些技巧都基于如下思想。考虑将一个浮点数 $x$ 除以另一个浮点数 $y$ 的任务，其中 $y$ 是预先已知的。我们可以做的是计算一个常量

$$
d \approx y^{-1}
$$

然后，在运行时计算

$$
x / y = x \cdot y^{-1} \approx x \cdot d
$$

$\frac{1}{y}$ 的结果偏差最多为 $\epsilon$，而乘法 $x \cdot d$ 只会再增加一个 $\epsilon$，因此总偏差最多为 $2 \epsilon + \epsilon^2 = O(\epsilon)$，对于浮点情形而言这是可接受的。

### Barrett 约减

如何将这一技巧推广到整数？计算 `int d = 1 / y` 似乎行不通，因为它只会得到零。我们所能做的最好的事情，是将它表达为

$$
d = \frac{m}{2^s}
$$

然后寻找一个"魔数" $m$ 和一个二进制移位 $s$，使得对于所有范围内的 `x` 都满足 `x / y == (x * m) >> s`。

$$
  \lfloor x / y \rfloor
= \lfloor x \cdot y^{-1} \rfloor
= \lfloor x \cdot d \rfloor
= \lfloor x \cdot \frac{m}{2^s} \rfloor
$$

可以证明这样的数对总是存在的，而编译器实际上会自行执行类似这样的优化。每当它们遇到除以常量的情形，就会用一次乘法和一次二进制移位来替代它。下面是将一个 `unsigned long long` 除以 $(10^9 + 7)$ 时生成的汇编代码：

```nasm
;  input (rdi): x
; output (rax): x mod (m=1e9+7)
mov    rax, rdi
movabs rdx, -8543223828751151131  ; load magic constant into a register
mul    rdx                        ; perform multiplication
mov    rax, rdx
shr    rax, 29                    ; binary shift of the result
```

这一技巧被称为 *Barrett 约减*（Barrett reduction），之所以叫"约减"（reduction），是因为它主要用于取模运算——凭借如下公式，取模可以用一次除法、乘法和减法替代：

$$
r = x - \lfloor x / y \rfloor \cdot y
$$

这一方法需要一定的预计算，其中包括执行一次真实的除法。因此，只有当你要执行的不止一次、而是多次使用同一常量的除法时，它才具有优势。

### 为什么它有效

为何这样的 $m$ 和 $s$ 总是存在，更不必说如何找到它们，这一点并不直观。但给定固定的 $s$，直觉告诉我们 $m$ 应当尽可能接近 $2^s/y$，以便让 $2^s$ 相互抵消。因此有两种自然的选择：$\lfloor 2^s/y \rfloor$ 和 $\lceil 2^s/y \rceil$。第一种不成立，因为如果你代入

$$
\Bigl \lfloor \frac{x \cdot \lfloor 2^s/y \rfloor}{2^s} \Bigr \rfloor
$$

那么对于任何整数 $\frac{x}{y}$（其中 $y$ 为奇数），结果将严格小于真实值。这就只剩另一种情况，即 $m = \lceil 2^s/y \rceil$。现在，让我们尝试推导计算结果的下界与上界：

$$
  \lfloor x / y \rfloor
= \Bigl \lfloor \frac{x \cdot m}{2^s} \Bigr \rfloor
= \Bigl \lfloor \frac{x \cdot \lceil  2^s /y \rceil}{2^s} \Bigr \rfloor
$$

我们先从 $m$ 的边界入手：

$$
2^s / y
\le
\lceil 2^s / y \rceil
<
2^s / y + 1
$$

现在考虑整个表达式：

$$
x / y - 1
<
\Bigl \lfloor \frac{x \cdot \lceil  2^s /y \rceil}{2^s} \Bigr \rfloor
<
x / y + x / 2^s
$$

我们可以看到，结果落在大小为 $(1 + \frac{x}{2^s})$ 的某个区间之内，如果该区间对所有可能的 $x / y$ 都恰好只包含一个整数，那么算法就保证给出正确答案。事实证明，我们总能把 $s$ 设得足够大来实现这一点。

这里的最坏情况是什么？如何选取 $x$ 和 $y$，使得区间 $(x/y - 1, x/y + x / 2^s)$ 包含两个整数？我们可以看到整数比值行不通，因为左边界不被包含在内，并且在假设 $x/2^s < 1$ 的前提下，区间内只会包含 $x/y$ 本身。最坏情况实际上是那个最接近 $1$ 而不超过它的 $x/y$。对于 $n$ 位整数，那就是次大的可能整数除以最大的可能整数：

$$
\begin{aligned}
    x = 2^n - 2
\\  y = 2^n - 1
\end{aligned}
$$

在这种情况下，下界为 $(\frac{2^n-2}{2^n-1} - 1)$，上界为 $(\frac{2^n-2}{2^n-1} + \frac{2^n-2}{2^s})$。左边界尽可能接近一个整数，而整个区间的大小则是次大的可能值。关键结论在于：若 $s \ge n$，则该区间中唯一包含的整数就是 $1$，因此算法总是会返回它。

### Lemire 约减

Barrett 约减有些复杂，并且由于取模是间接计算的，它还会为取模生成一段较长的指令序列。有一种新方法（[2019 年](https://arxiv.org/pdf/1902.01961.pdf)），更为简单，并且在某些情况下取模实际上更快。它目前还没有一个约定俗成的名字，但我将称之为 [Lemire](https://lemire.me/blog/) 约减。

核心思想如下。考虑某个整数分数的浮点表示：

$$
\frac{179}{6} = 11101.1101010101\ldots = 29\tfrac{5}{6} \approx 29.83
$$

我们如何"解剖"它以获得所需的各部分？

- 要得到整数部分（29），我们只需要在小数点之前对其向下取整或截断。
- 要得到小数部分（⅚），我们只取小数点之后的内容。
- 要得到余数（5），我们可以将小数部分乘以除数。

现在，对于 32 位整数，我们可以设 $s = 64$，并考察我们在"乘—移"方案中所做的计算：

$$
  \lfloor x / y \rfloor
= \Bigl \lfloor \frac{x \cdot m}{2^s} \Bigr \rfloor
= \Bigl \lfloor \frac{x \cdot \lceil  2^s /y \rceil}{2^s} \Bigr \rfloor
$$

我们在这里真正做的，是将 $x$ 乘以一个浮点常量（$x \cdot m$），然后截断结果 $(\lfloor \frac{\cdot}{2^s} \rfloor)$。

如果我们取的不是最高位而是最低位会怎样？这将对应于小数部分——如果我们再把它乘回 $y$ 并截断结果，那么这将恰好是余数：

$$
r = \Bigl \lfloor \frac{ (x \cdot \lceil  2^s /y \rceil \bmod 2^s) \cdot y }{2^s} \Bigr \rfloor
$$

这完美成立，因为这里我们做的可以解释为仅三次串接的浮点乘法，其总相对误差为 $O(\epsilon)$。由于 $\epsilon = O(\frac{1}{2^s})$ 且 $s = 2n$，误差将始终小于 1，因此结果精确。

```c++
uint32_t y;

uint64_t m = uint64_t(-1) / y + 1; // ceil(2^64 / y)

uint32_t mod(uint32_t x) {
    uint64_t lowbits = m * x;
    return ((__uint128_t) lowbits * y) >> 64; 
}

uint32_t div(uint32_t x) {
    return ((__uint128_t) m * x) >> 64;
}
```

我们还可以仅用一次乘法来检验 $x$ 是否能被 $y$ 整除——依据是：当且仅当小数部分（$m \cdot x$ 的低 64 位）不超过 $m$ 时，除法的余数为零（否则，它在被 $y$ 乘回并右移 64 位后会变成一个非零数）。

```c++
bool is_divisible(uint32_t x) {
    return m * x < m;
}
```

这一方法的唯一缺点在于，它进行乘法时需要用到原始大小四倍的整数类型，而其他约减方法只需用到 `double` 即可工作。

还有一种方法可以通过仔细操作中间结果的高低两半来计算 64×64 取模；具体实现留作练习。
