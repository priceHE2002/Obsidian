# 舍入误差

硬件浮点的舍入机制出奇地简单：当且仅当运算结果无法精确表示时才发生舍入，并且默认舍入到最近的可表示数（在出现平局时，倾向于选择以 0 结尾的数）。

考虑如下代码片段：

```c++
float x = 0;
for (int i = 0; i < (1 << 25); i++)
    x++;
printf("%f\n", x);
```

它打印出的不是 $2^{25} = 33554432$（数学上本应得到的结果），而是 $16777216 = 2^{24}$。为什么？

当我们反复对一个浮点数 $x$ 自增 1 时，最终会到达一个点：此时 $x$ 已经大到 $(x + 1)$ 会被舍入回 $x$。第一个这样的数是 $2^{24}$（即尾数位数加一），因为

$$2^{24} + 1 = 2^{24} \cdot 1.\underbrace{0\ldots0}_{\times 23} 1$$

它与 $2^{24}$ 和 $(2^{24} + 1)$ 的距离完全相同，但根据上述平局规则被向下舍入为 $2^{24}$。与此同时，低于该值的一切自增都可以精确表示，因此一开始就不存在舍入。

### 舍入误差与运算顺序

尽管在代数上是正确的，浮点计算的结果仍可能依赖于运算顺序。

例如，虽然加法和乘法在纯数学意义上是可交换且可结合的，但它们的舍入误差却不是：当我们拥有三个浮点变量 $x$、$y$ 和 $z$ 时，$(x+y+z)$ 的结果依赖于求和的顺序。同样的非交换性原理适用于几乎所有（即便不是全部）其他浮点运算。

编译器不允许产生 [[契约式编程.md|不符合规范]] 的结果，因此这一恼人的细微差别禁用了一部分涉及重新排列算术操作数的潜在优化。你可以通过 GCC 和 Clang 中的 `-ffast-math` 标志来关闭这种严格合规性。如果我们加上该标志并重新编译上面的代码片段，它会运行得 [[归约.md|明显更快]]，并且恰好输出了正确结果 33554432（尽管你需要意识到，编译器也可能选择了精度较低的计算路径）。

### 舍入模式

除了默认模式（也称为银行家舍入，Banker's rounding）之外，你还可以用另外 4 种模式 [设置](https://www.cplusplus.com/reference/cfenv/fesetround/) 其他舍入逻辑：

- 舍入到最近，平局时总是"远离"零；
- 向上舍入（趋向 $+∞$；因此负数结果趋向零）；
- 向下舍入（趋向 $-∞$；因此负数结果远离零）；
- 趋向零（对二进制结果进行截断）。

例如，如果在运行上面的循环之前调用 `fesetround(FE_UPWARD)`，它输出的既不是 $2^{24}$，甚至也不是 $2^{25}$，而是 $67108864 = 2^{26}$。这是因为当我们到达 $2^{24}$ 时，$(x + 1)$ 开始舍入到下一个最近的可表示数 $(x + 2)$，我们以一半的时间到达 $2^{25}$；此后，$(x + 1)$ 向上舍入到 $(x+4)$，于是我们开始以四倍的速度增长。

替代舍入模式的用途之一是用于诊断数值不稳定性。如果一个算法在切换到向正、负无穷舍入之间时结果产生显著变化，则表明它容易受到舍入误差的影响。

这一测试通常优于将所有计算切换到更低精度并检查结果是否变化过大，因为默认的"舍入到最近"策略在足够多次平均后会收敛到正确的"期望"值：一半时间里误差向上舍入，另一半时间里向下舍入——因此从统计上看它们相互抵消。

### 误差度量

期望从执行自然对数和平方根等复杂计算的硬件获得这一保证似乎令人惊讶，但事实确实如此：你 guaranteed 能从所有运算中获得尽可能高的精度。这使得分析舍入误差变得异常容易，我们稍后就会看到。

有两种自然的方式来度量计算误差：

* 制造硬件或符合规范的精确软件的工程师关注*最后一位单位*（units in the last place，ulps），即两个数之间的距离，以精确实数值与计算结果之间能容纳多少个可表示数来衡量。
* 从事数值算法工作的人关注*相对精度*（relative precision），即近似误差的绝对值除以真实答案：$|\frac{v-v'}{v}|$。

无论哪种情况，分析误差的通常策略是假设最坏情况，并简单地对其加以界定。

如果你执行一次基本的算术运算，那么可能发生的最坏情况就是结果舍入到最近的可表示数，这意味着误差不超过 0.5 ulps。为了以同样的方式推理相对误差，我们可以定义一个称为 *机器精度*（machine epsilon）的数 $\epsilon$，它等于 $1$ 与下一个可表示值之间的差（应等于 2 的负若干次幂，其中幂次等于专用于尾数的位数）。

这意味着，如果在一次算术运算之后你得到结果 $x$，那么真实值位于如下区间内的某处：

$$
[x \cdot (1-\epsilon),\; x \cdot (1 + \epsilon)]
$$

在基于浮点计算的结果做出离散的"是或否"决策时，误差的无处不在尤其需要牢记。例如，下面才是你应该如何检查相等性：

```c++
const float eps = std::numeric_limits<float>::epsilon; // ~2^(-23)
bool eq(float a, float b) {
    return abs(a - b) <= eps;
}
```

`eps` 的取值应当取决于具体应用：上面的取值——即 `float` 的机器精度——仅对不超过一次浮点运算的情形有效。

### 区间算术

若一个算法的误差（无论其成因）在运算过程中不会增长太多，则称该算法是*数值稳定*的（numerically stable）。这只有在问题本身是*良态*（well-conditioned）时才可能发生，即若输入数据有微小改变，解也只会改变很小的量。

在分析数值算法时，常常采用与实验物理中相同的方法会很有用：我们不再处理未知的实数值，而是处理它们可能所在的区间。

例如，考虑一串连续将变量乘以任意实数的运算：

```cpp
float x = 1;
for (int i = 0; i < n; i++)
    x *= a[i];
```

在第一次乘法之后，$x$ 相对于真实乘积值的比值被 $(1 + \epsilon)$ 所界定，而在每一次额外的乘法之后，这一上界又被乘以一个 $(1 + \epsilon)$。由归纳法可知，经过 $n$ 次乘法后，计算值的界限为 $(1 + \epsilon)^n = 1 + n \epsilon + O(\epsilon^2)$，并有一个类似的下界。

这意味着相对误差为 $O(n \epsilon)$，这大体上还可以接受，因为通常 $n \ll \frac{1}{\epsilon}$。

作为一个数值*不稳定*计算的例子，考虑如下函数：

$$
f(x, y) = x^2 - y^2
$$

假设 $x > y$，该函数能返回的最大值大致为

$$
x^2 \cdot (1 + \epsilon) - y^2 \cdot (1 - \epsilon)
$$

对应的绝对误差为

$$
x^2 \cdot (1 + \epsilon) - y^2 \cdot (1 - \epsilon) - (x^2 - y^2) = (x^2 + y^2) \cdot \epsilon
$$

因此相对误差为

$$
\frac{x^2 + y^2}{x^2 - y^2} \cdot \epsilon
$$

如果 $x$ 与 $y$ 量级相近，误差将为 $O(\epsilon \cdot |x|)$。

在直接计算中，减法"放大"了平方的误差。但这可以通过改用如下公式来修正：

$$
f(x, y) = x^2 - y^2 = (x + y) \cdot (x - y)
$$

对于这个式子，很容易证明误差被 $\epsilon \cdot |x - y|$ 所界定。它还更快，因为它需要 2 次加法和 1 次乘法：相比原式，多了一次快速的加法，少了一次缓慢的乘法。

### Kahan 求和

从前面的例子可以看出，一长串运算本身并不是问题，真正成问题的是将量级不同的数相加减。处理此类问题的通用思路是尽量让大数和大数在一起、小数和小数在一起。

考虑标准的求和算法：

```c++
float s = 0;
for (int i = 0; i < n; i++)
    s += a[i];
```

由于我们执行的是求和而非乘法，其相对误差不再仅仅被 $O(\epsilon \cdot n)$ 所界定，而是严重依赖于输入。

在最极端的情况下，如果第一个值是 $2^{24}$，而其他值都等于 $1$，那么无论 $n$ 多大，和都将是 $2^{24}$——这可以通过执行如下代码来验证，它会简单地两次打印出 $16777216 = 2^{24}$：

```cpp
const int n = (1<<24);
printf("%d\n", n);

float s = n;
for (int i = 0; i < n; i++)
    s += 1.0;

printf("%f\n", s);
```

发生这种情况是因为 `float` 只有 23 位尾数，因此 $2^{24} + 1$ 是第一个无法精确表示、必须向下舍入的整数，而每当我们试图向 $s = 2^{24}$ 加上 $1$ 时都会发生这种情况。误差确实是 $O(n \cdot \epsilon)$，但这是就绝对误差而言，而非相对误差：在上例中，它为 $2$，而如果最后一个数恰好是 $-2^{24}$，它会趋向无穷大。

显而易见的解决方案是切换到更大的类型，例如 `double`，但这并不是一个真正可扩展的方法。一个优雅的解决方案是将未能加进去的部分存入一个单独的变量，再将其加到下一个变量上：

```c++
float s = 0, c = 0;
for (int i = 0; i < n; i++) {
    float y = a[i] - c; // c is zero on the first iteration
    float t = s + y;    // s may be big and y may be small, losing low-order bits of y
    c = (t - s) - y;    // (t - s) cancels high-order part of y
    s = t;
}
```

这一技巧被称为 *Kahan 求和*（Kahan summation）。它的相对误差被 $2 \epsilon + O(n \epsilon^2)$ 所界定：第一项来自最后一次求和，第二项则是因为我们在每一步都用小于 $\epsilon$ 的误差进行计算。

当然，一个更通用、不仅适用于数组求和的方法是切换到更精确的数据类型，例如 `double`，这也有效地将机器精度平方。此外，它可以通过把两个 `double` 变量捆绑在一起来（某种程度上）扩展：一个用于存储数值，另一个用于存储其无法表示的误差，从而表示数值 $a+b$。这种方法被称为双精度加倍算术（double-double arithmetic），并且可以类似地推广以定义四精度加倍（quad-double）及更高精度的算术。
