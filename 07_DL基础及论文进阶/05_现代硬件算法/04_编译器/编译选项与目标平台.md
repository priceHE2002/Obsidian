# 编译选项与目标平台

从编译器获取高性能的第一步，是开口去要，这要通过一百多个不同的编译选项、属性和 pragma 来实现。

### 优化级别

在 GCC 中，为速度而进行的优化共有 4 个*半*主要级别：

- `-O0` 是默认级别，不做任何优化（尽管从某种意义上说，它确实做了优化：为编译时间而优化）。
- `-O1`（也别名为 `-O`）做了少许"唾手可得"的优化，几乎不影响编译时间。
- `-O2` 启用所有已知的、副作用极小且无、且耗时合理的优化（这是大多数项目用于生产构建的级别）。
- `-O3` 进行非常激进的优化，启用 GCC 中实现的几乎所有*正确*的优化。
- `-Ofast` 执行 `-O3` 中的一切，再加上一些可能破坏严格规范兼容性的额外优化标志，但其方式对大多数应用而言并不致命（例如，浮点运算可能被重排，使得尾数结果相差几个比特）。

还有许多其他优化标志，它们甚至未被包含在 `-Ofast` 中，因为它们极具情境性，默认启用更可能损害性能而非提升性能——我们将在[[情境化优化.md|下一节]]讨论其中一些。

### 指定目标平台

接下来你可能想做的是，告诉编译器更多关于这段代码将在哪台（些）计算机上运行的信息：平台集合越小越好。默认情况下，它会生成可在任何相对较新（>2000 年）的 x86 CPU 上运行的二进制文件。最简便的收窄方式是传入 `-march` 标志以指定确切的微架构：`-march=haswell`。如果你是在将运行该二进制的同一台计算机上编译，可以使用 `-march=native` 进行自动探测。

指令集通常是向后兼容的，因此往往只需使用你需要支持的最老微架构的名字即可。一种更稳妥的做法是列出 CPU 保证拥有的具体特性：`-mavx2`、`-mpopcnt`。当你只想针对某台特定机器*调优*程序、又不想使用任何可能在非兼容 CPU 上令其崩溃的指令时，可以使用 `-mtune` 标志（默认情况下 `-march=x` 也隐含 `-mtune=x`）。

这些选项也可以通过 pragma（而非编译标志）为某个编译单元指定：

```c++
#pragma GCC optimize("O3")
#pragma GCC target("avx2")
```

当你需要优化单个高性能过程、又不想增加整个项目的构建时间时，这很有用。

### 多版本函数

有时你可能还想在单个库中提供若干针对不同架构的实现。你可以用基于属性的语法，在编译时自动选择多版本函数：

```c++
__attribute__(( target("default") )) // fallback implementation
int popcnt(int x) {
    int s = 0;
    for (int i = 0; i < 32; i++)
        s += (x>>i&1);
    return s;
}

__attribute__(( target("popcnt") )) // used if popcnt flag is enabled
int popcnt(int x) {
    return __builtin_popcount(x);
}
```

在 Clang 中，你无法用 pragma 从源代码设置目标与优化标志，但你可以像在 GCC 中一样使用属性。
