# 预计算

当编译器能够推断某个变量并不依赖于任何用户提供的输入时，它就可以在编译期算出该变量的值，并将其作为常量嵌入到生成的机器码中。

这一优化对性能帮助很大，但它并非 C++ 标准的一部分，因此编译器并不*必须*这样做。当某项编译期计算难以实现或耗时过长时，编译器可能会放弃这一机会。

### 常量表达式

为了获得更可靠的方案，在现代 C++ 中你可以把一个函数标记为 `constexpr`；如果它以常量实参调用，其值保证在编译期算出：

```c++
constexpr int fibonacci(int n) {
    if (n <= 2)
        return 1;
    return fibonacci(n - 1) + fibonacci(n - 2);
}

static_assert(fibonacci(10) == 55);
```

这些函数有一些限制，例如只能调用其他 `constexpr` 函数、不能做内存分配，但除此之外，它们会"原样"执行。

注意，虽然 `constexpr` 函数在运行时不花费任何代价，它们仍会增加编译时间，因此至少要大致关心一下它们的效率，别把某个 NP 完全问题塞进去：

```c++
constexpr int fibonacci(int n) {
    int a = 1, b = 1;
    while (n--) {
        int c = a + b;
        a = b;
        b = c;
    }
    return b;
}
```

在早期的 C++ 标准中曾有许多更多的限制，例如你不能在函数内部使用任何形式的状态、必须依赖递归，因而整个过程更像是在写 Haskell 而非 C++。自 C++17 起，你甚至可以用命令式风格计算静态数组，这对于预计算查找表很有用：

```c++
struct Precalc {
    int isqrt[1000];

    constexpr Precalc() : isqrt{} {
        for (int i = 0; i < 1000; i++)
            isqrt[i] = int(sqrt(i));
    }
};

constexpr Precalc P;

static_assert(P.isqrt[42] == 6);
```

注意，当你以非常量调用 `constexpr` 函数时，编译器可能在编译期计算它们，也可能不计算：

```c++
for (int i = 0; i < 100; i++)
    cout << fibonacci(i) << endl;
```

在这个例子中，尽管从技术上讲我们执行了常数次迭代、并以编译期已知的参数调用 `fibonacci`，但它们在技术上并非编译期常量。是否优化这个循环取决于编译器——而对于繁重计算，它常常选择不优化。
