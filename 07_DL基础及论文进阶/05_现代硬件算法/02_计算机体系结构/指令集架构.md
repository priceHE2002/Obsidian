# 指令集架构

作为软件工程师，我们极其热衷于构建和使用抽象。

试想一下，当你加载一个 URL 时会发生多少事情。你在键盘上敲下字符；按键被操作系统以某种方式检测到并发送给浏览器；浏览器解析 URL 并请求操作系统发起网络请求；随后是 DNS、路由、TCP、HTTP 以及所有其他 OSI 层；浏览器解析 HTML；JavaScript 施展魔法；页面的某种表示被送往 GPU 进行渲染；图像帧被发送到显示器……而其中的每一步在过程中大概又涉及几十件更具体的事。

抽象帮助我们把这一切复杂性收敛为一个单一的*接口*（interface），它描述某个*模块*能做什么，而不固定具体实现。这带来双重好处：

- 工作在更高层模块上的工程师只需了解（小得多的）接口。
- 工作在模块本身的工程师只要符合其*契约*（contracts），就有自由去优化和重构其实现。

硬件工程师也喜欢抽象。CPU 的一种抽象称为*指令集架构*（instruction set architecture，ISA），它从程序员的角度定义了计算机应当如何工作。与软件接口类似，它让计算机工程师能够改进现有的 CPU 设计，同时也让我们这些程序员——用户——确信，以前能跑通的东西不会在新芯片上失效。

ISA 本质上定义了硬件应当如何解释机器语言。除了指令及其二进制编码外，ISA 还定义了寄存器的数量、大小和用途，内存模型，以及输入/输出模型。与软件接口类似，ISA 也可以扩展：事实上它们经常更新，且多数以向后兼容的方式进行，以加入新的、更专门的指令来提升性能。

### RISC 与 CISC

历史上曾有许多相互竞争的 ISA 在使用。但与 [字符编码和即时通讯协议](https://xkcd.com/927/) 不同，开发并维护一套完全独立的 ISA 代价高昂，因此主流 CPU 设计最终收敛到了两个家族之一：

- **Arm** 芯片，用于几乎所有移动设备，以及其他类计算机设备，如电视、智能冰箱、微波炉、[汽车自动驾驶](https://en.wikipedia.org/wiki/Tesla_Autopilot) 等等。它们由同名的一家英国公司以及包括苹果和三星在内的一批电子制造商设计。
- **x86**[^x86] 芯片，用于几乎所有服务器和台式机，但有几个显著的例外，如苹果的 M1 MacBook、AWS 的 Graviton 处理器，以及当前 [世界最快的超级计算机](https://en.wikipedia.org/wiki/Fugaku_(supercomputer))，它们都使用基于 Arm 的 CPU。它们由英特尔和 AMD 的双头垄断格局设计。

[^x86]: x86 的现代 64 位版本被称为「AMD64」「Intel 64」，或更中性的「x86-64」「x64」。Arm 类似的 64 位扩展称为「AArch64」或「ARM64」。本书中我们使用 plain「x86」和「Arm」，默认指 64 位版本。

它们之间的主要区别在于体系结构的复杂度，这更像是一种设计哲学，而非某种严格定义的属性：

- Arm CPU 是*精简*指令集计算机（RISC）。它们通过保持指令集小而高度优化来提升性能，尽管某些较不常见的操作必须用涉及多条指令的子例程来实现。
- x86 CPU 是*复杂*指令集计算机（CISC）。它们通过加入许多专门的指令来提升性能，其中有些指令在实际程序中可能很少用到。

RISC 设计的主要优势在于它能产生更简单、更小的芯片，这意味着更低的制造成本和功耗。市场自发地分化也就不足为奇了：Arm 主导了靠电池供电的通用设备，而把复杂的神经网络与伽罗瓦域（Galois field）计算留给服务器级的、高度专门化的 x86。
