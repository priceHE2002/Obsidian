# 函数与递归

要在汇编中「调用一个函数」，你需要 [[循环与条件分支.md|跳转]] 到它的开头，然后再跳回来。但这样一来就出现了两个重要问题：

1. 如果调用方把数据存于与被调用方相同的寄存器里，会怎样？
2. 「回来」的位置在哪里？

这两个问题都可以通过在内存中专门安排一个位置来解决：在调用函数之前，我们把返回所需的所有信息写到那里。这个位置称为*栈*（the stack）。

### 栈

硬件栈的工作方式与软件栈相同，同样只用两个指针实现：

- *基址指针*（base pointer）标记栈的起始位置，通常存于 `rbp`。
- *栈指针*（stack pointer）标记栈的最后一个元素，通常存于 `rsp`。

当你需要调用一个函数时，你把所有局部变量压入栈中（在其他情形下也可以这样做，例如当寄存器用尽时），压入当前的指令指针，然后跳转到函数的开头。从函数退出时，你查看栈顶存储的指针并跳转到它，然后小心地把栈上存储的所有变量读回各自的寄存器。

你可以用普通的 memory 操作和跳转来实现这一切，但由于它使用得如此频繁，有 4 条专门的指令来做这件事：

- `push` 在栈指针处写入数据并将其递减。
- `pop` 从栈指针处读出数据并将其递增。
- `call` 把下一条指令的地址压入栈顶并跳转到一个标号。
- `ret` 从栈顶读出返回地址并跳转到它。

如果它们不是真正的硬件指令，你会称其为「语法糖」——它们只是这些两条指令片段的融合等价形式：

```nasm
; "push rax"
sub rsp, 8
mov QWORD PTR[rsp], rax

; "pop rax"
mov rax, QWORD PTR[rsp]
add rsp, 8

; "call func"
push rip ; <- instruction pointer (although accessing it like that is probably illegal)
jmp func

; "ret"
pop  rcx ; <- choose any unused register
jmp rcx
```

`rbp` 与 `rsp` 之间的内存区域称为*栈帧*（stack frame），函数的局部变量通常就存储在这里。它在程序启动时预先分配，如果你压入栈的数据超过了它的容量（Linux 上默认为 8MB），就会遇到*栈溢出*（stack overflow）错误。由于现代操作系统在实际读写之前并不会真正分配内存页，你可以自由地指定一个很大的栈大小，它更像是对可用栈内存量的一个上限，而非每个程序都必须使用的固定数量。

### 调用约定

开发编译器和操作系统的人们最终就如何编写和调用函数达成了 [约定](https://wiki.osdev.org/Calling_Conventions)。这些约定促成了一些重要的 [[编译的各个阶段.md|软件工程奇迹]]，例如把编译拆分成独立的单元、复用已经编译好的库，甚至用不同的编程语言来编写它们。

考虑下面这个 C 语言例子：

```c
int square(int x) {
    return x * x;
}

int distance(int x, int y) {
    return square(x) + square(y);
}
```

<!--

When compiled without any optimization flags, it produces the following assembly:

```nasm

    push    rbp
    mov     rbp, rsp
    mov     DWORD PTR [rbp-4], edi

    imul    eax, eax

    ret
```

-->

按约定，函数应当在 `rdi`、`rsi`、`rdx`、`rcx`、`r8`、`r9` 中接收参数（若不够则其余从栈中取），把返回值放入 `rax`，然后返回。因此，`square` 作为一个简单的单参数函数，可以这样实现：

```nasm
square:             ; x = edi, ret = eax
    imul edi, edi
    mov  eax, edi
    ret
```

每次从 `distance` 中调用它时，我们只需要费点劲保存它的局部变量：

```nasm
distance:           ; x = rdi/edi, y = rsi/esi, ret = rax/eax
    push rdi
    push rsi
    call square     ; eax = square(x)
    pop  rsi
    pop  rdi

    mov  ebx, eax   ; save x^2
    mov  rdi, rsi   ; move new x=y

    push rdi
    push rsi
    call square     ; eax = square(x=y)
    pop  rsi
    pop  rdi

    add  eax, ebx   ; x^2 + y^2
    ret
```

这里还有更多细微之处，但我们不会深入细节，因为本书关注的是性能，而处理函数调用的最佳方式其实从一开始就不要去调用它们。

### 内联

把数据在栈之间搬进搬出，对这类小函数来说会带来明显的开销。你之所以必须这么做，是因为一般而言你不知道被调用方是否会修改你存储局部变量的那些寄存器。但当你能访问到 `square` 的代码时，你可以通过把数据存放在你确信不会被修改的寄存器里来解决这个问题。

```nasm
distance:
    call square
    mov  ebx, eax
    mov  edi, esi
    call square
    add  eax, ebx
    ret
```

这样更好，但我们仍在隐式地访问栈内存：每次函数调用你都需要压入和弹出指令指针。在像这样的简单情形中，我们可以通过把被调用方的代码缝合进调用方、并解决寄存器上的冲突来*内联*（inline）函数调用。在我们的例子中：

```nasm
distance:
    imul edi, edi       ; edi = x^2
    imul esi, esi       ; esi = y^2
    add  edi, esi
    mov  eax, edi       ; there is no "add eax, edi, esi", so we need a separate mov
    ret
```

这已经相当接近优化编译器从这段代码片段所产生的输出了——只不过它们会用 [[汇编语言.md|lea 技巧]] 让生成的机器码序列少几个字节：

```nasm
distance:
    imul edi, edi       ; edi = x^2
    imul esi, esi       ; esi = y^2
    lea  eax, [rdi+rsi] ; eax = x^2 + y^2
    ret
```

在这种情形下，函数内联显然是有益的，编译器大多会 [[情境化优化.md|自动]] 地进行内联，但也有不宜内联的情况——我们 [[机器码布局.md|稍后]] 会谈到。

### 尾调用消除

当被调用方不做出任何其它函数调用，或者至少这些调用不是递归的时候，内联是容易做到的。我们接着看一个更复杂的例子。考虑下面这个阶乘的递归计算：

```cpp
int factorial(int n) {
    if (n == 0)
        return 1;
    return factorial(n - 1) * n;
}
```

等价的汇编：

```nasm
; n = edi, ret = eax
factorial:
    test edi, edi   ; test if a value is zero
    jne  nonzero    ; (the machine code of "cmp rax, 0" would be one byte longer)
    mov  eax, 1     ; return 1
    ret
nonzero:
    push edi        ; save n to use later in multiplication
    sub  edi, 1
    call factorial  ; call f(n - 1)
    pop  edi
    imul eax, edi
    ret
```

如果函数递归，通常仍可以通过重构让它「免去调用」。当函数是*尾递归*（tail recursive）时便是如此，即它在做完递归调用之后立即返回。由于调用之后无需任何动作，也就没有必要在栈上保存任何东西，递归调用可以安全地替换为跳转到开头——实际上把函数变成了一个循环。

要让我们的 `factorial` 函数变成尾递归，可以给它传一个「当前乘积」参数：

```cpp
int factorial(int n, int p = 1) {
    if (n == 0)
        return p;
    return factorial(n - 1, p * n);
}
```

然后这个函数可以轻松地折叠成一个循环：

```nasm
; assuming n > 0
factorial:
    mov  eax, 1
loop:
    imul eax, edi
    sub  edi, 1
    jne  loop
    ret
```

递归之所以可能缓慢，主要原因是它需要对栈进行读写，而迭代和尾递归算法则不需要。这个概念在函数式编程中非常重要，因为在函数式编程中没有循环，你所能使用的就只有函数。如果没有尾调用消除，函数式程序的执行将需要多得多的内存和时间。
