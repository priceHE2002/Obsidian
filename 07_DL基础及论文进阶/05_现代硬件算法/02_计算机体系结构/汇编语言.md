# 汇编语言

CPU 由*机器语言*控制，机器语言不过是一串二进制编码的指令，用于指定

- 指令编号（称为*操作码*），
- 它的*操作数*是什么（如果有的话），
- 以及把*结果*存到哪里（如果产生了结果的话）。

机器语言一种对人类更友好的表示形式称为*汇编语言*，它用助记码指代机器码指令，用符号名称指代寄存器和其他存储位置。

直接来看，以下是在 Arm 汇编中如何把两个数相加（`*c = *a + *b`）：

```nasm
; *a = x0, *b = x1, *c = x2
ldr w0, [x0]    ; load 4 bytes from wherever x0 points into w0
ldr w1, [x1]    ; load 4 bytes from wherever x1 points into w1
add w0, w0, w1  ; add w0 with w1 and save the result to w0
str w0, [x2]    ; write contents of w0 to wherever x2 points
```

下面是同样的操作在 x86 汇编中的写法：

```nasm
; *a = rsi, *b = rdi, *c = rdx 
mov eax, DWORD PTR [rsi]  ; load 4 bytes from wherever rsi points into eax
add eax, DWORD PTR [rdi]  ; add whatever is stored at rdi to eax
mov DWORD PTR [rdx], eax  ; write contents of eax to wherever rdx points
```

从「它不像高级编程语言那样拥有众多语法结构」这个意义上说，汇编非常简单。从上面这些例子中可以观察到：

- 程序是一串指令序列，每条指令写成其名称后跟数量不定的操作数。
- `[reg]` 这种语法用于「解引用」寄存器中存储的指针；在 x86 上需要加上长度信息前缀（`DWORD` 此处表示 32 位）。
- `;` 号用于行注释，类似于其他语言中的 `#` 和 `//`。

汇编是一种极简的语言，因为它必须如此。它尽可能贴近机器语言，以至于机器码与汇编之间几乎存在 1:1 的对应关系。事实上，你可以用一个称为*反汇编*（disassembly）[^disassembly]的过程把任何已编译的程序还原成汇编形式——当然，注释这类非必要信息不会保留下来。

[^disassembly]: 在 Linux 上，要对已编译程序进行反汇编，可以调用 `objdump -d {path-to-binary}`。

注意，上面两段代码片段不止在语法上不同。两者都是编译器产出的优化代码，但 Arm 版本用了 4 条指令，而 x86 版本只用了 3 条。`add eax, [rdi]` 这条指令就是所谓的*融合指令*，它一次性完成加载与相加——这正是 [[指令集架构.md#指令集架构|CISC]] 思路所能提供的一项好处。

由于各体系结构之间的差异远不止这一处，从此处起直到本书余下部分，我们将只提供 x86 的示例，因为大多数读者优化的目标大概就是 x86，尽管我们引入的许多概念是与具体体系结构无关的。

### 指令与寄存器

出于历史原因，大多数汇编语言中的指令助记符都极其简略。在人们还手工编写汇编、反复书写同一组常用指令的年代，少打一个字符就意味着离崩溃近了一步。

例如，`mov` 表示「存/取一个字」，`inc` 表示「加 1」，`mul` 表示「相乘」，`idiv` 表示「整数除法」。你可以按指令名在 [x86 参考文档之一](https://www.felixcloutier.com/x86/) 中查到它的说明，不过多数指令做的事情正如你所想。

多数指令会把结果写入第一个操作数，而该操作数也可能参与运算，就像我们之前看到的 `add eax, [rdi]` 那样。操作数可以是寄存器、常量值或内存位置。

**寄存器**命名为 `rax`、`rbx`、`rcx`、`rdx`、`rdi`、`rsi`、`rbp`、`rsp`，以及 `r8`–`r15`，共 16 个。那些「字母」命名的寄存器是出于历史原因而得此名称的：`rax` 是「累加器（accumulator）」，`rcx` 是「计数器（counter）」，`rdx` 是「数据（data）」，如此等等——但当然，它们并不一定要用于这些本意。

此外还有 32 位、16 位和 8 位的寄存器，名称相似（`rax` → `eax` → `ax` → `al`）。它们并非完全独立，而是*别名*关系：`rax` 的最低 32 位是 `eax`，`eax` 的最低 16 位是 `ax`，依此类推。这样做是为了在保持兼容性的同时节省芯片面积，也是编译型编程语言中的基本类型转换通常免费的缘故。

这些只是*通用*寄存器，除 [[函数与递归.md|少数例外]] 之外，你在多数指令中可以随意使用它们。此外还有一组独立的寄存器用于 [[浮点数.md|浮点运算]]、一批非常宽的寄存器用于 [[SIMD并行.md|向量扩展]]，以及少数专门用于 [[循环与条件分支.md|控制流]] 的特殊寄存器，不过我们到时候自会讲到。

**常量**就是整数或浮点数值：`42`、`0x2a`、`3.14`、`6.02e23`。它们更常被称为*立即数*（immediate values），因为它们是直接嵌入机器码中的。由于这可能会增加指令编码的复杂度，某些指令不支持立即数，或者只支持其中的一个固定子集。有些情况下，你必须先把常量值载入寄存器，再用它来替代立即数。

除了数值之外，还有像 `hello` 或 `world\n` 这样的字符串常量，它们有自己一小撮专用操作，但那是一个相当冷僻的汇编语言角落，此处不展开讨论。

### 数据搬运

有些指令可能拥有相同的助记符，但操作数类型不同，这种情况下它们被视为不同的指令，因为它们可能执行略有差异的操作，且耗时不同。`mov` 指令就是一个鲜明的例子，它有大约 20 种不同的形式，全都和「搬运数据」相关：要么在内存与寄存器之间，要么就在两个寄存器之间。尽管名字如此，它并不是把数值*移动*进寄存器，而是*复制*它，保留原值。

当用于在两个寄存器之间复制数据时，`mov` 指令会在内部执行*寄存器重命名*——告诉 CPU 寄存器 X 所指的值其实存于寄存器 Y——除了解码指令本身可能带来的一点开销外，不会造成任何额外延迟。出于相同原因，交换两个寄存器的 `xchg` 指令也同样不花费任何代价。

正如我们前面在融合的 `add` 中看到的那样，你并不必为每次内存操作都使用 `mov`：某些算术指令顺带就支持把内存位置作为操作数。

### 寻址模式

内存寻址通过 `[]` 运算符完成，但它能做的远不止把寄存器中存储的值重新解释为内存位置。地址操作数最多接受 4 个参数，其语法如下：

```
SIZE PTR [base + index * scale + displacement]
```

其中 `displacement` 必须是整数常量，`scale` 可以是 2、4 或 8。它的作用是计算指针 `base + index * scale + displacement` 并对其进行解引用。

<!-- You can use them in any order: the assembler will figure it out. -->

使用复杂的寻址方式，比直接解引用指针最多只慢 [[指针的替代方案.md|一个周期]]；当你拥有一个结构体数组、并想加载其第 $i$ 个元素中某个特定字段时，它就很有用。

地址运算符需要加上一个指明所需数据位数的长度说明符：

- `BYTE`：8 位
- `WORD`：16 位
- `DWORD`：32 位
- `QWORD`：64 位

还有更稀见的 `TBYTE` 对应 [[浮点数.md|80 位]]，以及 `XMMWORD`、`YMMWORD`、`ZMMWORD` 分别对应 [[SIMD并行.md|128、256 与 512 位]]。所有这些类型都不必大写，但大多数编译器就是这样输出的。

地址计算本身往往很有用：`lea`（「加载有效地址」）指令在一个周期内计算出操作数的内存地址并存入寄存器，而不做任何实际的内存操作。虽然它的本意是用于计算内存地址，但它也常被当作一种算术技巧来使用，否则就需要 1 次乘法和 2 次加法——例如，你可以用它来乘以 3、5 和 9。

它也经常作为 `add` 的替代品，因为在你需要把结果搬到别处时它不需要单独的 `mov` 指令：`add` 只能在两个寄存器的 `a += b` 模式下工作，而 `lea` 让你可以写成 `a = b + c`（如果其中一个是常量，甚至可以写成 `a = b + c + d`）。

### 替代语法

实际上存在多个*汇编器*（由汇编生成机器码的程序），它们使用不同的汇编语言，但目前广泛使用的 x86 语法只有两种。它们通常以使用它们的两家公司命名，而这两家公司对那个时代的编程有着支配性影响：

- *AT&T 语法*，被所有 Linux 工具默认采用。
- *Intel 语法*，默认由 Intel 采用。

这些语法有时也分别被称为 *GAS* 与 *NASM*，取自使用它们的两个主要汇编器的名字（*GNU Assembler* 与 *Netwide Assembler*）。

本章我们使用了 Intel 语法，并且会在本书余下部分继续优先使用它。作为对比，下面同样是 `*c = *a + *b` 这个例子在 AT&T 汇编中的写法：

```asm
movl (%rsi), %eax
addl (%rdi), %eax
movl %eax, (%rdx)
```

关键差异可归纳如下：

1. *最后一个*操作数用于指定目标。
2. 寄存器与常量需分别加上 `%` 和 `$` 前缀（例如 `addl $1, %rdx` 使 `rdx` 自增）。
3. 内存寻址看起来像这样：`displacement(%base, %index, scale)`。
4. `;` 和 `#` 都可用于行注释，此外 `/* */` 可用于块注释。

而且，最重要的是，在 AT&T 语法中，指令名需要加上「后缀」（`addq`、`movl`、`cmpq` 等）以指明操作数的大小：

- `b` = byte（8 位）
- `w` = word（16 位）
- `l` = long（32 位整数或 64 位浮点）
- `q` = quad（64 位）
- `s` = single（32 位浮点）
- `t` = ten bytes（80 位浮点）

在 Intel 语法中，这一信息由操作数推断（这也是为什么你还必须指定指针的大小）。

大多数生成或解析 x86 汇编的工具都能使用这两种语法，所以你大可挑自己更喜欢的一种，不必担心。
