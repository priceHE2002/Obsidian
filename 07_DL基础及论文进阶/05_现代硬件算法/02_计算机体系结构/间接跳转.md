# 间接跳转

在汇编期间，所有标号都被转换为地址（绝对或相对），然后编码进跳转指令。

你也可以按寄存器里存储的非恒定值跳转，这称为*计算跳转*（computed jump）：

```nasm
jmp rax
```

这与动态语言以及实现更复杂的控制流有几项有趣的用途。

### 多路分支

如果你已经忘了 `switch` 语句是做什么的，下面是一段计算美国评分体系中 GPA 的小子程序：

```cpp
switch (grade) {
    case 'A':
        return 4.0;
        break;
    case 'B':
        return 3.0;
        break;
    case 'C':
        return 2.0;
        break;
    case 'D':
        return 1.0;
        break;
    case 'E':
    case 'F':
        return 0.0;
        break;
    default:
        return NAN;
}
```

我个人不记得上一次在非教学场景中使用 switch 是什么时候了。一般而言，switch 语句等价于一连串「if, else if, else if, else if……」，正因如此许多语言甚至根本没有 switch。尽管如此，这类控制流结构对于实现解析器、解释器和其他状态机十分重要，而它们通常由单个 `while (true)` 循环和其中的一个 `switch (state)` 语句构成。

当我们可以控制变量取值的范围时，就能利用计算跳转使用如下技巧。与其做 $n$ 个条件分支，不如创建一个*分支表*（branch table），其中包含指向可能跳转位置的指针/偏移量，然后用取值范围在 $[0, n)$ 的 `state` 变量来索引它。

当取值密集地排在一起时（不必严格连续，但值得在表里留出空白字段），编译器会使用这种技术。它也可以用*计算 goto*（computed goto）显式实现：

```cpp
void weather_in_russia(int season) {
    static const void* table[] = {&&winter, &&spring, &&summer, &&fall};
    goto *table[season];

    winter:
        printf("Freezing\n");
        return;
    spring:
        printf("Dirty\n");
        return;
    summer:
        printf("Dry\n");
        return;
    fall:
        printf("Windy\n");
        return;
}
```

基于 switch 的代码对编译器而言并非总是一目了然地可优化，因此在状态机的语境下，`goto` 语句经常被直接使用。`glibc` 中与 I/O 相关的部分充满了这样的例子。

### 动态分派

间接跳转在实现运行时多态方面也很有用。

考虑这个陈词滥调的例子：我们有一个 `Animal` 抽象类，带有一个虚方法 `.speak()`，以及两个具体实现：会叫的 `Dog` 和会喵的 `Cat`：

```cpp
struct Animal {
    virtual void speak() { printf("<abstract animal sound>\n");}
};

struct Dog {
    void speak() override { printf("Bark\n"); }
};

struct Cat {
    void speak() override { printf("Meow\n"); }
};
```

我们希望创建一只动物，并在事先不知道其类型的情况下调用它的 `.speak()` 方法，而它应当以某种方式调用正确的实现：

```c++
Dog sparkles;
Cat mittens;

Animal *catdog = (rand() & 1) ? &sparkles : &mittens;
catdog->speak();
```

实现这种行为的方法很多，但 C++ 是用一张*虚方法表*（virtual method table）来实现的。

对于 `Animal` 的所有具体实现，编译器会把它们的所有方法（即它们的指令序列）补齐，使它们对所有类都具有完全相同的长度（通过在 `ret` 之后插入一些 [[机器码布局.md|填充指令]]），然后把它们顺序地写到指令内存中的某处。接着它给结构体（也就是它的所有实例）加上一个*运行时类型信息*（run-time type information）字段，本质上就是指向该类虚方法正确实现的那个内存区域的偏移量。

通过虚方法调用，会从结构体的一个实例中取出该偏移量字段，并以此做一次普通的函数调用，利用的是每个派生类的所有方法和其他字段都具有完全相同偏移量这一事实。

当然，这会增加一些开销：

- 由于与 [[指令级并行.md|分支预测失败]] 相同的原因（流水线冲刷），你可能要多花大约 15 个周期。
- 编译器很可能无法内联这个函数调用本身。
- 类的大小会增加几个字节左右（这取决于具体实现）。
- 二进制文件自身也会略微增大。

出于这些原因，在性能关键的应用中通常会避免使用运行时多态。
