# 掩码与混合

SIMD 编程较大的挑战之一在于，它的控制流选项非常有限——因为你施加到向量上的操作对其所有元素都是一致的。

这使得通常用 `if` 或任何其他形式的分支就能轻易解决的问题变得困难得多。在 SIMD 中，它们必须通过各类[[无分支编程.md|无分支编程]]技术来处理，而应用这些技术并不总是那么直截了当。

### 掩码

使计算无分支的主要方式是通过*谓词化*（predication）——计算出两个分支的结果，然后利用某种算术技巧或一条特殊的"条件移动"指令：

```c++
for (int i = 0; i < N; i++)
    a[i] = rand() % 100;

int s = 0;

// 有分支：
for (int i = 0; i < N; i++)
    if (a[i] < 50)
        s += a[i];

// 无分支：
for (int i = 0; i < N; i++)
    s += (a[i] < 50) * a[i];

// 同样无分支：
for (int i = 0; i < N; i++)
    s += (a[i] < 50 ? a[i] : 0);
```

要向量化这个循环，我们将需要两条新指令：

- `_mm256_cmpgt_epi32`，它比较两个向量中的整数，若第一个元素大于第二个，则产生全 1 的掩码，否则产生全 0 的掩码。
- `_mm256_blendv_epi8`，它依据提供的掩码混合（组合）两个向量的值。

通过对向量的元素进行掩码与混合，使得只有被选中的那些子集受到计算影响，我们就能以类似于条件移动的方式执行谓词化：

```c++
const reg c = _mm256_set1_epi32(49);
const reg z = _mm256_setzero_si256();
reg s = _mm256_setzero_si256();

for (int i = 0; i < N; i += 8) {
    reg x = _mm256_load_si256( (reg*) &a[i] );
    reg mask = _mm256_cmpgt_epi32(x, c);
    x = _mm256_blendv_epi8(x, z, mask);
    s = _mm256_add_epi32(s, x);
}
```

（为简洁起见，省略了[[归约.md|水平求和以及处理数组剩余部分]]等次要细节。）

这就是 SIMD 中通常做谓词化的方式，但它并不总是最优的方法。我们可以利用其中一个被混合的值为零这一事实，用按位 `and` 配合掩码来替代混合：

```c++
const reg c = _mm256_set1_epi32(50);
reg s = _mm256_setzero_si256();

for (int i = 0; i < N; i += 8) {
    reg x = _mm256_load_si256( (reg*) &a[i] );
    reg mask = _mm256_cmpgt_epi32(c, x);
    x = _mm256_and_si256(x, mask);
    s = _mm256_add_epi32(s, x);
}
```

这个循环稍快一些，因为在这颗特定的 CPU 上，向量的 `and` 比 `blend` 少花一个周期。

另有几条指令以掩码作为输入，最值得注意的有：

- `_mm256_blend_epi32` 内建函数是一条 `blend`，它接受一个 8 位整数掩码而非向量（这正是它末尾没有 `v` 的原因）。
- `_mm256_maskload_epi32` 与 `_mm256_maskstore_epi32` 内建函数，它们从内存载入/存储一个 SIMD 块，并一次性用掩码与之做 `and`。

我们也可以将谓词化用于编译器的内建向量类型：

```c++
vec *v = (vec*) a;
vec s = {};

for (int i = 0; i < N / 8; i++)
    s += (v[i] < 50 ? v[i] : 0);
```

所有这些版本都运行在约 13 GFLOPS，因为这个例子实在太简单，编译器可以自行向量化该循环。让我们转向更复杂、无法被自动向量化的例子。

### 搜索

在下一个例子中，我们需要在一个数组中查找特定值并返回其位置（即 `std::find`）：

```c++
const int N = (1<<12);
int a[N];

int find(int x) {
    for (int i = 0; i < N; i++)
        if (a[i] == x)
            return i;
    return -1;
}
```

为了对 `find` 函数做基准测试，我们用 $0$ 到 $(N - 1)$ 的数填满数组，然后反复搜索一个随机元素：

```c++
for (int i = 0; i < N; i++)
    a[i] = i;

for (int t = 0; t < K; t++)
    checksum ^= find(rand() % N);
```

标量版本给出约 4 GFLOPS 的性能。这个数字包含了我们本不必处理的元素，所以请在脑海中把它除以二（我们预期需要检查的元素比例）。

要向量化它，我们需要将向量中的元素与搜索值做相等比较，产生一个掩码，然后以某种方式检查这个掩码是否为零。若不为零，说明所需元素就在这 8 个元素的块中某处。

要检查掩码是否为零，我们可以用 `_mm256_movemask_ps` 内建函数，它取一个向量中每个 32 位元素的第一位，并据此产生一个 8 位整数掩码。然后我们就能检查这个掩码是否非零——若非零，还能立刻用 `ctz` 指令得到下标：

```c++
int find(int needle) {
    reg x = _mm256_set1_epi32(needle);

    for (int i = 0; i < N; i += 8) {
        reg y = _mm256_load_si256( (reg*) &a[i] );
        reg m = _mm256_cmpeq_epi32(x, y);
        int mask = _mm256_movemask_ps((__m256) m);
        if (mask != 0)
            return i + __builtin_ctz(mask);
    }

    return -1;
}
```

这个版本给出约 20 GFLOPS，大约比标量版本快 5 倍。它在热循环中只用 3 条指令：

```nasm
vpcmpeqd  ymm0, ymm1, YMMWORD PTR a[0+rdx*4]
vmovmskps eax, ymm0
test      eax, eax
je        loop
```

检查一个向量是否为零是一项常见操作，而 SIMD 中存在一个类似于 `test` 的操作可供我们使用：

```c++
int find(int needle) {
    reg x = _mm256_set1_epi32(needle);

    for (int i = 0; i < N; i += 8) {
        reg y = _mm256_load_si256( (reg*) &a[i] );
        reg m = _mm256_cmpeq_epi32(x, y);
        if (!_mm256_testz_si256(m, m)) {
            int mask = _mm256_movemask_ps((__m256) m);
            return i + __builtin_ctz(mask);
        }
    }

    return -1;
}
```

我们仍在使用 `movemask` 以便稍后做 `ctz`，但热循环现在少了一条指令：

```nasm
vpcmpeqd ymm0, ymm1, YMMWORD PTR a[0+rdx*4]
vptest   ymm0, ymm0
je       loop
```

这并没有改善多少性能，因为 `vptest` 和 `vmovmskps` 的吞吐都是一，无论循环中还做了什么，它们都会成为计算的瓶颈。

为了绕过这一限制，我们可以以 16 个元素为一块进行迭代，并用按位 `or` 合并两个 256 位 AVX2 寄存器独立比较的结果：

```c++
int find(int needle) {
    reg x = _mm256_set1_epi32(needle);

    for (int i = 0; i < N; i += 16) {
        reg y1 = _mm256_load_si256( (reg*) &a[i] );
        reg y2 = _mm256_load_si256( (reg*) &a[i + 8] );
        reg m1 = _mm256_cmpeq_epi32(x, y1);
        reg m2 = _mm256_cmpeq_epi32(x, y2);
        reg m = _mm256_or_si256(m1, m2);
        if (!_mm256_testz_si256(m, m)) {
            int mask = (_mm256_movemask_ps((__m256) m2) << 8)
                     +  _mm256_movemask_ps((__m256) m1);
            return i + __builtin_ctz(mask);
        }
    }

    return -1;
}
```

障碍既除，性能现在峰值达到约 34 GFLOPS。但为什么不是 40？难道不该快一倍吗？

下面是一轮循环在汇编中的样子：

```nasm
vpcmpeqd ymm2, ymm1, YMMWORD PTR a[0+rdx*4]
vpcmpeqd ymm3, ymm1, YMMWORD PTR a[32+rdx*4]
vpor     ymm0, ymm3, ymm2
vptest   ymm0, ymm0
je       loop
```

每一轮迭代，我们都需要执行 5 条指令。虽然所有相关执行端口的吞吐允许平均在一个周期内完成，但我们做不到，因为这颗特定 CPU（Zen 2）的解码宽度为 4。因此，性能被限制在理论值的 ⅘。

为了缓解它，我们可以再次把每轮迭代处理的 SIMD 块数量翻倍：

```c++
unsigned get_mask(reg m) {
    return _mm256_movemask_ps((__m256) m);
}

reg cmp(reg x, int *p) {
    reg y = _mm256_load_si256( (reg*) p );
    return _mm256_cmpeq_epi32(x, y);
}

int find(int needle) {
    reg x = _mm256_set1_epi32(needle);

    for (int i = 0; i < N; i += 32) {
        reg m1 = cmp(x, &a[i]);
        reg m2 = cmp(x, &a[i + 8]);
        reg m3 = cmp(x, &a[i + 16]);
        reg m4 = cmp(x, &a[i + 24]);
        reg m12 = _mm256_or_si256(m1, m2);
        reg m34 = _mm256_or_si256(m3, m4);
        reg m = _mm256_or_si256(m12, m34);
        if (!_mm256_testz_si256(m, m)) {
            unsigned mask = (get_mask(m4) << 24)
                          + (get_mask(m3) << 16)
                          + (get_mask(m2) << 8)
                          +  get_mask(m1);
            return i + __builtin_ctz(mask);
        }
    }

    return -1;
}
```

它现在显示出 43 GFLOPS 的吞吐——大约比最初的标量实现快 10 倍。

把它扩展到每周期 64 个值并无帮助：小数组在命中条件时要承受所有这些额外 `movemask` 的开销，而大数组无论如何都受[[内存带宽.md|内存带宽]]瓶颈限制。

### 计数

作为最后一个练习，我们不再只找某个值在数组中的首次出现，而是求它在数组中的出现次数：

```c++
int count(int x) {
    int cnt = 0;
    for (int i = 0; i < N; i++)
        cnt += (a[i] == x);
    return cnt;
}
```

要向量化它，我们只需要把比较掩码转换为每个元素上一或零，再求和：

```c++
const reg ones = _mm256_set1_epi32(1);

int count(int needle) {
    reg x = _mm256_set1_epi32(needle);
    reg s = _mm256_setzero_si256();

    for (int i = 0; i < N; i += 8) {
        reg y = _mm256_load_si256( (reg*) &a[i] );
        reg m = _mm256_cmpeq_epi32(x, y);
        m = _mm256_and_si256(m, ones);
        s = _mm256_add_epi32(s, m);
    }

    return hsum(s);
}
```

两种实现都给出约 15 GFLOPS：编译器可以自行向量化第一个。

但编译器发现不了一个技巧：注意到全 1 的掩码在重新解释为整数时就是[[整数.md|负一]]（minus one）。所以我们可以跳过"与最低位相与"那一步，直接用掩码本身，然后只对整个结果取负：

```c++
int count(int needle) {
    reg x = _mm256_set1_epi32(needle);
    reg s = _mm256_setzero_si256();

    for (int i = 0; i < N; i += 8) {
        reg y = _mm256_load_si256( (reg*) &a[i] );
        reg m = _mm256_cmpeq_epi32(x, y);
        s = _mm256_add_epi32(s, m);
    }

    return -hsum(s);
}
```

这在这套特定架构上并没有改善性能，因为吞吐实际上受更新 `s` 的瓶颈限制：它依赖于前一轮迭代，所以循环无法快于每 CPU 周期一轮迭代。如果我们利用[[归约.md#归约|指令级并行]]，把累加器一分为二，就能派上用场：

```c++
int count(int needle) {
    reg x = _mm256_set1_epi32(needle);
    reg s1 = _mm256_setzero_si256();
    reg s2 = _mm256_setzero_si256();

    for (int i = 0; i < N; i += 16) {
        reg y1 = _mm256_load_si256( (reg*) &a[i] );
        reg y2 = _mm256_load_si256( (reg*) &a[i + 8] );
        reg m1 = _mm256_cmpeq_epi32(x, y1);
        reg m2 = _mm256_cmpeq_epi32(x, y2);
        s1 = _mm256_add_epi32(s1, m1);
        s2 = _mm256_add_epi32(s2, m2);
    }

    s1 = _mm256_add_epi32(s1, s2);

    return -hsum(s1);
}
```

它现在给出约 22 GFLOPS 的性能，这已经是所能达到的上限。

当把这段代码改造为更短的数据类型时，请记住累加器可能会溢出。要绕过它，可以再增加一个更大型的累加器，并定期停下循环，把局部累加器中的值加到它上面，然后重置局部累加器。例如，对于 8 位整数，这意味着再创建一个内层循环，执行 $\lfloor \frac{256-1}{8} \rfloor = 15$ 轮迭代。
