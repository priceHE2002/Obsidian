# 编程语言

如果你正在读这本书，那么在你学习计算机科学的某个时刻，你一定曾第一次开始在意自己代码的效率。

我的那个时刻是在高中，当时我意识到做网站和做"有用"的编程并不能帮你考上大学，于是我进入了激动人心的算法竞赛世界。作为一个高中生，我算是个还不错的程序员，但此前我从未真正想过自己的代码需要执行多长时间。但突然之间，这件事变得重要起来：每道题现在都有严格的时间限制。我开始数自己的操作次数。一秒钟能完成多少次？

我对计算机体系结构知之甚少，无法回答这个问题。但我也并不需要正确答案——我需要的是一个经验法则。我的思路是："2–3GHz 意味着每秒执行 20 到 30 亿条指令，而在一个对数组元素做某些操作的简单循环里，我还需要递增循环计数器、检查循环结束条件、做数组索引之类的事，所以每条有用指令再预留 3–5 条指令的余量"，最终我用了 $5 \cdot 10^8$ 作为估算。这些说法没有一句是真的，但数出我的算法需要多少次操作再除以这个数，对我的用途而言是个不错的经验法则。

真实的答案当然要复杂得多，并且在很大程度上取决于你心中指的是哪种"操作"。它可以低至 [[内存延迟.md|指针追踪]] 的 $10^7$，也可以高达 [[SIMD并行.md|SIMD 加速]] 线性代数的 $10^{11}$。为了展示这些惊人的差异，我们将以用不同语言实现的矩阵乘法为案例，并深入探究计算机是如何执行它们的。

## 语言的类型

<!--

处理器可以被看作*状态机*（state machines）。它们把*状态*保存在若干固定长度的*寄存器*中，其中一个寄存器——指令指针——指示下一条待读取并执行的指令的内存位置。这条指令以某种方式修改寄存器，并将指令指针移动到下一条待执行的指令，如此反复。

这些指令——称为*机器码*（machine code）——是二进制编码的、古怪的，并且极难驾驭，所以如今没有正常人会直接写它们。相反，我们使用更高层的编程语言，并借助其他方式把指令喂给处理器。

-->

在最底层，计算机执行由二进制编码的指令（instructions）组成的机器码（machine code），这些指令用于控制 CPU。它们具体、古怪，并且需要极大的智力投入才能驾驭，因此人们在创造出计算机之后做的第一件事之一，就是创建编程语言（programming languages），以抽象掉计算机运行方式的一些细节，从而简化编程过程。

编程语言从根本上说只是一个接口。用它所写的任何程序，都只是一种更友好、更高层次的表示，但它最终仍需要在某个时刻被转换为机器码以在 CPU 上执行——而实现这一点有若干不同的方式：

- 从程序员的角度看，语言有两种类型：编译型（compiled），即在执行前预处理；解释型（interpreted），即在运行时由一个称为解释器（interpreter）的单独程序执行。
- 从计算机的角度看，语言也有两种类型：原生型（native），直接执行机器码；托管型（managed），依赖某种运行时（runtime）来执行。

由于在解释器中运行机器码没有意义，这总共构成了三种语言类型：

- 解释型语言，例如 Python、JavaScript 或 Ruby。
- 带运行时的编译型语言，例如 Java、C# 或 Erlang（以及在它们虚拟机上运行的语言，例如 Scala、F# 或 Elixir）。
- 编译为原生代码的语言，例如 C、Go 或 Rust。

执行计算机程序没有"正确"的方式：每种方法都有自身的收益与代价。解释器和虚拟机提供了灵活性，并支持一些不错的高级编程特性，例如动态类型、运行时代码修改和自动内存管理，但这些都伴随着某些不可避免的性能权衡——我们现在就来谈谈这些。

### 解释型语言

下面是一个用纯 Python 编写的、按定义的 $1024 \times 1024$ 矩阵乘法的例子：

```python
import time
import random

n = 1024

a = [[random.random()
      for row in range(n)]
      for col in range(n)]

b = [[random.random()
      for row in range(n)]
      for col in range(n)]

c = [[0
      for row in range(n)]
      for col in range(n)]

start = time.time()

for i in range(n):
    for j in range(n):
        for k in range(n):
            c[i][j] += a[i][k] * b[k][j]

duration = time.time() - start
print(duration)
```

这段代码运行耗时 630 秒。超过 10 分钟！

让我们试着理解这个数字。运行它的 CPU 时钟频率为 1.4GHz，意味着它每秒执行 $1.4 \cdot 10^9$ 个周期，整个计算总计接近 $10^{15}$ 个周期，最内层循环每次乘法约 880 个周期。

如果你考虑 Python 为了搞清楚程序员意图需要做的事，这就不足为奇了：

- 它解析表达式 `c[i][j] += a[i][k] * b[k][j]`；
- 试图弄清 `a`、`b`、`c` 分别是什么，并在一个存有类型信息的特殊哈希表中查找它们的名字；
- 理解 `a` 是一个列表，获取其 `[]` 运算符，取得 `a[i]` 的指针，发现它也是一个列表，再次获取其 `[]` 运算符，得到 `a[i][k]` 的指针，然后再取得元素本身；
- 查找其类型，确认它是 `float`，并获取实现 `*` 运算符的方法；
- 对 `b` 和 `c` 做同样的事情，最后将结果加赋给 `c[i][j]`。

不可否认，Python 等广泛使用语言的解释器都经过了良好优化，它们可以在同一段代码的重复执行中跳过其中某些步骤。但由于语言设计本身，某些相当可观的开销仍不可避免。如果我们去掉所有这些类型检查和指针追踪，也许就能把每次乘法的周期比（cycles per multiplication）拉近到 1，或无论原生乘法"代价"是多少？

### 托管语言

同样的矩阵乘法过程，但用 Java 实现：

```java
import java.util.Random;

public class Matmul {
    static int n = 1024;
    static double[][] a = new double[n][n];
    static double[][] b = new double[n][n];
    static double[][] c = new double[n][n];

    public static void main(String[] args) {
        Random rand = new Random();

        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                a[i][j] = rand.nextDouble();
                b[i][j] = rand.nextDouble();
                c[i][j] = 0;
            }
        }

        long start = System.nanoTime();

        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                for (int k = 0; k < n; k++)
                    c[i][j] += a[i][k] * b[k][j];
                
        double diff = (System.nanoTime() - start) * 1e-9;
        System.out.println(diff);
    }
}
```

现在它运行耗时 10 秒，约等于每次乘法 13 个 CPU 周期——比 Python 快 63 倍。考虑到我们需要从内存中非顺序地读取 `b` 的元素，这个运行时间大致就是它应有的样子。

Java 是一种编译型、但非原生的语言。程序首先编译为字节码（bytecode），然后由虚拟机（JVM）解释执行。为了获得更高性能，代码中频繁执行的部分（例如最内层的 `for` 循环）会在运行时被编译为机器码，随后以几乎零开销执行。这种技术称为即时编译（just-in-time compilation）。

JIT 编译并非语言本身的特性，而是其实现方式的特性。Python 也有一个 JIT 编译版本，叫 [PyPy](https://www.pypy.org/)，它在无需对代码做任何改动的情况下，执行上述代码大约需要 12 秒。

### 编译型语言

现在轮到 C 了：

```cpp
#include <stdlib.h>
#include <stdio.h>
#include <time.h>

#define n 1024
double a[n][n], b[n][n], c[n][n];

int main() {
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            a[i][j] = (double) rand() / RAND_MAX;
            b[i][j] = (double) rand() / RAND_MAX;
        }
    }

    clock_t start = clock();

    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            for (int k = 0; k < n; k++)
                c[i][j] += a[i][k] * b[k][j];

    float seconds = (float) (clock() - start) / CLOCKS_PER_SEC;
    printf("%.4f\n", seconds);
    
    return 0;
}
```

用 `gcc -O3` 编译时，它需要 9 秒。

这看起来不算很大的提升——相比 Java 和 PyPy 那 1–3 秒的优势，可以归因于 JIT 编译所额外花费的时间——但我们尚未利用 C 编译器生态系统中远为出色的部分。如果我们加上 `-march=native` 和 `-ffast-math` 标志，时间会骤降至 0.6 秒！

这里发生的情况是，我们 [[编译选项与目标平台.md|向编译器传达]] 了所运行的 CPU 的确切型号（`-march=native`），并赋予了它重新排列 [[浮点数.md|浮点计算]]（`-ffast-math`）的自由，于是它利用这一点，通过 [[SIMD并行.md|向量化]] 实现了这一加速。

并非说不可能在不大幅改动源码的情况下，把 PyPy 和 Java 的 JIT 编译器调优到相同性能，但对于直接编译为原生代码的语言而言，这确实更容易。

### BLAS

最后，让我们看看专家级优化实现能做什么。我们将测试一个广泛使用的优化线性代数库 [OpenBLAS](https://www.openblas.net/)。最简单的使用方式是回到 Python，直接从 `numpy` 中调用它：

```python
import time
import numpy as np

n = 1024

a = np.random.rand(n, n)
b = np.random.rand(n, n)

start = time.time()

c = np.dot(a, b)

duration = time.time() - start
print(duration)
```

现在大约需要 0.12 秒：相比自动向量化的 C 版本约 5 倍加速，相比我们最初的 Python 实现约 5250 倍加速！

你通常不会看到如此戏剧性的提升。目前，我们还无法确切告诉你这是如何实现的。OpenBLAS 中稠密矩阵乘法的实现通常是 [针对每种架构分别手工编写的约 5000 行汇编](https://github.com/xianyi/OpenBLAS/blob/develop/kernel/x86_64/dgemm_kernel_16x2_haswell.S)。在后续章节中，我们将逐一讲解所有相关技术，然后 [[矩阵乘法.md|回到]] 这个例子，仅用不到 40 行 C 代码开发出我们自己的 BLAS 级实现。

### 要点

这里的核心教训是：使用原生的底层语言并不一定会给你性能；但它确实给了你对性能的控制权。

与"每秒 N 次操作"的简化思路互补的是，许多程序员还存在一种误解，认为使用不同编程语言会对那个数字产生某种乘数效应。以这种方式并[比较语言](https://benchmarksgame-team.pages.debian.net/benchmarksgame/index.html)的性能并没有太大意义：编程语言从根本上说只是一些工具，它们以让出部分性能控制权为代价，换取便利的抽象。无论执行环境如何，利用硬件所提供的机会在很大程度上仍是程序员自己的职责。
