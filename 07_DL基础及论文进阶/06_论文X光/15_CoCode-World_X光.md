# CoCode-World_X光

**CoCode-World: Shared 3D Proxy Representation for Multi-Player World Models**
*Qirui Li（上海交大 / 中国电信 TeleAI）, Xin Zhang, Yabo Chen（TeleAI）, Jinkun Hao（上海交大）, Paul L Rosin, Yu-Kun Lai（Cardiff）, Haibin Huang, Yin Chen（TeleAI）, Ran Yi（上海交大，通讯）, Chi Zhang（TeleAI，通讯） | arXiv 2026*

## 论文说了什么

**问题**：多人生成式世界模型必须在两个相机各自运动、互相遮挡的情况下，对**同一批实体**给出一致的观测。两条现成路线各有硬伤：显式世界表示（每张地图精确建模）能控空间，但一个模型只能服务一张地图，场景多样性被绑死；只共享几何（深度/点云条件）保不住外观——同一个角色在两个视角里衣服、发型、体型都对不上。

**视角**：把「结构」与「外观」彻底分给两个输入。结构由**共享 3D 代理视频**给出（无纹理、只有轮廓/尺度/遮挡/类别色），外观由**一对 RGB 参考图**给出；一致性不靠新模块，而靠把两路视角放进**同一张画布、同一次去噪**，让预训练视频 DiT 的原生注意力自己完成跨视角通信。

**结果**：在自建双人 GTA V 基准（150 个 case，参考图用 GPT Image 2.5 风格化）上，跨视角身份分 3.847（Seedance 2.5 为 3.552、底座 MiniMax-H3 仅 2.868），DOVER/LAION/Edge F1 同步领先；代价是第一帧保真 0.684 略低于 Seedance 的 0.700。

## 方法拆解

1. **共享 3D 代理**：给定共享地图 $M$、玩家 $p$ 的实体观测 $E_t^{(p)}$ 与相机 $C_t^{(p)}$，渲染代理
$$P_t^{(p)}=R\big(M,E_t^{(p)},C_t^{(p)}\big),\qquad p\in\{1,2\}$$
代理是**无纹理**的：保留表面、障碍、角色/车辆的低模几何与遮挡关系，颜色只区分粗类别。外观细节一概不给，留给参考图与视频先验。
2. **配对数据**：私有 FiveM 服务器采双人 GTA V——每客户端记录 RGB、相机参数、玩家与邻近实体位姿，并导出同坐标系静态地图；用服务器时间戳对齐两路录制，只保留双方都有观测的区间。共 **7,846 条 ≈5 s 片段**（探索 66.4% / 骑行 18.7% / 交互 9.8% / 战斗 5.1%）。每个样本 = 两路 RGB + 两路代理 + 一张联合参考图 + caption；训练时参考图取各自首帧。
3. **联合画布**：沿宽度拼接 $V_t=[V_t^{(1)}\,|\,V_t^{(2)}]$、$P_t=[P_t^{(1)}\,|\,P_t^{(2)}]$，玩家 1 永远占左半、玩家 2 占右半（参考图同样左右拼）。生成目标
$$p_{\theta,\phi}(V\mid P,I,c)$$
$\theta$ 为冻结的 MiniMax-H3 参数，$\phi$ 为 LoRA 适配器。
4. **参考条件**：直接用 H3 原生的 image-and-video reference 接口，把联合 RGB 参考图（外观证据）与联合代理视频（演化结构）编码进同一注意力上下文；全双向注意力让目标区域可以读任意一路的参考与目标特征——左视角里看到的衣服，能直接决定右视角里同一角色的样子。
5. **训练**：沿用 backbone 的 flow-matching 目标，
$$\mathcal{L}(\phi)=\mathbb{E}\Big[\tfrac1N\big\|v_{\theta,\phi}(z_\tau,\tau;P,I,c)-(z-\epsilon)\big\|_2^2\Big],\quad z_\tau=\tau z+(1-\tau)\epsilon$$
损失只覆盖两路目标区、排除参考段。LoRA 加在注意力的投影层与前馈层，骨干冻结。
6. **推理**：同布局拼接 → 50 步双向去噪 → 裁掉 padding → 拆成两路视频。每个输出在整个区间上都以录制的代理运动为条件（不是只给首帧）。
7. **评测**：150 个双人 case，四类事件；参考图用 GPT Image 2.5 把玩家外观、背景、画风改掉，考「同一段共享玩法在不同外观/场景下能否保持一致」。指标沿用 SolarRenderer：DOVER、LAION 美学、DINO Adj.（时序外观稳定）、Edge F1（代理轮廓贴合）、First-frame（参考保真）、Cross-view（用 Qwen3.8-27B 对同步裁剪做 0–5 身份/动作一致性打分）。

## 结果

Table 1（150 case 平均，越高越好）：

| 方法 | DOVER↑ | LAION↑ | DINO Adj.↑ | Edge F1↑ | First-frame↑ | Cross-view↑ |
|---|---|---|---|---|---|---|
| Gamma-World | 0.170 | 4.364 | 0.923 | 0.038 | 0.160 | 0.697 |
| SolarRenderer | 0.454 | 5.477 | 0.968 | 0.073 | 0.655 | 3.696 |
| MiniMax-H3（底座） | 0.441 | 5.397 | 0.958 | 0.060 | 0.659 | 2.868 |
| Seedance 2.5 | 0.469 | 5.568 | 0.973 | 0.120 | 0.700 | 3.552 |
| **CoCode-World** | **0.524** | **5.655** | 0.970 | **0.124** | 0.684 | **3.847** |

消融：

- **代理表示**（Fig. 5，定性）：Raw（粗几何）在复杂工业场景出现黑块、深度/遮挡关系错；加 Detail & Lighting 明显改善；再加 Skeleton 反而**过约束**——角色会逐字复制代理的肢体轨迹，动作僵硬，用人类骨架驱动非人角色（如比格犬）时最明显。作者最终选「环境细 + 角色粗」。
- **生成方式**（Fig. 6，定性，同为 step-2,000 checkpoint）：双分支 + 跨分支 cross-attention（MetaWorld 式）在跨视角服装一致性上出错，拼接联合生成更稳；**无量化指标**。
- **效率**：50 步双向去噪；作者称蒸馏到 8 步画质仍可，但 1–2 步尚未达标。

## 锐评

- **对照一：Seedance 2.5（商业视频模型，本身支持无纹理 3D 渲染参考）**。本文在结构贴合（Edge F1 0.124 vs 0.120）、跨视角身份（3.847 vs 3.552）、画质（DOVER 0.524 vs 0.469）上赢，但在**参考保真**（First-frame 0.684 vs 0.700）与**时序外观稳定**（0.970 vs 0.973）上略输。这不是噪声能解释的方向性差异：更强的结构约束会挤压模型「照抄参考图」的自由度，作者在结论里也承认仍有 adjacent-frame 与 reference-preservation 误差。换言之，这篇不是全面碾压商业模型，而是用一点参考保真换跨视角一致。
- **对照二：Gamma-World（多 agent 世界模型，置换对称编码 + 稀疏 hub 注意力）**。它的跨视角身份只有 0.697，接近完全失败，作者归因于「从单视角数据迁移到多视角多样场景很难」。这条对照说明**一致性可以放在数据布局里，也可以放在模块里**；本文选了前者（同一画布 + 原生注意力 + 配对监督），代价是 token 数随人数线性增长。
- **对照三：MetaWorld 双分支**。同底座、同数据、同 checkpoint 的定性对比中双分支在跨视角服装上出错，支持「拼接优于分支互注」；但没有数字、没有多 case 统计，属于本文评测最薄弱的一环——一个只靠定性图支撑的架构结论。
- **真实局限**：仅支持两人；每加一名玩家，token 序列与注意力成本线性上涨，作者明确说扩展需要更高效的上下文管理。50 步去噪离实时（1–2 步）仍有距离。评测只覆盖 GTA V 一个游戏、以「外观迁移」为目标，动作驱动的状态转移被明确排除在渲染器之外（需要外部引擎提供 $E_t$）。跨视角身份分由 Qwen3.8-27B 判官给出，判官偏差未校准。

## 借鉴意义

- **代理即接口**：世界模型里最该被显式控制的不是像素，而是「谁在哪、挡了谁」；把结构压成无纹理代理、把外观交给参考图，是把「可控性」和「真实感」解耦的最省做法。
- **一致性靠数据布局，而不是新模块**：把多视角拼进同一上下文，预训练注意力天然做跨视角通信；新加 cross-attention 分支反而要重新学对齐。任何多视角/多智能体生成任务都可以先试这一招。
- **过约束会反噬**：给代理加骨架这类「更精确的控制」会限制视频先验，产生僵硬动作。控制强度要按「模型先验能补多少」来定，不是越精确越好。
- **LoRA 够用**：冻结大 DiT、只训低秩适配器即可把「渲染器」角色装上去，说明底座视频模型的先验已足以承担新任务。
