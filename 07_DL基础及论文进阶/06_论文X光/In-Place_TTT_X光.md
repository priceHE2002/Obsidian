# In-Place_TTT_X光

**In-Place Test-Time Training**
*Guhao Feng, Shengjie Luo, Kai Hua, Ge Zhang, Di He, Wenhao Huang, Tianle Cai（ByteDance Seed / 北大） | ICLR 2026 Oral | arXiv 2604.06169*

## 论文说了什么

**问题**：现在的 LLM 是"训完就冻住"。部署之后权重再也不变，所以它只能靠"把历史都塞进上下文"来适应新信息，而上下文窗口又是有限的。Test-Time Training（推理时更新一部分权重）本来是对症的解法，但一直落不了地，卡在三件事上：得引入新的专用层（那就得从头预训练）、机制天生串行（只能小 chunk，跑不满 GPU）、以及更新权重用的目标函数跟语言模型真正在做的事对不上。

**视角**：三个卡点用三个动作解开，其中最聪明的是第一个。

不新加层，而是**把已经存在的 MLP 输出投影 $W_{\text{down}}$ 直接拿来当"快权重"**（$W_{\text{gate}}$、$W_{\text{up}}$ 冻住）。理由很干净：MLP 早就被理解成一种键值记忆，它本来就是"慢权重"——存预训练学到的一般知识；那让同一个模块顺便当"快权重"、存临时的上下文信息，是最自然的事。因为是复用而不是新增，模型的预训练权重的完整性一点没动，这就是"drop-in"。顺带一个红利：注意力机制原封不动地留在那里，所以不必再靠小 chunk 维持因果性，可以用 512–1024 的大 chunk，配上并行扫描后在 context parallelism 下跑。

第二个动作是**换目标函数**，这是全文最承重的一块。

原来的 TTT 让快权重去"重建当前 token"——预测的靶子是**现在**。这篇说这不对：靶子应该是**下一个 token**。用做笔记来想这件事。开会时你只记"刚才谁说了什么"，记录很完整，但你没法用它预判下一句；改记"这句话之后，对方回了什么"，笔记才开始有预测力；再进一步，不只记紧接的一句，而是用一个小卷积把"接下来几步"揉成一个加权靶子——笔记就变成了"接下来大概会往哪走"。

形式上，把靶子从 $V_t^{\text{rec}} = \mathbf{E}_{x_t}$ 换成 $V_t^{\text{LM}} = \mathbf{E}_{x_{t+1}}$，配合内积损失，梯度一步就化成一次干净的写入：

$$W_{\text{down}}^{(i)} = W_{\text{down}}^{(i-1)} + \eta\, \hat{V}_{[i]}^{\top} Z_{[i]}$$

"现在"当键，"未来"当值。定理 1 把这个直觉钉死：在接近正交的嵌入假设下，用重建靶子时，**正确下一个 token 的 logit 期望变化被 $\lambda\epsilon c_{\text{align}}$ 卡住**（$\epsilon$ 就是嵌入间近正交的那个小常数，所以基本等于零）；换成 LM 对齐靶子，它至少涨 $\lambda c_{\text{norm}}^2 c_{\text{align}}$，而其他 token 的 logit 仍被 $\lambda\epsilon c_{\text{align}}$ 压住。也就是说：记"现在"对预测毫无贡献，记"未来"才有。

还有一处工程洁癖值得记：**文档边界处快权重复位到预训练状态**，防止跨独立序列的上下文泄漏。

**结果**：

- 实验证明：在 Qwen3-4B-Base 上，两个模型走完全相同的继续训练课程（20B tokens@32k + 15B tokens@128k），唯一变量是加不加 In-Place TTT。RULER 平均准确率（%）：

  | | 4k | 8k | 16k | 32k | 64k | 128k | 256k |
  |---|---|---|---|---|---|---|---|
  | Baseline | 96.6 | 94.1 | 92.1 | 88.7 | 74.3 | 74.8 | 41.7 |
  | In-Place TTT | 96.1 | 95.6 | 92.7 | 89.3 | **78.7** | **77.0** | **43.9** |
  | 差值 | -0.5 | +1.5 | +0.6 | +0.6 | **+4.4** | +2.2 | +2.2 |

- 实验证明：换模型也成立。LLaMA-3.1-8B 在 64k 从 81.6 到 83.7（+2.1），Qwen3-14B-Base 在 64k 从 67.9 到 70.6（+2.7）；并且与 YaRN 位置外推叠加后增益仍在（Qwen3-14B 的 64k+YaRN：81.3 -> 82.5），说明与 RoPE 外推技术正交。
- 实验证明：1.7B 模型上的消融——状态越大（TTT 层越多）越好；chunk size 512 与 1024 最优且 1024 更快；目标函数里 Conv1D（引入未来信息）与 $W_{\text{target}}$（投影）**两个都必需**，其中 Conv1D 在长上下文起作用、$W_{\text{target}}$ 在短上下文起作用。
- 实验证明：prefill 吞吐和峰值显存的开销可以忽略。
- 作者推测：这套东西"朝向一个更动态、持续学习的 LLM 范式迈出了一步"。作者在 Discussion 里也主动留了口子：框架的核心原则与损失函数、优化器的具体选择正交，后两者"留给未来工作"——也就是本文只用了一次梯度步 + 内积损失。

**一句话**：这篇论文是说——别给模型加新零件了，就把它现成的"记忆层"当作工作台：每读进来一段话，就用"这段话之后发生了什么"去改一下那张记忆的写法，改完接着用，读完一篇就擦掉重来。

```
  主干 Transformer 架构一点不动
  |
  +-- 注意力层:   原样冻结
  |
  +-- MLP 层:     W_gate / W_up 冻结(慢权重,存预训练知识)
                  W_down 拿出来当"快权重"(读写目标)   <-- 只动这一个

  每读进一块 token, 两步:
     (1) apply:  用当前 W_down 算出这块的输出
     (2) update: W_down += eta * (未来)^T (现在)

  靶子取"下一个 token 的嵌入", 不是"当前 token 的嵌入"
        |
        +-- 取"现在" -> 对预测下一词的 logit 几乎零贡献 (定理 1)
        +-- 取"未来" -> 正确 token 的 logit 必然上升 (定理 1)

  读完一篇文档 -> 快权重复位, 下一篇从头开始
```

## 对我意味着什么

**可能改变我的**：我默认"每个结构动作都得先预测价值才敢做"，本文给了一个更省的判据——先问这一步能不能便宜地退回去；能退的不用预测。

### 可逆的动作不该动用 critic

本文最狠的一步不是选对了 $W_{\text{down}}$，而是让整套机制**天生可逆**。快权重只在处理一篇文档期间存在，读完复位。于是它的成本模型完全变了：改了不怕错，因为擦得掉；错了不用提前预判，因为后果是临时的。作者根本不需要任何"这个写入值不值得"的预测器。

我在 CounterStruct 里的成本模型正相反。掩码位置一动就是永久的，所以每个动作都要先过反事实 shadow bundle + horizon critic，算力全砸在"预测价值"上。

```
  我原来的默认:
     所有结构动作 --> 都要先预测价值 --> 才敢做
                          |
                     shadow bundle
                     horizon critic
                     反事实 rollout
                          |
                     贵, 但以为这样才安全

  本文给的判据: 先问"退回去要多少钱"
                          |
          +---------------+---------------+
          |                               |
      一步就能退回                    退不回来
     (换掉的边再换回来)            (冷启动新生权重,
                                    旧能力已被破坏)
          |                               |
          v                               v
      不必预测                        才需要预测
      直接试, 看观测结果              动用 critic / shadow
      不行就换回来
          |                               |
          +---------------+---------------+
                          |
            算力配给跟着"可逆性"走,
            而不是跟着"预期收益"走
```

我的 §24 是 edge-turnover budget，§23 是在 Johnson 图上做 group-wise search——**换边在定义上就是一步可逆的**。按本文的逻辑，这些动作根本不该排队等 horizon critic：它们的价值应该由"试完直接观测"来决定，退回成本约等于零。真正需要 critic 的只有那些退不回来的动作——新生权重的冷启动（SMET）、以及会破坏旧能力的合并。

> 别问这个动作值多少，先问它错了要赔多少。赔得起的不需要预测。

### 把"形状主张"写进预注册

论文的原话是 In-Place TTT 相对基线"建立起一个**持续变宽的**优势（a consistent and widening advantage as the sequence length increases）"。把表里的差值摊开看：

```
  论文画的形状(prose):
   增益
    ^
    |                    /
    |                  /
    |                /
    |              /
    +--------------------------> 上下文长度
        "持续变宽"

  表里的实际差值(Qwen3-4B-Base, RULER 平均准确率):
    4k    8k    16k   32k   64k   128k  256k
   -0.5  +1.5  +0.6  +0.6  +4.4  +2.2  +2.2
     |                      ^     |     |
     |                      |     +-----+  这里在变窄
     |                   峰值
     +-- 短上下文这一格是负的

  两条曲线的形状不一样: 一条单调上升, 一条是驼峰
```

诚实地看：增益从 32k 到 64k 确实明显拉开（+0.6 -> +4.4），长上下文整体优于短上下文，这个方向性结论站得住。但"持续变宽"是个**形状主张**，而数据是驼峰——峰值在 64k，之后收窄。更要说的是最后一列：256k 上两个模型是 41.7 和 43.9，都在接近崩塌的区间，"+2.2 支撑了外推能力"这个说法建立在一个已经掉到地板的指标上。

对我有用的部分在这里：**我现有的预注册 gate 全是点阈值**——$\rho_{\text{critic}}(64) \ge 0.30$、$\Delta\rho \ge 0.10$、shadow overhead ≤ 45%、P0 用 `max_memory_allocated` 校准 VRAM 表。点阈值能抓住"有没有过线"，但抓不住"优势是否随某个量单调变宽"这类**形状**。而形状恰恰是我最想主张的那类结论（"越长的任务上保留率越好"、"sparsity 越高优势越大"）。点阈值全过，形状可能是个驼峰，审稿人一眼就看出来。

> 结论的形状和结论的大小一样需要预注册——只卡阈值，等于放行驼峰。

### 开放问题

论文的对照是"同样继续训练课程，加不加 In-Place TTT"，并声称"唯一变量是 In-Place TTT"。这句话在代码层面成立，但在**算力**层面不成立：In-Place TTT 每读一块都要多跑一次梯度写入，实验组花了更多的测试时算力。

```
  论文的对照:
     基线 = 同样的继续训练课程
     实验 = 同样的课程 + In-Place TTT
     => "唯一的变量是 In-Place TTT"        (论文的说法)

  但 In-Place TTT 每块都要额外做一次梯度写入
  实验组 = 多花了测试时算力

        缺的那一组:
        +-----------------------------------------+
        | 同样课程 + 同样多的额外算力,            |
        | 但花在别的机制上                        |
        | (在 W_down 上挂 LoRA / 多跑几遍前向     |
        |  做自洽性投票 / 更长的 CoT)             |
        +-----------------------------------------+
                          |
                          v
        64k 那 +4.4 分里, 有多少来自"把未来当靶子"
        这个机制, 有多少只是"多算了"?
```

这个洞对我很熟——我的 P0 待办里就写着"SMET 归因需独立 optimizer-control ablation"，同一个病。看别人的论文时我一眼能挑出来，写自己的方案时却要专门列一条待办提醒，这件事本身值得注意：**归因缺陷不是"别人会犯的错"，是我每次都会犯的错，所以它必须是一个固定检查项，而不是一次临时判断。**

顺带一个同源的细节：消融（状态规模、chunk size、目标函数）是在 1.7B 模型上做的，而头条结果在 4B/8B/14B 上。作者没说明这些结论能否外推到更大的模型——目标函数里 Conv1D 与 $W_{\text{target}}$ 的"长/短上下文分工"，在 1.7B 上测量出来的分工，换到 14B 上还成立吗？

---

**所以真正该问的是：你会把哪个动作划进"可逆、所以不用预测"那一栏？如果换边真的算可逆，那你为它建的整套 critic 是在给一个本可以直接试的问题预付保险费——这笔保险费，你打算怎么证明它值？**
