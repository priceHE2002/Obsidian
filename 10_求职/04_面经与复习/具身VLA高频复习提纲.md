## 1. π0 / π0.5 / π0.6 系列

### 1.1 答题骨架（先背这条主线）

- **π0**：VLM 主干（PaliGemma 3B）+ action expert（约 300M）+ Flow Matching 动作头；输入图像 + 语言（+ 本体状态），输出约 50 步 action chunk；高频控制靠 chunk 摊薄大模型推理延迟。
- **π0-FAST**：给 π0 配 FAST 分词器——用 DCT 把动作序列压到频域再离散成 token，自回归生成动作；token 数比逐维逐帧离散少，训练/推理更快；代价是频域截断/离散化误差，精细高频控制不友好。
- **π0.5**：面向开放世界泛化。三件事要讲全：① 异构数据共同训练（多机器人 + 网络数据 + 高层子任务标注）；② **knowledge insulation**——动作 loss 只更新动作侧，阻断梯度回流 VLM，避免机器人数据把语义能力带偏；③ 离散 state token + 高层子任务推理（把"做什么"拆给高层，"怎么做"交给低层动作）。
- **π0.6**：最新迭代，方向是精细操作 / 真机可靠性 / 与 RL 后训练结合；具体改动以论文与官方发布为准，不确定就讲趋势，别硬编。

### 1.2 高频问法（原题）

- π0 为什么用 Flow Matching，不用自回归离散——篇 20

- state token 放在哪、连续 state 怎么变成 token、分桶离散的缺点——篇 20
- π0.5 主打的开放世界泛化是怎么做到的——篇 20

### 1.3 关键机制（面试可讲的口径）

1. **VLM–Action Expert 交互**：不要只说"取 VLM 最后 hidden state"。动作专家是一组额外参数/token，通过 attention 读 VLM 的视觉-语言特征，输出动作 token 表示，再经 FM 头生成动作；VLM 管语义，action expert 管动作分布。
2. **knowledge insulation**：动作 loss 只更新 action expert，结构上阻断对 VLM 的梯度回传（不是加正则）；这样机器人数据的动作监督不会破坏 VLM 的语义知识。没有它会怎样：VLM 被动作数据带偏 → 语言泛化和开放世界理解退化。
3. **state token**：关节角/末端位姿/夹爪等连续状态分桶离散成 token，与图像、语言 token 同流输入；缺点：精度损失、桶边界跳变；替代：连续编码 / Fourier 特征 / 单独 state encoder。
4. **action chunk**：一次预测 H 步，摊薄推理延迟、学短程时序结构；H 太短频繁推理，H 太长开环误差累积；执行 k 步后滚动重规划。
5. **泛化从哪来**：异构数据 + 高层子任务标注 + 网络数据，不是单纯"数据量大"。

### 1.4 追问陷阱

- "代码上 π0 和 π0.5 差哪？"→ 答：knowledge insulation 的实现（stop-gradient / 分离训练）、state token、子任务头、数据管线；别只报超参。
- "为什么选 π0.5 当 baseline？"→ 生态成熟、开源权重、FM+VLM 兼顾泛化与动作质量；同时说风险（推理延迟、数据成本）。
- "π0.6 相比前代改了什么？"→ 没吃透就诚实说版本细节没把握，转讲趋势：精细操作、真机可靠性、RL 后训练、数据质量；别编。
- "knowledge insulation 和 LoRA 冻结 VLM 有什么区别？"→ LoRA 仍在更新 VLM 参数、只是低秩；隔离是彻底切断动作监督对 VLM 的更新路径。
- "π0 为什么不用 AR token？"→ 连续高维动作离散化误差大、token 序列长、延迟高；FM 直接建模连续多峰分布、采样少步。

## 2. Flow Matching

### 2.1 一句话

学一个从噪声到真实动作（chunk）的**速度场**，用 ODE 积分生成动作；训练目标直接回归"指向真实动作的方向"，比 diffusion 的 score/去噪形式更直接、采样步数更少。

### 2.2 高频问法（原题）

- Flow Matching 原理、公式推导、伪代码——篇 1、4、5、17、19、20、24、29（**几乎必考**）
- Flow Matching vs 扩散策略、ODE 八股——篇 24、29
- AR vs Flow Matching 怎么选、AR 与 diffusion 的核心思想——篇 24
- 为什么 MSE 不行：会平均多峰动作——篇 21
- 为什么 π0 用 FM——篇 20
- UniVLA 里直出式 action decoder 为什么比 FM 好——篇 19
- 手撕：Flow Matching 伪代码——篇 1、4、9、17

### 2.3 答题骨架（推导 + 伪代码）

**构造直线路径**（线性插值，OT 路径的简单版）：

- 噪声 `x0 ~ N(0, I)`，真实动作 `x1`（形状 `[H, D]` 的 chunk）
- 插值：`x_t = (1 - t) · x0 + t · x1`，`t ∈ [0, 1]`
- 速度场真值：`v_t = dx_t/dt = x1 - x0`
- 训练损失：`L = E_{t,x0,x1} || v_θ(x_t, t, c) - (x1 - x0) ||²`
- 推理：从 `x0 ~ N(0,I)` 出发，沿速度场积分 `x ← x + v_θ(x, t, c)·Δt`，到 `t=1` 得 `x1`

**伪代码（PyTorch，面试版）**：

```python
import torch
import torch.nn.functional as F

def fm_loss(policy, action, cond):
    """action: (B, H, D) 真实动作 chunk；cond: 视觉/语言/state 条件特征"""
    x0 = torch.randn_like(action)                 # 噪声
    t = torch.rand(action.shape[0], 1, 1)         # 每个样本一个 t
    xt = (1 - t) * x0 + t * action                # 直线插值
    v_target = action - x0                        # 速度真值
    v_pred = policy(xt, t, cond)                  # 预测速度场
    return F.mse_loss(v_pred, v_target)

@torch.no_grad()
def fm_sample(policy, cond, shape, steps=10):
    x = torch.randn(shape, device=cond.device)    # 初始噪声
    dt = 1.0 / steps
    for i in range(steps):
        t = torch.full((shape[0], 1, 1), i * dt, device=x.device)
        x = x + policy(x, t, cond) * dt           # Euler 积分
    return x                                      # 近似 x1
```

**答题加分点**：

- 路径选择：直线/OT 路径比 diffusion 的 SDE 更直，可少步采样
- `t` 采样：uniform 稳；logit-normal 更强调中间难时刻
- 条件注入：VLM 特征经 cross-attention 进动作网络
- 推理步数 vs 延迟：10 步左右是常见折中；步数太少误差累积

### 2.4 FM vs Diffusion vs AR（对比表）

| 维度 | Diffusion Policy | Flow Matching | AR 离散 token |
|---|---|---|---|
| 训练目标 | 学 score/去噪 | 学速度场（ODE） | 交叉熵，逐 token |
| 采样步数 | 几十步 | 少步（约 10） | 逐 token（可能几十~上百步） |
| 多峰建模 | 好 | 好 | 可学但离散化误差 |
| 动作空间 | 连续 | 连续 | 离散 |
| 延迟 | 高 | 中 | 高（序列长） |
| 典型 | DP、RDT | π0、π0.5 | RT-2、FAST 自回归 |

**选型口径**：低延迟高频控制 + 连续高维动作 → FM；要复用 LLM 词表/大规模多任务自回归 → AR token（FAST 降 token 数）；数据少/任务简单 → 单峰回归或少量步 diffusion。

### 2.5 追问陷阱

- **为什么 MSE 不行**：多峰分布下单峰回归会把多个可行动作平均成"中间不可执行动作"（左右绕障平均成撞障）；FM/diffusion 学整条分布。
- **FM 为什么比 diffusion 快**：路径更直、少步 ODE；但步数太少有误差，需要中点/高阶 solver 或蒸馏。
- **为什么 FM 损失能回归 `x1-x0`**：条件流匹配（CFM）定理保证最小化该回归等价于匹配目标速度场。
- **训练 t 分布**：uniform、logit-normal 的影响要能说。
- **与 RL 结合**：FM 策略 + flow-DPO / RLT 后训练（篇 25 提到 flow DPO）。

### 2.6 手撕清单

- 10 步 Euler 版 FM 采样（能写能跑）
- 推导：为什么 `∂L/∂v = vθ - (x1 - x0)`
- 联合考法：MHA 输出 → 动作头 / FM 去噪网络的输入输出维度

### 2.7 自测

1. 不看书讲完 FM 的设定、损失、采样三步。
2. FM 和 diffusion 的数学差异（速度场 vs score）。
3. 为什么 π0 用 FM 而 RT-2 用 token。
4. 采样步数从 10 降到 3 会有什么后果，怎么补偿。

## 3. KV Cache

### 3.1 一句话

自回归/迭代解码时，缓存每层历史的 **K 和 V**，每步只算新 token 的 Q/K/V 并复用缓存，避免对整个前缀重复计算——本质是**用显存换计算**。

### 3.2 高频问法（原题）

- 自回归解码用 KV Cache 时，key 和 value 分别缓存什么特征——篇 19 Q1
- 在机器人视觉-动作模型中启用 KV Cache，会对时序动作推理有什么影响——篇 19 Q1
- GQA 或 MHA 时，KV Cache 的存储和索引方式有什么不同——篇 19 Q2
- 长序列机器人任务中 KV Cache 过大导致显存溢出怎么办——篇 19 Q2
- 解释 QKV、KV Cache，并说明张量形状——篇 5 Q10
- self-attention 八股 + 伪代码——篇 17 Q2
- RoPE 位置编码、KV Cache 对 VLA 时序动作推理的影响——篇 29 Q3
- 为什么除以 √d_k、GQA 的结构和作用——篇 19 Q5、Q6
- 手撕 MHA 并追问 shape 流转——篇 17 Q9

### 3.3 答题骨架（先把形状讲清）

**单层 self-attention**：输入 `X ∈ R^{B×L×d_model}`

- `Q = X W_Q`、`K = X W_K`、`V = X W_V`
- MHA 拆 H 个头，每头 `d_head = d_model / H`
- `score = Q Kᵀ / √d_head` → softmax → `out = A V` → concat → `W_O`

**KV Cache 做什么**：解码第 t 步只算新 token 的 `q_t, k_t, v_t`，把 k/v 追加到缓存：

- `K_cache ∈ [B, H, L_hist, d_head]`，`V_cache` 同形状（每层各一份）
- 用 `q_t` 与整个 `K_cache` 算 attention
- **Q 不缓存**（只需要当前步）

**GQA/MQA**：

- MHA：每个 Q 头有独立 K/V，`K_cache ∈ [B, H, L, d_head]`
- GQA：Q 有 H 头，KV 分 G 组（G < H），`H/G` 个 Q 头共享一组 KV，`K_cache ∈ [B, G, L, d_head]`，显存降到 `1/(H/G)`
- MQA：G=1 的极端情况
- 索引：`kv_group = q_head // (H/G)`（或按实现的分组规则）

**显存估算（能现场算，很加分）**：

`显存 ≈ 2 × B × H_kv × L × d_head × n_layers × 每参数字节`

例：7B、32 层、H=32、d_head=128、bf16、L=2048、B=1
→ `2 × 32 × 2048 × 128 × 32 × 2B ≈ 1.0 GB`；GQA G=8 时约 256 MB。

**在 VLA 里的影响（重点，别只背 LLM 八股）**：

1. 单次推理内：视觉/语言前缀的 KV 可复用（同一帧多步去噪、多次采样）；但 FM 每步输入动作不同，动作 token 部分要重算——收益取决于实现。
2. 跨 chunk：观测更新后旧 KV 必须重算（画面变了），盲目复用会导致动作滞后/漂移。
3. 长任务：多帧历史 KV 线性增长 → 滑窗、attention sink、KV 压缩/量化；chunk 内复用最划算。

**优化清单**：GQA/MQA、PagedAttention、KV 量化（FP8/INT8）、滑窗 + attention sink、prefix caching、chunk 级重算、多帧下采样。

### 3.4 追问陷阱

- "缓存 K 还是 V？"→ 都缓存；Q 不缓存（每步新算）。
- "GQA 省什么？"→ 省 KV 显存和带宽，不省 Q 计算；精度损失通常很小。
- "为什么 VLA 推理不常开 KV Cache？"→ chunk 间观测变、控制延迟敏感、模型相对小；开了也主要是 prefix/图像特征复用。
- "为什么除以 √d_k？"→ 点积方差随 d_head 增大而增大，softmax 饱和、梯度消失；缩放让方差回到 1。
- "KV Cache 和 action chunk 什么关系？"→ chunk 解码越长 KV 越大；FM 非自回归时 KV 收益有限，AR 动作 token（FAST）收益明显。

### 3.5 自测

1. 手推 MHA 一步：从 `X` 到输出，标出每个张量形状。
2. 解释 KV Cache 前后每步计算量差异。

4. VLA 里哪部分 KV 能复用、哪部分必须重算，为什么。

## 4. 数据 pipeline

### 4.1 一句话

把"真实操作"变成可训练数据：**采集 → 对齐/清洗 → 标注 → 组织 → 配比训练 → 评测闭环**。每一步都决定策略上限，面试官靠这块判断你有没有真做过项目。

- DAgger 数据注意点、失败数据利用、接管数据采集——篇 4、11、25、27、29
- 训练数据用关节角还是末端位姿、数据量/卡数/时长、全参 vs LoRA——篇 11、17、18、25、30
- 真机/ego/仿真/互联网数据配比与分布冲突——篇 24、25、28、29
- 数据增强、消融实验、抽帧影响——篇 17、23、5
- 关键帧标注、subtask 时间段标注——篇 25、10 Q18
- 仿真数据/Sim2Real 的坑——篇 10 Q14–15

### 4.3 答题骨架（按链路讲，别跳步）

1. **采集**：遥操作（主从臂/VR/外骨骼/UMI 手持夹爪）、动捕、视频（ego/互联网）、仿真。答题要点：为什么选这种（成本/精度/规模/本体无关）。
2. **UMI**：手持夹爪 + 鱼眼相机采集人手操作 → 重定向到机器人动作。优点：低成本大规模、不受本体限制；问题：相机视角/夹爪标定差异、时间尺度（人手快、机器人慢）、动作空间映射误差；规范：工位固定、多场景多物体、成功 + 失败样本、统一帧率。
3. **LeRobot**：统一数据集格式（episode/帧/多相机/video+parquet 元数据）；v2.1 → v3 的组织变化以官方文档为准。面试讲"为什么统一格式重要"：跨本体、跨数据集混训、工具链复用。
4. **对齐与清洗**：图像帧率 vs 关节控制频率（时间戳插值/最近邻）、坐标系/TCP 标定、滤波降采样、异常帧剔除、失败样本保留（负例/DAgger 种子）。
5. **标注**：subtask 时间段、关键帧、语言指令、成功/失败标签、RL 用奖励。
6. **组织与配比**：真机/ego/仿真/互联网。阶段式（篇 28 口径）：持续预训练互联网为主（约 70/20/10）→ 领域适应（30/40/30）→ 真机微调（0/20/80）；初始量可讲 60/25/15（互联网/仿真/真机）。分布冲突：互联网保语义、仿真扩规模、真机补精度；比例靠成功率/遗忘指标调，不照抄。
7. **训练配置**：数据量（小时/episode/帧）、卡数（A100/H100 × N）、batch、lr、epoch、全参 vs LoRA；先报量级再报瓶颈。
8. **评测闭环**：成功率、泛化、离线指标 vs 真机、失败案例回流再训练。

### 4.4 DAgger 专题（常单独问）

- 流程：初始策略 → 真机 rollout → 人工接管纠正新状态 → 混合新旧数据重训 → 迭代。
- 注意点：接管数据分布（人的纠正状态 vs 模型失败状态）、标注成本、灾难性遗忘（混入旧数据）、安全（接管延迟/急停）。
- 失败数据利用：负样本/恢复数据、flow-DPO 偏好对、过滤后混训。

### 4.5 追问陷阱

- "抽帧会影响精度吗？"→ 降低时间分辨率；长程任务可、精细高频动作受损；靠补数据/提帧率解决，并说明怎么验证。
- "数据量不够怎么办？"→ 仿真/UMI/互联网/增强/预训练，别只说"多采"。
- "为什么不用人手视频直接训？"→ 2D→3D 动作对齐、本体差异、无动作标签；需重定向/逆动力学/UMI。
- "离线指标涨、真机不涨怎么排查？"→ 分布偏移、评测集泄漏、闭环误差累积、动作后处理/延迟。
- "配比怎么定？"→ 消融 + 指标驱动，讲清楚"先验比例—小规模消融—全量训练"的流程。

## 5. RTC（Real-Time Chunking）

### 5.1 一句话

在 action chunk 推理延迟期间继续执行，并用**已执行动作**约束新 chunk 的生成，让异步控制不抖、不跳变——本质是"用条件生成解决 chunk 边界连续性"。

### 5.2 高频问法（原题）

- "训练时 RTC" 与原始推理期 RTC 怎么区别——篇 4 Q1
- 同步 / 异步 / 推理 RTC / 训练 RTC 怎么比较——篇 4 Q2
- RTC 原理——篇 1 二面、篇 9 Q6
- ACT 推理流程与 RTC 的区别——篇 5 Q9
- RTC 的软约束 vs 硬覆盖；inpainting 训练版怎么做——篇 24 Q16
- RTC 相关概念（π0.5 项目里）——篇 11 Q7
- 1–3Hz 动作怎么满足 50–200Hz 控制——篇 28 图 4–5

### 5.3 答题骨架（为什么 → 怎么做 → 怎么训）

1. **问题**：7B VLA 单次推理数百 ms；同步等结果机器人会停/顿；直接异步执行旧 chunk，切换处动作跳变。
2. **核心思想**：把"已执行的动作"作为条件，新 chunk 生成时要求开头与已执行动作衔接（inpainting / 软约束），于是可以边执行边推理。
3. **推理期 RTC（不改模型）**：新 chunk 采样时对重叠前缀做引导/加权，或对重叠区混合；软约束 = 在去噪/积分过程加 guidance，让生成动作贴近已执行段，同时保留后续自由度。
4. **训练期 RTC（inpainting 训练版）**：训练时随机模拟"轨迹前缀已执行"，让模型学会在给定前缀动作条件下生成后续动作；推理时直接条件生成。好处：边界更自然；代价：训练复杂、要构造前缀分布。
5. **同步 vs 异步**：同步 = 推理完再执行（延迟高、简单）；异步 = 执行旧 chunk 同时推理新 chunk，需要时间戳对齐、队列、超时回退；RTC 是异步框架下的连续性保障。
6. **与 ACT 的区别**：ACT 是"预测 chunk 后开环执行"，chunk 边界可能不连续；RTC 在边界做融合/条件生成，并支持异步。
7. **工程约束**：chunk 长 H、执行 k 步、推理时间 T_infer、控制周期 T_ctrl；要满足 `T_infer ≤ (H-k)·T_ctrl` 才能无缝；缓冲队列/双缓冲；安全 fallback。

### 5.4 追问陷阱

- "软约束和硬覆盖到底区别？"→ 软：引导生成贴近旧轨迹、允许调整；硬：直接替换重叠段，简单但可能不连续/冲突。
- "RTC 和 temporal ensemble 什么关系？"→ TE 是多历史 chunk 加权平均、延迟大；RTC 针对推理延迟做边界条件生成，目标不同。
- "执行中观测更新怎么办？"→ 重推理/回退；KV/prefix 缓存失效；chunk 越短越灵敏、越长越稳，需权衡。
- "那为什么不直接训个更快的模型？"→ 两条路线可叠加；RTC 解决 chunk 边界连续性，不是模型速度。

### 5.5 自测
