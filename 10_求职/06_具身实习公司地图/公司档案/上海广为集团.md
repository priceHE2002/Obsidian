## 四、与我的匹配度（强项 / 短板 / 证据缺口）

- **强匹配**：只有一条——Python 基础 + 愿意学 ROS/Linux。诚实说，这一条几乎不构成匹配。
- **短板与缺口（直说）**：
  1. **岗位已下线**，投了也无入口，这是最硬的事实。
  2. 用户完全没有 C++、ROS2、Linux 系统编程、嵌入式部署经验，四条要求零命中。
  3. 端侧推理（ONNX/TensorRT/量化）完全没接触。
  4. 与职业主线（VLA / 真机 RL）偏离：即使拿到，对后续申请帮助有限，还会挤占 P1/P2 的时间。

- **1–3 周内可补的最小动作**：**不建议投入**。若只想验证兴趣，可在 2 天内装 ROS2 Humble 跑通 turtlesim + 写一个订阅图像话题的 Python 节点，感受一下即可，不要继续深入。

## 五、如何提升进入概率（具体准备清单）

1. **简历上要出现的项目/关键词**（若未来遇到同类嵌入式岗）：ROS2 节点、话题/服务、OpenCV、ONNX 导出与推理、Linux 命令行与编译。
2. **3 个可能面试题及答题要点**：
   - 「ROS2 里话题、服务、动作的区别？」→ 话题是异步单向流、服务是同步请求响应、动作是长任务带反馈与取消；给一个「相机图像用话题、标定用服务、导航用动作」的例子。
   - 「模型怎么部署到端侧？」→ 导出 ONNX → 量化（INT8）→ TensorRT/OpenVINO 推理 → 校验精度掉点；讲清吞吐与延迟的权衡。
   - 「实时性怎么保证？」→ 控制回路周期、线程优先级、内存分配预分配、避免在回调里做重计算。
3. **可产出的作品/证据**：一个 ROS2 Python 节点 demo（订阅图像 → OpenCV 处理 → 发布结果）+ 一段录屏。仅此即可，不要再加码。
4. **软性动作**：无需内推（岗位已关）；若对嵌入式方向真有兴趣，等 2027 年后按「机器人软件工程师」路线重新评估，而不是现在。
