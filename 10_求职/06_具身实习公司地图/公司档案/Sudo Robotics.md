## 四、与我的匹配度（强项 / 短板 / 证据缺口）

- **强匹配**：① 两条线正好落在用户第一/第二优先级的延长线上（运控是底座，RL 是主线）；② 无学历硬门槛表述，研0 有对话空间；③ 小团队更可能接受「先做小项目再谈」的弹性安排（**推断**）。
- **短板与缺口（直说）**：
  1. **无法评估匹配度**——这是最大问题：不知道要 C++ 还是 Python、要不要真机、要不要论文。
  2. 用户无 C++、无真机、无 ROS，若对方按「运控实习」的行业惯例招人，大概率要求其中至少一项（**推断**）。
  3. 无公开投递入口细节（只有 `/zh/careers` 列表页），可能投了也没人看。
- **1–3 周内可补的最小动作**：写一封**问询邮件**（不是投简历），一次问清「岗位职责、技术栈、学历要求、每周最少天数、是否接受 2027 届本科（研0）」；同时准备一页 RL 小项目说明（MuJoCo PPO 或行为克隆）作为附件，让对方一眼看到能做什么。

## 五、如何提升进入概率（具体准备清单）

1. **简历上要出现的项目/关键词**：因为对方 JD 空白，反而要主动定义自己——「MuJoCo + PPO 的连续控制复现」「Python/PyTorch」「愿意从数据与仿真工程做起」。关键词宁少勿虚。
2. **3 个可能面试题及答题要点**（按最可能的方向准备）：
   - 「PPO 的 clip 是干什么的，为什么不用 vanilla policy gradient？」→ 限制策略更新幅度、避免一步更新过大导致崩溃；讲 ratio 与 clip 区间、advantage 估计（GAE）。
   - 「连续控制的动作空间怎么处理？」→ 高斯策略输出均值与方差、tanh 压缩到动作范围、动作平滑与限幅；提执行器延迟对训练的影响。
   - 「仿真里训好的策略上真机，最先出问题的是什么？」→ 观测分布差、执行器建模、控制频率不匹配；对应域随机化与系统辨识。
3. **可产出的作品/证据**：一页 PDF「我能做什么」——一个 MuJoCo 连续控制任务的训练曲线 + 视频链接 + 复现步骤；比简历更能打动没有 JD 的小团队。
4. **软性动作**：官网表单 + 公开邮箱双投；如果 GitHub 上有 sudo.ai 相关组织，从 issue 切入；找不到人就在 LinkedIn 搜公司名 + 「robotics」找人。
