## 三、JD 要求偏好（重点，要细）

### 高频技能 / 工具
- 两条都要求：`Python`、`PyTorch`（J075 原文「Python、PyTorch、VLA及数据集/训练流程」；J076 原文「Python/PyTorch与生成式模型研究基础」）。
- J075 独有：`OpenVLA`、`π 模型`、`SFT`、`Evaluation`、`Transformer`，职责里明写「机器人操作数据清洗/转换/筛选」「构建 OpenVLA/π 模型训练与评测流程」「分析 bad cases 和数据规模」。
- J076 独有：`World Model`、`VLM`、`Diffusion`、`Transformer`，职责「驾驶物理场景的多模态推理」「未来状态预测与生成式世界模型研究」。
- **两条都不要求 C++、ROS、真机**——这是切片里少见的「纯 Python 侧」岗位，对你的技能栈友好度明显高于智元。

### 学历与学籍倾向
- J075：「本科及以上在读」——**这是全部 34 条里对研0 最友好的学历措辞之一**，本科即可，不要求硕博。
- J076：「硕士在读」，明确卡硕 → 研0 需按「已录取硕士」沟通，成功率不确定，且它本身是 C 级、偏驾驶场景。
- 两条都**没有提论文要求**，J076 用「研究基础」这种软措辞，不是「有顶会论文」。

### 出勤 / 时长硬门槛
- **两条都是 5 天/周，没有例外**，且都没写最短月数。
- 默认线下（地点上海），无远程表述。
- 这是全档案里对你**最硬的现实约束**：5 天/周 = 全职，与你 2026-11 至 2027 年初「每周 ≤3h」完全冲突；只有等到学业节点结束、能拿出 25–30h/周之后才可能满足。

### 职责重心
- J075 **偏数据 + 训练流程**，不偏算法创新：四个动词全是「清洗/转换/筛选」「构建训练与评测流程」「分析 bad cases」「分析数据规模」。换句话说，它要的是一个能把 VLA 训练管线跑起来、并且能说清「数据多少条才够」的人。
- J076 **偏研究**：多模态推理、未来状态预测、生成式世界模型，属于探索型，产出不确定。
- 两条都不涉及部署、不涉及硬件调试。

### 隐性偏好与关键词
- 「**bad cases**」「**数据规模**」——这两个词说明团队当前卡在数据侧，不是模型结构侧。面试大概率会问「你觉得多少条轨迹够训一个抓取策略」「失败样本怎么归因」。
- 「**数据清洗/转换/筛选**」写进职责第一条 → 不要以为是脏活就可以糊弄，这是这个 HC 的真实工作内容。
- 「训练与评测流程」= 工程化能力（脚本、配置、可复现），而不是刷点。
- 「-BUD」后缀含义未核实，不要臆测为某个部门缩写。
- J076 的「驾驶物理场景」是**自动驾驶**，不是机器人操作——技术相邻但方向不同，若你只想做机器人，这条优先级应下调。

### 与同类公司的差异
切片里唯一一家「外资大厂背景 + 纯 Python、不要 C++/ROS/真机」的岗位，学历写「本科及以上在读」，且**有明确截止日期**（其余多数公司未写截止或已过期）；代价是 5 天/周的全勤硬门槛。

## 四、与我的匹配度（强项 / 短板 / 证据缺口）

- **强匹配**
  - J075 的工作内容（数据清洗/转换、跑 OpenVLA/π 的训练与评测流程、分析 bad cases）**恰好是 P1/P2 阶段能长出来的能力**，不需要你先有真机或 C++。
  - 学历口径「本科及以上在读」对你最友好，研0 按本科身份沟通有明确依据。
  - 你「能读代码、跑通小实验」的现状，对「把训练脚本跑起来 + 记录指标」这类工作要求是够用的起点。
- **短板与缺口（直说）**
  - **5 天/周全勤**：这是硬门槛，不是加分项。你目前每周 ≤3h，直接不满足；即便 2027 年春季后能到 25–30h/周，也未必等于「每周 5 天到岗」。
  - **没有跑过 OpenVLA/π**：JD 直接点名这两个模型，你零经验。数据清洗你也许能做，但「构建训练与评测流程」需要你至少完整跑通过一次。
  - **没有数据规模判断经验**：JD 要「分析 bad cases 和数据规模」，你现在答不出「多少条轨迹够用」这种问题。
  - **无实习无论文**：外资大厂实习流程通常有简历初筛，研0 + 零经历在筛简历阶段就容易被过滤（**推断**，无 JD 证据）。
  - **截止只剩 14 天**：就算现在开始准备，也来不及产出能打动人的证据。
- **1–3 周内可补的最小动作**
  1. 用公开数据集（如 LeRobot 的 aloha/pusht 数据）跑通 1 次 OpenVLA 或 π0 的**推理**，不强求训练；产出：环境配置记录 + 推理结果截图。
  2. 写 1 页《数据规模与 bad case 分析》：拿公开数据集做一次「训练样本数 vs 成功率」的小实验或文献对照，形成可讲的观点。
  3. 准备一句诚实的出勤方案（见第六节话术），先争取「远程/兼职做数据管线」的可能性。

## 五、如何提升进入概率（具体准备清单）

1. **简历上要出现的项目/关键词**：`数据清洗/转换`、`OpenVLA`、`π0 推理`、`训练与评测流程`、`bad case 分析`、`数据规模 ablation`。把「跑通」写成「复现并记录指标」，不要写「熟悉」。
2. **可能被问的 3 个问题及答题要点**
   - Q1「我们的数据是不同机器人、不同相机的，你怎么做统一？」要点：先讲格式层（统一到 LeRobot 的 episode/observation 结构、时间戳对齐、动作空间归一化），再讲质量层（丢帧/抖动/失败 episode 的判定规则），最后讲「先抽样人工过一遍再定规则」。
   - Q2「训练集加到 10 万条，成功率为啥不涨？」要点：数据多样性 > 数量；先看是否同一分布重复采样、再看任务难度分布、最后看评测口径是否覆盖了新场景。可引用你 P1 的曲线。
   - Q3「bad case 怎么归类？」要点：分感知失败（看不清/遮挡）、执行失败（抓空/滑落）、指令歧义三类，每类给出可量化的判据与修复优先级。
3. **可产出的作品/证据**：一份《OpenVLA/π 复现环境 + 推理 demo》repo；一份数据清洗脚本（输入原始 episode，输出统一格式 + 质量报告），这个比模型 demo 更贴 JD。
4. **软性动作**：截止仅 14 天，走「先投递 + 后补证据」策略——今天投，同时在邮件里说明「正在做 X，两周内可给 demo」；另外在即刻/小红书/B站搜「博世 具身 实习」找在职实习生问内推（**未核实**是否存在公开内推渠道）。
