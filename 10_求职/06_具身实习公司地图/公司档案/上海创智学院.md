## 一、公司是谁 / 做什么（仅据 JD 可见线索，其余「未核实」）

从 17 条 JD 的岗位名与职责看，这是一家**做具身智能基础模型与训练/评测基础设施的科研机构**：既有灵巧手动作重定向与 RL（J040 点名复现 SPIDER-H 与 DexMachina）、全身协同操作基础模型（J042）、视频生成世界模型（J043/J052/J110），也有仿真环境维护（J044 MuJoCo/Isaac）、评测基准建设（J041）、端侧部署（J045 FlashVLA + TensorRT）。岗位几乎全部以「科研实习」命名，并要求「复现」「实验记录」「可复现实验平台」，**研究属性强于产品属性**。

是否为企业法人、团队规模、是否有高校/政府背景：**未核实**。薪资、转正、工位地点细节：JD 未写。

## 三、JD 要求偏好（重点，要细）

- **高频技能 / 工具**：Python 17/17（每条都写）；PyTorch 11/17；VLA 8/17；RL 8/17；World Model 7/17；Evaluation 6/17；Control 5/17；C++ 4/17；Linux 4/17；Diffusion 与 Transformer 各 3/17；MuJoCo 3/17；Simulation 6/17；Isaac Sim 2/17；ROS2 2/17；Dexterous Hand 3/17；Planning 3/17。
  - 原文措辞：「**复现** SPIDER-H 动作重定向与 DexMachina 强化学习；分析接触状态、动作参考、训练种子与实验记录」（J040）
  - 「构建 VLA/RL 算法**评测基准**和**可复现实验平台**，维护评测用例与分析工具」（J041）
  - 「维护 **MuJoCo/Isaac** 机器人训练环境、数据生产与验证、场景和动作表征」（J044）
- **学历与学籍倾向**：**全切片最宽松的一类**——12 条明写「本科或硕士」「本科及以上」，只有 J045（端侧部署）单独抬到「硕士在读」。**没有任何一条出现「研0」字样**；「本科/硕士在读」是唯一可就近套用的口径，因此研0 用「本科在读 + 已录取研究生」沟通是合理路径，但**能否签实习协议仍需 HR 确认学籍状态**。
- **出勤 / 时长硬门槛**：**硬**。写出小时数的 4 条里 3 条是 20–30h/周 或 ≥30h/周，只有 J048（外骨骼）是 10–20h/周；另有 5 条要求 **≥6 个月**，其中 J042 明确「**线下** ≥6 个月，≥30 小时/周」。这不是"灵活实习"型岗位，是按科研项目周期招人。
- **职责重心**：**偏研究 + 偏基础设施**，两端分化。
  - 研究型：J040（复现 + 消融 + 实验记录）、J042（长程决策与失败恢复）、J043/J052/J110（视频生成、扩散、交互世界模型）。
  - 工程/数据型：J041（评测平台）、J044（仿真环境与数据生产）、J051（样本构建与筛选）、J049（实机接口与嵌入式联调）。
  - 几乎没有"产品交付"类职责描述。
- **隐性偏好与关键词**：「**复现**」（J040/J043 明写）、「**可复现实验**」（J041/J044）、「**实验记录 / 训练种子**」（J040，罕见地写到种子级别）、「**长期投入**」（J041/J046/J052）、「**真机验证**」（J042/J047/J108）、「**跨场景泛化**」（J107）、「英文论文阅读」（J042）。
  - 这几个词合起来等于一句潜台词：**他们要能坐下来跑几十组对照实验、并且把过程写清楚的人**，而不是"会用框架"的人。
- **与同类公司的差异**：别的公司 JD 写"参与项目/交付功能"，创智写"复现某篇工作的某个模块"——**这是全切片里唯一把"复现"作为岗位职责动词的公司**，也是唯一给出明确每周科研小时数的。

## 四、与我的匹配度（强项 / 短板 / 证据缺口）

- **强匹配**：
  - J040 的要求原文是「Python/Linux/Git 基础，PyTorch/RL/仿真**加分**」——这是全切片里少见的"基础项只要你会的、进阶项算加分"的写法，和"研0 + Python/PyTorch 起步"的现状对得上。
  - J040 的职责（动作重定向 + RL + 分析训练种子）与用户作品集 **P1「可复现 RL 抓取」** 是同一类工作，只是对象从夹爪换成灵巧手。
  - J044（MuJoCo/Isaac 环境维护 + 数据生产）与 **P0** 完全同构；J041（评测基准）对 RL/实验设计的要求低于对"工程整洁度"的要求。
  - 用户已有研究方案构想（DexWeaver 灵巧手），与 J040/J108 的灵巧手主线方向一致——但**只是构想，未落地**，不能当经历写。
- **短板与缺口**（直说）：
  1. **出勤是硬冲突**：2026-11 → 2027-01 用户每周 ≤3h，而这些岗位最低也要 10–20h/周，主流是 20–30h/周 或 ≥30h/周、≥6 个月。**按当前时间投入，物理上不满足 J040/J041/J042 的门槛**，这不是靠简历能补的。
  2. **RL 没有真跑过收敛**：能读代码、跑通小实验 ≠ 调过 PPO 收敛、看过 reward 曲线崩掉。J040 要求"分析训练种子"，这需要有踩坑经验。
  3. **MuJoCo / Isaac 未系统使用**：J044 直接以仿真环境维护为职责，用户目前是"装过/看过"级别。
  4. **无实验记录习惯**：JD 明确写"实验记录"，用户目前没有实验日志类产出。
  5. **学籍口径未确认**：研0 未入学，实习协议、是否需要学校三方、能否算"在读"，全部未知。
- **1–3 周内可补的最小动作**：
  - 跑通 **MuJoCo Playground** 或 `gymnasium-robotics` 里一个抓取任务，用 PPO 训到能抓起来；**同时**用 git 建一个 `repro-notes/` 目录，写清 seed、并行环境数、reward 缩放、失败的三次尝试。→ 这一份东西同时对上 J040 的"实验记录/种子"和 J044 的"仿真环境"。
  - 把 SPIDER-H / DexMachina 两篇的 abstract + method 图读一遍，写 300 字中文摘要，说清"重定向解决什么问题"。→ 面试能接上话。
  - 发一封邮件问 HR：研0（2027 入学、现本科在读）能否以本科身份投 J040/J044、能否接受 2026-12 前每周 3h + 寒假起 20h。**先问，不要先投**。

## 五、如何提升进入概率（具体准备清单）

1. **简历上要出现的项目 / 关键词**：
   - 「MuJoCo 抓取任务 PPO 复现，成功率从 x% → y%，固定 5 个 seed 报均值±方差」——**必须带数字和 seed**，这是这家最认的写法。
   - 「实验记录规范：配置 yaml 外置、commit 哈希、wandb 本地备份」——一句话点出可复现性。
   - 关键词排序：`复现` > `MuJoCo / Isaac` > `PPO / RL` > `灵巧手 / 动作重定向` > `评测基准`。
2. **面试可能被问的 3 个问题及答题要点**：
   - **Q1「动作重定向（motion retargeting）是什么，为什么灵巧手需要它？」**
     要点：把人类手或源机器人的示教轨迹映射到目标手关节空间；难点是自由度/连杆长度/接触点不一致，不能只对齐关节角，要**优先保证接触点与抓取构型一致**；常用 IK + 优化，加物理可行性约束。
   - **Q2「你训的 RL 不收敛，排查顺序是什么？」**
     要点：① 先确认环境和 reward 没错（打印 reward 分量、看是否被某一项主导）② 观测/动作归一化 ③ 换固定 seed 小规模对照 ④ 再动 PPO 超参（lr、clip、epoch）⑤ 最后怀疑探索不足/奖励稀疏 → 加 curriculum 或 demo。**强调"先二分定位，再调参"**。
   - **Q3「你怎么保证实验可复现？」**
     要点：固定 seed 并记录、锁定环境版本与 commit、配置外置、日志集中存、**失败的实验也记**；同一结论至少 3 个 seed；给出跑一次的成本（GPU 小时）。
3. **可产出的作品 / 证据**：一份 `repro-notes/` 仓库（含 README + 实验表 + 曲线图），比任何"我熟悉 MuJoCo"的自述有用。若时间够，把 J041 的思路做小：给一个公开 benchmark 写 5 条评测用例 + 一个跑分脚本。
4. **软性动作**：走官网飞书招聘投递后，找同济做具身的师兄师姐问是否有组内合作/内推（**未核实**是否有内推通道）；GitHub 上给 LeRobot / MuJoCo Playground 提 1 个 doc fix 级 PR，作为"能读别人代码"的证据。

## 六、投递策略（时机 / 简历突出点 / 开场话术 / 跟进）

- **简历突出**：`MuJoCo 复现` · `PPO + 固定 seed 对照` · `实验记录/可复现`
- **开场话术**（邮件正文，2 句）：
