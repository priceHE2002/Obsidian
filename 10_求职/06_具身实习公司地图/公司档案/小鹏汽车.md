## 四、与我的匹配度（强项 / 短板 / 证据缺口）

- **强匹配**：J130 的届别口径对得上你；J131 的方向（Agent/评测/RL 后训练）与你第三优先级一致；J104 的 3DGS/扩散与你的世界模型兴趣相关。
- **短板与缺口**：① J130 要 C++ STL/多线程/CMake/GDB/ONNX/TensorRT，你一样没系统用过，这是纯工程岗；② J131 博士优先 + PPO/GRPO/RLHF/RLAIF 全栈，研0 无竞争力；③ J104 已过截止且限硕博；④ 三岗城市含上海/北京/深圳，具体到岗地需确认，可能不在上海。
- **1–3 周内可补的最小动作**：把 P1 的抓取策略导出 ONNX，用 onnxruntime 在 CPU 上跑通推理并测 P50/P99 延迟，写 1 页「训练 → 导出 → 推理」记录。这一件事同时对上 J130 的 ONNX Runtime 关键词与你的 P1 交付。

## 五、如何提升进入概率（具体准备清单）

1. **简历上要出现的项目/关键词**：ONNX Runtime、模型导出、推理延迟、Linux、Python；C++ 可写「能读、在学」但不要写精通。
2. **可能被问的 3 个问题及答题要点**：
   - Q：PyTorch 模型导出 ONNX 常见坑？→ 答：动态轴设置、算子不支持、opset 版本、导出后用 allclose 做数值对齐校验。
   - Q：端侧推理怎么定位性能瓶颈？→ 答：算子级 profiling、内存拷贝与零拷贝、线程数/绑核、量化前后精度对比。
   - Q：你说熟悉 VLA，具体读过哪篇？部署时怎么处理动作 chunk？→ 答：诚实说只精读 π0/OpenVLA 的 inference 部分，讲清 action chunk + 时序 ensembling（取平均/加权）的取舍与延迟代价。
3. **可产出的作品/证据**：ONNX 导出脚本 + 推理延迟对比表（FP32 vs 量化，CPU）、一张 latency 分布图。
4. **软性动作**：J130 走官方投递，简历第一行放「模型部署」；J131 不投，但可关注其论文/技术博客，为 2028 年后铺路。
