## 五、如何提升进入概率（具体准备清单）

1. **简历上要出现的项目 / 关键词**：
   - 「OpenVLA / LeRobot 在 ×× 数据集上 LoRA 微调，LIBERO 平均成功率 x%」——一条就够，但**必须有数字**。
   - 「复现 Diffusion Policy / ACT 并做对照（成功率、训练步数、推理延迟）」——对应 P2。
   - 关键词排序：`VLA` > `OpenVLA` > `微调 / SFT` > `IL` > `LIBERO / 操作评测`。
2. **面试可能被问的 3 个问题及答题要点**：
   - **Q1「微调一个 VLA 和从零训一个 VLA，差别在哪？」**
     要点：微调只更新部分参数（LoRA/adapter 或动作头），依赖预训练的表征与动作先验，数据需求小（几百到几千条示教）、算力低；从零训要跨本体大规模数据、成本高且易过拟合小数据集。
   - **Q2「OpenVLA 的架构大致是什么？动作怎么输出？」**
     要点：视觉编码器（DINOv2+SigLIP 双塔）+ 语言模型主干（Llama-2 7B 级）+ 动作 detokenizer；把连续 7 维动作离散化成 token 预测，再反离散化。**能说清"动作被当 token"这一点就算过关**。
   - **Q3「机器人操作任务的成功率怎么评才算公平？」**
     要点：固定初始状态集合与随机种子、固定评测次数（≥20 次/任务）、按任务套件分组报（而非只报平均）、区分"抓到"与"放到目标"的分阶段成功率；说明是否允许人干预/重置。
3. **可产出的作品 / 证据**：一个 `vla-finetune-notes` 仓库：README（环境+显存+数据格式）+ 训练日志 + 成功率表 + 3 张失败案例截图。**失败案例比成功案例更能证明真跑过**。
4. **软性动作**：每周刷一次 deizao 聚合站看是否重新开放（**推断**这类校园渠道岗位会周期性重发）；在 OpenVLA / LeRobot 的 GitHub issue 区回答问题，建立"能读源码"的公开痕迹。
