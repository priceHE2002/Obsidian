## 四、与我的匹配度（强项 / 短板 / 证据缺口）

- **强匹配**：几乎没有直接强匹配项。勉强算的两点：① 学历未写，研0 有沟通空间；② Python 可用（但这条 JD 的主语言是 C++）。
- **短板与缺口（直说）**：
  1. **C++ 是主语言，用户不会**。JD 把 C++ 写在 Python 前面，且导航栈（Nav2、costmap、TF）几乎全是 C++ 生态。
  2. **三个规划算法一个都没实现过**。A*、RRT、DWA 是这条 JD 的核心考点，用户目前只有「听说过」的水平。
  3. **无 ROS/实车经验**。「调优实际机器人导航算法」需要上过真车、处理过定位漂移和传感器噪声，用户零经验。
  4. **方向偏离**。这条线学不到操作/策略/世界模型，对 P2–P5 路线没有直接增益，只提供「一段机器人实习」的履历。
- **1–3 周内可补的最小动作**：在 Python 里手写 A* 与 DWA（各 100 行内），在一个 2D 栅格地图上跑通并出可视化 GIF；再把 A* 移植到 ROS2 Nav2 的 `planner_server` 插件模板里（只跑通编译与加载，不必上真车）。约 7–10 天，足以在面试里讲清原理。

## 五、如何提升进入概率（具体准备清单）

1. **简历上要出现的项目/关键词**：`A*`、`RRT`、`DWA`、`Nav2`、`costmap`、`C++`、`ROS2`。项目写「在 X 栅格地图上实现 A* + DWA，路径长度/耗时对比」，不要写「了解导航算法」。
2. **面试可能被问的 3 个问题，及答题要点**：
   - **Q1：A* 和 Dijkstra、BFS 的区别？启发函数怎么选？** 要点：A* = Dijkstra + 启发式 h(n)；h 必须可采纳（不高估）才保证最优；栅格四连通用曼哈顿、八连通用对角距离、欧氏用于任意方向；h 过大退化成贪心、过小退化成 Dijkstra。
   - **Q2：DWA 怎么选速度？评价函数有哪几项？** 要点：在动态窗口（受加速度/速度约束）内采样 (v, ω)，用「朝向、障碍距离、速度」三项加权评分；说清为什么局部规划会陷入局部极小，以及怎么用全局路径引导。
   - **Q3：实车导航定位漂移/原地打转，你怎么排查？** 要点：先看 TF 树与时间戳、再看里程计标定（轮距/半径）、再看 costmap 膨胀半径与传感器噪声；用 rosbag 回放复现，而不是在车上盲调。
3. **可产出的作品/证据**：A*/DWA 的可视化 demo（GIF + 代码）+ 一份「Nav2 参数调优记录」；这两样对纯导航岗的说服力很强。
4. **软性动作**：领英上直接问 HR「是否接受研0、每周最少几天」；同时把这条线与上汽 J136 一起准备，两者考点高度重叠（ROS2 + 规划）。
