一句话主线：**总线是「一群设备共享的传输通道」**，所以本章所有计算都归结为一句话——
**一次能并行传多少位（宽度）× 每秒能传多少次（频率）= 带宽**。

> [!note] 考情
> **选择题 1—2 题**：带宽计算、同步/异步定时的区别与适用、地址总线宽度与寻址空间、串行与并行。大题很少单独出，偶尔在 I/O 或存储综合题里让你算「传输这批数据要多久」。
> **本章计算清单**：① 带宽 = 宽度(B) × 频率 ÷ 每周期时钟数　② 传输时间 = 数据量 ÷ 带宽　③ 地址线位数 ↔ 寻址空间　④ 地址/数据复用后带宽减半。

# 6.1 总线概述

## 6.1.1 基本概念与四大特性　★★

🔴 **总线（Bus）**：连接多个部件的一组**共享**信息传输线，是各部件之间传送信息的公共通道。
🔴 **共享**是总线的本质：同一时刻只允许**一对**设备使用总线（主设备发起，从设备响应），这也是「总线带宽成为系统瓶颈」的根源。

**为什么用总线而不是点对点连线？**

| 好处 | 说明 |
|---|---|
| 减少连线 | $n$ 个部件两两互连要 $n(n-1)/2$ 组线，用总线只要 1 组 |
| 便于扩展 | 新设备挂上去即可 |
| 标准化 | 接口统一，不同厂商设备可互换 |

🟡 **主设备 / 从设备**：主设备（master）发起总线事务、控制总线；从设备（slave）被动响应。CPU 通常是主设备，存储器与 I/O 接口通常是从设备（DMA 时 I/O 也可当主设备）。

### 四大特性（🔴 选择题原话）

| 特性 | 管什么 | 例子 |
|---|---|---|
| **机械特性** | 尺寸、形状、引脚数、排列顺序 | 插头多少针、多长 |
| **电气特性** | 信号的电压高低、电流大小、传输方向 | TTL 电平；单向/双向 |
| **功能特性** | 每根信号线的功能 | 这 32 根是数据线，那 20 根是地址线 |
| **时间特性** | 各信号在什么时刻有效、时序关系 | 地址先出、读命令后发 |

> [!tip] 记忆
> 机械管「长什么样」，电气管「电怎么给」，功能管「线干什么」，时间管「什么时候有效」。

## 6.1.2 总线的分类　★★★

### ① 按传输的信息分（最常考）

| 类别 | 方向 | 宽度决定什么 |
|---|---|---|
| **数据总线** | **双向**（CPU↔主存/IO） | 一次能传多少位，通常等于机器字长或存储字长 |
| **地址总线** | **单向**（CPU → 主存/IO） | **寻址空间**：$n$ 根地址线 → $2^n$ 个编址单元 |
| **控制总线** | 单向/双向混合 | 读/写、中断请求、总线请求、时钟、复位等 |
| 电源与地线 | — | 供电与参考地 |

🔴 **地址线位数与寻址空间**：地址线 $n$ 根 → 最多 $2^n$ 个地址；按字节编址时寻址空间 $=2^n$ 字节。
例：20 根地址线 → $2^{20}=1\text{M}$ 个单元 → 按字节编址即 **1MB**。

### ② 按连接的对象/层次分

| 类型 | 位置 | 例子 |
|---|---|---|
| **片内总线** | CPU 芯片内部 | 寄存器与 ALU 之间 |
| **系统总线**（板级） | 主板，连接 CPU、主存、I/O 接口 | 数据/地址/控制三组线 |
| **通信总线**（设备级） | 设备之间、计算机之间 | USB、RS-232、以太网 |

### ③ 按数据传输方式分

| 方式 | 特点 | 适用 |
|---|---|---|
| **并行传输** | 多位同时传，速率高；线多、成本高、**线间干扰与同步问题** | 短距离、机内 |
| **串行传输** | 逐位传，线少、成本低、抗干扰、易远距离 | 长距离、设备间 |

> [!warning] 反直觉
> 「并行一定比串行快」是错的。现代高速接口（PCIe、USB 3.x、SATA）都改用**串行 + 差分信号 + 多通道**，因为并行在高速下会出现线间串扰与时钟偏移，反而上不去。

### ④ 按时序控制方式分

**同步总线 / 异步总线 / 半同步总线 / 分离事务总线**——这一组在 6.2 展开，是本章的重点。

## 6.1.3 总线结构　★

| 结构 | 组成 | 优点 | 缺点 |
|---|---|---|---|
| **单总线** | CPU、主存、I/O 全部挂在一组系统总线上 | 结构简单、成本低、易扩展 | **同一时刻只能一对设备通信**，带宽瓶颈 |
| **双总线** | 主存总线 + I/O 总线，之间用桥/通道连接 | 内存访问与 I/O 可并行 | 结构复杂、成本上升 |
| **三总线** | 主存总线 + I/O 总线 + **DMA 总线** | DMA 传输不占用主存总线 | 控制复杂 |
| **多总线/层次化** | 北桥（高速）、南桥（低速）、PCIe 点对点 | 按速度分层，效率高 | 结构最复杂 |

## 6.1.4 性能指标　★★★

| 指标 | 含义 | 单位 |
|---|---|---|
| **总线宽度** | 数据线根数，一次能并行传的位数 | bit |
| **总线工作频率** | 总线时钟频率 | MHz / GHz |
| **总线带宽** | 单位时间最多传多少数据 | B/s、MB/s、GB/s |
| **总线周期** | 完成一次总线操作所需时间，可含多个时钟周期 | ns |
| **信号线数** | 数据 + 地址 + 控制 + 电源地的总根数 | 根 |
| **总线复用** | 同一组线分时传不同信息（如地址/数据复用） | — |
| **总线利用率** | 有效传输时间 / 总时间 | % |

🔴 **核心公式**（三种写法，按题目给的条件选）：

$$\text{带宽} = \text{总线宽度（字节）} \times \text{总线频率}$$

$$\text{带宽} = \frac{\text{总线宽度（字节）} \times \text{频率}}{\text{一个总线周期含的时钟数}}$$

$$\text{带宽} = \frac{\text{一个总线周期传输的字节数}}{\text{总线周期}}$$

> [!important] 三个例题（覆盖常见问法）
> **① 宽度 × 频率**：数据线 32 位（4B），时钟 66MHz，每个时钟传一次
> → $4 \times 66\text{M} = 264\text{MB/s}$。
> **② 周期含多个时钟**：同样 32 位、66MHz，但每 **2 个时钟**才完成一次传输
> → $4 \times 66/2 = 132\text{MB/s}$。
> **③ 给周期时间**：一个总线周期 100ns，每周期传 4B
> → $4\text{B}/100\text{ns} = 40\text{MB/s}$。
> 传 1MB 数据耗时 $= 1\text{MB}/40\text{MB/s} = 25\text{ms}$（不计寻址与总线请求开销）。

🟡 **总线复用的代价**：32 位地址/数据复用总线，传「32 位地址 + 32 位数据」要 **2 个总线周期**，同频率下带宽**减半**，换来的是引脚数减少。

> [!warning] 易错
> ① 带宽算的是**字节**不是位：32 位 = 4B，别忘了除以 8。
> ② 题目给「总线周期 4 个时钟」时，不能直接用时钟频率乘宽度。
> ③ 地址线宽度决定**寻址空间**，数据线宽度决定**一次传输量**，两者别混。

# 6.2 总线操作和定时

## 6.2.1 总线事务　★★

🔴 **总线事务**：主设备与从设备之间**一次完整的数据交换过程**。五个阶段：

```
① 请求（申请）  主设备提出总线请求
② 仲裁          总线仲裁器决定谁获得总线（大纲已删细节）
③ 寻址          主设备把目标地址放到地址线上
④ 传输          读/写数据，可含多个数据周期（突发）
⑤ 释放          交出总线控制权
```

🟡 三个「周期」的关系：**指令周期 ≫ 总线周期 ≥ 时钟周期**；一个总线事务可能含多个总线周期，一个总线周期含若干时钟周期。
🟡 **突发传输（burst）**：一次寻址后连续传多个数据，省掉重复的寻址与仲裁开销，是提高总线利用率的关键手段。

## 6.2.2 同步定时　★★★

🔴 **做法**：总线上的所有设备共用**统一的时钟信号**，每个动作发生在固定的时钟节拍上。

**优点**：控制简单、协议简单、速度快、可靠性高（不需要握手判断）。
**缺点**：必须以**最慢的设备**为准；速度差异大时不划算；时钟偏移限制总线长度。
**适用**：总线短、各设备速度接近（如 CPU 与高速缓存之间）。

> [!tip] 时序直觉
> 100MHz 时钟（10ns）：T1 送地址 → T2 发读命令 → T3 从设备把数据放上数据线 → T4 主设备采样。所有设备都在同一节拍上动作，谁慢就拖累整体。

## 6.2.3 异步定时　★★★

🔴 **做法**：没有统一时钟，靠**请求（Request）— 应答（Acknowledge）**握手信号协调，也叫应答方式。

**三种互锁方式（🔴 必背，选择题常考「谁等谁」）**：

| 方式 | 请求方 | 应答方 | 特点 |
|---|---|---|---|
| **不互锁** | 发出请求后经固定延时**自动撤销**，不等应答 | 收到请求后经固定延时**自动发应答**，不等确认 | 最快，可靠性最低 |
| **半互锁** | 发出请求后**等应答**才撤销 | 发出应答后**不等**主设备确认 | 折中 |
| **全互锁** | 等应答才撤销 | 等主设备的**确认**信号才撤销应答 | 最可靠，最慢 |

**优点**：能适应速度差异很大的设备，可靠性高，传输距离可较远。
**缺点**：控制复杂、速度比同步慢（每次都要等握手）。

> [!warning] 一句话区分
> **不互锁 = 谁都不等；半互锁 = 主等从、从不的主；全互锁 = 互相都等。**

## 6.2.4 半同步通信　★★

**做法**：整体用统一时钟（像同步），但允许慢设备通过 **WAIT 信号**把总线周期拉长。
**效果**：兼顾同步的「快」与异步的「能迁就慢设备」，是很多实际总线的做法。

## 6.2.5 分离事务（Split Transaction）　★★

**做法**：把一次事务拆成两个子事务——
① 主设备发出请求后**立即释放总线**；② 从设备准备好数据后，再申请总线把数据送回。

**优点**：等待期间总线可被别人使用，**显著提高利用率**（尤其读慢速设备）。
**缺点**：控制复杂；写操作难以拆分；总线被多次申请，仲裁开销增加。

## 6.2.6 四种定时方式对比（🔴 一张表收口）

| | 同步 | 异步 | 半同步 | 分离事务 |
|---|---|---|---|---|
| 时钟 | 统一时钟 | 无，靠握手 | 统一时钟 + WAIT | 无固定，两次申请 |
| 速度 | 快 | 慢 | 较快 | 有效利用率最高 |
| 适应性 | 差（以最慢为准） | 好 | 较好 | 好 |
| 复杂度 | 低 | 高 | 中 | 最高 |
| 典型场景 | 高速缓存、CPU 内部 | 速度差异大的 I/O | 多数系统总线 | 读慢速设备 |

# 6.3 拓展：仲裁与标准（408 大纲已删，了解即可）　★

## 6.3.1 总线仲裁

| 方式 | 怎么选 | 控制线 | 优点 | 缺点 |
|---|---|---|---|---|
| **链式查询** | 总线允许信号 BG 沿设备链串行传递，先到先得 | 少（3 根） | 简单、易扩展 | **离控制器近的优先**，一处断链后面全瘫 |
| **计数器定时查询** | 计数器轮询设备号 | 中 | 较公平 | 速度慢、线数增加 |
| **独立请求** | 每个设备一对请求/允许线 | 多 | **最快、最灵活** | 线多、成本高 |

## 6.3.2 总线标准（只记特征）

| 标准 | 特征 |
|---|---|
| ISA / EISA | 早期并行系统总线，已淘汰 |
| PCI | **并行**、共享、即插即用 |
| **PCIe** | **串行、点对点**、多通道（x1/x4/x16），现代主流 |
| AGP | 专为显卡，已被 PCIe 取代 |
| USB | 串行、支持热插拔、可供电、树形拓扑 |
| SATA | 串行硬盘接口 |

# 附 B · 20 条速记

1. 总线是**共享**传输通道，同一时刻只允许一对设备通信。
2. 主设备发起、从设备响应；DMA 时 I/O 设备也可当主设备。
3. 四特性：机械、电气、功能、时间。
4. 数据总线**双向**，地址总线**单向**，控制总线混合。
5. 地址线 $n$ 根 → 寻址 $2^n$ 个单元（按字节编址即 $2^n$ 字节）。
6. 并行适合短距离，串行适合长距离；高速时代串行反超。
7. 单总线结构简单但带宽是瓶颈。
8. 带宽 = 总线宽度（字节）× 频率。
9. 一个总线周期含 $k$ 个时钟时，带宽要除以 $k$。
10. 32 位 = 4B，别忘除以 8。
11. 地址/数据复用省引脚，但传一次要两个周期，带宽减半。
12. 总线事务：请求 → 仲裁 → 寻址 → 传输 → 释放。
13. 突发传输：一次寻址连传多个数据，提高利用率。
14. 同步定时：统一时钟，快，但以最慢设备为准。
15. 异步定时：握手，适应速度差异，但慢。
16. 不互锁谁都不等；半互锁主等从；全互锁互相都等。
17. 半同步 = 同步 + WAIT 信号。
18. 分离事务：请求后释放总线，准备好再申请，利用率最高。
19. 链式查询简单但近端优先、断链全瘫；独立请求最快但线多。
20. PCIe 是串行点对点，PCI 是并行共享（大纲已删，知道即可）。

# 附 C · 自测（合上笔记答）

1. 总线的本质特征是什么？→ 共享，同一时刻只有一对设备通信。
2. 地址线 24 根，按字节编址的寻址空间？→ $2^{24}\text{B} = 16\text{MB}$。
3. 数据线 64 位、时钟 100MHz、每时钟传一次，带宽？→ $8\text{B} \times 100\text{M} = 800\text{MB/s}$。
4. 同上但每 4 个时钟传一次？→ 200MB/s。
5. 总线周期 50ns、每周期传 8B，带宽？→ 160MB/s。
6. 传 2MB 数据要多久（带宽 160MB/s）？→ 12.5ms。
7. 地址/数据复用为什么带宽减半？→ 传地址与数据要分两个周期。
8. 总线事务五个阶段？→ 请求、仲裁、寻址、传输、释放。
9. 同步定时最大的缺点？→ 以最慢设备为准，速度差异大时不划算。
10. 异步三种互锁谁等谁？→ 不互锁都不等；半互锁主等从；全互锁互相等。
11. 半同步怎么迁就慢设备？→ 插 WAIT 延长总线周期。
12. 分离事务为什么能提高利用率？→ 等待数据期间释放总线。
13. 突发传输省掉了什么开销？→ 重复的寻址与仲裁。
14. 链式查询的缺点？→ 近端优先，断链后后续设备全失效。

# 附 D · 计算模板（照着套）

**① 带宽**
$\text{带宽} = \dfrac{\text{宽度(bit)}}{8} \times \dfrac{\text{频率}}{\text{每周期时钟数}}$；若给总线周期 $T$，则 $\text{带宽} = \dfrac{\text{每周期字节数}}{T}$。

**② 传输时间**
$t = \dfrac{\text{数据量}}{\text{带宽}}$（题目给了寻址/仲裁开销就逐项相加）。

**③ 寻址空间**
地址线 $n$ 根 → $2^n$ 个单元；按字节编址 → $2^n$ 字节。

**④ 复用总线**
地址与数据复用 → 一次完整传输需要 2 个（或以上）总线周期 → 有效带宽按周期数折算。
