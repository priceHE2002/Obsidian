# 第四章 文件管理 · 重点记忆点

> [!info] 定位

> 标注：🔴 必背（选择题原话级别）· 🟡 常考细节 · ⚠️ 易错

## 0. 全章骨架

```
4.1 文件系统基础  文件（逻辑结构）→ 目录 → 共享 → 保护 → 基本操作
```

# 4.1 文件系统基础

## 4.1.1 文件的概念与基本操作

🔴 **文件**：以计算机硬盘为载体的、存储在计算机上的相关信息的集合。**目录本身也是文件**（目录文件）。

**文件属性**：名称、标识符（唯一，用户不可见）、类型、位置、大小、保护（权限）、时间戳（创建/修改/访问）、所有者。

**六个基本操作**（🔴 区分「打开」与「读」）：

| 操作 | 实际动作 |
|---|---|
| 创建 create | 分配外存空间 + 建目录项/FCB |
| 删除 delete | 释放空间 + 删目录项 |
| **打开 open** | 把 **FCB 调入内存**的打开文件表，返回**文件描述符**（不读内容！） |
| 关闭 close | 从打开文件表删除表项，必要时写回 FCB |
| 读 read | 按「读指针」读，读后指针自动后移 |
| 写 write | 按「写指针」写，写后指针后移 |
| 定位 seek/lseek | 只改文件指针，不读写 |

> [!warning] 三个易错
> ① **open 不等于把文件读入内存**，只是把 FCB 调入内存。
> ② 系统打开文件表（全局，含 FCB 副本 + 打开计数）与进程打开文件表（每进程一张，含读写指针）是两张表。
> ③ inode 中**不含文件名**，文件名在目录项里。

## 4.1.2 文件的逻辑结构（用户视角）

| 类型 | 细分 | 要点 |
|---|---|---|
| **无结构文件**（流式） | 字符流 | 以字节为单位，如源程序、目标代码、库函数；长度即字节数 |
| **有结构文件**（记录式） | 定长记录 / 变长记录 | 由记录组成，记录是数据项的集合 |

**有结构的三种组织方式**（🔴 顺序 / 索引 / 索引顺序）：

| 方式 | 结构 | 查找 | 适用 |
|---|---|---|---|
| **顺序文件** | 串结构（按存入时间）或顺序结构（按关键字排序） | 串结构只能顺序找 $O(n)$；顺序结构可折半 $O(\log n)$ | 批量处理 |
| **索引文件** | 为**变长记录**建索引表（关键字 → 逻辑地址） | 先查索引再定位，$O(\log n)$ | 变长记录、随机访问 |
| **索引顺序文件** | 记录分组，每组建一个索引项 | 组间索引 + 组内顺序，约 $O(\sqrt{n})$ | 折中方案 |
| **直接文件/散列文件** | 关键字经哈希直接得物理地址 | 期望 $O(1)$ | 按关键字随机存取 |

> [!tip] 记忆
> 顺序文件「排好队」，索引文件「加目录」，索引顺序文件「分班 + 班长」，散列文件「算地址」。

## 4.1.3 目录（🔴 高频）

🔴 **目录 = FCB 的有序集合**，本质是一种特殊文件（目录文件）。

| 目录结构 | 特点 | 缺点 |
|---|---|---|
| **单级目录** | 全系统一张表 | **文件名不能重名**、查找慢、不便于共享 |
| **两级目录** | 主文件目录 MFD + 用户文件目录 UFD | 解决了重名与多用户隔离；仍不便于分类 |
| **树形目录** | 绝对路径 / 相对路径、当前目录 | 层次清晰、可重名；**不便于文件共享** |
| **无环图目录** | 允许一个文件/目录有多个父目录（共享） | 需引用计数，删除要小心 |
| **通用图目录** | 允许环 | 需垃圾回收，实现复杂 |

🟡 **路径**：绝对路径从根开始；相对路径从当前目录开始；`..` 上级，`.` 当前。

🔴 **索引结点（inode）**：把 FCB 中**除文件名以外**的信息（大小、权限、物理地址、时间等）集中放到索引结点，**目录项只保留「文件名 + inode 号」**。

- 好处：目录项变小 → 一个盘块能装更多目录项 → **减少检索时的磁盘 I/O 次数**
- 磁盘索引结点（常驻外存）+ 内存索引结点（调入内存后增加：引用计数、是否被修改、打开标志）

**目录实现**：线性列表（简单，查找 $O(n)$）；哈希表（查找快，插入删除麻烦、要处理冲突）。

## 4.1.4 文件共享（🔴 硬链接 vs 软链接）

| | 硬链接（基于索引结点） | 软链接（符号链接） |
|---|---|---|
| 本质 | 多个目录项指向**同一个 inode** | 新建一个 **Link 型文件**，内容是目标路径 |
| inode 计数 | 建立时 count++，删除时 count--，**为 0 才真正删数据** | 不增加目标 inode 计数 |
| 跨文件系统 | **不能** | **能** |
| 原文件删除后 | 数据仍在（还有别的目录项） | 变成**悬空链接**（访问失败） |
| 访问开销 | 与普通文件相同 | 需**逐级解析路径**，多几次 I/O |

> [!warning] 易错
> 删除一个硬链接只是删目录项并让 count−1，**不等于删除文件**；只有当 count=0 且没有进程打开时才回收磁盘块。

## 4.1.5 文件保护

| 方式 | 做法 | 评价 |
|---|---|---|
| 口令保护 | 每个文件设口令，存在 FCB/系统中 | 开销小；口令**存于系统内部**，安全性差 |
| 加密保护 | 用密钥把文件加密 | 安全性高；加解密耗时 |
| **访问控制** | 访问控制表 ACL：按用户/用户组列出权限（读/写/执行/删除/列表） | 灵活、最常用；表可能很大 |

🟡 UNIX 权限：9 位 `rwxrwxrwx`，分别对应**所有者 / 同组用户 / 其他用户**；目录的 `x` 表示「可进入（搜索）」，`r` 表示「可列出内容」，`w` 表示「可在其中创建/删除文件」。

# 4.2 文件系统实现

## 4.2.1 文件系统的层次结构（🔴 记顺序）

```
用户接口（系统调用）
   → 文件目录系统（路径解析、找 inode）
   → 存取控制验证（权限检查）
   → 逻辑文件系统与文件信息缓冲区（逻辑块号）
   → 物理文件系统（逻辑块号 → 物理块号）
   → 辅助分配模块 / 设备管理模块
   → 设备
```

> [!tip] 一句话
> 上层管「名字和权限」，中层管「逻辑块」，下层管「物理块和磁盘」。

## 4.2.2 文件系统在磁盘上的布局

- **MBR（主引导记录）**：含引导程序 + 分区表，位于磁盘第一个扇区
- **分区内部**：引导块（引导扇区）→ **超级块**（文件系统元数据：inode 总数、块数、空闲块指针等）→ 空闲空间管理区 → **inode 区**（索引结点表）→ 根目录 → 数据区
- 🟡 超级块在内存中保留一份拷贝；文件系统挂载时读入。

## 4.2.3 文件分配方式（物理结构，🔴 全章最核心）

| 方式 | 目录项内容 | 优点 | 缺点 | 随机访问 |
|---|---|---|---|---|
| **连续分配** | 起始块号 + 长度 | 顺序/随机都快，寻道最少 | **外部碎片**；文件不易扩展；要求连续空间 | 支持，$O(1)$ |
| **链接分配（隐式）** | 首块指针 | 无外部碎片、易扩展 | **只能顺序访问**；指针占空间；断链即丢数据 | 不支持 |
| **链接分配（显式 FAT）** | 首块号 | 无外部碎片、**可随机访问**（FAT 常驻内存） | FAT 表占内存；FAT 本身是单点故障 | 支持（查 FAT） |
| **索引分配** | 索引块号 | 支持随机访问、易扩展 | 索引块占空间；大文件需多级 | 支持 |
| **混合索引（UNIX inode）** | inode 号 | 小文件省索引块、大文件可扩展 | 计算复杂 | 支持 |

🔴 **索引分配的三种扩展**：链接方案（索引块链起来，只适合大文件）、多层索引（一级/二级/三级）、混合索引（直接 + 一级 + 二级 + 三级）。

**混合索引寻址模板**（🔴 大题）：设 inode 有 10 个直接指针、1 个一级、1 个二级、1 个三级；块大小 $4\text{KB}$，指针 $4\text{B}$ → 每块 $1024$ 个指针。

| 层次 | 可寻址数据量 |
|---|---|
| 10 个直接块 | $10 \times 4\text{KB} = 40\text{KB}$ |
| 一级间接 | $1024 \times 4\text{KB} = 4\text{MB}$ |
| 二级间接 | $1024^2 \times 4\text{KB} = 4\text{GB}$ |
| 三级间接 | $1024^3 \times 4\text{KB} = 4\text{TB}$ |

则最大文件 $= 40\text{KB} + 4\text{MB} + 4\text{GB} + 4\text{TB}$。
若问「逻辑块号 $k$ 落在哪一级」：先减去 10（直接块），再与 $1024$、$1024^2$ 比较。

> [!warning] 访问次数
> 读一个**间接块中的数据**：一级间接要读 1 次索引块 + 1 次数据块；二级间接 2 + 1；三级间接 3 + 1。
> 连续分配读第 $k$ 块只需 1 次（甚至可预读）；隐式链接要顺序读 $k$ 次。

## 4.2.4 文件存储空间管理（🔴 计算题）

| 方法 | 思想 | 适用 / 特点 |
|---|---|---|
| 空闲表法 | 记录空闲区（起始块、长度） | 连续分配；分配回收像内存动态分区 |
| 空闲链表法 | 空闲盘块链 / 空闲盘区链 | 实现简单；分配时可能要遍历 |
| **位示图** | 1 个二进制位 = 1 个盘块，0 空闲 1 占用 | 易找连续块；位示图本身占空间 |
| **成组链接法** | 每 100 个空闲块号为一组，组内第一项存**下一组块号** | UNIX 采用；兼顾效率与空间 |

🔴 **位示图换算**（块号从 0 开始，字长 $n$ 位/字）：
$$\text{字号} = \left\lfloor \frac{b}{n} \right\rfloor,\qquad \text{位号} = b \bmod n$$
若题中块号、字号、位号都**从 1 开始**，先把块号减 1 再套公式，最后结果再按题目口径调整。

🟡 **位示图大小**：盘块数 $N$ → 需要 $N$ 位 = $N/8$ 字节。例：$1\text{TB}$ 磁盘、块 $4\text{KB}$ → $2^{28}$ 块 → 位示图 $2^{25}\text{B} = 32\text{MB}$。

🟡 **成组链接**：超级块中存放第一组（栈式使用）；栈空时把下一组读入；回收时栈满则把当前栈内容写入新块，该块成为新的组头。

## 4.2.5 虚拟文件系统 VFS

🔴 目的：**屏蔽不同文件系统的差异**，向上提供统一接口（同一套 `open/read/write`），向下兼容 FAT、NTFS、ext4 等。

四个对象：**超级块对象**（一个已挂载文件系统）、**索引结点对象**（一个文件）、**目录项对象**（一个路径分量）、**文件对象**（一个已打开文件）。
🟡 VFS 只存在于**内存**，系统启动时建立，卸载时消失。

# 4.3 磁盘与固态硬盘

## 4.3.1 磁盘结构、地址与容量

- 盘片 → 盘面（每面一个磁头）→ 磁道 → 扇区；**柱面 = 所有盘面上相同半径的磁道集合**
- 🔴 **磁盘地址 = (柱面号, 盘面号, 扇区号)**；扇区是最小读写单位（常见 512B，现多为 4KB）
- 🔴 容量：
$$\text{容量} = \text{盘面数} \times \text{每面磁道数} \times \text{每道扇区数} \times \text{扇区大小}$$

> [!tip] 例
> 8 个盘面、每面 1000 磁道、每道 200 扇区、扇区 512B → $8 \times 1000 \times 200 \times 512\text{B} = 819.2\text{MB}$。

## 4.3.2 访问时间（🔴 公式）

$$\text{平均访问时间} = \text{平均寻道时间} + \text{平均旋转延迟} + \text{传输时间}$$

- 平均旋转延迟 = 转半圈的时间 $=\dfrac{1}{2}\cdot\dfrac{60}{r}$（$r$ 为转速，单位 r/min）
- 传输时间 = $\dfrac{\text{读取字节数}}{\text{传输速率}}$，或 $\dfrac{\text{读取扇区数}}{\text{每道扇区数}} \times$ 转一圈的时间

> [!tip] 例
> 转速 $7200\text{ r/min}$ → 一圈 $8.33\text{ms}$ → 平均旋转延迟 $4.17\text{ms}$；若平均寻道 $5\text{ms}$，则平均访问时间约 $9.17\text{ms}$（不含传输）。

## 4.3.3 磁盘调度算法（🔴 必考计算）

| 算法 | 规则 | 优点 | 缺点 |
|---|---|---|---|
| **FCFS** | 按请求到达顺序 | 公平、简单 | 平均寻道长 |
| **SSTF** | 每次选**离当前磁头最近**的请求 | 平均寻道短 | **远处请求饥饿** |
| **SCAN（电梯）** | 单向扫到端点再反向 | 兼顾公平与效率 | 中间磁道更占便宜 |
| **C-SCAN** | 只单向服务，回程**不服务** | 各磁道更公平 | 回程空跑 |
| **LOOK** | 扫到**最远请求**就返回（不到端点） | 比 SCAN 少跑空路 | 实现稍复杂 |
| **C-LOOK** | 单向服务，到最远请求即返回 | 公平 + 少空跑 | 同上 |

🟡 计算模板：画数轴 → 按算法顺序连线 → **总移动磁道数 = 相邻访问点距离之和** → 平均寻道长度 = 总移动量 / 请求数（注意题目是否含初始磁头位置）。

## 4.3.4 减少延迟时间的方法

| 方法 | 做法 | 解决什么 |
|---|---|---|
| **交替编号** | 相邻逻辑扇区在物理上隔开 | 给控制器处理时间，避免「读完处理不及、转一圈再等」 |
| **错位命名** | 不同盘面的扇区起始位置错开 | 换盘面读同一柱面时不用等整圈 |
| **按柱面存放** | 同一柱面的数据连续放 | 减少寻道次数（柱面内换头几乎无寻道） |

## 4.3.5 磁盘管理

- **低级格式化（物理格式化）**：划分扇区、写头尾标志与校验码，出厂前完成
- **分区**：把磁盘划分为若干逻辑区
- **高级格式化（逻辑格式化）**：建立文件系统——初始化 FCB/inode 区、根目录、空闲空间管理结构
- **引导块**：存放自举程序；开机先执行 MBR 中的引导程序，再读活动分区的引导块
- **坏块处理**：简单磁盘在 FAT 中标记；复杂磁盘用**扇区备用**（滑动替换）对 OS 透明

## 4.3.6 固态硬盘 SSD

- 基于闪存：**页（page）为读写单位，块（block）为擦除单位**；写前必须先擦除整块
- 特点：**读快写慢**、无机械部件（无寻道/旋转延迟）、随机访问快、抗震动、功耗低
- 寿命：每块擦写次数有限（如 TLC 约千次量级）；靠 **磨损均衡**（动态/静态）+ **垃圾回收** + **FTL 地址映射**延长寿命
- 对比磁盘：SSD 随机读写远快，顺序写不一定占优；按块擦除带来**写放大**

| 对比项 | 机械磁盘 HDD | 固态硬盘 SSD |
|---|---|---|
| 寻道/旋转延迟 | 有（毫秒级） | 无（微秒级） |
| 随机访问 | 慢 | 快 |
| 最小读写单位 | 扇区 | 页 |
| 最小擦除单位 | — | 块 |
| 寿命限制 | 机械磨损 | 擦写次数有限 |

# 附 A · 20 条速记（考前 10 分钟）

1. 目录本身也是文件；目录项 = 文件名 + inode 号。
2. **inode 不含文件名**（文件名在目录项里）。
3. open 只是把 FCB/inode 调入内存，返回文件描述符。
4. 系统打开文件表全局一张，进程打开文件表每进程一张。
5. 顺序文件：串结构只能顺序查，顺序结构可折半。
6. 索引文件为**变长记录**服务；索引顺序文件 = 分组 + 组索引。
7. 树形目录解决重名与分类，但不便于共享；无环图解决共享。
8. 硬链接：同一 inode，count++，不能跨文件系统。
9. 软链接：独立 Link 文件存路径，可跨文件系统，原文件删除后悬空。
10. 连续分配：随机访问快、有外部碎片、难扩展。
11. 隐式链接只能顺序访问；FAT 显式链接可随机访问（FAT 常驻内存）。
12. 索引分配：一级 1 次索引 I/O，二级 2 次，三级 3 次。
13. 混合索引最大文件 = 直接 + 一级 + 二级 + 三级之和。
14. 位示图：字号 $=\lfloor b/n \rfloor$，位号 $= b \bmod n$。
15. 成组链接：每组第一项存下一组块号，UNIX 用。
16. 磁盘地址 = 柱面号 + 盘面号 + 扇区号。
17. 平均访问时间 = 寻道 + 半圈旋转 + 传输。
18. SSTF 会饥饿；SCAN 是电梯；C-SCAN 回程不服务；LOOK 不到端点。
19. 交替编号给处理时间，错位命名给换面时间，按柱面存放减少寻道。
20. SSD：页读写、块擦除，写前先擦，靠磨损均衡与 GC 续命。

# 附 B · 自测（合上笔记答）

1. 目录项里存什么？→ 文件名 + inode 号。
2. 为什么要把 FCB 拆成目录项 + inode？→ 目录项变小，一个盘块装更多，减少检索 I/O。
3. 打开文件的本质？→ 把 FCB 调入内存打开文件表，返回描述符。
4. 硬链接能跨文件系统吗？→ 不能；软链接能。
5. 删除一个硬链接后文件还在吗？→ 在，count 减 1，为 0 才回收。
6. 隐式链接为什么不能随机访问？→ 必须从头顺着指针找。
7. FAT 为什么能随机访问？→ 链接指针集中且常驻内存，可沿表跳转。
8. 读二级间接块中的文件块要几次磁盘 I/O？→ 2 次索引块 + 1 次数据块 = 3 次。
9. 位示图 1 个字 32 位，块号 130（从 0）对应？→ 字号 $\lfloor 130/32 \rfloor = 4$，位号 $130 \bmod 32 = 2$。
10. 成组链接法第一组存在哪？→ 超级块。
11. VFS 的四个对象？→ 超级块、inode、目录项、文件。
12. 平均旋转延迟怎么算？→ 半圈时间 $=\frac{1}{2}\cdot\frac{60}{r}$。
13. SCAN 与 C-SCAN 的区别？→ C-SCAN 回程不服务，更公平。
14. SSTF 的缺点？→ 远端请求饥饿。
15. 为什么要交替编号？→ 给控制器处理时间，避免等整圈。
16. 高级格式化做什么？→ 建立文件系统：初始化 inode 区、根目录、空闲空间管理。

18. SSD 为什么需要磨损均衡？→ 每块擦写次数有限，避免热点块先坏。
