# 第 0 章 · 总览

> [!abstract] 先建立坐标系：性能指标怎么分类、公式怎么串、单位怎么换
> `响应时间` · `吞吐量` · `五步解题链` · `单位换算` · `符号表`


## 0.1 性能到底是什么：两条主线

> 计算机的「性能」永远在回答两个问题：**完成一个任务要多久**（响应时间 / 执行时间），以及**单位时间能完成多少任务**（吞吐量 / 带宽）。408 四门课的所有性能指标，都是这两条主线的不同投影。

### 响应时间（执行时间） `个体视角`

从用户发出请求到系统给出结果所经历的时间。对 CPU 而言就是**程序的 CPU 执行时间**；对磁盘、网络而言是**一次访问/一次传输的端到端时延**。它衡量「快不快」。

**公式**：`T = 完成时刻 − 提交时刻`

> [!example] 例
> 一个程序 10:00:00 开始、10:00:02 结束，响应时间 = 2 s；若其中 CPU 只跑了 0.5 s，其余在等 I/O，则 CPU 时间只有 0.5 s。

> [!warning] 易错
> 响应时间 ≠ CPU 时间。含 I/O、排队、调度等待的「墙钟时间」才是响应时间，比 CPU 时间大得多。

### 吞吐量（Throughput） `系统视角`

单位时间内系统处理完的任务数、指令数或数据量，衡量「能扛多少」。计组的 IPS/MIPS、计网的 bit/s、操作系统的作业吞吐量都是它。

**公式**：`X = N / T（任务/s、指令/s、bit/s）`

> [!example] 例
> 某服务器 1 s 内处理 500 个请求，吞吐量 = 500 请求/s；若 8 核并行，吞吐量可线性增长而单请求响应时间不变。

> [!warning] 易错
> 响应时间与吞吐量**不一定同向变化**。提高并行度通常提升吞吐量，却可能因排队让响应时间变长。

> [!tip] 两条主线的关系
> **吞吐量 ≈ 并行度 ÷ 平均响应时间**（Little 定律的直观版）。所以「加机器/加流水线」是拿响应时间换吞吐量，「优化单条指令」是拿吞吐量换响应时间——考试里先判断题目问的是哪一个。


## 0.2 通用解题链：五步法

**任何一道性能计算题，都按这五步走**

| 指标 | 说明 |
|---|---|
| ① 定对象 | 是 CPU、Cache、磁盘、进程还是端到端链路？对象不同，公式的分子分母完全不同。 |
| ② 挑公式 | 从「指标定义」出发写公式，而不是凭记忆套；写不出就先画时间线或访存路径。 |
| ③ 统一单位 | 频率用 Hz、时间用 s、容量用 B、速率用 bit/s；先全部换成基本单位再代数运算。 |
| ④ 判条件 | 是否命中、是否流水、是否重叠、是否含 I/O；条件不满足时公式要加修正项。 |
| ⑤ 验数量级 | 结果是否落在常识区间（主频 1–5 GHz、内存访问 100 ns、磁盘寻道 5–10 ms、跨洋 RTT 100 ms）。 |

> [!warning] 五步法里最常垮的一步
> 第 ③ 步。408 的失分大多不是公式错，而是 **MHz 没换成 Hz、ms 没换成 s、bit 与 Byte 混用、2¹⁰ 与 10³ 混用**。第 0.4 节的换算表必须背到条件反射。


## 0.3 一条主线串起四科

> 四门课的性能指标不是孤立的：数据结构回答「算法要做多少次基本操作」，计组回答「这些操作在硬件上花多少时钟」，操作系统回答「多个任务怎么分这些时间」，计网回答「数据在网络上传多久」。下面四条链，就是四科性能计算的骨架。

```text
数据结构：问题规模 n  →  基本操作次数 f(n)  →  时间复杂度 O(f(n))  →  空间复杂度 O(g(n))
计组：指令条数 IC  →  CPI  →  时钟周期数 IC×CPI  →  CPU 执行时间 IC×CPI×Tc = IC×CPI/f
操作系统：到达时间 + 运行时间  →  完成时间  →  周转时间  →  带权周转时间  →  平均周转/平均带权周转
计算机网络：数据量 L  →  发送时延 L/R  →  传播时延 d/v  →  总时延  →  时延带宽积  →  吞吐量/信道利用率
```

> [!abstract] 核心公式
> `T_CPU = IC × CPI × Tc = IC × CPI / f`
>
> 408 计组第一公式：指令条数、每条指令周期数、时钟周期，三者缺一不可


## 0.4 单位换算：丢分重灾区

> [!warning] 先记住一条总规则
> **存储容量、地址空间用 2 的幂（1 KB = 2¹⁰ B）；速率、频率、传输时间用 10 的幂（1 kbps = 10³ bit/s）。** 磁盘厂商标称容量、网络带宽、主频都用十进制；内存容量、Cache 容量、页大小用二进制。题目没写清时，看它问的是「容量」还是「速率」。


### 容量单位（二进制，2 的幂）

| 单位 | 换算 | 说明 |
|---|---|---|
| 1 B | 8 bit | 字节是编址单位，位是存储最小单位 |
| 1 KB | 2¹⁰ B = 1 024 B | 内存、Cache、文件系统块 |
| 1 MB | 2²⁰ B = 1 024 KB | 主存容量、地址空间 |
| 1 GB | 2³⁰ B | 磁盘容量、内存条 |
| 1 TB | 2⁴⁰ B | 大容量存储 |


### 速率与频率单位（十进制，10 的幂）

| 单位 | 换算 | 典型场景 |
|---|---|---|
| 1 kbps | 10³ bit/s | 网络带宽、调制解调器 |
| 1 Mbps | 10⁶ bit/s | 局域网、宽带 |
| 1 Gbps | 10⁹ bit/s | 千兆以太网、总线带宽 |
| 1 kHz / MHz / GHz | 10³ / 10⁶ / 10⁹ Hz | 主频、总线时钟、采样率 |


### 时间单位

| 单位 | 换算 | 典型量级 |
|---|---|---|
| 1 s | 10³ ms = 10⁶ μs = 10⁹ ns = 10¹² ps | — |
| 1 ms | 10³ μs = 10⁶ ns | 磁盘寻道、缺页处理 |
| 1 μs | 10³ ns | 内存访问、TLB 命中 |
| 1 ns | 10³ ps | Cache 访问、1 GHz 的一个时钟周期 |

> [!tip] 30 秒换算训练
> 主频 2 GHz ⇒ 时钟周期 = 1/(2×10⁹) s = 0.5 ns = 500 ps；内存访问 100 ns ⇒ 相当于 200 个时钟周期；磁盘寻道 8 ms ⇒ 相当于 1 600 万个时钟周期。把这三组数字记熟，做题时能立刻判断「这题的数量级对不对」。

## 0.6 性能评价方法（考纲边缘，读懂真题背景）

### 基准测试程序（Benchmark） `评价方法`

用一组有代表性的真实程序测试机器性能，避免用单条指令或合成程序带来的偏差。SPEC CPU 是最常用的整数/浮点基准测试集，其结果以**相对参考机的比值**表示。

> [!example] 例
> SPECint 得分 30 表示比参考机快 30 倍；不同版本（SPEC2006/2017）之间不可直接比较。

> [!warning] 易错
> 不能用 MIPS 直接比较不同指令系统的机器——指令的「含量」不同，MIPS 高不代表程序跑得快。

### 算术平均与几何平均 `评价方法`

多个程序性能取平均时：**执行时间用算术平均**；**性能比值（速度提升倍数）用几何平均**。几何平均能保证「A 比 B 快 k 倍」与「B 比 A 慢 k 倍」自洽。

**公式**：`G = ⁿ√(x₁·x₂·…·xₙ)`

> [!example] 例
> 三个程序相对参考机的加速比 2、4、8，几何平均 = ∛(2×4×8) = 4。

### Amdahl 定律 `评价方法`

系统中某部分被加速 k 倍、该部分占总时间比例为 p 时，整体加速比的上限。它解释了「只优化一部分，收益有天花板」。

**公式**：`S = 1 / [(1−p) + p/k]`

> [!example] 例
> 程序 60% 时间可并行、用 4 核加速，则 S = 1/(0.4+0.15) = 1.82，即使核数无穷大也只到 2.5。

> [!warning] 易错
> Amdahl 定律问的是**加速比**，不是时间；k→∞ 时 S→1/(1−p)，这是选择题常设的极限。


## 0.7 开始之前：五个高频误区

| 误区 | 正确理解 | 常考位置 |
|---|---|---|
| 主频越高，机器越快 | 还要看 CPI 与指令条数：T = IC×CPI/f | 计组选择题 |
| MIPS 越大性能越好 | 跨指令系统不可比；MIPS 只对同一指令系统有意义 | 计组概念题 |
| 带宽 = 传输速率 | 计网的「带宽」常指 bit/s，计组的「总线带宽」是 B/s，物理层「带宽」是 Hz | 第 5 章辨析 |
| 命中率越高，平均访问时间一定越短 | 还要看缺失代价：AMAT = H·Tc + (1−H)·Tm | Cache 计算题 |
| 平均周转时间短 = 响应时间短 | 周转时间含等待+运行+I/O，响应时间是首次响应；SJF 优化前者，RR 优化后者 | OS 调度题 |

> [!warning] 一句话总结第 0 章
> 所有性能题都能还原成「**一个比值**」：分子是「完成的工作量」，分母是「花掉的时间或资源」。先把分子分母的单位对齐，再谈公式。

# 第 1 章 · 数据结构

> [!abstract] 算法要做多少次基本操作：时间复杂度、ASL、排序与图算法的量化指标
> `时间复杂度` · `空间复杂度` · `ASL` · `排序` · `图算法` · `B 树`


## 1.1 时间复杂度：只看增长趋势

> 数据结构里的「性能」= 算法随问题规模 n 增长时，基本操作次数（时间）与额外存储（空间）的增长速度。408 不要求严格证明，只要求会**数循环层次、会解递推式、会区分最好/最坏/平均**。

### 时间复杂度 `渐进分析`

算法中基本语句执行次数的数量级。记 T(n) 为语句频度，若存在正常数 C 和 n₀，使 n ≥ n₀ 时 T(n) ≤ C·f(n)，则 T(n) = O(f(n))。**大 O 是上界**，只保留最高阶项、忽略常数系数。

**公式**：`T(n) = O(f(n))`

> [!example] 例
> 语句 `for(i=0;i<n;i++) for(j=0;j<n;j++) a++;` 执行 n² 次 ⇒ O(n²)；若内层是 `j<n-i`，仍是 O(n²)，因为系数 1/2 被忽略。

> [!warning] 易错
> O(n²) 不代表「恰好 n² 次」，只代表同阶。写答案时要化简：O(2n²+3n+1) 必须写 O(n²)。

### 空间复杂度 `渐进分析`

算法运行**额外**占用的存储空间随 n 的增长阶。只算辅助空间，不算输入数据本身。递归算法的空间复杂度 = 递归深度 × 每层栈帧大小。

**公式**：`S(n) = O(g(n))`

> [!example] 例
> 冒泡排序只用常数个临时变量 ⇒ O(1)（原地）；归并排序需要长度 n 的辅助数组 ⇒ O(n)；递归计算阶乘的递归深度 n ⇒ O(n)。

> [!warning] 易错
> 递归的**时间**不等于空间；快排空间是 O(log n)（递归栈期望深度），最坏 O(n)。


### 常见增长阶与大小关系

| 阶 | 名称 | n=10 时的量级 | n=1000 时 | 典型算法 |
|---|---|---|---|---|
| O(1) | 常数阶 | 1 | 1 | 数组下标访问、哈希查找（理想） |
| O(log n) | 对数阶 | ≈3 | ≈10 | 折半查找、平衡树查找 |
| O(n) | 线性阶 | 10 | 1 000 | 顺序查找、遍历 |
| O(n log n) | 线性对数阶 | ≈33 | ≈10 000 | 归并/堆/快排平均、排序下界 |
| O(n²) | 平方阶 | 100 | 10⁶ | 冒泡/插入/选择、邻接矩阵遍历 |
| O(n³) | 立方阶 | 1 000 | 10⁹ | Floyd、朴素矩阵乘法 |
| O(2ⁿ) | 指数阶 | 1 024 | 天文数字 | 汉诺塔、朴素递归斐波那契 |
| O(n!) | 阶乘阶 | 3.6×10⁶ | 不可行 | 全排列、TSP 暴力 |

> [!warning] 三个必须区分清楚的概念
> **最好/最坏/平均**：插入排序最好 O(n)（已有序）、最坏 O(n²)、平均 O(n²)；快排最好/平均 O(n log n)、最坏 O(n²)（基本有序且取首元素为枢轴）。题目问「平均」时不能答最坏，问「最坏」时不能答平均。


### 递推式解法（递归算法的命门）

| 递推式 | 解 | 对应算法 |
|---|---|---|
| T(n) = T(n−1) + 1 | O(n) | 单层递归遍历、求阶乘 |
| T(n) = T(n−1) + n | O(n²) | 递归中做一层循环 |
| T(n) = 2T(n−1) + 1 | O(2ⁿ) | 汉诺塔、朴素斐波那契 |
| T(n) = T(n/2) + 1 | O(log n) | 折半查找、二分递归 |
| T(n) = 2T(n/2) + n | O(n log n) | 归并排序、快排平均 |
| T(n) = 2T(n/2) + 1 | O(n) | 二叉树遍历 |
| T(n) = T(n/2) + n | O(n) | 等比级数求和（主定理第二种情形） |

> [!tip] 主定理速用版
> T(n) = aT(n/b) + f(n)：比较 f(n) 与 n^(log_b a)。f(n) 更小 ⇒ T = Θ(n^(log_b a))；同阶 ⇒ 乘 log n；f(n) 更大（且满足正则条件）⇒ T = Θ(f(n))。408 只需记住上表七个特例，不必背主定理全文。


## 1.2 各结构基本操作的复杂度

| 数据结构 | 查找 | 插入 | 删除 | 额外空间 | 关键说明 |
|---|---|---|---|---|---|
| 顺序表 | O(n) | O(n) | O(n) | O(1) | 按下标随机访问 O(1)，插入/删除平均移动 n/2 个元素 |
| 单链表 | O(n) | O(1)* | O(1)* | O(n) | *已定位到前驱时；按值查找仍 O(n) |
| 双链表 | O(n) | O(1)* | O(1)* | O(n) | 可 O(1) 找前驱，删除更方便 |
| 栈 / 队列 | — | O(1) | O(1) | O(n) | 顺序栈/循环队列；链栈/链队列 |
| 循环队列 | — | O(1) | O(1) | O(m) | 牺牲一个单元区分队空/队满 |
| 串（KMP） | O(n+m) | — | — | O(m) | 朴素匹配 O(nm)，next 数组 O(m) |
| 二叉排序树 | O(log n)~O(n) | O(log n)~O(n) | O(log n)~O(n) | O(n) | 退化成单支树时 O(n) |
| 平衡二叉树 AVL | O(log n) | O(log n) | O(log n) | O(n) | 旋转调整，高度 ≤ 1.44log₂n |
| 堆 | O(1) 取堆顶 | O(log n) | O(log n) | O(1) | 建堆 O(n)；查找任意元素 O(n) |
| 散列表 | O(1) 期望 | O(1) 期望 | O(1) 期望 | O(n) | 冲突时退化，ASL 与装填因子 α 有关 |
| 邻接矩阵 | O(1) 判边 | O(1) | O(1) | O(n²) | 适合稠密图 |
| 邻接表 | O(deg) | O(1) | O(1) | O(n+e) | 适合稀疏图，遍历 O(n+e) |

> [!warning] 循环队列的三个公式
> 队空：`front == rear`；队满：`(rear+1)%m == front`；**元素个数 = (rear − front + m) % m**。注意队满时实际只能存 m−1 个元素，这是「牺牲一个单元」的代价；若题目用「增设 size 变量」或「tag 标志」，队满条件要相应改写。


## 1.3 查找性能：ASL 是核心指标

### 平均查找长度 ASL `查找`

查找过程中关键字比较次数的期望值，pᵢ 是查第 i 个元素的概率（等概率时 = 1/n），cᵢ 是找到它需要的比较次数。**ASL 要区分「查找成功」与「查找失败」**，两者分母不同。

**公式**：`ASL成功 = Σ pᵢcᵢ（i=1..n）；ASL失败 = Σ qⱼcⱼ（j=1..m，m 为失败结点数）`

> [!example] 例
> 顺序表 {10,20,30} 等概率查找，成功 ASL = (1+2+3)/3 = 2；失败时与全部 3 个元素比较 ⇒ ASL失败 = 3。

> [!warning] 易错
> **分母不同**——成功是 n（元素个数），失败是 m（外部结点/空链个数），不是同一个 n。折半查找失败 ASL 的分母等于判定树的空指针个数。

### 顺序查找 `线性`

从表头逐个比较。等概率成功 ASL = (1+2+…+n)/n = (n+1)/2；失败需比较 n 次（无哨兵）或 n+1 次（有哨兵）。适用：顺序表与链表、无序表。

**公式**：`ASL成功 = (n+1)/2，ASL失败 = n`

> [!example] 例
> n = 10 的顺序表，成功 ASL = 5.5，失败 ASL = 10。

> [!warning] 易错
> 设置哨兵可减少一次循环边界判断，但**失败比较次数变成 n+1**；王道教材两种口径都出现过，按题目给的存储结构判断。

### 折半查找 `有序`

在有序顺序表上二分。判定树是平衡二叉树，查找成功的比较次数 = 结点所在层数；ASL 成功 = log₂(n+1) − 1（n = 2^h − 1 时精确）。时间复杂度 O(log n)，但只适用于**顺序存储的有序表**。

**公式**：`h = ⌈log₂(n+1)⌉，ASL成功 ≈ log₂(n+1) − 1`

> [!example] 例
> n = 7 的判定树为满二叉树（3 层），成功 ASL = (1×1+2×2+3×4)/7 = 17/7 ≈ 2.43 = log₂8 − 1。

> [!warning] 易错
> 链表不能折半查找（无法随机访问）；折半查找的**判定树不唯一**（mid 取整方式不同），但 ASL 相同。

### 分块查找 `索引顺序`

把表分成 b 块、每块 s 个元素（n = b×s），块间有序、块内无序。先查索引表（可顺序或折半），再在块内顺序查找。

**公式**：`ASL = (b+1)/2 + (s+1)/2；当 s = √n 时取最小值 ASL ≈ √n + 1`

> [!example] 例
> n = 100，分成 10 块每块 10 个，顺序查索引：ASL = 5.5 + 5.5 = 11。

> [!warning] 易错
> 分块查找的索引表若用折半查找，ASL 前项变为 log₂(b+1)−1；最优块长 s = √n 是选择题高频结论。

### 二叉排序树 ASL `动态查找`

ASL 等于各结点所在层数的平均值，取决于插入顺序。最好情况（平衡）ASL = O(log n)；最坏（插入有序序列，退化成单链表）ASL = (n+1)/2 = O(n)。

**公式**：`ASL = (Σ 层数ᵢ)/n`

> [!example] 例
> 依次插入 50,30,70,20,40 得到的 BST，成功 ASL = (1+2+2+3+3)/5 = 2.2。

> [!warning] 易错
> BST 的 ASL **不是固定值**，同一组关键字不同插入顺序得到不同形态；删除结点后形态也会变化。

### 平衡二叉树 AVL `动态查找`

任一结点左右子树高度差 ≤ 1 的 BST。n 个结点的 AVL 树高度 h 满足 log₂(n+1) ≤ h ≤ 1.44log₂(n+2)，查找/插入/删除均为 O(log n)。失衡时用 LL/RR/LR/RL 四种旋转恢复。

**公式**：`h ≤ 1.44·log₂(n+2) − 0.328`

> [!example] 例
> n = 10 时 h ≤ 1.44×log₂12 ≈ 5.16，即最多 5 层；最坏查找 5 次。

> [!warning] 易错
> AVL 的「平衡」是高度平衡，不是结点数平衡；插入后只需**沿插入路径向上找到第一个失衡结点**调整一次（或两次旋转）即可恢复全树平衡。

### B 树 / B+ 树高度 `外存索引`

m 阶 B 树每个结点最多 m 棵子树、m−1 个关键字。含 n 个关键字的 B 树高度 h 满足：log_m(n+1) ≤ h ≤ log_⌈m/2⌉((n+1)/2) + 1。B+ 树所有关键字都在叶结点，叶结点用指针串成有序链表，支持**顺序查找与范围查询**。

**公式**：`h_min = ⌈log_m(n+1)⌉`

> [!example] 例
> m = 5、n = 1000 时，h ≥ log₅1001 ≈ 4.3 ⇒ 至少 5 层，即查找最多 5 次磁盘 I/O。

> [!warning] 易错
> B 树查找可能在内部结点命中，B+ 树**必须走到叶子**；B+ 树内部结点只存索引不存记录，同样阶数下能容纳更多关键字、树更矮。

### 散列表 ASL `散列查找`

装填因子 α = n/m（n 个元素、m 个桶）。α 越大冲突越多、ASL 越大。**ASL 与 α 有关，与 n 和 m 的绝对值无关**——这是散列表最重要的结论。

**公式**：`线性探测 成功 ≈ ½(1+1/(1−α))，失败 ≈ ½(1+1/(1−α)²)；链地址 成功 = 1+α/2`

> [!example] 例
> α = 0.5 时线性探测成功 ASL ≈ ½(1+2) = 1.5；α = 0.75 时 ≈ ½(1+4) = 2.5。

> [!warning] 易错
> 这些是**理论期望值**，408 真题通常给出具体散列表让你逐个数比较次数，务必按表算而不是套公式；失败 ASL 的分母是**散列函数值域大小 m**（不是 n）。


### 查找算法对比

| 算法 | 存储要求 | 时间复杂度 | ASL 成功 | ASL 失败 | 能否动态插入 |
|---|---|---|---|---|---|
| 顺序查找 | 顺序/链式，无序可 | O(n) | (n+1)/2 | n | 可以 |
| 折半查找 | 顺序存储且有序 | O(log n) | log₂(n+1)−1 | 由判定树空指针算 | 插入代价高 |
| 分块查找 | 块间有序、块内无序 | O(√n) | (b+1)/2+(s+1)/2 | — | 块内可插 |
| 二叉排序树 | 链式 | O(log n)~O(n) | 与形态有关 | 与形态有关 | 可以 |
| 平衡二叉树 | 链式 | O(log n) | — | — | 可以（旋转） |
| B/B+ 树 | 外存块 | O(log_m n) | — | — | 可以 |
| 散列表 | 散列存储 | O(1) 期望 | 与 α、冲突处理有关 | 同左 | 可以 |

## 1.4 排序性能：时间、空间、稳定性

| 排序算法 | 最好 | 平均 | 最坏 | 空间 | 稳定性 | 记忆要点 |
|---|---|---|---|---|---|---|
| 直接插入 | O(n) | O(n²) | O(n²) | O(1) | 稳定 | 基本有序时最快 |
| 折半插入 | O(n log n) 比较 | O(n²) | O(n²) | O(1) | 稳定 | 比较次数减少，移动次数不变 |
| 希尔排序 | — | O(n^1.3) | O(n²) | O(1) | 不稳定 | 增量序列影响复杂度 |
| 冒泡排序 | O(n) | O(n²) | O(n²) | O(1) | 稳定 | 一趟无交换即可提前结束 |
| 快速排序 | O(n log n) | O(n log n) | O(n²) | O(log n) | 不稳定 | 基本有序时最慢；枢轴影响大 |
| 简单选择 | O(n²) | O(n²) | O(n²) | O(1) | 不稳定 | 比较次数固定 n(n−1)/2 |
| 堆排序 | O(n log n) | O(n log n) | O(n log n) | O(1) | 不稳定 | 建堆 O(n)，适合取前 k 大 |
| 归并排序 | O(n log n) | O(n log n) | O(n log n) | O(n) | 稳定 | 外排序基础；空间换时间 |
| 基数排序 | O(d(n+r)) | O(d(n+r)) | O(d(n+r)) | O(r) | 稳定 | 非比较排序，d 位数、r 基数 |

> [!warning] 排序题最爱设的四个坑
> ① **「稳定」不等于「快」**：冒泡稳定但慢，快排快但不稳定。② 快排最坏 O(n²) 出现在**基本有序**时（取首/尾元素为枢轴），不是随机时。③ 堆排序建堆是 **O(n)**，不是 O(n log n)——这是证明题/选择题高频。④ 一趟排序后「至少有一个元素到位」的是**冒泡、快排、选择、堆**；插入、归并、希尔不保证。

### 建堆的时间复杂度 `排序`

自底向上对每个非叶结点向下调整：结点数为 n 的完全二叉树，高度为 h 的结点有 ⌈n/2^(h+1)⌉ 个、每个最多下调 h 层，总代价 Σ h·n/2^(h+1) = O(n)。而每次插入建堆（自顶向下）是 O(n log n)。

**公式**：`建堆 = O(n)；堆排序整体 = O(n log n)`

> [!example] 例
> n = 1000 时建堆约需 1000 次比较量级，而非 10⁴ 次。

> [!warning] 易错
> **建堆 O(n) 与「堆排序 O(n log n)」不矛盾**：建堆只做一次，之后 n 次取堆顶+调整每次 O(log n)。

### 外部排序的 I/O 次数 `外排序`

内存可容纳 m 个记录、待排 n 个记录：初始归并段数 r = ⌈n/m⌉；k 路归并趟数 s = ⌈log_k r⌉；每趟读写各一遍 n 个记录，加上初始建段一遍，总 I/O 次数 = 2n(s+1)（按记录或磁盘块计）。

**公式**：`r = ⌈n/m⌉，s = ⌈log_k r⌉，总读写 = 2n(s+1)`

> [!example] 例
> n = 10⁶、m = 10⁵ ⇒ r = 10；2 路归并 s = ⌈log₂10⌉ = 4；总 I/O = 2×10⁶×5 = 10⁷ 次。

> [!warning] 易错
> **增加归并路数 k 减少趟数 s，从而减少 I/O**，但 k 受内存缓冲区限制；最佳归并树（哈夫曼）用于**不等长归并段**时进一步减少 I/O；置换-选择排序可把平均初始段长从 m 提到 2m。

### 排序的稳定性 `性质`

稳定性定义：若排序前 a 在 b 前且 a.key = b.key，排序后 a 仍在 b 前，则算法稳定。**稳定**：插入、冒泡、归并、基数、折半插入；**不稳定**：希尔、快排、选择、堆。

> [!example] 例
> 对 (2a, 2b, 1) 排序，稳定算法必得 (1, 2a, 2b)，不稳定算法可能得 (1, 2b, 2a)。

> [!warning] 易错
> 稳定性与时间复杂度无关；「堆排序不稳定」是因为堆顶与末尾交换会打乱相等元素的相对次序。


## 1.5 树与图：空间与时间的量化

| 性质 / 算法 | 公式或复杂度 | 说明 |
|---|---|---|
| 二叉树第 i 层最多结点 | 2^(i−1) | 根为第 1 层 |
| 高度 h 的二叉树最多结点 | 2^h − 1 | 满二叉树 |
| 叶子与度为 2 结点 | n₀ = n₂ + 1 | 任意非空二叉树 |
| 完全二叉树高度 | ⌈log₂(n+1)⌉ | n 个结点 |
| 完全二叉树编号关系 | 左孩子 2i，右孩子 2i+1，父 ⌊i/2⌋ | 从 1 开始编号 |
| 哈夫曼树 WPL | Σ wᵢlᵢ | 带权路径长度最小 |
| 哈夫曼树结点数 | 2n−1（n 个叶子） | 无度为 1 的结点 |
| 邻接矩阵空间 | O(n²) | 适合稠密图、判断边 O(1) |
| 邻接表空间 | O(n+e) | 适合稀疏图 |
| BFS / DFS | O(n²) 矩阵，O(n+e) 表 | 遍历 |
| Dijkstra | O(n²)，堆优化 O((n+e)log n) | 单源最短路，不能有负权 |
| Floyd | O(n³) | 多源最短路，可处理负权（无负环） |
| Prim | O(n²) | 稠密图最小生成树 |
| Kruskal | O(e log e) | 稀疏图最小生成树 |
| 拓扑排序 | O(n+e) | AOV 网，判有环 |
| 关键路径 | O(n+e) | AOE 网，最长路径 = 最短工期 |

### 哈夫曼树与 WPL `树`

给定 n 个权值，构造 WPL 最小的二叉树：每次取权值最小的两个结点合并，新结点权值为二者之和放回。WPL 即所有叶子权值 × 路径长度之和，也等于**所有非叶结点权值之和**。

**公式**：`WPL = Σ wᵢlᵢ = Σ（内部结点权值）`

> [!example] 例
> 权值 {1,2,3,4}：合并 1+2=3 → {3,3,4}；合并 3+3=6 → {4,6}；合并 4+6=10。WPL = 10+6+3 = 19（也 = 1×3+2×3+3×2+4×2 = 19）。

> [!warning] 易错
> 哈夫曼树不唯一（左右子树可交换），但 **WPL 唯一**；n 个叶子的哈夫曼树共 2n−1 个结点，没有度为 1 的结点。

### 关键路径 `图`

AOE 网中，从源点到汇点的最长路径为关键路径，其长度为完成工程的最短时间。关键活动的时间余量 = 最晚开始 − 最早开始 = 0。求法：先正推 ve（最早发生时间），再逆推 vl（最晚发生时间）。

**公式**：`e(i) = ve(弧尾)，l(i) = vl(弧头) − 权；d(i) = l(i) − e(i)，d = 0 为关键活动`

> [!example] 例
> 三条路径长度 5、6、7，则工期 7，关键路径为最长那条；缩短工期必须缩短**所有**关键路径共有的活动。

> [!warning] 易错
> 关键路径可能不唯一；缩短某条关键路径上的一个活动，若它不在所有关键路径上，工期不变；关键路径长度是**最长**路径，不是最短。

### KMP 的时间复杂度 `串`

朴素模式匹配最坏 O(nm)（每趟失配后主串指针回退）。KMP 利用 next 数组，失配时主串指针不回退、模式串右移，主串每个字符最多比较一次 ⇒ O(n+m)，其中求 next 数组 O(m)。

**公式**：`T = O(n+m)，S = O(m)`

> [!example] 例
> 主串长 10⁶、模式串长 10³，朴素最坏 10⁹ 次比较，KMP 约 10⁶ 次。

> [!warning] 易错
> KMP 的**空间**是 O(m)（next 数组），不是 O(1)；nextval 优化减少不必要的比较，但复杂度不变。
