## 阅读说明与通用单位

> [!tip] 核心结论
>
> **一条通用解题链：**先辨认**对象**（CPU、单个作业、磁盘还是端到端链路）→明确**分子/分母**→统一**单位**→判断**重叠、流水、缓存命中和额外开销**→最后代数计算。


| 计算前的检查项 | 必须确认的事情 |
|:---|:---|
| 同名异义 | 带宽可能是 Hz 或 bit/s；吞吐量可能是任务/s、指令/s 或 bit/s；响应时间在 CPU 和 OS 调度场景也不同。 |
| 平均值有统计口径 | 算术平均、按指令数加权的 CPI、按查找概率加权的 ASL、按文件访问概率加权的平均访存时间，不可混用。 |
| 缓存“未命中时间”两种定义 | 若给“未命中**总时间**”做加权平均；若给“未命中**额外代价**”，直接在命中基础时间上增加代价。 |
| 流水线题标理想条件 | 相等分段、无相关冲突、无竞争、无额外气泡时的公式，不能不加条件推广。 |
| 单位先统一 | $1\,\mathrm{B}=8\,\mathrm{bit}$；通信速率中的 $\mathrm{M}=10^6$，存储容量中的 $\mathrm{Mi}=2^{20}$。题目若另行约定，以题目为准。 |

### 通用符号与单位

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **时间** | $T,t$：s、ms、$\mu$s、ns | $1\,\mathrm{ms}=10^{-3}\,\mathrm{s}$, $1\,\mu\mathrm{s}=10^{-6}\,\mathrm{s}$, $1\,\mathrm{ns}=10^{-9}\,\mathrm{s}$。 |
| **频率** | $f=1/T$：Hz | $1\,\mathrm{GHz}=10^9\,\mathrm{Hz}$。频率越高，并不保证完整程序越快。 |
| **二进制容量** | $1\,\mathrm{KiB}=2^{10}\,\mathrm{B}$； $1\,\mathrm{MiB}=2^{20}\,\mathrm{B}$ | $1\,\mathrm{GiB}=2^{30}\,\mathrm{B}$；厂商标称 KB/MB/GB 可能采用十进制。 |
| **速率/吞吐** | $\text{数据量}/\text{时间}$ | 单位为 bit/s、B/s 或 次/s；必须看“数据量”的统计范围。 |
| **效率/利用率** | $\text{有效部分}/\text{整体部分}$ | 无量纲，通常用 $0\!\sim\!1$ 或百分比表达；分子分母必须同类。 |
| **加速比** | $S=T_{\mathrm{old}}/T_{\mathrm{new}}$ | 同一任务、相同工作量下比较，$S>1$ 表示加速。 |

### 算法总体指标与复杂度

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **时间复杂度** | $T(n)$，常写 $O(f(n))$ | 计算基本操作执行次数随输入规模 $n$ 的增长阶；不直接等于真实秒数。 |
| **空间复杂度** | $S(n)$，常写 $O(g(n))$ | 通常关注**辅助空间**（含递归栈），需区别输入本身所占空间。 |
| **大 $O$ 上界** | $T(n)=O(f(n))$ | 存在常数 $c,n_0$，当 $n\ge n_0$ 时 $T(n)\le cf(n)$。上界可不紧。 |
| **大 $\Omega$ 下界** | $T(n)=\Omega(f(n))$ | 渐近下界；$\Theta(f(n))$ 同时给出上下界（紧确阶）。 |
| **最好、最坏、平均** | $T_{\min}(n),\ T_{\max}(n),\ E[T(n)]$ | 平均时间必须有输入分布假设；不等于最好和最坏的简单算术平均。 |
| **均摊时间** | $\bar T=\frac{\sum_{i=1}^m c_i}{m}$ | 用于动态数组扩容等；均摊 $O(1)$ 不保证每次单独操作为 $O(1)$。 |
| **递归栈深度** | $\text{空间}\propto\text{最大递归深度}$ | 如二分查找递归栈 $O(\log n)$，迭代写法可为 $O(1)$。 |
| **比较次数** | $C(n)=\#\text{关键字比较}$ | 查找/排序复杂度的核心计数；和交换次数、移动次数分别统计。 |
| **交换/移动次数** | $M(n)=\#\text{记录移动}$ | 一次交换可能涉及 3 次赋值；按试题指定口径计数。 |
| **分治递推** | $T(n)=aT(n/b)+f(n)$ | 一般用递推展开、递归树估阶；无需把所有分治算法都套成统一结论。 |

> [!warning] 易错提醒
>
> **高频辨析：**$O(n)$ 不表示恰好执行 $n$ 次；$O(1)$ 不表示“一秒”；最坏时间与平均时间可能同阶，也可能相差很大。$\log n$ 在复杂度记号中底数不影响增长阶。


### 线性表、栈、队列、数组的操作代价

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **顺序表按下标访问** | $O(1)$ | 已知元素位置，直接按地址计算；不等于按值查找。 |
| **顺序表按值查找** | $O(n)$ | 无序、顺序查找；有序顺序表可用折半查找（$O(\log n)$）。 |
| **顺序表插入移动** | $n-i+1$ 个（在第 $i$ 位插入） | $n$ 个元素，位置取 $1\ldots n+1$；若各位置等概率，平均 $n/2$ 个。 |
| **顺序表删除移动** | $n-i$ 个（删第 $i$ 位） | $i=1\ldots n$ 等概率时，平均 $(n-1)/2$ 个。 |
| **单链表按序号访问** | $O(n)$ | 通常需从头遍历；若已有目标位置前驱指针，插入/删除的局部改链为 $O(1)$。 |
| **栈 / 队列基本操作** | $O(1)$ | 在给定栈顶、队头、队尾指针的标准实现下成立；队列扩容可能有额外代价。 |
| **牺牲一个单元的循环队列** | $\mathrm{size}=(rear-front+m)\bmod m$ | 数组长度 $m$；$\mathrm{full}\iff(rear+1)\bmod m=front$，可用容量 $m-1$。 |
| **顺序存储二维数组** | $\mathrm{addr}(i,j)=base+(i\cdot N+j)w$ | 0 起始下标、行优先、每行 $N$ 列，单元素 $w$ 字节。列优先公式不同。 |
| **对称矩阵压缩** | $n(n+1)/2$ 个元素 | 只存上（或下）三角含对角线；注意两部分访问时的地址映射。 |
| **三角矩阵压缩** | $n(n+1)/2+1$ 个存储单元 | 若把另一三角区的相同常数另存 1 个单元；题设若不另存，则不加 1。 |

### 树、图与路径相关指标

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **二叉树深度/高度** | $h$ | 按**层数**计：非空满二叉树 $n=2^h-1$；有 $n$ 个结点的二叉树最小高度 $\lceil\log_2(n+1)\rceil$。 |
| **路径长度** | $PL=\sum_i d_i$ | $d_i$ 为根到各有关结点的边数；是“长度”而非“深度层号”。 |
| **哈夫曼带权路径长度** | $WPL=\sum_i w_i d_i$ | 只对**叶结点**的权重求和；哈夫曼树使给定叶权值下的 WPL 最小。 |
| **编码平均码长** | $\bar L=\sum_i p_i\ell_i$ | 符号概率 $p_i$，编码长度 $\ell_i$，单位 bit/符号；等于概率归一化的带权路径长度。 |
| **图密度（无向简单图）** | $D=\frac{2E}{V(V-1)}$ | $V$ 个顶点、$E$ 条边；有向简单图无自环：$D=\frac{E}{V(V-1)}$。补充直观指标。 |
| **邻接矩阵空间** | $O(V^2)$ | 建矩阵后判定任意两点是否相邻为 $O(1)$；遍历某顶点所有邻居为 $O(V)$。 |
| **邻接表空间** | $O(V+E)$ | 无向图每条边常存两份邻接关系；遍历顶点所有邻居为 $O(\deg(v))$。 |
| **BFS / DFS** | 邻接表 $O(V+E)$； 邻接矩阵 $O(V^2)$ | 一般以**遍历完整图**为对象；BFS 队列、DFS 栈/递归均可能占 $O(V)$。 |
| **最小生成树权值** | $W(T)=\sum_{e\in T}w(e)$ | 连通无向带权图，生成树 $V-1$ 条边；目标是权值总和最小。 |
| **Prim 朴素实现** | $O(V^2)$ | 邻接矩阵 + 顺序选最小代价；适合稠密图。堆优化可能有不同复杂度。 |
| **Kruskal 排序 + 并查集** | $O(E\log E)$ | 边排序通常主导；并查集近乎常数均摊。 |
| **Dijkstra 朴素实现** | $O(V^2)$ | 适用于**非负边权**的最短路；带堆可达 $O((V+E)\log V)$（常用实现）。 |
| **Floyd 多源最短路** | 时间 $O(V^3)$，空间 $O(V^2)$ | 可处理负边，但不能有使最短路无定义的可达负权环。 |
| **关键路径 / 工期** | $T_{\mathrm{proj}}=ve(\mathrm{end})$ | AOE 网，从起点到终点的**最长**路径决定最早完工时刻。 |
| **活动时间余量** | $\mathrm{slack}=l(e)-e(e)$ | $e(e)=ve(u)$，$l(e)=vl(v)-w(u,v)$；余量为 0 的活动为关键活动。 |

### 查找效率：ASL、装填因子与树高

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **平均查找长度 ASL** | $ASL=\sum_i p_i c_i$ | $p_i$：查找事件概率；$c_i$：比较次数或探测次数。**必须交代成功/失败及计数口径**。 |
| **无序顺序查找成功** | $ASL_s=(n+1)/2$ | $n$ 个关键字等概率、逐个比较的普通顺序表。 |
| **无序顺序查找失败** | $ASL_f=n$ | 失败需检查全部 $n$ 个关键字；若把“与哨兵比较”计入，则题设可能给其他数。 |
| **折半查找成功** | $O(\log_2 n)$ | 有序顺序表；具体 ASL 由判定树各层结点数算，不宜一概写 $\log_2 n$。 |
| **折半最坏比较次数** | $\lfloor\log_2 n\rfloor+1$（成功） | 在通常每次与中间关键字比较一次的口径下；失败路径长度依具体划分。 |
| **BST 查找** | $O(h)$ | 二叉排序树高度 $h$ 决定查找代价；极端退化为 $O(n)$。 |
| **AVL 树操作** | $O(\log n)$ | 平衡保证树高为对数阶；红黑树查找/插入/删除也为 $O(\log n)$。 |
| **B 树查找** | $O(\log_m n)$ 层级量级 | 阶数 $m$、结点内可有多个键；磁盘 I/O 次数主要与**访问结点层数**有关。 |
| **散列表装填因子** | $\alpha=n/m$ | $n$：已插入元素数，$m$：哈希地址槽数；拉链法可有 $\alpha>1$，开放定址通常要求 $\alpha<1$。 |
| **线性探测近似 ASL** | $ASL_s\approx\frac{1}{2}(1+\frac1{1-\alpha})$； $ASL_f\approx\frac{1}{2}(1+\frac1{(1-\alpha)^2})$ | 经典均匀散列假设下**线性探测**的近似分析。考试给定实际表时，以逐个模拟探测次数为准。 |
| **拉链法近似 ASL** | $ASL_s\approx1+\alpha/2$； $ASL_f\approx\alpha$ | 成功式常按均匀散列及链表头插、均匀选取已有关键字推导；失败式按**只数链上键比较**。计数口径不同需调整。 |
| **查找成功率** | $\frac{\text{成功次数}}{\text{查找总次数}}$ | 工程统计量；**不等同**于成功查找的 ASL。 |

> [!warning] 易错提醒
>
> **ASL 常见陷阱：**“成功 ASL”和“失败 ASL”必须分开算。等概率时才可直接平均各位置比较次数；散列表查找失败不是简单“关键字个数 $n$”；题目有空地址、同义词冲突时按探测序列逐个计数。


### 模式匹配、分块查找与常用算法复杂度

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **朴素串模式匹配** | 最坏时间 $O(nm)$ | 主串长 $n$、模式串长 $m$；每次失配可能让模式串从头比较。额外空间通常 $O(1)$。 |
| **KMP 模式匹配** | 预处理 $O(m)$，匹配 $O(n)$ | 总时间 $O(n+m)$、next / 前缀函数空间 $O(m)$；匹配中主串指针不回退。 |
| **分块查找：顺序索引** | $ASL\approx\frac{1}{2}(\frac{n}{b}+1)+\frac{1}{2}(b+1)$ | $n$ 个关键字，$b$ 个/块，假设索引和块内都顺序查找、等概率且块等长；忽略边界，最佳 $b$ 量级为 $\sqrt n$。 |
| **分块查找：折半索引** | $O(\log(n/b)+b)$ | 索引表有序且随机存取，块内无序线性扫描；对更具体的 ASL 应依索引判定树计算。 |
| **二叉树遍历** | $O(n)$ | 访问每个结点一次；递归附加栈一般为 $O(h)$，其中 $h$ 为树高。 |
| **堆插入 / 删堆顶** | $O(\log n)$ | 每次向上或向下调整堆，最多经过树高量级的层数。 |
| **自底向上建堆** | $O(n)$ | 把整个数组原地建堆与“逐个插入建堆”不是同一过程；建堆不能一概算 $O(n\log n)$。 |
| **哈夫曼树构造** | $O(n\log n)$（用最小堆） | $n$ 个权重，反复取两最小并合并；若朴素每轮遍历找最小，复杂度可能变为 $O(n^2)$。 |
| **并查集** | 合并 + 路径压缩：均摊近常数 | 用于连通性与 Kruskal 算法；若不做按秩合并/路径压缩等优化，单次操作可退化。 |
| **拓扑排序** | 邻接表 $O(V+E)$ | 用入度数组和队列或 DFS；含环的有向图无法得到包含所有顶点的拓扑序列。 |
| **AOE 最早/最迟时刻** | 邻接表 $O(V+E)$ | 已有拓扑序列时可分别沿正向/逆向推进；**关键路径**指持续时间最长的起点到终点路径。 |
| **无权图单源最短路** | BFS：$O(V+E)$ | 按边数定义距离，无权或每边权相同的图中 BFS 可求最短路径。 |

### 排序：时间、空间、稳定性与趟数

**排序算法对照（Mac 端横向速查表）**

| 排序算法 | 最好 | 平均 | 最坏 | 辅助空间 | 稳定性 |
|:---|:---|:---|:---|:---|:---:|
| 直接插入 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 |
| 折半插入 | $O(n\log n)$ 比较 | $O(n^2)$ 移动 | $O(n^2)$ 移动 | $O(1)$ | 稳定 |
| 冒泡 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 |
| 简单选择 | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 不稳定 |
| 希尔 | 依增量序列 | 依增量序列 | 依增量序列 | $O(1)$ | 不稳定 |
| 快速 | $O(n\log n)$ | $O(n\log n)$ | $O(n^2)$ | 递归平均 $O(\log n)$ | 不稳定 |
| 堆排序 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(1)$ | 不稳定 |
| 二路归并 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(n)$ | 稳定 |
| 基数（LSD） | $O(d(n+r))$ | $O(d(n+r))$ | $O(d(n+r))$ | $O(n+r)$ | 稳定 |

> [!tip] 核心结论
>
> **排序表说明：**冒泡排序“最好 $O(n)$”针对某一趟无交换就提前结束的优化版；未优化版最好也可能是 $O(n^2)$。LSD 基数排序需每一趟都使用**稳定分配/收集**才能保证整体稳定，其中 $d$ 为位数、$r$ 为基数。


| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **比较排序下界** | $\Omega(n\log_2 n)$ | 基于比较的排序在最坏情况下至少需要对数阶决策树深度；不能据此否定计数/基数等非比较排序。 |
| **直接插入移动次数** | 逆序输入可达 $\Theta(n^2)$ | 近乎有序时较快；区分“关键字比较”和“记录移动”。 |
| **快速排序递归深度** | 平均 $O(\log n)$，最坏 $O(n)$ | 取决于每次划分是否均衡；枢轴选择影响最坏情形出现概率，不改经典最坏阶。 |
| **归并排序趟数** | $\lceil\log_2 n\rceil$ | 从长度 1 有序段两两归并的常见自底向上做法。 |
| **外部排序初始归并段数** | $r_0=\lceil N/M\rceil$ | $N$ 个**磁盘块**的数据，内存可一次容纳 $M$ 块，采用普通内部排序生成初始段；置换选择可变长。 |
| **多路归并趟数** | $p=\lceil\log_k r_0\rceil$ | 每趟最多将 $k$ 个段合为 1 段，且存在足够输入/输出缓冲区。 |
| **外部排序块 I/O** | $Q\approx2N(1+p)$ | **含初始段生成**：读 $N$ 写 $N$；每次归并也读 $N$ 写 $N$。忽略缓冲、特殊输出和磁盘寻道。 |

> [!example] 算例演示
>
> **例题｜外部归并为何不能只算“归并趟数”**
>
> 数据占 $N=1200$ 块，内存可同时放 $M=100$ 块，采用 4 路归并。初始段 $r_0=\lceil1200/100\rceil=12$ 个；归并 $p=\lceil\log_4 12\rceil=2$ 趟；如果把初始段生成算入，则理论块 I/O 约为 $2\times1200\times(1+2)=7200$ 次。**题目若只问“归并阶段” I/O，则是 $2Np=4800$ 次。**

### 数据结构补遗 · 查漏补缺

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **二叉树边数与度关系** | 非空树 $e=n-1$；非空二叉树 $n_0=n_2+1$。 | $n_0$ 表示度为 0 的结点数，$n_2$ 表示度为 2 的结点数；不是所有结点度都固定为 2。 |
| **满二叉树 / 完全二叉树结点上限** | 高度为 $h$（根为第 1 层），结点数最多 $2^h-1$；含 $n$ 个结点的最小高度为 $\lceil\log_2(n+1)\rceil$。 | 高度有「层数」与「边数」两种定义；本册按层数。 |
| **有序顺序表等概率成功 ASL** | 若仍按顺序比较，则 $ASL_s=(n+1)/2$；若采用折半查找，应画判定树后按各层结点数加权。 | **有序不代表自动使用折半查找**；算法给什么就算什么。 |
| **折半查找判定树成功 ASL** | $ASL_s=\dfrac{\sum_{d=1}^{h}d\,n_d}{n}$。 | $n_d$ 为在第 $d$ 次关键字比较处查中的关键字数；假定每个关键字被查找到的概率相同。 |
| **$m$ 阶 B 树关键字上下限** | 非根结点：$\lceil m/2\rceil-1\le k\le m-1$；若根非叶，则 $1\le k\le m-1$。 | 「阶」指最大孩子数，关键字数 $=$ 孩子数减 1（非叶结点）；不同教材对 B 树结点定义可能不同，以题设为准。 |
| **$m$ 阶 B 树高度与键数（选学）** | 根算第 1 层、高 $h$ 时，$n_{\min}(h)=2\lceil m/2\rceil^{h-1}-1$，$n_{\max}(h)=m^h-1$（$h\ge 2$）。 | 上下界为标准 B 树、非空、内结点满足最小孩子数约束下的理论值；$h=1$ 时单个根有 $1\sim m-1$ 个键。实际磁盘 I/O 与驻留缓存状态有关。 |
| **基数排序与比较排序的下界** | 基于比较排序最坏至少 $\Omega(n\log n)$ 次比较；LSD 基数排序的时间 $O(d(n+r))$。 | 基数排序不是纯比较排序，不违反比较排序下界。 |
| **逆序对与交换次数** | 只使用**相邻元素交换**把序列排成有序，每次交换一对逆序元素，最少交换次数等于初始**逆序对数**。 | 不能推广为「任意位置交换」的最少次数；可用归并计数 $O(n\log n)$。 |
| **外部排序败者树（扩展）** | $k$ 路归并中，采用败者树选择下一记录通常约需 $O(\log k)$ 次关键字比较。 | 降低的是选取代价，并不凭空减少必须读写的数据盘块数；增加归并路数仍受内存缓冲限制。 |

### 整机性能：时间、CPI、MIPS、FLOPS

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **吞吐量（Throughput）** | $Q=\text{完成任务数}/\text{总时间}$ | 单位：任务/s 或其他；反映单位时间处理**多少**任务。注意与单任务响应时间不同。 |
| **响应时间（Response Time）** | $T_{\mathrm{resp}}=t_{\mathrm{完成}}-t_{\mathrm{提交}}$ | 一个任务从提交到完成的总经历时间；包含执行和各种等待。 |
| **CPU 时钟周期** | $T_{\mathrm{clk}}=1/f$ | $f$ 为主频；例如 2 GHz 的周期为 0.5 ns。 |
| **CPU 时钟周期数** | $N_{\mathrm{cycle}}=\sum_i IC_i\cdot CPI_i$ | 执行特定程序消耗的总 CPU 周期；指令计数与每类指令 CPI 按类别求和。 |
| **平均 CPI** | $CPI=\frac{\sum_i IC_iCPI_i}{\sum_i IC_i}$ | **按动态指令条数加权**；不能直接对不同指令类的 CPI 求普通平均。 |
| **CPU 执行时间** | $T_{\mathrm{CPU}}=\frac{IC\cdot CPI}{f}$ | 等价于总 CPU 周期数 $\times T_{\mathrm{clk}}$；不包含题目明确排除的 I/O 等其他耗时。 |
| **IPC（每周期指令数）** | $IPC=IC/N_{\mathrm{cycle}}$ | 同一统计区间平均有 $IPC=1/CPI$（若 CPI 非零）；IPC 可高于 1（多发射）。 |
| **MIPS** | $MIPS=\frac{IC}{10^6 T_{\mathrm{CPU}}}=\frac{f}{10^6\cdot CPI}$ | 每秒**百万条指令**；只对“指令集、指令复杂度相近”的系统做粗略比较，不能直接等同程序快慢。 |
| **FLOPS** | $FLOPS=\frac{N_{\mathrm{FP\ ops}}}{T}$ | 每秒浮点运算次数（不是“浮点指令条数”）；必须注明统计精度、运算计数规则。 |
| **MFLOPS / GFLOPS** | $10^6/10^9\ \mathrm{FLOP/s}$ | M = mega，G = giga，均为十进制数量级。 |
| **TFLOPS / PFLOPS** | $10^{12}/10^{15}\ \mathrm{FLOP/s}$ | T = tera，P = peta。 |
| **EFLOPS / ZFLOPS** | $10^{18}/10^{21}\ \mathrm{FLOP/s}$ | E = exa，Z = zetta；不要误用计算机容量的二进制前缀。 |
| **加速比** | $S=T_{\mathrm{old}}/T_{\mathrm{new}}$ | 同一工作负载的用时比较；新旧系统的**CPU 时间**和**总完成时间**不能混算。 |
| **性能比** | $P_A/P_B=T_B/T_A$ | 在工作量相同且性能取“任务/时间”时，$A$ 性能是 $B$ 的几倍。 |
| **Amdahl 定律** | $S=\frac{1}{(1-p)+p/s}$ | 原运行时间中可优化占比 $p$，该部分提速 $s$ 倍；不可优化部分产生性能上限。 |
| **多类工作加速** | $S=\frac{1}{\sum_i p_i/s_i}$ | $\sum_i p_i=1$，$p_i$ 是**优化前时间占比**；把不优化部分的 $s_i$ 设为 1。 |
| **功耗 / 能耗（扩展）** | $E=P\cdot T$ | 功率 W、能量 J；仅在题目给电学或能效数据时使用，不列为 408 核心性能公式。 |

> [!example] 算例演示
>
> **例题｜CPU 时间、MIPS 和“主频越高越快”的误区**
>
> 程序执行动态指令数 $IC=10^9$，平均 $CPI=1.8$，主频 $f=3\,\mathrm{GHz}$。
>
> $N_{\mathrm{cycle}}=1.8\times10^9$；$T_{\mathrm{CPU}}=1.8\times10^9/(3\times10^9)=0.6\,\mathrm{s}$；$MIPS=3\times10^9/(1.8\times10^6)\approx1666.7$。
>
> 如果某种优化使主频提升 20%，但平均 CPI 上升 50%，那么新旧时间比 $T_{\mathrm{new}}/T_{\mathrm{old}}=1.5/1.2=1.25$；**主频虽然增加，程序反而慢 25%。**


### 容量、地址与半导体存储器

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **存储容量** | $C=\text{存储单元数}\times\text{单元位数}$ | 一般用 bit、B、KiB；如 $64\mathrm{K}\times8$ 位芯片容量 $=64\,\mathrm{KiB}$。 |
| **地址空间大小** | $2^a$ 个可编址单元 | 地址 $a$ 位；若按字节编址，容量 $2^a$ B；若按字编址，还要乘每字节数。 |
| **地址线 / 数据线** | $a=\log_2\!\text{单元数}$； $w=\text{每单元数据位数}$ | 典型存储芯片 $2^a\times w$ bit；总线数据宽度与地址线条数不是同一个指标。 |
| **位扩展片数** | $k_w=W_{\mathrm{target}}/W_{\mathrm{chip}}$ | 单片数据位宽不足时并联；位宽整倍数时直接计算。 |
| **字扩展片数** | $k_d=D_{\mathrm{target}}/D_{\mathrm{chip}}$ | 存储深度不足时按地址段扩展；总片数为字扩展片数 $\times$ 位扩展片数。 |
| **数据传输带宽** | $B=\frac{w}{8}\cdot r$ | $w$ 为每次传输的 bit 数，$r$ 为每秒传输次数；如果 $r=f\times q$，则每时钟 $q$ 次传输。 |
| **存储器存取周期** | $T_{\mathrm{memcycle}}$ | 存储器可连续启动两次操作的最小间隔；可能**大于存取时间**。 |
| **存取时间** | $T_{\mathrm{access}}$ | 从发出访问请求到取到有效数据所需时间；不同器件读写时序不同。 |
| **多体交叉存储器** | $m\ge \lceil T_{\mathrm{memcycle}}/t\rceil$ | $m$ 个模块、同一模块连续可接受请求间隔 $T_{\mathrm{memcycle}}$、访问启动间隔 $t$；无冲突连续流水访问的**必要配置量级**。 |
| **DRAM 刷新间隔** | $T_{\mathrm{row}}=T_{\mathrm{refresh}}/N_{\mathrm{row}}$ | 集中、分散、异步刷新方案时序不同；在“异步逐行平均分布”条件下理解为每行刷新计划间隔。 |
| **主存访问次数** | $\text{实际主存访问次数}$ | 读写数据、查页表、Cache 未命中等需分清；**CPU 发出访存请求数**并不一定等于主存物理访问次数。 |

### Cache：命中、缺失与平均访问时间

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **Cache 命中率** | $h=N_{\mathrm{hit}}/N_{\mathrm{access}}$ | 命中次数 / 访问次数；缺失率 $m=1-h$。 |
| **Cache 缺失率** | $m=N_{\mathrm{miss}}/N_{\mathrm{access}}$ | 缺失可能源于冷启动、容量不足、冲突等；随机替换和具体访问序列需模拟。 |
| **AMAT：标准写法** | $AMAT=T_{\mathrm{hit}}+mP_{\mathrm{miss}}$ | $P_{\mathrm{miss}}$ 是**未命中额外代价**（从下层取回等）；每次请求先花一次命中判断时间。 |
| **未命中总时间口径** | $T_{\mathrm{avg}}=hT_{\mathrm{hit}}+mT_{\mathrm{miss,total}}$ | $T_{\mathrm{miss,total}}$ 已含查 Cache 和下层访问全程；切忌把两种口径混用。 |
| **Cache 平均访问速率** | $R=\text{传输数据量}/T_{\mathrm{avg}}$ | 只在“每次访问传输数据量固定、且以平均访问时间为统计基础”时可这样换算。 |
| **Cache 块数** | $N_{\mathrm{lines}}=C_{\mathrm{data}}/B_{\mathrm{block}}$ | 总数据容量 $C_{\mathrm{data}}$、块大小 $B_{\mathrm{block}}$；标签、有效位等**不包含在数据容量内**。 |
| **组数** | $N_{\mathrm{sets}}=N_{\mathrm{lines}}/A$ | $A$ 路组相联；块大小、总行数和相联路数给定时求组数。 |
| **地址字段位数** | 块内位 $b=\log_2 B$； 组号位 $s=\log_2 N_{\mathrm{sets}}$ | 按字节编址、2 的幂；tag 位 $t=a-b-s$。全相联无组号位；直接映射 $A=1$。 |
| **Cache 存储开销** | $C_{\mathrm{physical}}=C_{\mathrm{data}}+C_{\mathrm{tags}}+\cdots$ | 物理实现需考虑 tag、有效位、脏位、替换状态等；**精确位数由题设字段决定**。 |
| **访存停顿 CPI** | $CPI_{\mathrm{real}}=CPI_{\mathrm{base}}+\mathrm{stall/cmd}$ | $\mathrm{stall/cmd}$ 按每条指令平均访存次数 $\times$ 缺失率 $\times$ 未命中停顿周期估算；需区分取指与数据访存。 |
| **总缺失次数** | $N_{\mathrm{miss}}=N_{\mathrm{access}}m$ | 若给“每千条指令未命中次数 MPKI”，则 $MPKI=1000N_{\mathrm{miss}}/IC$。**MPKI 为补充术语。** |

> [!warning] 易错提醒
>
> **两种平均访问时间：**$h=0.95$、命中判断 2 ns、额外未命中代价 80 ns，则 $AMAT=2+0.05\times80=6$ ns；若“未命中总时间”是 80 ns，则加权平均为 $0.95\times2+0.05\times80=5.9$ ns。**同一组数字，口径不同，结果不同。**


### TLB、页表与磁盘 / SSD 性能

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **TLB 命中率** | $h_T=N_{\mathrm{TLBhit}}/N_{\mathrm{VA}}$ | 以虚拟地址转换访问次数为分母；不等同 Cache 命中率。 |
| **TLB 有效访问时间** | $EAT=h_Tt_H+(1-h_T)t_M$ | $t_H$：TLB 命中路径总时间；$t_M$：TLB 未命中但**不缺页**的页表查询+数据访问总时间。 |
| **单级页表简化** | $t_H=t_{\mathrm{TLB}}+t_{\mathrm{mem}}$； $t_M=t_{\mathrm{TLB}}+2t_{\mathrm{mem}}$ | 假设页表项在内存、不在 Cache、TLB 并行性忽略、同一访存时间；多级页表不能照抄“2 次”。 |
| **多级页表访存次数** | 未命中 TLB：$k+1$ 次内存访问 | $k$ 级页表逐级取表项再访问数据（不计 Cache、页故障）；TLB 查找本身另计。 |
| **磁盘平均访问时间** | $T=T_{\mathrm{seek}}+T_{\mathrm{rot}}+T_{\mathrm{xfer}}+T_{\mathrm{overhead}}$ | 平均寻道、旋转等待、传输以及可能的控制器开销，具体题目可能忽略最后一项。 |
| **平均旋转等待** | $T_{\mathrm{rot}}=1/(2r)$ | 磁盘每秒 $r$ 转，随机到达、旋转位置均匀时平均等**半圈**。 |
| **单圈时间** | $T_{\mathrm{rev}}=60/R_{\mathrm{rpm}}$ | $R_{\mathrm{rpm}}$ 单位为转/分；旋转延迟平均为 $T_{\mathrm{rev}}/2$。 |
| **磁盘传输时间** | $T_{\mathrm{xfer}}=D/R_{\mathrm{seq}}$ | 连续传输 $D$ 字节、顺序速率 $R_{\mathrm{seq}}$ 字节/s；也可按一圈可传数据与转速换算。 |
| **磁盘顺序数据率** | $R_{\mathrm{seq}}=r\cdot C_{\mathrm{track}}$ | $C_{\mathrm{track}}$：单磁道可读数据量；忽略磁道切换和开销的理想情形。 |
| **IOPS（扩展）** | $IOPS\approx1/T_{\mathrm{request}}$ | 串行、无排队、同质独立请求时可近似；并发设备 IOPS 不是简单求单请求延迟倒数。 |
| **SSD 访问时间** | $T\approx T_{\mathrm{ctrl}}+T_{\mathrm{flash}}+T_{\mathrm{transfer}}$ | SSD 无磁头寻道与旋转等待；页读、块擦除、写放大、垃圾回收影响真实性能。 |
| **Flash 写放大（扩展）** | $WA=\text{实际闪存写入量}/\text{主机写入量}$ | $WA>1$ 表示额外内部搬移，SSD 并非“没有额外内部开销”。 |

> [!example] 算例演示
>
> **例题｜TLB 命中路径和未命中路径分别有几次访存？**
>
> 单级页表、无缺页、无 Cache，TLB 查询 1 ns，内存访问 100 ns，TLB 命中率 90%。
>
> 命中路径：$1+100=101$ ns；未命中路径：$1+100+100=201$ ns；$EAT=0.9\times101+0.1\times201=111$ ns。**TLB 命中免去的是查页表的内存访问，不是免去读取数据本身。**


### 指令流水线、并行执行与加速

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **流水线时钟周期** | $t=\max\{t_1,\ldots,t_k\}+t_{\mathrm{reg}}$ | 各段执行时延与流水寄存器开销；**最慢段**限制吞吐节拍。 |
| **理想流水线总时间** | $T_{\mathrm{pipe}}=(k+n-1)t$ | $k$ 段、$n$ 条指令、各段每拍可推进、无停顿；先装满，再每拍完成一条。 |
| **非流水线总时间** | $T_{\mathrm{serial}}=n\sum_{i=1}^{k}t_i$ | 逐条顺序执行，每条经过全部阶段；与流水线比较时要保持工况一致。 |
| **理想等长阶段加速比** | $S=\frac{nkt}{(k+n-1)t}=\frac{nk}{k+n-1}$ | 分段时间均为 $t$、忽略寄存器开销且无停顿；$n\to\infty$ 时接近 $k$。 |
| **流水线吞吐率** | $Q=n/T_{\mathrm{pipe}}$ | 理想稳态 $Q_{\max}=1/t$ 条指令/s；有气泡时要用真实完成数除真实时间。 |
| **流水线效率** | $\eta=\frac{\text{工作阶段格数}}{\text{总阶段格数}}$ | 理想等长 $k$ 段处理 $n$ 条时 $\eta=\frac{n}{k+n-1}$。 |
| **流水线 CPI** | $CPI=\frac{\text{总执行周期}}{IC}$ | 理想单发射稳态 $CPI\to1$；$n$ 条启动/排空时 $CPI=(k+n-1)/n$。 |
| **气泡/停顿影响** | $T=(k+n-1+s)t$ | $s$ 是总**额外停顿周期**；对应总 CPI $=(k+n-1+s)/n$。 |
| **超标量发射宽度** | $IPC_{\mathrm{ideal}}\le w$ | $w$ 路发射，理想稳态 $CPI\ge 1/w$，真实运行受相关、功能部件与分支等限制。 |
| **多核加速上限** | $S=1/[(1-p)+p/k]$ | $k$ 核，仅占比 $p$ 的部分理想均分并行；其他通信同步开销未计。 |
| **利用率 vs 效率** | $\eta\in[0,1]$ | 硬件**某阶段忙碌率**不一定等于整条流水线的空间-时间效率，需根据题目定义。 |

> [!example] 算例演示
>
> **例题｜100 条指令经过 5 级流水线**
>
> 假设 5 段等长，每段 2 ns，无冲突、无额外开销。
>
> 流水时间：$T_{\mathrm{pipe}}=(5+100-1)\times2=208$ ns；串行时间：$100\times5\times2=1000$ ns；加速比：$1000/208\approx4.81$；效率：$100/(100+5-1)\approx96.15%$。
>
> **注意：**加速比不等于 5（装入、排空开销存在）；流水线也不使**单条指令**的每个阶段本身变短。


### 总线、I/O、DMA：带宽和时间

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **总线时钟周期** | $T_{\mathrm{busclk}}=1/f_{\mathrm{bus}}$ | 与总线周期不是同义词；一次数据传输可能占多个总线时钟周期。 |
| **总线周期** | $T_{\mathrm{cycle}}=q\,T_{\mathrm{busclk}}$（同步简化） | 总线完成一次**事务**所需时间；$q$ 取决于地址、数据与握手阶段。 |
| **总线峰值带宽** | $B_{\mathrm{peak}}=\frac{w}{8}\cdot f\cdot n_t$ | 数据通路宽 $w$ bit，每时钟传 $n_t$ 次，单位 B/s；不算空转及协议开销。 |
| **总线有效带宽** | $B_{\mathrm{eff}}=\frac{\text{有效负载字节}}{\text{总时间}}$ | 有效带宽 $\le B_{\mathrm{peak}}$；总线被仲裁、地址、等待和刷新等占用会降低它。 |
| **总线带宽利用率** | $\eta_B=B_{\mathrm{eff}}/B_{\mathrm{peak}}$ | 若“有效负载”范围不同（含不含首部），计算结果会不同。 |
| **突发传输时间** | $T=T_{\mathrm{setup}}+n\,T_{\mathrm{beat}}$ | 初始化/寻址之后连续传 $n$ 个节拍；具体总线协议可能需考虑首拍与握手。 |
| **程序查询 I/O 的 CPU 占用** | $U_{\mathrm{CPU}}\approx T_{\mathrm{busywait}}/T_{\mathrm{total}}$ | CPU 等待设备就绪时可能空转；中断方式减轻忙等，不等于中断开销为零。 |
| **DMA 传输** | $T_{\mathrm{DMA}}\approx T_{\mathrm{setup}}+D/R+T_{\mathrm{finish}}$ | DMA 传输可减少 CPU**逐字节参与**，但仍使用系统数据通路/总线资源；该式为抽象模型。 |
| **中断处理开销** | $T_{\mathrm{interrupt}}=T_{\mathrm{save}}+T_{\mathrm{ISR}}+T_{\mathrm{restore}}$ | 总耗时随中断次数和每次处理成本增大；不应直接当作设备的真实服务时间。 |
| **设备吞吐量** | $Q=\text{完成 I/O 请求数}/T$ | 单位请求/s；若每请求大小不同，则不能直接等价于 B/s。 |

> [!warning] 易错提醒
>
> **几组容易串台的指标：**CPU 主频 $\ne$ 总线时钟；存储器**存取时间** $\ne$ **存取周期**；一个**总线时钟周期** $\ne$ 一个**总线事务周期**；磁盘的**寻道时间** $\ne$ **旋转时间**；总线**峰值带宽** $\ne$ **有效吞吐量**。

### 计算机组成原理补遗 · 查漏补缺

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **磁盘原始容量（机械盘）** | $C=\text{盘片的有效记录面数}\times\text{每面磁道数}\times\text{每磁道扇区数}\times\text{每扇区字节数}$。 | 等磁道容量的简化模型；真实磁盘可采用分区位记录，内外圈每轨扇区数不相同；是否计保留区、文件系统开销看题意。 |
| **磁盘顺序数据率（已知扇区）** | $R=\text{每磁道扇区数}\times\text{每扇区字节数}\times\text{每秒转数}$。 | 持续读同一磁道的理想速率；跨磁道/柱面可能有额外时间。 |
| **访存停顿导致的有效 CPI** | $CPI_{\mathrm{eff}}=CPI_{\mathrm{base}}+(\text{每条指令平均访问次数})\times(\text{缺失率})\times(\text{每次额外停顿周期})$。 | 只有在访问次数和停顿代价都按**每条指令**口径，且不会被重叠隐藏时才能相加；取指和读写数据常要分开算。 |
| **分支预测失败造成的 CPI 损失** | $\Delta CPI=f_b\,p_m\,c_p$。 | 分支频率 $f_b$ 按「分支指令/总指令」，预测失误率 $p_m$ 按「失误/分支」，每次错误的**额外**代价 $c_p$（周期）。和基础 CPI 加总前先看是否重叠。 |
| **低位交叉存储器理想启动间隔** | 若每模块存取周期 $T_m$，连续访存启动间隔 $\delta$，为避免轮转回原模块时仍未就绪，通常需要 $m\delta\ge T_m$。 | 理想轮转连续地址、无总线争用；因此 $m\ge\lceil T_m/\delta\rceil$ 是容量配比/节拍条件，不表示真实带宽必然达到峰值。 |
| **有效存储带宽** | $B_{\mathrm{eff}}=\dfrac{\text{有效读取/写入字节}}{\text{含等待和仲裁的总时间}}$。 | 不可拿 CPU 时钟频率直接替换总线实际传输次数；DDR 的「双沿传输」是每时钟两个数据节拍的条件之一。 |
| **数据对齐产生的访问次数（定性）** | 若一个数据跨越总线/Cache 块/页边界，实际所需访问次数可能大于对齐访问。 | 具体增加几次由字长、总线与体系结构决定，不能一律写「非对齐 = 2 次访存」。 |

### 进程调度：周转、等待、响应和吞吐

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **完成时间** | $C_i$ | 作业/进程$i$ 完成的绝对时刻；应和到达时刻在同一时间轴。 |
| **到达时间** | $A_i$ | 作业进入就绪系统/就绪队列的时刻（按题目约定）；不是首次获得 CPU 时刻。 |
| **服务时间** | $B_i$ | 题设规定的 CPU 运行时间总需求；**有 I/O 的进程**要明确是否只统计 CPU 段。 |
| **周转时间** | $T_i=C_i-A_i$ | 从到达到完成的全过程时长，包含运行和等待等。 |
| **平均周转时间** | $\overline T=\frac{1}{n}\sum_{i=1}^n T_i$ | 每个进程按相同权重算术平均，除非题设另有权重。 |
| **带权周转时间** | $W_i=T_i/B_i$ | 周转 / 服务时长；无量纲，$B_i>0$。服务时间短的任务对等待更敏感。 |
| **平均带权周转** | $\overline W=\frac{1}{n}\sum_i(T_i/B_i)$ | 必须**先每个作业相除，再平均**；一般不等于总周转时间 / 总服务时间。 |
| **就绪队列等待时间** | $T_{\mathrm{ready}}=\sum_j t_{\mathrm{wait,j}}$ | 只算等 CPU 的时间；**不包含阻塞等待 I/O**。若系统仅有 CPU 运行与就绪等待，$T_{\mathrm{ready}}=T_i-B_i$。 |
| **响应时间（调度）** | $R_i=S_i-A_i$ | $S_i$：**首次**获得 CPU 的时刻。抢占后再次执行的时间不参与响应时间。 |
| **CPU 利用率** | $U=\frac{\text{CPU 忙碌时间}}{\text{观察总时间}}$ | 题目可能要求“执行有效程序的比例”，需明确是否把上下文切换算作有效忙碌。 |
| **系统吞吐量** | $Q=N_{\mathrm{completed}}/T$ | 单位时间完成作业/进程数；需给观察区间。吞吐量高不代表每个作业响应快。 |
| **上下文切换开销** | $T_{\mathrm{over}}=N_{\mathrm{switch}}t_{\mathrm{switch}}$ | 每次切换耗时固定的**简化模型**；切换不负责执行用户有效工作。 |
| **时间片占比** | $\eta\approx q/(q+s)$ | 若每运行 $q$ 时间单位后都有额外 $s$ 切换开销；实际可能有提前阻塞/完成。 |
| **CPU 繁忙度与响应** | 可同时存在高 $U$、高 $R_i$ | CPU 利用率高并不保证用户体验好；优先级策略可能导致饥饿。 |
| **多核加速比（OS）** | $S=T_{1\rm core}/T_{k\rm core}$ | 与 CPU Amdahl 一致，但实际会受到互斥、共享资源和调度负载不均影响。 |

> [!example] 算例演示
>
> **例题｜FCFS 调度的 4 种时间，一张表算清**
>
> 单 CPU、无 I/O，三个进程按先来先服务运行：$P_1:(A=0,B=5)$，$P_2:(A=1,B=3)$，$P_3:(A=2,B=1)$。执行区间依次是 $P_1:[0,5),\ P_2:[5,8),\ P_3:[8,9)$。
>
> | 进程  | 完成 $C$ | 周转 $T$ | 等待 $T-B$ | 响应 $S-A$ | 带权周转 $T/B$ |
> |:------|---------:|---------:|-----------:|-----------:|---------------:|
> | $P_1$ |        5 |        5 |          0 |          0 |           1.00 |
> | $P_2$ |        8 |        7 |          4 |          4 |           2.33 |
> | $P_3$ |        9 |        7 |          6 |          6 |           7.00 |
>
> 平均周转：$19/3\approx6.33$；平均等待：$10/3\approx3.33$；平均带权周转：$(1+7/3+7)/3\approx3.44$。**注意不同平均值的分母，特别是带权周转要逐项除以服务时间。**


### 内存：利用率、分页、页表与碎片

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **内存利用率** | $U_{\mathrm{mem}}=\frac{\text{被有效使用空间}}{\text{可用空间}}$ | “有效”可指已分配、有效载荷或物理页驻留；**题目必须界定分子口径**。 |
| **分页大小** | $P=2^p\,\mathrm{B}$ | 按字节编址，页内偏移字段 $p$ 位；页框大小与页面大小相同。 |
| **虚拟页数** | $N_v=V/P$（整齐划分） | 若给虚拟地址宽 $a$ 位：$N_v=2^{a-p}$；文件占用的实际页数则是 $\lceil F/P\rceil$。 |
| **物理页框数** | $N_f=M/P$ | $M$ 是可用于分页管理的物理内存大小；按页对齐且容量为整数倍。 |
| **页表大小** | $C_{\mathrm{PT}}=N_v\cdot s_{\mathrm{PTE}}$ | 单级线性页表、每虚拟页一个页表项；实际多级页表可按需分配，不能直接这样估总常驻页表空间。 |
| **每页页表项数** | $e=P/s_{\mathrm{PTE}}$ | 一页大小为 $P$，页表项 $s_{\mathrm{PTE}}$ 字节，通常整除。 |
| **多级页表覆盖范围** | 末级一页覆盖 $eP$ 字节 | 从末级开始，每增加一级可用的索引页表项数乘 $e$；有可能浪费部分地址位。 |
| **内部碎片** | $F_{\mathrm{int}}=\sum(\text{已分配容量}-\text{有效载荷})$ | 固定页框/固定分区的最后一页常产生碎片；若每个对象余数均匀，平均尾部碎片近似 $P/2$。 |
| **外部碎片** | 不连续空闲块的总量及分布 | 可用总空闲内存足够但无法满足大块**连续**分配。普通分页在页框层面避免外部碎片。 |
| **缺页率** | $p=N_{\mathrm{pagefault}}/N_{\mathrm{memref}}$ | 分母是所规定的内存访问数；真实缺页可能引发淘汰、写回和重启。 |
| **缺页平均有效访存** | $EAT=(1-p)t_0+p(t_0+P_f)=t_0+pP_f$ | $t_0$ 是正常访问的时间；$P_f$ 是**额外**缺页服务代价。如果给“缺页总耗时”，则用加权总时间。 |
| **工作集大小** | $W(t,\Delta)=\#\text{近}\Delta\text{次引用的不同页}$ | 按最近窗口的**不同页数**计；它不是进程可见虚拟页数，也不是物理内存大小。 |
| **驻留集大小** | $RSS=\text{进程当前驻留的物理页数}$ | 缺页率与驻留集相关，但**不应**假定固定函数关系；需给访问序列/置换算法。 |
| **抖动 / 颠簸** | 高缺页率、低有效工作吞吐 | 系统忙于换页而非完成有效计算；不是某个固定数值公式。 |

> [!warning] 易错提醒
>
> **重要：**请求分页与基本分页**都采用分页思想**；按页分配没有页框层面的外部碎片，但可能有内部碎片。段式动态分配会有外部碎片；段页式在页框分配层面也不产生外部碎片。若试题把内存中其他管理区、预留区一并统计，须遵循其定义。


### 虚拟内存：TLB / 缺页叠加计算

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **地址转换加权** | $E[t]=\sum_j p_jt_j$ | 先列出 TLB 命中、TLB 未命中、缺页等**互斥路径**及发生概率，再求总期望。 |
| **不缺页的平均访问** | $t_0=h_Tt_H+(1-h_T)t_M$ | 把**TLB 和页表访问**计算进“正常访存路径”，再考虑缺页率。 |
| **加上额外缺页代价** | $EAT=t_0+pP_f$ | 当 $P_f$ 是每次缺页额外耗时、且缺页处理结束后正常访问开销已正确计入时成立。 |
| **发生脏页写回时** | $P_f=\text{换出}+\text{换入}+\text{管理与重启}$ | 若淘汰页干净可无写回；若脏可能先写再读，均需依具体题设计数。 |
| **访存地址拆分** | $VA=(\text{页号},\text{页内偏移})$ | 页号 = $\lfloor VA/P\rfloor$；偏移 = $VA\bmod P$，只把“页号”交给查表。 |
| **页表访问次数** | 多级 $k$ 级：$k$ 次查表 + 1 次读数据 | **前提**是 TLB 未命中、每级页表项在内存、忽略 Cache，且未缺页。 |

> [!example] 算例演示
>
> **例题｜缺页率极低，为什么仍可能严重拖慢访存？**
>
> 正常有效访存时间 $t_0=100$ ns；缺页率 $p=10^{-4}$；每次缺页**额外**服务时间 8 ms。
>
> $EAT=100\,\mathrm{ns}+10^{-4}\times8\,\mathrm{ms}=100\,\mathrm{ns}+800\,\mathrm{ns}=900\,\mathrm{ns}$。
>
> 即使 10000 次访问只发生 1 次缺页，平均时间也上升为原来的 9 倍。**计量转换是这类题的第一难点。**


### 文件系统：盘块开销、索引容量与存储效率

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **文件数据块数** | $N_{\mathrm{data}}=\lceil F/B\rceil$ | 文件大小 $F$ 字节，盘块 $B$ 字节；**不含索引块**。 |
| **末块内部浪费** | $W=N_{\mathrm{data}}B-F$ | 若 $F$ 恰为块大小整数倍则为 0；只针对文件数据区，不含其他元数据。 |
| **磁盘空间效率** | $\eta=F/(N_{\mathrm{data}}B+N_{\mathrm{index}}B+\cdots)$ | 如题目要求**计入索引块、目录与管理信息**，必须全部计入分母。 |
| **每个索引块指针数** | $K=B/p$ | 盘块 $B$ 字节，每磁盘块指针 $p$ 字节；一般为整数。 |
| **直接索引可达数据块** | $D$ | 索引结点含 $D$ 个直接块号；访问这些数据块不需要另读间接索引块（假定 inode 已在内存）。 |
| **单级间接索引** | $K$ 个数据块 | 最多再管理 $K$ 个数据块；该指针所指向的是**索引块**，不是数据块。 |
| **二级间接索引** | $K^2$ 个数据块 | 满额使用时需 $1+K$ 个间接索引块（一级指向二级），外加 $K^2$ 个数据块。 |
| **三级间接索引** | $K^3$ 个数据块 | 满额使用时索引块数 $1+K+K^2$；需按题设实际分配计数。 |
| **索引节点最大文件容量** | $F_{\max}=(D+n_1K+n_2K^2+n_3K^3)B$ | $n_i$ 为相应级别间接指针个数；**注意与 inode 本身大小区分**。 |
| **位示图空间** | $N_{\mathrm{bits}}=N_{\mathrm{blocks}}$ | 每磁盘块占 1 bit；字节数 $\lceil N_{\mathrm{blocks}}/8\rceil$（若要按字/块对齐可能进一步进位）。 |
| **FAT 表空间** | $N_{\mathrm{entries}}\times s_{\mathrm{entry}}$ | 每簇/盘块对应 FAT 表项的简化模型；真实 FAT 类型还可能有保留项。 |
| **目录/ inode 缓存效果** | $\text{实际 I/O}=\text{未驻留元数据与数据的读取次数}$ | 题目说“全部读入内存”时，**文件实际数据盘块仍需被读取**；已缓存的 inode/间接块不必重复读。 |

### 磁盘调度、缓冲与设备利用率

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **磁头总移动量** | $L=\sum_i\vert c_i-c_{i-1}\vert $ | $c_i$ 为按照调度顺序访问的柱面号；单位道（柱面），**不是秒**。 |
| **平均寻道长度** | $\bar L=L/N_{\mathrm{requests}}$ | 常用于 FCFS、SSTF、SCAN、LOOK 对比；如果问时间，还要给平均每柱面移动耗时模型。 |
| **寻道时间（模型）** | $T_{\mathrm{seek}}\approx L\cdot t_{\mathrm{per\ track}}$ | 只有**题目显式允许**线性模型时才能把寻道长度按比例换算成时间。 |
| **平均磁盘请求服务时间** | $T_{\mathrm{service}}\approx T_{\mathrm{seek}}+T_{\mathrm{rot}}+T_{\mathrm{xfer}}$ | 与机组磁盘公式一致；还要看是否有排队、控制器处理及回写。 |
| **磁盘队列等待时间** | $T_{\mathrm{queue}}=T_{\mathrm{response}}-T_{\mathrm{service}}$ | 若响应时间定义为入队到服务完成，且只有排队和服务两段。 |
| **磁盘服务吞吐** | $Q=\text{完成请求数}/T$ | 随机 I/O 和顺序 I/O 的吞吐可显著不同，且数据吞吐 B/s 与请求吞吐 IOPS 不同。 |
| **单缓冲（简化）** | $T_1=n(T_{\mathrm{I/O}}+T_{\mathrm{proc}})$ | 一缓冲读入后处理，无法**同时用同一缓冲**读下一块；每块的 I/O 和处理顺序执行。 |
| **双缓冲（理想）** | $T_2=T_{\mathrm{I/O}}+T_{\mathrm{proc}}+(n-1)\max(T_{\mathrm{I/O}},T_{\mathrm{proc}})$ | 两缓冲交替、输入与处理可并行，忽略切换/复制时间；有额外复制需改公式。 |
| **设备利用率** | $U_{\mathrm{dev}}=T_{\mathrm{busy}}/T_{\mathrm{obs}}$ | 设备忙于服务请求的比例；高利用率可能伴随排队等待增大。 |
| **SCAN / LOOK 等算法** | 按真实移动路径求 $\sum\vert \Delta c\vert $ | SCAN 通常会扫到端点；LOOK 仅到该方向最后一个请求。循环版本是否计返程移动要按模型计入。 |

> [!example] 算例演示
>
> **例题｜文件“全部读入内存”，磁盘 I/O 数怎么数？**
>
> 盘块 $B=4096$ B，指针 $p=4$ B，因此一个索引块有 $K=1024$ 个块号。某文件大小为 30 个盘块，采用 12 个直接地址和其余经单级间接索引。
>
> 如 **inode 已在内存，其他内容均未缓存**，则需要读**18 个经间接索引的数据块** + **12 个直接数据块** + **1 个间接索引块**，总共 $30+1=31$ 次读盘。
>
> **若间接索引块已缓存**，则 30 次；**若题目还要求目录查询或 inode 读取**，再按题设分别增加。这说明“文件全部读入”与“索引结构额外读盘”必须分开。

### 操作系统补遗 · 查漏补缺

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **高响应比优先 HRRN（必背）** | $\text{响应比}=\dfrac{W+S}{S}=1+\dfrac WS$，$W$ 为已等待时间，$S$ 为预计服务时间。 | **响应比**是调度的无量纲优先级，**响应时间**是从到达到首次运行的时间，二者完全不同。非抢占式 HRRN 通常每次选择作业时重新计算。 |
| **CPU 忙碌率 vs 有效工作率** | $U_{\mathrm{busy}}=\dfrac{T_{\mathrm{run}}+T_{\mathrm{switch}}}{T_{\mathrm{obs}}}$；$U_{\mathrm{useful}}=\dfrac{T_{\mathrm{run}}}{T_{\mathrm{obs}}}$。 | 这是两种**不同统计定义**；有些题目将切换时间计入「忙碌」，但从有效用户工作角度通常应排除。先看题意。 |
| **单缓冲：含工作区复制耗时的教材模型（重点补正）** | 输入一块耗时 $T$，从系统缓冲区复制到用户工作区耗时 $M$，处理一块耗时 $C$；稳态每块节拍 $\max(T,C)+M$。输入 $n$ 块的总完成时间可写为 $T_{\mathrm{single}}=n[\max(T,C)+M]+\min(T,C)$。 | 复制期间系统缓冲区不可再接收新输入，复制与同一 CPU 处理均不得重叠；复制后用户处理与下一块设备输入可并行。**如果题目不设置独立工作区或不允许重叠，此公式不适用**。 |
| **双缓冲：含复制耗时的教材模型（重点补正）** | 稳态每块节拍 $\max(T,M+C)$；理想总时间 $T_{\mathrm{double}}=n\max(T,M+C)+\min(T,M+C)$。 | 两个系统缓冲区轮换、CPU 复制与处理串行、输入和 CPU 工作可并行，忽略换缓冲额外开销。$n=1$ 时式子应退化为 $T+M+C$。 |
| **缓冲例题（自行设计）** | $n=10$、$T=100\,\mu s$、$M=50\,\mu s$、$C=50\,\mu s$；单缓冲 $T_1=10(100+50)+50=1550\,\mu s$；双缓冲 $T_2=10\times100+100=1100\,\mu s$。 | 与仅用「I/O + 处理」二阶段的简化公式不同，**必须看题目是否给了缓冲区复制过程**。 |
| **页故障率与页面引用串** | $p=\dfrac{\text{发生的缺页次数}}{\text{被统计的页面访问次数}}$。 | 初始化页表、冷启动、是否统计写入都以题目为准；按访问序列模拟置换算法。FIFO 在某些序列可能出现 Belady 异常：页框更多而缺页反增。 |
| **磁盘 I/O 总耗时和总移动量** | 同时算多个随机访问请求时，磁头移动量 $L=\sum\vert c_i-c_{i-1}\vert $；若题给「每跨一道恒定耗时」，才可用 $L\cdot t_{\mathrm{track}}$ 推寻道时间。 | 总移动道数不是总访问时间，仍可能有旋转、数据传输与排队时间。 |

### 速率、带宽、吞吐量与负载

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **数据传输速率** | $R=\text{传输比特数}/T$ | 单位 bit/s 或 bps；不是 B/s。计网中通常 $1\,\mathrm{Mb/s}=10^6\,\mathrm{bit/s}$。 |
| **频谱带宽** | $B=f_{\mathrm{high}}-f_{\mathrm{low}}$ | 单位 Hz；这是**信号频率范围**，和链路速率的“带宽”含义不同。 |
| **链路带宽（数据率）** | $R_{\max}$ bit/s | 特指网络设备/链路标称传输能力；端到端吞吐受瓶颈与协议开销等限制。 |
| **码元速率 / 波特率** | $R_s=\text{码元个数}/T$ | 单位 baud（Bd），即码元/s；码元不是比特。 |
| **比特率与波特率** | $R_b=R_s\log_2M$ | 在一个码元可表示 $M$ 种等概率状态、每码元承载 $\log_2M$ 个信息 bit 的**理想条件**下成立。 |
| **曼彻斯特编码** | $R_s=2R_b$ | 按“半比特电平区间作为码元”的常见教材口径；一个数据 bit 含两段半比特信号。 |
| **吞吐量 Throughput** | $Q=\text{实际送达的比特数}/T$ | 一般低于瓶颈链路标称速率；若把协议首部算入，需注明。 |
| **有效吞吐量 Goodput** | $G=\text{成功交付的应用有效数据}/T$ | 剔除协议首部、重传等开销。一般 $G\le Q$，二者**统计口径须一致**。 |
| **协议效率** | $\eta=\frac{L_{\mathrm{payload}}}{L_{\mathrm{transmitted}}}$ | $L_{\mathrm{transmitted}}$ 需包含指定层的首部/尾部及其他协议开销；多次重传要计总线上实际流量。 |
| **链路利用率** | $U=\text{链路忙于传输时长}/T$ | 只按“占用时间”统计；若表示吞吐比则 $\eta_R=Q/R_{\mathrm{link}}$，须看题目定义。 |
| **多跳端到端瓶颈速率** | $R_{\mathrm{end}}\le\min_iR_i$ | 长时间连续数据流、理想无额外开销时可接近最慢链路速率；**单个分组时延**不能只取最小速率推断。 |
| **用户平均服务速率** | $R_{\mathrm{user}}\approx R_{\mathrm{link}}/n$ | 仅在 $n$ 个用户均分并持续饱和、协议开销可忽略时成立；不代表严格保证。 |

### 物理层：信道极限、信噪比与误码率

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **奈奎斯特准则** | $R_{\max}=2B\log_2M$ | 理想**无噪声、带宽受限的基带信道**，$B$ 为 Hz，$M$ 种离散码元状态。 |
| **香农容量** | $C=B\log_2(1+S/N)$ | $B$：Hz；$S/N$：**线性**信噪功率比；得到 bit/s 的理论上界。 |
| **信噪比 dB** | $SNR_{\mathrm{dB}}=10\log_{10}(S/N)$ | $S/N=10^{SNR_{\mathrm{dB}}/10}$；**30 dB 对应 1000，不是 30**。 |
| **系统容量约束** | $R\le\min(R_{\mathrm{Nyquist}},C_{\mathrm{Shannon}})$ | 在同一信道/调制假设下同时受码元数限制和噪声限制；分别计算后取较小值。 |
| **码元持续时间** | $T_s=1/R_s$ | 单位秒/码元；比特持续时间 $T_b=1/R_b$。 |
| **误码率 BER** | $BER=N_{\mathrm{err\ bits}}/N_{\mathrm{received\ bits}}$ | 表示接收比特出错的占比；不同编码与信道条件下数值不同。 |
| **帧差错率 FER** | $FER=N_{\mathrm{error\ frames}}/N_{\mathrm{frames}}$ | 一帧内只要存在导致帧判错的错误即计一帧；不可简单等同 BER。 |
| **独立比特出错模型** | $P(\text{帧至少 1 位错})=1-(1-p)^L$ | 仅当每位独立、同一误码率 $p$、帧长 $L$ bit 时成立；实际突发差错不满足。 |
| **传播速度** | $v=d/T_{\mathrm{prop}}$ | 光纤、电缆内常取 $v\approx 2\times10^8\,\mathrm{m/s}$ 作为**题设近似**；绝不等于链路 bit/s。 |

> [!example] 算例演示
>
> **例题｜“30 dB”和“16 进制码元”，两个上界一起限制**
>
> 信道频谱带宽 $B=3000$ Hz，16 种离散码元状态，信噪比为 30 dB。
>
> 奈奎斯特：$2\times3000\times\log_2 16=24000$ bit/s；香农：$3000\log_2(1+1000)\approx29900$ bit/s。**同时满足两种限制时，理论可用上界不超过 24 kb/s。**不要将香农的 30 dB 直接作为 $S/N=30$。


### 四大时延、RTT、带宽时延积与存储转发

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **发送 / 传输时延** | $T_{\mathrm{tx}}=L/R$ | $L$ bit 的完整分组推入速率 $R$ bit/s 的链路所需时间；**和链路长度无关**。 |
| **传播时延** | $T_{\mathrm{prop}}=d/v$ | 信号走完距离 $d$ 所需时间；**与报文长度无关**。 |
| **处理时延** | $T_{\mathrm{proc}}$ | 检查差错、查转发表、处理协议等的耗时；一般由题目给定。 |
| **排队时延** | $T_{\mathrm{queue}}$ | 在输出队列等待链路可用的时间；与到达速率、突发流量、调度方式有关。 |
| **端到端总时延** | $T_{\mathrm{total}}=\sum(T_{\mathrm{tx}}+T_{\mathrm{prop}}+T_{\mathrm{proc}}+T_{\mathrm{queue}})$ | 对途经各链路与节点逐段加；勿把所有链接都按同一速率计算。 |
| **往返时间 RTT** | $RTT\approx T_{\mathrm{forward}}+T_{\mathrm{backward}}$ | 从发出某请求到收到相应反馈的往返总时间；可能含发送/排队/处理等，不一定恰为 $2T_{\mathrm{prop}}$。 |
| **时延带宽积 BDP** | $BDP=R\cdot RTT$ | 单位 bit；常用于**往返确认机制**下需要多少在途数据才能填满链路。单向链路“管道”比特量为 $R\cdot T_{\mathrm{prop}}$。 |
| **单向传播管道容量** | $N_{\mathrm{pipe}}=RT_{\mathrm{prop}}$ | 把“链路上正在传播的 bit 数”看作传输率 $\times$ 传播时间；不要自动替换成 RTT。 |
| **单分组 $H$ 跳存储转发** | $T=H\frac{L}{R}+\sum_{i=1}^HT_{{\mathrm{prop}},i}$ | 各链路速率均为 $R$，路由器必须收齐全包后再转发，忽略处理/排队。 |
| **$N$ 分组、$H$ 跳流水** | $T=(H+N-1)\frac{L}{R}+\sum_iT_{{\mathrm{prop}},i}$ | 各分组长度相等、链路同速、无排队/开销，发送与下游转发可流水重叠。 |
| **单段分组突发传输** | $T\approx NL/R$ | $N$ 个同长度分组，连续上线，不含传播与每包处理；发送完最后一位与对端收到最后一位的时刻不同。 |
| **简单流量强度** | $\rho=\lambda L/R$ | $\lambda$：平均每秒到达的分组数，$L$：平均包长 bit，$R$：服务速率；$\rho\ge1$ 不能长期稳定。 |
| **Little 定律（选学）** | $N_{\mathrm{avg}}=\lambda W$ | 稳定系统：平均系统内人数/任务数 = 平均到达率 $\times$ 平均停留时间；不能据此直接推出具体排队时延。 |

> [!example] 算例演示
>
> **例题｜传播时延为什么与 100 Mb/s 无关？**
>
> 长度 $1000$ B 的帧，经速率 $10$ Mb/s 的链路传输，距离 $500$ km，信号速度 $2\times10^8$ m/s。
>
> 发送时延 $=8000/10^7=0.8$ ms；传播时延 $=500000/(2\times10^8)=2.5$ ms。单段最小完成时延 $=3.3$ ms（不计处理、排队）。
>
> **增加速率会减少发送时延；缩短物理距离、增加传播速度才会缩短传播时延。**


### 数据链路层：ARQ、滑动窗口和利用率

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **停止-等待利用率** | $U=\frac{T_f}{T_f+RTT+T_{\mathrm{ACK}}}$ | $T_f=L/R$ 为数据帧发送时间；这里的 RTT **仅取反馈前的传播往返部分**，若实际 RTT 已含发送/ACK，不得重复计数。 |
| **停止-等待简式** | $U\approx1/(1+2a)$ | $a=T_{\mathrm{prop}}/T_f$，忽略 ACK 发送与处理，双向传播对称、无重传。 |
| **滑动窗口利用率** | $U\approx\min\!\left(1,\frac{WT_f}{T_f+RTT+T_{\mathrm{ACK}}}\right)$ | 窗口 $W$ 帧、等长、同速、无误码、连续发送可流水；ACK 等待定义与上行一致。 |
| **满流水所需窗口** | $W\ge\lceil1+2a\rceil$ | 只在**忽略 ACK 发送、处理和排队**的理想简化式成立。 |
| **GBN 发送窗口上限** | $W_s\le2^n-1$ | $n$ bit 帧序号，采用累计确认的后退 N 帧协议；避免新旧帧序号歧义。 |
| **选择重传 SR** | $W_s+W_r\le2^n$ | 常见设置 $W_s=W_r=W$，则 $W\le2^{n-1}$。不要与 GBN 上限混淆。 |
| **帧序号位数** | GBN: $n\ge\lceil\log_2(W+1)\rceil$； SR 等窗: $n\ge\lceil\log_2(2W)\rceil$ | $W$ 为期望发送窗口；序号位宽向上取整，必须说明协议。 |
| **重传开销** | $\eta=\text{成功有效载荷}/\text{总发送量}$ | GBN 错一帧可能重传后续多帧；SR 通常只重传相应丢失/损坏帧。 |
| **帧传输总时长** | $T_f=L_{\mathrm{frame}}/R$ | 要把首部、尾部计入 $L_{\mathrm{frame}}$，只用净载荷会**高估**链路有效率。 |

> [!example] 算例演示
>
> **例题｜停止-等待为何在长距离上浪费带宽？**
>
> 帧长 1500 B，链路速率 10 Mb/s，单向传播 10 ms，忽略 ACK 的发送时间。
>
> $T_f=1500\times8/10^7=1.2$ ms；往返传播为 20 ms。
>
> 停止-等待 $U=1.2/(1.2+20)\approx5.66%$。若用无差错的帧窗口流水发送，要让连续发送不空闲，需 $W\ge\lceil(1.2+20)/1.2\rceil=18$ 帧。**RTT 大、帧短时，窗口机制显著提升利用率。**


### 介质访问：以太网、CSMA/CD 与开销

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **CSMA/CD 冲突检测约束** | $T_{\mathrm{frame}}\ge2\tau$ | 经典**半双工共享以太网**中，最远两端单向传播 $\tau$，发送方须在最坏往返冲突传播之前仍保持发送。 |
| **最小帧长** | $L_{\min}\ge2\tau R$ | $R$ bit/s；经典 10 Mb/s 以太网最小 MAC 帧长 64 B（不含前导码/SFD）。现代全双工交换以太网不使用 CSMA/CD 争用。 |
| **以太网 MAC 帧效率** | $\eta=\frac{L_{\mathrm{payload}}}{L_{\mathrm{frame}}}$ | 经典以太网 MAC 帧 64--1518 B（不含 VLAN、前导码等）；具体题目若含前导码/帧间隙，分母必须扩展。 |
| **共享信道利用率** | $U=\text{成功传输时段}/T$ | 竞争、碰撞、退避、控制帧均可能导致有效吞吐低于物理速率。 |
| **退避时长** | $T_{\mathrm{backoff}}=K\cdot T_{\mathrm{slot}}$ | 二进制指数退避的 $K$ 从随冲突次数扩展的范围内随机取；需按题给最小/最大范围算。 |
| **CRC 检测开销** | $\eta=\frac{L_{\mathrm{data}}}{L_{\mathrm{data}}+r}$ | 若帧仅含信息位和 $r$ 位冗余校验，比例成立；CRC 检错**不等于**自动纠错。 |
| **交换机端口线速** | $R_{\mathrm{port}}$ | 端口标称链路速率，不等于整台交换机背板的总无阻塞交换能力；多个流可能争同一输出端口。 |
| **802.11 数据效率** | $\eta=\frac{T_{\mathrm{payload}}}{T_{\mathrm{total}}}$ | 总时间可能含等待间隔、退避、ACK、RTS/CTS 等，具体时间由题设给定。 |

> [!example] 算例演示
>
> **例题｜经典以太网 64 字节最小帧长怎么来？**
>
> 若 $R=10\,\mathrm{Mb/s}$，最坏单向传播 $\tau=25.6\,\mu\mathrm{s}$，则 $2\tau R=2\times25.6\times10^{-6}\times10^7=512$ bit $=64$ B。
>
> **结论只是在这一经典半双工冲突检测模型下推导。**不能把它理解成“任何局域网只要 64 B 就能检测冲突”。


### 网络层：子网容量、分片与跳数

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **IPv4 子网地址数** | $N_{\mathrm{addr}}=2^h$ | 前缀长度 $/p$，主机位 $h=32-p$；地址数包括特殊地址。 |
| **普通 IPv4 可用主机数** | $N_{\mathrm{host}}=2^h-2$ | 通常**排除网络地址和广播地址**；$/31$ 点对点与 $/32$ 主机路由是特殊情形，不能硬套。 |
| **IPv4 最大不分片载荷** | $D_{\max}=MTU-H$ | MTU 为**含 IP 首部的 IP 数据报**可承载的最大大小，$H$ 为 IP 首部字节数。 |
| **IPv4 普通分片数据量** | $D_f=8\left\lfloor\frac{MTU-H}{8}\right\rfloor$ | 除最后一个分片外，IP 数据部分应为 8 字节的整数倍，因为片偏移以 8 B 为单位。 |
| **IP 片偏移** | $\mathrm{offset}=\frac{\text{原始数据起始字节位置}}{8}$ | 字段单位是 8 字节；**不是**以“原始 IP 首部起始位置”为基准。 |
| **分片数量** | $N_{\mathrm{frag}}=\left\lceil\frac{D}{D_f}\right\rceil$ | 原报文数据部分长度为 $D$，$D_f$ 为非末片最大数据量；忽略特殊选项首部差异。 |
| **端到端路由跳数** | $H$ | 经过的路由器/链路数量要依题目定义；**跳数最少不一定时延最低**。 |
| **IP 数据报封装效率** | $\eta=\frac{D}{D+H}$ | 只计 IP 首部 $H$ 时成立；下层链路头尾开销要额外计。分片后每个片都带 IP 首部。 |
| **路由选择成本** | $\text{path cost}=\sum_i c_i$ | 链路费用可代表跳数、延迟、管理代价等；不同协议 metric 定义不一定可直接比较。 |

### TCP：窗口、在途数据、拥塞窗口和速率

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **有效发送窗口** | $W_{\mathrm{eff}}=\min(rwnd,cwnd)$ | $rwnd$：接收窗口（流量控制）；$cwnd$：拥塞窗口（拥塞控制），均以字节等统一单位计。 |
| **理论 TCP 窗口限制** | $R_{\mathrm{TCP}}\lesssim W_{\mathrm{eff}}/RTT$ | 稳定长流、ACK 正常返回、忽略头部和应用限制；实际还受瓶颈物理速率、丢包、接收端等约束。 |
| **填满链路所需窗口** | $W_{\mathrm{eff}}\gtrsim R_{\mathrm{bottleneck}}\times RTT$ | 带宽时延积；仅当发送方有足够数据且协议等开销忽略时可近似满速。 |
| **TCP 实际窗口可用量** | $W_{\mathrm{avail}}=W_{\mathrm{eff}}-N_{\mathrm{in\ flight}}$ | 已发送未确认数据 $N_{\mathrm{in\ flight}}$ 占用窗口；不能仅按 $W_{\mathrm{eff}}$ 判定马上还能发多少。 |
| **序号空间与字节** | $ACK=x\Rightarrow\text{累计确认至 }x-1$ | TCP 序号按**字节**计；SYN、FIN 通常各消耗 1 个序号；ACK-only 不消耗数据序号。 |
| **慢开始理想增长** | $cwnd$ 每 RTT 约翻倍 | 假设 ACK 反馈足够、每报文段增量按经典模型计算，直到阈值/网络信号触发改变；真实 TCP 细节更多。 |
| **拥塞避免理想增长** | 每 RTT 约增加 $1\,MSS$ | 经典 AIMD 加性增模型；不同 TCP 实现与延迟确认策略有差异。 |
| **超时后的窗口变化** | $ssthresh\approx\frac{1}{2}\text{拥塞前窗口}$ | 经典教材模型常设 $cwnd\leftarrow1\,MSS$；实际标准和实现可能不同，题设优先。 |
| **快重传后的处理** | 取决于 Reno / Tahoe 等实现 | 不能统一写“收到 3 个重复 ACK 后 cwnd 一律变 1”；按**试题指定 TCP 版本**处理。 |
| **TCP 段封装效率** | $\eta\approx\frac{MSS}{MSS+H_{\mathrm{TCP}}+H_{\mathrm{IP}}+H_{\mathrm{link}}}$ | 忽略选项、填充、重传和链路前导等；$MSS$ 是 TCP**数据**部分大小。 |
| **TCP 重传定时** | $RTO$ 由 RTT 估计与波动决定 | 标准算法通常包含平滑 RTT 与 RTT 方差；408题目未给具体估计规则时**不能任意代入一个通式**。 |

> [!example] 算例演示
>
> **例题｜100 Mb/s 链路，窗口至少需要多大？**
>
> 瓶颈链路速率 $R=100$ Mb/s，往返时延 $RTT=40$ ms。
>
> $BDP=100\times10^6\times0.04=4\times10^6$ bit = 500,000 B（约 488.3 KiB）。
>
> 忽略开销时，TCP 的有效窗口 $\min(rwnd,cwnd)$ 至少需接近**500,000 B** 才可能让链路持续满载。即使拥塞窗口很大，接收窗口较小也可能形成瓶颈。


### 应用层：HTTP、DNS 和文件传输时间

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **HTTP 非持久连接** | 单对象约 $2RTT+T_{\mathrm{object}}$ | 经典**HTTP/1.0 教材模型**，TCP 握手 1 RTT、请求响应首字节再 1 RTT；忽略 DNS、排队、TLS。 |
| **HTTP 持久连接** | 连接建立的 1 RTT 可复用 | 多对象顺序请求时每个后续对象通常再需请求/响应时延；流水化可减少等待 RTT，须按传输顺序计算。 |
| **HTTP 并行连接** | 总体时间取**最长并行链**，非各链简单求和 | 仅当题目允许多 TCP 连接并行及链路资源足够时成立；并行流会竞争瓶颈带宽。 |
| **DNS 查询时间** | $T_{\mathrm{DNS}}\approx\sum_jRTT_j+\text{处理时间}$ | 迭代、递归、命中本地缓存等条件不同；不能默认每次都查根域名服务器。 |
| **应用下载时间下界** | $T_{\mathrm{download}}\ge F/R_{\mathrm{bottleneck}}$ | $F$ 为有效文件数据量，忽略协议开销和连接启动；实际下载时间通常更长。 |
| **FTP 控制 / 数据连接** | 控制与数据连接独立 | 只有协议流程、每次连接时延与数据量给定后，才能算总时间。 |
| **TCP 连接 / 关闭往返** | 依握手、半关闭和连接复用模型 | “三次握手”是**报文次数**，并不等于从客户端发 SYN 到收到 SYN-ACK 要 3 个 RTT。 |

> [!warning] 易错提醒
>
> **计网六连辨析：**频谱带宽(Hz) $\ne$ 链路速率(bit/s)；发送时延 $L/R$ $\ne$ 传播时延 $d/v$；RTT $\ne$ 必然 $2d/v$；$rwnd$ 是接收端流控、$cwnd$ 是发送端拥塞控制；码元/s $\ne$ bit/s；$MSS$ 不含 TCP/IP 首部，而 $MTU$ 约束 IP 分组总长度。

### 计算机网络补遗 · 查漏补缺

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **汉明距离的检错/纠错能力（必背）** | 码字最小距离 $d_{\min}$，最多保证检测 $d_{\min}-1$ 位错误；最多保证纠正 $\lfloor(d_{\min}-1)/2\rfloor$ 位错误。 | 是对任意错误位置组合的最小距离保证；不要把「检错位数」误写成「纠错位数」。 |
| **单错纠正汉明码校验位数** | $2^r\ge k+r+1$，$k$ 为信息位数、$r$ 为校验位数。 | 用于能定位并纠正**单比特错误**的常见汉明码设计；若还要整体双错检测（SECDED），通常另加全局奇偶校验位。 |
| **CRC 冗余位数** | 若生成多项式最高次数为 $r$，则通常附加 $r$ 位 CRC 校验序列。 | CRC 检错能力还取决于多项式和错误类型，不是「$r$ 位 CRC 一定能纠正 $r$ 位错误」。 |
| **多跳链路速率不同时的单包总时延** | $T=\sum_{i=1}^{H}\dfrac{L}{R_i}+\sum_{i=1}^H\dfrac{d_i}{v_i}+\sum T_{\mathrm{proc},i}+\sum T_{\mathrm{queue},i}$。 | 整包存储转发、单一长度为 $L$ 的数据包，不同链路速率不同时不能统一拿 $H L/R$ 计算。 |
| **TCP MSS 与 MTU 换算** | 无 IP/TCP 选项的典型 IPv4 网络中，$MSS=MTU-20\,\mathrm{B}-20\,\mathrm{B}$。 | 一旦含 IP/TCP 选项、隧道、特殊网络，首部总长度改变，不能固定减 40 B。MSS 仅 TCP 数据，MTU 约束链路能承载的 IP 包总长。 |
| **以太网帧实际占线效率（选学）** | 如将 8 B 前导码与帧开始定界符、12 B 帧间隙计入，则 $\eta=\dfrac{L_{\mathrm{payload}}}{L_{\mathrm{MAC\ frame}}+8+12}$。 | 这是**按一个完整发送帧的链路占线字节数**计算、无 VLAN 的例子；不同课程习题有时只统计 MAC 帧本身，需按题目指定分母。 |
| **最小发送窗口（从等待周期推得）** | 在无错理想滑窗协议中，若一帧发送用时 $T_f$，ACK 额外发出用时 $T_a$，往返传播为 $T_r$，窗口至少需 $W\ge\left\lceil\dfrac{T_f+T_r+T_a}{T_f}\right\rceil$ 才可能连续满速。 | 是由窗口内全部帧发送与首帧 ACK 返回的时间关系得到，前提是等长、无误码、ACK 能及时返回；不要把 $T_r$ 又当成已包含帧发送时间的完整 RTT。 |

## 05 · 跨学科辨析

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **时间 $T$** | $T=\text{执行、等待或传播的时长}$ | **机组**常问 CPU 执行时间；**OS**常问周转/响应/等待；**计网**常问发送/传播/排队。写公式前先指定区间。 |
| **吞吐量 $Q$** | $Q=\text{完成数量}/T$ | 机组：任务/s；OS：作业/s；计网：bit/s；磁盘：B/s 或 IOPS。**数量的对象不同**。 |
| **平均值** | $E[X]=\sum_ip_iX_i$ | 按概率/指令数加权时，不能取未加权算术平均。典型：ASL、CPI、AMAT。 |
| **利用率 $U$** | $U=\frac{\text{占用时长}}{\text{观察总时长}}$ | 可指 CPU、磁盘、链路；它不一定是**有效负载吞吐**/**峰值吞吐**。 |
| **效率 $\eta$** | $\eta=\frac{\text{有效工作量}}{\text{总工作量}}$ | 数据结构看空间浪费；机组看流水线格子利用；计网看协议载荷占比。 |
| **时延 $T_{\mathrm{lat}}$** | $\text{请求发起}\to\text{完成}$ | 机组关注存储层级和指令依赖；OS 包含排队/服务；计网需要分发送/传播/节点处理/排队。 |
| **带宽 $B$** | $\text{单位时间可传输的数据量}$ 或 Hz | 总线/内存/网络链路常用 B/s 或 bit/s；物理层频谱带宽用 Hz。两者**量纲不同**。 |
| **加速比 $S$** | $T_{\mathrm{old}}/T_{\mathrm{new}}$ | CPU 优化、多核/流水、算法优化都适用，但**相同问题规模、相同结果与相同时间口径**是前提。 |
| **命中率 $h$** | $\text{命中次数}/\text{访问次数}$ | Cache、TLB 均存在命中率；各自的分母和未命中代价不同，不能共用同一变量但不区分层次。 |
| **块 $B$** | 可能是字节、磁盘块、Cache 块、分组 | “块”不是统一的度量单位；内存页、盘块、Cache 行、网络数据帧不同。 |
| **速率与时延** | $\text{速率}=\text{量}/\text{时长}$ | 吞吐通常受瓶颈速率限制，但“单次操作延迟短”不必然意味着“最高吞吐大”。 |
| **计数 vs 时间** | $N$ 次操作 $\ne$ $N$ 秒 | 比较次数、柱面移动量、页面访问次数、磁盘 I/O 次数只在**单次成本已知**时可转成总时间。 |

### 最容易混错的 20 对概念

| 序号 | 易混概念 | 区分要点 |
|:---:|:---|:---|
| 1 | 时间复杂度 vs 实际用时 | 前者描述增长阶，后者取决于常数、平台与具体输入。 |
| 2 | 最坏时间 vs 平均时间 | 后者必须附输入概率分布，不能取极值均值代替。 |
| 3 | 成功 ASL vs 失败 ASL | 两类事件比较/探测路径不同，另算。 |
| 4 | 堆排序 vs 堆数据结构 | 堆排序辅助空间 $O(1)$；堆本身可以装 $n$ 个元素。 |
| 5 | 吞吐量 vs 响应时间 | 高吞吐不保证单任务低时延。 |
| 6 | CPI vs IPC | 在同一统计区间互为倒数；不等于“IPC 必定不大于 1”。 |
| 7 | MIPS vs FLOPS | 前者按指令，后者按浮点运算；跨体系结构比较程序快慢不能只看 MIPS。 |
| 8 | CPU 主频 vs 总线频率 | 时钟源和传输单位不同，无法直接相互替代。 |
| 9 | 命中时间 vs 缺失代价 | 未命中**额外**时间与**总**时间写法不同。 |
| 10 | Cache vs TLB 命中 | Cache 缓存数据/指令块，TLB 缓存虚拟页地址映射。 |
| 11 | 存储器存取时间 vs 存取周期 | 后者是连续两次启动访问的最小间隔。 |
| 12 | 磁盘寻道 vs 旋转等待 | 前者移动磁头，后者等待盘面转到目标扇区。 |
| 13 | 周转时间 vs 就绪等待 | 周转可能含 I/O 阻塞；就绪等待只算等 CPU。 |
| 14 | 响应时间 vs 周转时间 | 前者（调度）到首次运行，后者到最终完成。 |
| 15 | 内部碎片 vs 外部碎片 | 已分配块内部浪费 vs 分散空闲块无法满足连续分配。 |
| 16 | 文件数据块 vs 索引块 | 读取文件所有数据块不代表索引块 I/O 为 0。 |
| 17 | 波特率 vs 比特率 | 每个码元可以承载多个信息 bit，也可能编码产生更高的信号变化率。 |
| 18 | 发送时延 vs 传播时延 | 发送看 $L/R$，传播看 $d/v$。 |
| 19 | BDP 的 RTT vs 单向传播 | TCP 窗口通常用 RTT，链路正在传播的在途 bit 可用单向传播时间。 |
| 20 | TCP 接收窗口 vs 拥塞窗口 | 分别解决接收能力和网络拥塞问题，取两者较小者约束未确认数据。 |

## 06 · 考场速查

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **“程序执行了多久”** | $IC\cdot CPI/f$ | 若给多类指令，先求 $\sum IC_iCPI_i$。 |
| **“CPU 快了几倍”** | $T_{\mathrm{old}}/T_{\mathrm{new}}$ | 只优化部分程序：Amdahl。 |
| **“每秒多少百万指令”** | $IC/(10^6T)$ | MIPS 指令级性能，别混成 FLOPS。 |
| **“Cache 平均访问”** | $T_{\mathrm{hit}}+mP$ | 先确认 $P$ 是否为额外未命中代价。 |
| **“TLB 访存次数”** | 命中：数据一次；未命中：查页表层数 + 数据一次 | 另有 TLB 查询时间、Cache 命中时要调整。 |
| **“磁盘读一块多久”** | 寻道 + 旋转 + 传输 | SSD 不按机械旋转模型套算。 |
| **“流水线做 $n$ 条”** | $(k+n-1)t$ | 一定写“理想无停顿”的条件。 |
| **“多路归并几趟”** | $\lceil\log_k r\rceil$ | 如果问 I/O 次数，还要算初始段生成。 |
| **“哈夫曼平均码长”** | $\sum p_i\ell_i$ | 权重未归一化时先求 WPL，再除以权值和。 |
| **“Hash 装多少了”** | $\alpha=n/m$ | 失败 ASL 和成功 ASL 要按哈希策略分别求。 |
| **“周转 / 带权周转”** | $C-A$, $(C-A)/B$ | 平均带权要**逐项先除**。 |
| **“首次等多久”** | $S-A$ | 响应时间，不是总周转。 |
| **“缺页后的有效访存”** | $t_0+pP_f$ | 仅当 $P_f$ 是额外的缺页代价。 |
| **“文件有多少块”** | $\lceil F/B\rceil$ | 读盘次数还看目录、inode、索引块是否缓存。 |
| **“网络单跳发多久”** | $L/R+d/v$ | 别漏发送/传播，必要时再加节点处理/排队。 |
| **“一个信道最多多快”** | $2B\log_2 M$, $B\log_2(1+S/N)$ | 两种上界取更严格者，dB 先换线性功率比。 |
| **“信号在链路上多少 bit”** | $R\,d/v$ | 往返流控占用窗口：$R\cdot RTT$。 |
| **“停止等待利用率”** | $1/(1+2a)$ | ACK 可忽略、单向传播对称、无差错。 |
| **“窗口要多大”** | $W\ge\lceil1+2a\rceil$ | 一般是帧窗口；TCP 字节窗口看 BDP。 |
| **“GBN / SR 的序号”** | $2^n-1$ / $2^{n-1}$ | 后者等收发窗口时成立。 |
| **“是否能检测碰撞”** | $L/R\ge2\tau$ | 只用于使用 CSMA/CD 的半双工共享网络。 |
| **“IP 能分多少片”** | $\lceil D/[8\lfloor(MTU-H)/8\rfloor]\rceil$ | 分片长度每片带 IP 首部，偏移以 8 B 为单位。 |
| **“TCP 最高可传速率”** | $\min(R_{\mathrm{bottleneck}},W_{\mathrm{eff}}/RTT)$ | 忽略重传、首部、应用端处理和其他限制的上界。 |
| **“HTTP 一个对象几个 RTT”** | 非持久经典模型 $2RTT+T_{\mathrm{object}}$ | 不计 DNS、TLS、代理和连接复用。 |

### 单位速记与自检

| 指标 | 公式 / 结论 | 适用条件 / 易错点 |
|:---|:---|:---|
| **1 字节** | $1\,\mathrm{B}=8\,\mathrm{bit}$ | 网络速率与内存容量常跨这两种单位。 |
| **1 Mb/s** | $10^6\,\mathrm{bit/s}=125000\,\mathrm{B/s}$ | 注意 $\mathrm{Mb}$ 的小 b 表示 bit。 |
| **1 MiB** | $2^{20}\,\mathrm{B}=1048576\,\mathrm{B}$ | 十进制 1 MB = $10^6$ B。 |
| **主频 GHz** | $1\,\mathrm{GHz}\Rightarrow T=1\,\mathrm{ns}$ | 2 GHz $\Rightarrow0.5$ ns，3 GHz $\Rightarrow\frac{1}{3}$ ns。 |
| **旋转速度 rpm** | $T_{\mathrm{rev}}=60/\mathrm{rpm}$ | 7200 rpm $\Rightarrow$ 一圈约 8.33 ms，平均等 4.17 ms。 |
| **40 ms 与 100 Mb/s** | $0.04\times10^8=4\times10^6\,\mathrm{bit}$ | BDP = 4 Mbit = 0.5 MB = 500000 B。 |
| **30 dB 信噪比** | $S/N=10^{30/10}=1000$ | 0 dB 对应比值 1，10 dB 对应 10，20 dB 对应 100。 |
| **页大小 4 KiB** | $2^{12}\,\mathrm{B}$ | 页内偏移 12 位，页号位数 = 虚拟地址总位数 - 12。 |

> [!tip] 核心结论
>
> **最后 5 秒的量纲检查**
>
> **时间**类结果应有 $\mathrm{s,ms,\mu s,ns}$；**速率**类结果应有 $\mathrm{bit/s,B/s,requests/s}$；**容量**类为 bit 或 B；**占比、加速比、CPI、ASL**一般为无量纲或“次/每次指令（查找）”这种计数单位。
>
> 如果算出的“吞吐量”单位仍是秒，或“传播时延”公式中出现 bit/s 却没有分组长度，通常是选错公式。
