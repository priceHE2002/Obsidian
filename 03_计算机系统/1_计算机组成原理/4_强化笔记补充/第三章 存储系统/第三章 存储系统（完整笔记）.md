# 3.1 存储系统基本概念

> 📎 **对应讲义**：`3.1 存储系统基本概念.pdf`

## 3.1.1 存储器的分类（五个维度）

**① 按在计算机中的作用**

| 类型 | 说明 |
|---|---|
| **主存储器（主存 / 内存）** | 存放当前运行的程序和数据，**CPU 可直接访问** |
| **辅助存储器（辅存 / 外存）** | 磁盘、SSD、U 盘、光盘等，**CPU 不能直接访问**，数据要先调入主存 |
| **高速缓冲存储器（Cache）** | 位于 CPU 与主存之间，缓存主存数据副本，**速度最快、容量最小** |

> [!note] "辅存"与"外存"的叫法
> 有的教材把装在机箱内的磁盘叫"辅存"，把 U 盘、光盘叫"外存"；也有的把磁盘、U 盘、光盘统称"辅存"或"外存"。408 中不区分，按语境理解即可。

**② 按存储介质**

- 半导体存储器（主存、Cache）
- 磁表面存储器（磁盘、磁带）
- 磁芯存储器（早期）
- 光存储器（CD、DVD、蓝光）

**③ 按存取方式**（高频选择题）

| 类型 | 特点 |
|---|---|
| **随机存取存储器 RAM**（Random Access） | 读写任一存储单元所需时间都相同，**与物理位置无关** |
| **顺序存取存储器 SAM**（Sequential） | 读写时间**取决于物理位置**，如磁带 |
| **直接存取存储器 DAM**（Direct） | 既有随机存取特性，也有顺序存取特性：先直接定位到区域，再按顺序查找，如**磁盘** |
| **相联存储器 CAM**（Content Addressed） | **按内容访问**，不是按地址访问；**"快表"就是一种相联存储器** |

> [!tip] 分类边界
> **串行访问存储器 = SAM + DAM**，这是常考的分类边界。

**④ 按信息的可更改性**

- **读写存储器**（Read/Write Memory）：可读可写，如磁盘、内存、Cache
- **只读存储器**（Read Only Memory）：如 CD-ROM、BIOS 所在的 ROM
  - 注意：**很多 ROM 其实也可以多次读写，只是比较麻烦**（如 EPROM/EEPROM/Flash）

**⑤ 按信息的可保存性**

| 维度 | 分类 |
|---|---|
| 断电后信息是否丢失 | **易失性**（主存、Cache）；**非易失性**（磁盘、光盘、ROM） |
| 读出后原信息是否被破坏 | **破坏性读出**（DRAM，读出后要"再生"/重写）；**非破坏性读出**（SRAM、磁盘、光盘） |

## 3.1.2 存储器的层次化结构

```
          速度 ↑ 容量 ↓ 价格 ↑
   ┌────────────────────────────────┐
   │  CPU  ←→  Cache（SRAM）        │   ← 硬件自动完成
   │            ↕  「Cache—主存」层 │
   │        主存（DRAM）            │
   │            ↕  「主存—辅存」层  │   ← 硬件 + 操作系统
   │        辅存（磁盘 / SSD）      │
   └────────────────────────────────┘
          速度 ↓ 容量 ↑ 价格 ↓
```

| 层次 | 实现者 | 解决的问题 |
|---|---|---|
| **Cache — 主存** | **硬件自动完成**（对程序员透明） | 解决**主存与 CPU 速度不匹配**的问题 |
| **主存 — 辅存** | **硬件 + 操作系统**共同管理 | 实现**虚拟存储系统**，解决**主存容量不够**的问题 |

> [!important] 必背两句
> **Cache—主存：解决速度问题；主存—辅存：解决容量问题。**
> Cache 全由硬件自动管理；虚存由操作系统 + 硬件共同管理。

各层速度/价格的大致量级（讲义给出）：寄存器 > Cache > 主存（DRAM）> SSD > 磁盘 > 磁带。

## 3.1.3 存储器的性能指标

| 指标 | 定义/公式 |
|---|---|
| **存储容量** | 存储字数 × 字长，如 `1M × 8位` |
| **单位成本** | 每位价格 = 总成本 / 总容量 |
| **存取时间 $T_a$** | 从启动一次存储器操作到完成该操作所经历的时间，分读出时间与写入时间 |
| **存取周期 $T_m$** | 存储器进行一次完整读写操作所需的全部时间，即**连续两次独立访存之间所需的最小时间间隔** |
| **主存带宽 $B_m$** | 又称数据传输率，表示每秒从主存进出的最大信息量，单位 字/s、B/s、b/s |

$$
B_m = \frac{\text{数据的宽度（存储字长）}}{\text{存取周期 } T_m}
$$

> [!warning] $T_m > T_a$
> 因为一次读写之后存储单元需要**恢复时间**（DRAM 尤其明显，恢复时间可达存取时间的数倍）。
> 例：$T_a = r$，$T_m = T$，若恢复时间较长则 $T = 4r$。

## 3.1.4 存储字长、存储单元与寻址方式

- **存储元**：存放 1 位二进制信息的元件。
- **存储单元**：若干个存储元组成，可存放一串二进制代码，即**存储字**。
- **存储字长**：存储字的二进制位数，一般是 1B 的整数倍（8、16、32、64 bit）。
- **存储体**：所有存储单元的集合。

**地址线根数与容量**：
$$
n \text{ 位地址} \Rightarrow 2^{n} \text{ 个存储单元}

\text{总容量} = \text{存储单元个数} \times \text{存储字长} = 2^{n} \times \text{存储字长}
$$

**同一块主存，不同寻址方式下的"单元数"完全不同**（高频！）：

> 例：主存容量 `1KB`，存储字长 `4B`（字长为 4B）
> - 按**字节**寻址：$1\text{KB}/1\text{B} = 1024$ 个单元，每个单元 1B，地址线 10 根
> - 按**字**寻址：$1\text{KB}/4\text{B} = 256$ 个单元，每个单元 4B
> - 按**半字**寻址：512 个单元，每个单元 2B
> - 按**双字**寻址：128 个单元，每个单元 8B
>
> **结论：容量不变，编址粒度越细，单元数越多，地址位数越多。**

> [!tip] 机器字长 / 存储字长 / 指令字长 三者区别
> - **机器字长**：CPU 一次能处理的二进制位数（= 寄存器、ALU、内部数据总线位数）
> - **存储字长**：一个存储单元的二进制代码长度（= MDR 位数）
> - **指令字长**：一条指令所含的二进制位数
> **三者可以互不相等。**

## 3.1.5 自测

1. 相联存储器是按什么方式寻址的？平常说的"快表"属于哪种存储器？
2. 某主存容量 4KB，存储字长 8B，按字寻址共有多少个存储单元？需要几根地址线？
3. 存取时间和存取周期哪个大？为什么？

<details>
<summary>答案</summary>

1. **按内容访问**（Content Addressed），不按地址访问；"快表"（TLB）就是一种相联存储器。
2. $4\text{KB}/8\text{B} = 512$ 个单元；地址线 $= \log_2 512 = 9$ 根。
3. **存取周期更大**。一次读写操作结束后存储单元需要一定的恢复时间，连续两次访存之间要等这段恢复时间。

# 3.2 主存储器

> 📎 **对应讲义**：`3.2.0+3.2.3 主存储器的基本组成.pdf`、`3.2.1 SRAM和DRAM.pdf`、`3.2.2 只读存储器ROM.pdf`、`3.2.4 双端口RAM和多模块存储器.pdf`

## 3.2.1 半导体存储器的基本组成

**层次关系**：

```
存储元（1 bit）→ 存储单元（一个存储字）→ 存储体（所有单元的集合）
```

**一个存储芯片的对外引脚/信号**：

| 信号 | 作用 |
|---|---|
| **地址线** | $n$ 根地址线 → $2^{n}$ 个存储单元 |
| **数据线** | 宽度 = 存储字长（与 CPU 的数据总线相连） |
| **片选线 $\overline{CS}$** | **选中本芯片**（一片芯片内部不区分地址空间，靠片选来分） |
| **读/写控制线** | 有两种形式：①两根线 $\overline{WE}$（允许写）、$\overline{OE}$（允许读）；②一根线 $WE$，**低电平写、高电平读** |

> [!note] MAR 与 MDR
> - **MAR**（Memory Address Register）：存放地址，位数 = 地址线根数（= PC 位数）
> - **MDR**（Memory Data Register）：暂存读出/写入主存的数据，**位数 = 存储字长**
> 现代计算机中 MAR、MDR 通常**集成在 CPU 内部**，存储芯片内只需一个普通的数据寄存器。

**容量公式**：

$$
\text{总容量} = \text{存储单元个数} \times \text{存储字长}
$$

> 例：`8K × 8位` 芯片 → $2^{13} \times 8\text{bit} = 8\text{KB}$，需要 **13 根地址线**、8 根数据线。

**同一容量下不同编址粒度**（讲义例题）：某存储器容量 `1KB`、字长 `4B`
- 按字节寻址：1K 个单元 × 1B —— 地址线 10 根
- 按字寻址：256 个单元 × 4B
- 按半字寻址：512 个单元 × 2B
- 按双字寻址：128 个单元 × 8B

## 3.2.2 SRAM 与 DRAM（**高频对比题**）

| 对比项 | **SRAM（静态 RAM）** | **DRAM（动态 RAM）** |
|---|---|---|
| 存储元 | **双稳态触发器**（约 6 个 MOS 管） | **栅极电容**（1 个 MOS 管） |
| 信息表示 | 触发器两个稳定状态：A 高 B 低 = 1，A 低 B 高 = 0 | 电容有电荷 = 1，无电荷 = 0 |
| 读出是否破坏 | **非破坏性读出** | **破坏性读出** |
| 读出后需要重写（再生）？ | **不需要** | **需要**（读出后立即重写） |
| 运行速度 | **快** | 慢 |
| 集成度 | 低 | **高** |
| 发热量 / 功耗 | 大 / 高 | **小 / 低** |
| 存储成本 | 高 | **低** |
| 是否易失 | 易失 | 易失 |
| 是否需要刷新 | **不需要** | **需要**（一般 **2ms** 刷一次） |
| 地址送法 | **一次送完**（行列同时送） | **分两次送**（行地址、列地址分时送） |
| 常用作 | **Cache** | **主存** |

> [!danger] 必背三句话
> 1. **核心区别在"存储元"不一样**：触发器 vs 电容。
> 2. **DRAM 是破坏性读出**，所以读出后要"再生"；**DRAM 还要定时刷新**（刷新由存储器独立完成，不需要 CPU 干预，但**占用读写周期**）。
> 3. **DRAM 地址分两次送**（地址线复用），所以地址引脚可以减半。

## 3.2.3 DRAM 的刷新

**四个基本问题**（讲义原文顺序）：

| 问题 | 答案 |
|---|---|
| ① 多久刷新一次？ | **刷新周期一般为 2ms**（电容电荷只能维持约 2ms） |
| ② 每次刷新多少单元？ | **以行为单位，每次刷新一整行** |
| ③ 如何刷新？ | 由**硬件支持**：读出一行信息后**重新写入**，占用 **1 个读/写周期** |
| ④ 什么时刻刷新？ | 见下面三种策略 |

**三种刷新策略**（讲义例题：DRAM 内部 128×128，读/写周期 0.5μs，$2\text{ms}/0.5\mu s = 4000$ 个周期）

| 策略 | 做法 | 结果 |
|---|---|---|
| **集中刷新** | 在 2ms 内集中安排一段时间把 128 行全部刷新完 | 有 **访存"死区"**：128 个周期（$128\times0.5\mu s = 64\mu s$）不能访存；其余 3872 个周期（1936μs）正常读写 |
| **分散刷新** | 每次读写完就刷新一行 | **无死区**，但系统**存取周期变为 1μs**（0.5μs 读写 + 0.5μs 刷新）→ **速度变慢** |
| **异步刷新** | 把 128 次刷新平均分散到 2ms 内：每 $2\text{ms}/128 = 15.6\mu s$ 刷新一行 | 每 15.6μs 内有 **0.5μs 死时间**，死时间很短（可在**译码阶段**刷新）→ 综合最优 |

> [!tip] 记忆
> **集中刷新区间长但死区大；分散刷新无死区但整体变慢；异步刷新是两者的折中，最常用。**

## 3.2.4 DRAM 的行列地址与地址线复用

**为什么要用行列地址？**

若 $2^{n}$ 个存储单元排成一列，需要 $2^{n}$ 根选通线。若排成 $2^{n/2}\times 2^{n/2}$ 的**矩阵**，则只需：

$$
2^{n/2} + 2^{n/2}\ \text{根选通线}
$$

> 例：$2^{8} = 256$ 个单元 → 排成 $16\times16$ 矩阵，选通线从 256 根降到 $16+16 = 32$ 根。

**地址线复用（DRAM 特有）**：

- DRAM 的**行地址与列地址位数相等**，**分两次送**（先送行地址，再送列地址）
- 送两次 ⇒ **地址线、地址引脚数量减半**
- SRAM 不需要复用，一次送完

> [!warning] 易错
> 问"DRAM 芯片有 n 位地址，需要几根地址线"→ 注意是**芯片外部引脚**还是**芯片内部地址位数**。
> 芯片采用地址复用后，**外部引脚数 ≈ 内部地址位数 / 2**。

## 3.2.5 只读存储器 ROM

**共同点**：**非易失性**，断电后信息不丢失；很多 ROM 也具有"随机存取"特性。

| 类型 | 写入方式 | 可重写？ | 备注 |
|---|---|---|---|
| **MROM**（掩模式） | 厂家按客户需求在**生产过程中直接写入** | 不可 | 可靠性高、灵活性差、生产周期长、适合批量定制 |
| **PROM**（可编程） | 用户用专门的 **PROM 写入器**写入 | **写一次**后不可改 | — |
| **EPROM**（可擦除可编程） | 用户可写入，用某种方法擦除后可多次重写 | 可多次 | **UVEPROM**：用**紫外线照射 8~20 分钟**擦除**全部**信息（不可局部擦除） |
| **EEPROM**（电可擦除可编程） | 用**电擦除**方式 | 可多次 | 可以**擦除特定的字**（可局部擦除），写入时间长 |
| **Flash（闪速存储器）** | 在 EEPROM 基础上发展 | 可多次快速擦除重写 | U 盘、SD 卡就是闪存；**必须先擦除再写入 ⇒ 写速度比读速度慢** |
| **SSD（固态硬盘）** | 控制单元 + Flash 芯片 | 可多次 | 与闪存核心区别在**控制单元**；速度快、功耗低、价格高 |

> [!important] 考点
> 1. **每个存储元只需单个 MOS 管，位密度比 RAM 高。**
> 2. **闪存的"写"比"读"慢**，因为写入前要先擦除。
> 3. 计算机内的重要 ROM：**主板 BIOS 芯片**里的"自举装入程序"，负责开机时引导装入操作系统。
> 4. 逻辑上主存 = RAM + ROM，二者常**统一编址**；主板上的 ROM 也是"主存"的一部分。

## 3.2.6 双端口 RAM（**408 大纲已删**，了解即可）

> [!warning] 大纲已删除
> `3.2.4` 讲义明确说明：**双端口 RAM 已从 408 大纲删除**，408 考生简要了解即可（部分自命题院校仍会考）。

- 有**两组完全独立的**数据线、地址线、控制线，允许两个独立控制器**同时异步**访问存储单元
- 作用：优化**多核 CPU 访问同一根内存条**的速度
- 两个端口同时对同一地址单元操作时的 4 种情况：

| 情况 | 结果 |
|---|---|
| 同时对**不同**地址单元存取 | 正常，不冲突 |
| 同时对**同一**地址单元**读** | 正常，不冲突 |
| 同时对**同一**地址单元**写** | ❌ **写入错误** |
| 同时对同一地址单元，**一个写一个读** | ❌ **读出错误** |

- **解决方法**：置"忙"信号为 0，由判断逻辑决定**暂时关闭一个端口**（被延时的端口稍后再访问）
- 类比操作系统的**"读者-写者问题"**

## 3.2.7 多模块存储器（**考试重点**）

**为什么要多模块？** CPU 读写速度比主存快很多，且 DRAM 存取周期 $T$ 远大于存取时间 $r$（恢复时间长），一根内存条"缓不过来"。

$$
\text{存取周期 } T \gg \text{存取时间 } r \quad(\text{如 } T = 4r)
$$

### ① 单体多字存储器

- 每个存储单元存放 **m 个字**，总线宽度也是 m 个字
- 一次**并行读出 m 个字**
- 缺点：**每次只能同时取 m 个字，不能单独取其中某个字**；要求**指令和数据在主存内必须连续存放**

### ② 多体并行存储器

条件：每个模块容量、存取速度相同，各自有独立的读写控制电路、地址寄存器和数据寄存器，既能**并行工作**又能**交叉工作**。

| | **高位交叉编址（顺序方式）** | **低位交叉编址（交叉方式）** |
|---|---|---|
| 体号位置 | **高位地址是体号**，低位是体内地址 | **低位地址是体号**，高位是体内地址 |
| 地址公式 | 地址 = 体号 ‖ 体内地址 | 地址 = 体内地址 ‖ 体号 |
| 连续地址分布 | 集中在**同一个体**内 | **分散在各体**中 |
| 效果 | 相当于**单纯扩容**（加内存条扩容） | 采用**流水线**方式并行存取（宏观并行、微观串行），**提高带宽** |
| 俗称 | — | **"双通道"** |

> [!important] 低位交叉的定量结论（必背）
> 设存取周期 $T$、存取时间 $r$、模块数 $m$：
>
> **① 连续读取 n 个字所需时间：**
> $$
> t = T + (n-1)\,r
> $$
>
> **② 为保证流水线不间断，模块数必须满足：**
> $$
> m \ge \frac{T}{r}
> $$
>
> **③ 宏观上，一个存取周期内 m 体交叉存储器可提供的数据量为单个模块的 m 倍。**

**典型例题**：设 $T = 4r$，采用低位交叉编址多体存储器，问至少需要几个存储体？连续读 8 个字需要多长时间？

- 模块数 $m \ge T/r = 4$ → **至少 4 个**
- 连续读 8 个字：$t = T + (8-1)r = 4r + 7r = 11r$
- 若不用交叉（单模块）：$t = 8T = 32r$ → 加速比约 $32/11$

> [!tip] 买内存条的现实版
> 选**相同主频、相同容量**的两根内存条，插在主板对应插槽上组成**双通道**（即低位交叉），带宽翻倍。

## 3.2.8 自测

1. 为什么 DRAM 需要刷新而 SRAM 不需要？
2. 一种 DRAM 芯片内部有 1M 个存储单元，若采用行列地址复用，外部地址引脚至少几根？
3. 低位交叉编址、$T = 5r$、共 4 个存储体，连续读 10 个字需多长时间？该配置能否保证流水线不间断？

<details>
<summary>答案</summary>

1. DRAM 用**栅极电容**存信息，电容会漏电，电荷只能维持约 2ms，必须周期性刷新（充电）；SRAM 用**双稳态触发器**，只要不断电状态就保持，不需要刷新。
2. $10^6 \approx 2^{20}$ → 内部地址 20 位，行列各 10 位，采用复用后外部地址引脚约 **10 根**。
3. $t = T + (10-1)r = 5r + 9r = 14r$。模块数需满足 $m \ge T/r = 5$，实际只有 4 个 → **不能**保证流水线不间断（会插入等待）。

</details>

# 3.3 主存储器与 CPU 的连接

> 📎 **对应讲义**：`3.3 主存储器与CPU的连接.pdf`

## 3.3.1 单块存储芯片与 CPU 的连接

| 芯片引脚 | 连到 CPU 的 |
|---|---|
| 地址线 | 地址总线（低位部分） |
| 数据线 | 数据总线（宽度 = 存储字长） |
| 片选线 $\overline{CS}$ | 由地址总线高位经**译码**产生 |
| 读控制线 $\overline{OE}$ / 写控制线 $\overline{WE}$ | 读/写控制总线（低电平有效） |

> 现在计算机把 MAR、MDR 集成到 CPU 内部，存储芯片内只留一个普通寄存器暂存输入输出数据。

## 3.3.2 位扩展（增加存储字长）

**动机**：数据总线宽度 > 存储芯片字长。

**做法**：把多片芯片的**地址线、片选线、读写控制线全部并联**，**数据线分别引出**（每片负责数据总线的一段）。

> **例**：用 8 片 `8K × 1位` 芯片 → 组成一个 `8K × 8位` 的存储器，容量 **8KB**。
> 8 片同时被选中，每片提供 1 位，合起来 8 位。

- 位扩展**不增加存储单元个数**，只增加字长。
- 位扩展后芯片组**共用一个片选信号**。

## 3.3.3 字扩展（增加存储单元个数）

**动机**：需要更多存储单元（更大容量），芯片字数不够。

**做法**：把多片芯片的**地址线、数据线、读写控制线并联**，**片选线分开**，用地址总线的高位去**选择不同的芯片**。

**两种片选方式（高频对比）**：

| | **线选法** | **译码片选法** |
|---|---|---|
| 实现 | 用 $n$ 根高位地址线**一一对应**作为片选信号 | 用 $n$ 根高位地址线经**译码器**产生 $2^{n}$ 个片选信号 |
| 片选信号数 | $n$ 条线 → **$n$ 个** | $n$ 条线 → **$2^{n}$ 个** |
| 电路 | **简单** | 复杂 |
| 地址空间 | **不连续**（有空洞） | **连续** |
| 举例（2 根高位线） | 选片信号只能是 `01` 或 `10`（一次只能有一位有效） | 产生 `00`/`01`/`10`/`11` 四个片选 |

> [!warning] 线选法为什么地址不连续
> 线选法要求同一时刻**只有一个片选有效**，因此像 `00`、`11` 这样的组合被浪费掉，对应的地址区间成为**空洞**。
> 译码片选法把 $n$ 根线全部利用，$2^{n}$ 个组合都有意义，所以地址**连续**。

**译码器补充**：译码器有**使能端 Enable**（作用类似 CS），可用 CPU 的访存请求信号控制片选信号的**生效时间**——先送地址、等地址稳定后再发出存储器请求信号。

## 3.3.4 字位同时扩展

既增加存储单元个数、又增加存储字长：先按"字"分**组**，每组内部按"位"并联。

> **例**：用 `1K × 4位` 芯片组成 `4K × 8位` 存储器
> - 需要的芯片数 $= \dfrac{4\text{K}}{1\text{K}} \times \dfrac{8}{4} = 4 \times 2 = \mathbf{8}$ **片**
> - 地址总线 $= \log_2 4\text{K} =$ **12 根**
> - 片内地址（低位）$= \log_2 1\text{K} =$ **10 根**
> - 片选地址（高位）$= 12 - 10 =$ **2 根** → 译码产生 **4 个片选**，每个片选对应 **2 片并联**（构成 8 位）

**连接要点**：

1. 地址总线的**低 10 位**接所有芯片的地址线；
2. 地址总线的**高 2 位**送译码器，译码输出（4 个）分别接 4 组芯片的片选；
3. 每组内 2 片的数据线分别接**数据总线的高 4 位 / 低 4 位**；
4. 所有芯片的读写控制线并接。

## 3.3.5 解题模板（主存扩展）

> 给定"用 `A字 × B位` 芯片构成 `M字 × N位` 存储器"，求片数、地址线分配、片选。

**步骤**

1. **片数** $= \dfrac{M}{A} \times \dfrac{N}{B}$（前者为字扩展倍数，后者为位扩展倍数）
2. **总地址线位数** $= \log_2 M$
3. **片内地址线位数** $= \log_2 A$
4. **片选地址线位数** $= \log_2 M - \log_2 A$
5. 片选信号个数 $= M/A$（译码器输出个数）
6. 每组的芯片数 $= N/B$（这组芯片**共享一个片选**，数据线分别接 N 位数据总线的不同段）
7. 写出各组的**地址范围**（从低位地址全 0 开始依次分配）

**地址范围写法示例**（接上面 4K×8 的例子）：
- 第 0 组（片选 `00`）：`0000 0000 0000 0000` ~ `0011 1111 1111 1111` = 000H ~ 3FFH
- 第 1 组（片选 `01`）：400H ~ 7FFH
- 第 2 组（片选 `10`）：800H ~ BFFH
- 第 3 组（片选 `11`）：C00H ~ FFFH

## 3.3.6 自测

1. 用 `2K × 8位` 的芯片组成 `16K × 8位` 的存储器，需要几片？地址线怎么分配？
2. 线选法与译码片选法各有什么优缺点？
3. 位扩展和字扩展分别改变存储器的什么参数？

<details>
<summary>答案</summary>

1. 片数 $=16\text{K}/2\text{K}=8$ 片。总地址线 $\log_2 16\text{K}=14$ 根；片内地址 $\log_2 2\text{K}=11$ 根；片选地址 $14-11=3$ 根 → 经译码器产生 8 个片选信号，地址空间连续。
2. 线选法电路简单但**地址空间不连续**；译码片选法电路复杂但**地址空间连续**、利用率高。
3. **位扩展**增加**存储字长**（数据线宽度）；**字扩展**增加**存储单元个数**（容量）。

</details>

# 3.4 外部存储器

> 📎 **对应讲义**：`3.4.1 磁盘存储器.pdf`、`3.4.2 固态硬盘SSD.pdf`

## 3.4.1 磁盘存储器的组成与磁记录原理

**外存储器又称辅助存储器**，目前主要使用**磁表面存储器**。外存储器**既可以作输入设备，也可以作输出设备**。

**磁表面存储**：把磁性材料涂在金属铝/塑料表面作载磁体存储信息。磁盘、磁带、磁鼓都属于磁表面存储器。

> [!note] 磁表面存储器的优缺点
> **优点**：① 存储容量大、位价格低；② 记录介质可重复使用；③ 记录信息可长期保存、可脱机存档；④ **非破坏性读出**，读出时不需要再生。
> **缺点**：① 存取速度慢；② 机械结构复杂；③ 对工作环境要求较高。

**磁盘的物理结构**：

```
盘片（若干记录面）→ 每个记录面分若干磁道 → 每条磁道分若干扇区
```

- **扇区（块）是磁盘读写的最小单位** —— 磁盘**按块**存取
- **柱面**：一个盘组中，不同记录面上**相同编号（位置）的诸磁道**构成一个圆柱面

**磁盘存储器由三部分组成**：

| 部件 | 说明 |
|---|---|
| **磁盘驱动器** | 核心是**磁头组件**和**盘片组件**；"温彻斯特盘"是可移动磁头、固定盘片的硬盘 |
| **磁盘控制器** | 硬盘存储器与主机的**接口**，主流标准 IDE、SCSI、SATA |
| **盘片** | 记录介质 |

**磁记录原理**：磁头与磁性记录介质**相对运动**时，通过**电磁转换**完成读/写。
- **编码方法**：把二进制信息变换成磁层中磁化翻转状态的序列
- **磁记录方式**：通常采用**调频制（FM）**和**改进型调频制（MFM）**

## 3.4.2 磁盘的性能指标

### ① 磁盘容量

| 类型 | 定义 |
|---|---|
| **非格式化容量** | 磁记录表面**可以利用的磁化单元总数** |
| **格式化容量** | 按照某种**特定记录格式**所能存储信息的总量 |

> 格式化容量 < 非格式化容量（要扣除地址信息、校验信息等）。

### ② 记录密度

| 密度 | 定义 |
|---|---|
| **道密度** | 沿磁盘**半径方向**单位长度上的磁道数 |
| **位密度** | **磁道单位长度**上能记录的二进制位数 |
| **面密度** | 位密度 × 道密度 |

> [!warning] 高频易错点
> **磁盘所有磁道记录的信息量一定是相等的**（并不是圆越大信息越多），因此**每个磁道的位密度都不同 —— 越靠内侧的磁道，位密度越大。**

### ③ 平均存取时间

$$
\text{平均存取时间} = \text{寻道时间} + \text{旋转延迟时间} + \text{传输时间}
$$

| 组成部分 | 说明 | 常用公式 |
|---|---|---|
| **寻道时间** | 磁头移动到目的磁道 | 题目一般直接给"平均寻道时间" |
| **旋转延迟时间** | 磁头定位到所在扇区 | **平均旋转延迟 = $\dfrac{1}{2r}$**（$r$ 为转速，转/秒） |
| **传输时间** | 传输数据所花时间 | $\dfrac{\text{要传的字节数}}{\text{数据传输率}}$ |

> 若转速为 $r$ 转/分，则平均旋转延迟 $=\dfrac{1}{2}\times\dfrac{60}{r}$ 秒。

### ④ 数据传输率

$$
D_r = r \times N
$$

其中 $r$ 为磁盘转速（转/秒），$N$ 为**每条磁道容量**（字节数）。

**典型计算题**：转速 7200 r/min，每条磁道 1KB，则

$$
D_r = \frac{7200}{60}\text{ 转/s} \times 1\text{KB} = 120\text{KB/s}
$$

## 3.4.3 磁盘地址与工作过程

**磁盘地址的构成**（主机向磁盘控制器发送的寻址信息）：

$$
\text{磁盘地址} = \text{驱动器号} \mid \text{柱面（磁道）号} \mid \text{盘面号} \mid \text{扇区号}
$$

> 讲义例题：系统有 4 个驱动器，每个驱动器带一个磁盘，每个磁盘 **256 个磁道、16 个盘面**，每个盘面划分 **16 个扇区**，则
> - 驱动器号 $= \log_2 4 = 2$ bit
> - 柱面号 $= \log_2 256 = 8$ bit
> - 盘面号 $= \log_2 16 = 4$ bit
> - 扇区号 $= \log_2 16 = 4$ bit
> - **每个扇区地址共 18 位二进制代码**

**硬盘的工作过程**：

- 硬盘的主要操作是**寻址、读盘、写盘**，每个操作对应一个**控制字**
- 工作第一步**取控制字**，第二步**执行控制字**
- 硬盘属于**机械式部件**，读写操作是**串行**的：不可能同一时刻既读又写，也不可能同一时刻读两组或写两组数据

## 3.4.4 磁盘阵列 RAID

**RAID**（Redundant Array of Inexpensive Disks，廉价冗余磁盘阵列）：把多个独立的物理磁盘组成一个独立的**逻辑盘**，数据在多个物理盘上**分割交叉存储、并行访问**，具有更好的存储性能、可靠性和安全性。

| 级别 | 名称 | 特点 |
|---|---|---|
| **RAID0** | 无冗余和无校验的磁盘阵列 | 逻辑上相邻的扇区物理上存到不同磁盘（类比**低位交叉编址的多体存储器**）；几个磁盘交叉并行读写 → **容量与速度提升，但无容错能力** |
| **RAID1** | 镜像磁盘阵列 | 两个磁盘同时读写、**互为备份**；一个坏了可从另一个读；**容量减半**，可靠性最高 |
| **RAID2** | 采用纠错**海明码**的磁盘阵列 | 逻辑上连续的几个 bit 物理上分散存储在各盘；如 4bit 信息位 + 3bit 海明校验位，**可纠正一位错** |
| **RAID3** | **位交叉**奇偶校验的磁盘阵列 | 按位交叉 + 一个校验盘 |
| **RAID4** | **块交叉**奇偶校验的磁盘阵列 | 按块交叉 + 一个校验盘 |
| **RAID5** | **无独立校验盘**的奇偶校验磁盘阵列 | 校验信息分散存放在各盘中 |

> [!important] RAID 的四个收益
> ① 通过**同时使用多个磁盘**提高传输率；② 通过**并行存取**提高数据吞吐量；③ 通过**镜像**提高安全可靠性；④ 通过**数据校验**提供容错能力。
> 在 RAID1～RAID5 中，**无论何时有磁盘损坏，都可以随时拔出受损磁盘再插入好磁盘，数据不会损坏**。

## 3.4.5 固态硬盘 SSD

- SSD 是一种**基于闪存技术**的存储器，与 U 盘没有本质差别，只是容量更大、性能更好
- **结构**：控制单元 + 存储单元（**Flash 芯片**）
  - **块大小：16KB ~ 512KB**
  - **页大小：512B ~ 4KB**
- **优点**：由半导体存储器构成，**没有移动部件** → 随机访问时间比机械磁盘快、无机械噪声和震动、能耗低、抗震性好、安全性高
- **缺点**：**反复写之后闪存块会磨损**，所以 SSD 也容易磨损（写入前必须先擦除，写速度比读慢）

**磨损均衡技术（Wear Leveling）**：让 SSD 中每个闪存块被擦除的次数尽量均衡，从而延长寿命。

> [!tip] 典型寿命计算题（讲义原题）
> 某 SSD 大小 $2^{40}\text{B} = 1\text{TB}$，闪存块的擦写寿命只有 $2^{10} = 1\text{K}$ 次。某人平均每天写 $2^{37}\text{B} = 128\text{GB}$。
> 采用磨损均衡，最理想情况下每个块被擦除次数完全均衡：
> - $1\text{TB} / 128\text{GB} = 8$ 天 → **平均每 8 天所有块被擦一遍**
> - 每个块可擦 $1\text{K}$ 次 → 总寿命 $8 \times 1\text{K} = 8\text{K}$ 天 ≈ **23 年**

## 3.4.6 自测

1. 磁盘的所有磁道容量相等吗？位密度相等吗？
2. 转速 6000 r/min 的磁盘，平均旋转延迟是多少？
3. RAID0 和 RAID1 各自的主要目的是什么？

<details>
<summary>答案</summary>

1. **容量相等**（每条磁道记录的信息量相同）；**位密度不相等**，越靠内侧的磁道位密度越大。
2. $r = 6000/60 = 100$ 转/s，平均旋转延迟 $= 1/(2r) = 1/200\text{ s} =$ **5 ms**。
3. RAID0 目的是**提高速度与容量**（无容错）；RAID1 目的是**提高可靠性**（镜像备份，容量减半）。

</details>

# 3.5 高速缓冲存储器 Cache

> 📎 **对应讲义**：`3.5.1+3.5.2 Cache的基本原理.pdf`、`3.5.3 Cache和主存的映射方式.pdf`、`3.5.4 Cache替换算法.pdf`、`3.5.5 Cache写策略.pdf`

## 3.5.1 Cache 的基本原理

### ① 引入目的

解决 **CPU 与主存速度不匹配** 的矛盾（主存速度远慢于 CPU）。

> 提高访存速度的两条路：**① 更高速的存储单元设计**（成本高）；**② 改进存储体系结构** → 引入 **Cache—主存** 层次。
> 之前讲的双端口 RAM、多模块存储器优化后，速度与 CPU 的差距**依然很大**。

### ② 程序访问的局部性原理（Cache 能生效的理论基础）

| 类型 | 含义 | 典型例子 |
|---|---|---|
| **空间局部性** | 最近未来要用到的信息，很可能与**现在正在使用的信息在存储空间上邻近** | 数组元素、顺序执行的指令代码 |
| **时间局部性** | 最近未来要用到的信息，很可能是**现在正在使用的信息本身** | 循环结构的指令代码 |

> 例：按"行优先"访问二维数组的空间局部性优于按"列优先"访问。
> 基于局部性，可以把 CPU 当前访问地址"周围"的部分数据放到 Cache 中。

### ③ 性能分析（**必考公式**）

$$
\text{命中率 } H = \frac{\text{CPU 欲访问的信息已在 Cache 中的次数}}{\text{总访问次数}}
$$

$$
\text{缺失（未命中）率 } M = 1 - H
$$

设 $t_c$ 为访问一次 Cache 的时间，$t_m$ 为访问一次主存的时间：

| 访问方式 | 平均访问时间 |
|---|---|
| **先访问 Cache，未命中再访问主存**（串行） | $T_a = H\,t_c + (1-H)(t_c + t_m)$ |
| **同时访问 Cache 和主存**，命中则立即停止访主存（并行） | $T_a = H\,t_c + (1-H)\,t_m$ |

> [!important] 讲义例题 3-2
> Cache 的速度是主存的 **5 倍**，Cache 命中率 **95%**，求采用 Cache 后存储器性能提高多少（Cache 与主存同时被访问）。
>
> 设 Cache 存取周期为 $t$，则主存为 $5t$。
> - **同时访问**：命中 $t$，未命中 $5t$ → $T_a = 0.95t + 0.05\times5t = \mathbf{1.2t}$
>   性能为原来的 $5t/1.2t \approx \mathbf{4.17}$ 倍
> - **先访问 Cache 再访问主存**：命中 $t$，未命中 $t+5t$ → $T_a = 0.95t + 0.05\times6t = \mathbf{1.25t}$
>   性能为原来的 $5t/1.25t = \mathbf{4}$ 倍
>
> **同一道题，两种口径差值就在于未命中时是否重复计算那次 Cache 访问时间。**

### ④ 由局部性引出的三个待解决问题

| 问题 | 对应机制 |
|---|---|
| 如何界定被调入的数据范围？ | 把主存"分块"，**主存与 Cache 之间以"块"为单位交换数据** → **映射方式** |
| Cache 满了怎么办？ | **替换算法** |
| CPU 改了 Cache 中的副本，如何保证主存母本一致？ | **Cache 写策略** |

**术语提醒**：操作系统中把主存中的"一个块"也称为"一个页/页面/页框"，Cache 中的"块"也称为"**行**"。

**Cache 的组成**：

| 部分 | 内容 |
|---|---|
| **数据存储体** | 存放主存数据块的副本 |
| **标记阵列** | 每行含：**标记 Tag + 有效位 + （脏位）+ （替换控制位）** |
| **地址映射机构** | 完成主存地址 → Cache 地址的转换 |
| **替换机构** | 未命中且无空闲行时按算法选行淘汰 |

> [!note] 补充
> 每次被访问的主存块，一定会被立即调入 Cache。

## 3.5.2 Cache 与主存的三种映射方式

> 设：物理（主存）地址 $n$ bit，Cache 块大小 $2^{o}$ B，Cache 共 $L$ 块。

### ① 全相联映射

- 主存数据块可以装入 Cache 中的**任何位置**
- 地址划分：`标记 \| 块内地址`，标记 $= n - o$
- 优点：冲突最少、命中率高；缺点：**比较电路规模大**，要跟所有行并行比较

### ② 直接映射

- 主存数据块只能装入 Cache 中**唯一的位置**
- 地址划分：`标记 \| 行号 \| 块内地址`
  - 行号 $= \log_2 L$，标记 $= n - \log_2 L - o$
- 定位：**行号 = 主存块号 mod Cache 行数**（硬件按位取，不需比较）
- 优点：硬件最简单、速度最快；缺点：**冲突最严重**（物理块号相差 $L$ 的整数倍会撞到同一行）

### ③ 组相联映射

- 把 Cache 分成若干**组**：**组间直接映射，组内全相联**
- 地址划分：`标记 \| 组号 \| 块内地址`
  - 组号 $= \log_2 \dfrac{L}{N}$（$N$ 为路数），标记 $= n - \log_2\frac{L}{N} - o$
- 优点：冲突、成本、命中率三者折中；现代 CPU 普遍采用（如 2 路 / 4 路 / 8 路组相联）

### 三种方式对照总表

| | **全相联** | **直接映射** | **N 路组相联** |
|---|---|---|---|
| 定位方式 | 不用定位，**全表比较** | **行号直接算出** | **组号直接算出** |
| 比较范围 | 所有行（并行） | 1 行 | 组内 N 路（并行） |
| 定位字段位数 | 无 | 行号 $\log_2 L$ | 组号 $\log_2(L/N)$ |
| 冲突 | 无 | 最严重 | 折中 |
| 硬件成本 | 最高 | 最低 | 折中 |
| 命中率 | 最高 | 最低 | 折中 |

> [!tip] 一句话记忆
> **全相联"全比"、直接映射"直接算"、组相联"先分组再组内比"。**

### 地址划分通用公式

$$
\text{块内地址位数} = \log_2(\text{Cache 块大小})
$$

$$
\text{标记位数} = \text{物理地址位数} - \text{定位字段位数} - \text{块内地址位数}
$$

$$
\text{定位字段位数} = \begin{cases} 0 & \text{全相联} \\ \log_2 L & \text{直接映射} \\ \log_2(L/N) & \text{N 路组相联} \end{cases}
$$

> [!important] 算完别急着用
> 上面这三个字段里，**只有 Tag 会被真正存进 Cache 行**；
> 行号 / 组号、块内地址都只是 CPU 地址里的"选择信号"。
> 算 Cache 容量时只数"存了什么" → **见第 3.5.7 节**。

## 3.5.3 【强化讲义图 10～图 15】通过物理地址访问 Cache

> [!info] 这一节要解决什么
> 强化讲义图 2 的 **⑥⑦⑧⑨** 只有四个箭头，图 10～图 15 把它展开成 6 种情况：
> **{全相联 / 直接映射 / 2 路组相联} × {命中 / 未命中}**。

**访问 Cache 的完整顺序（通用）**：

```
① 用物理地址的「行号 / 组号」定位到唯一的一行（或一组）
② 比较「Cache 标记」是否与物理地址中的标记字段完全一致
③ 检查「有效位」是否为 1
④ ②③ 同时满足 → Cache 命中 → 用「块内地址」在块中取出目标字节/字
   否则 → 未命中 → 用物理地址访问主存，并把主存块调入 Cache
```

> [!warning] 三个最容易记错的地方
> 1. **有效位必须检查**！图 11 就是"标记匹配但有效位 = 0 → 仍未命中"。
> 2. **直接映射的"行号"是隐含的**（Cache 顺序存放，像数组，行号不单独存）。
> 3. 命中判定的对象是**物理地址**，不是虚拟地址 —— 所以 Cache 与虚拟存储器**解耦**，进程切换不用清 Cache。

### 讲义示例计算（物理地址 `AE866996H`）

```
PA = AE866996H = 1010 1110 1000 0110 0110 1001 1001 0110   (32 bit)
```

| 映射方式 | 划分 | 拆分结果 | 物理意义 |
|---|---|---|---|
| **全相联** | 26 + 6 | 标记 `10101110100001100110100110` ／ 块内 `010110` | 与**所有行**的标记比较 |
| **直接映射**（共 16 行） | 22 + 4 + 6 | 标记 `1010111010000110011010` ／ 行号 `0110` = **6** ／ 块内 `010110` | 必须落在 **第 6 行** |
| **2 路组相联**（8 组 × 2 块） | 23 + 3 + 6 | 标记 `10101110100001100110100` ／ 组号 `110` = **6** ／ 块内 `010110` | 落在 **第 6 组**，组内 2 路任选 |

> **行号 = 6、组号 = 6** 与讲义图 12、图 14 中高亮的行/组完全吻合 ✔
> **块内地址 `010110B = 22`** → 访问的是块内第 22 个字节（图 10 里那个蓝色小方块）。

## 3.5.4 Cache 替换算法

**只在"组相联 / 全相联"且该组（或整个 Cache）已满时才需要。** 直接映射没有选择余地，**不需要替换算法**。

| 算法 | 中文名 | 淘汰谁 | 备注 |
|---|---|---|---|
| **RAND** | 随机算法 | 随机确定被替换的行 | 硬件最简单 |
| **FIFO** | 先进先出 | 最早调入 Cache 的行 | 可能出现 **Belady 异常**（Cache 容量增大命中率反而下降） |
| **LRU** | **近期最少使用** | **最近最久未被访问**的行 | 命中率最高，**最常考手算**；需硬件计数器 |
| **LFU** | **最不经常使用** | 一段时间内**被访问次数最少**的行 | 计数器记录"被访问次数"，新调入行计数从 0 开始 |

> [!important] LRU 的硬件实现（必考细节）
> 给**每一行**配一个**计数器**：
> 1. 某行被**命中** → 该行计数器**清零**，**其余所有行计数器 +1**；
> 2. 需要替换时 → 淘汰**计数值最大**的那一行（即最久未被访问）。
>
> **计数器位数**：$n$ 路组相联时，计数值最大为 $n-1$，故每行计数器只需
> $$
> \lceil \log_2 n \rceil \ \text{位}
> $$
> 例：4 路组相联 → 计数值最大 3 → 每位行需 **2 位**计数器。

> [!warning] LRU 与 LFU 的区别（易混）
> **LRU 看"时间"**（最久没被访问）；**LFU 看"次数"**（被访问次数最少）。
> 一个刚调入 Cache 的行如果被频繁访问，LFU 会一直留着它；LRU 只关心最近有没有被访问。

## 3.5.5 Cache 写策略

### ① 写命中（Write Hit）

| 策略 | 做法 | 特点 |
|---|---|---|
| **写直达法（Write Through / 直写法）** | **同时**把数据写入 Cache 和主存 | 一致性好；**访存频繁**，常配**写缓冲**（先写入缓冲，由缓冲慢慢写主存） |
| **写回法（Write Back）** | **只写 Cache**，并置该行**脏位（修改位）= 1**；**只有该行被替换出去时**才写回主存 | 减少访存次数，性能好；存在**主存与 Cache 不一致**问题，需要脏位 |

### ② 写不命中（Write Miss）

| 策略 | 做法 |
|---|---|
| **写分配（Write Allocate）** | 先把主存块**调入 Cache**，再在 Cache 里写 |
| **非写分配（No-Write Allocate）** | **直接写主存**，不把块调入 Cache |

> [!important] 固定搭配（高频）
> **写直达 + 非写分配**；**写回 + 写分配**。
> 原因：写直达每次都写主存，把块调进 Cache 没有意义；写回需要脏位管理，把块调进来才好统一处理。

## 3.5.6 多级 Cache（大纲新增考点）

现代 CPU 通常有三级 Cache，**越靠近 CPU 越小越快**：

| 层级 | 典型容量 | 典型速度 | 说明 |
|---|---|---|---|
| **L1 Cache** | 几十 KB | 1~4 个时钟周期 | 常**分为指令 Cache 和数据 Cache**（避免结构冒险） |
| **L2 Cache** | 几百 KB ~ 几 MB | 10 个左右时钟周期 | 通常每个核私有 |
| **L3 Cache** | 几 MB ~ 几十 MB | 30~50 个时钟周期 | 多核**共享** |

**命中率的两种口径**：

- **局部命中率**：只统计该级 Cache 自身被访问的次数
- **全局命中率**：统计**所有访存请求**中由该级命中的比例

$$
H_{\text{全局}} = H_1 + (1-H_1)\,H_2
$$

$$
T_{avg}= H_1 t_{c1} + (1-H_1)H_2(t_{c1}+t_{c2}) + (1-H_1)(1-H_2)(t_{c1}+t_{c2}+t_m)
$$

> [!tip] 两级 Cache 例题
> L1 命中率 90%、L2 命中率 80%
> 全局命中率 $= 0.9 + 0.1\times0.8 = 0.98$，即**只有 2% 的请求会访问主存**。

## 3.5.7 Cache 容量怎么算：只有 Tag 要存

> [!important] 一句话结论
> **块内地址位不是 Cache 里"存"的内容，而是 CPU 地址里的"选择信号"。**
> 算 Cache 实际需要多少存储位时，**只数真正存进去的东西：Tag + 数据 + 控制位**。

记号沿用第 3.5.2 节：物理地址 $n$ bit，块大小 $2^{o}$ B（块内地址 $o$ 位），Cache 共 $L$ 行、$N$ 路组相联。

### ① 为何只需额外存储 Tag

一个 Cache 行只有三段：

$$
\boxed{\text{有效位}\;|\;\text{Tag}\;|\;\text{数据块}}
$$

| 组成 | 作用 | 位数 |
|---|---|---|
| **有效位** | 标记这一行是否装了有效数据 | 1 |
| **Tag（标记）** | 记录"装的是主存哪一块"，命中时与 CPU 地址的 Tag 字段比较 | 见 ② |
| **数据块** | 真正的数据 | $2^{o}\times 8$ |
| **脏位**（写回法才配） | 该行是否被改过、换出时要不要写回主存 | 1 |
| **替换位**（LRU 才配） | 该行多久没被使用（口径见第 3.5.4 节） | $\lceil\log_2 N\rceil$ |

CPU 地址却被切成三段：

$$
\boxed{\text{Tag}\;|\;\text{Index（组号 / 行号）}\;|\;\text{Offset（块内地址）}}
$$

| 字段 | 干什么 | 存不存进 Cache 行 |
|---|---|---|
| **Tag** | 与行内 Tag 比较，**确认身份** | ✔ **要存** |
| **Index（组号 / 行号）** | **直接选出**第几组 / 第几行 | ✗ 不存 |
| **Offset（块内地址）** | **直接选出**块内第几个字节 | ✗ 不存 |

为什么 Index、Offset 不用存？因为它们是**选择信号**，硬件按位"读"出来就能用，Cache 没必要记住它们。
以 32B 的块（$o=5$）为例，某一行装入数据后：

```
Byte0  Byte1  Byte2  Byte3  ...  Byte31
  ↑
  │
  └─ Offset 只负责在这 32 个字节里选中一个
```

而 Tag 必须存：CPU 访问某组时，Cache 必须回答"**这一行装的是主存中的哪一块**"，
这件事只有靠 Tag 才能知道。

> [!important] 一般规律
> **地址字段中，通常只有 Tag 需要随 Cache 行保存。**
> Index 找组、Offset 找块内位置、Tag 确认身份 —— 前两个是"找位置"，只有 Tag 是"记身份"。

> [!note] 而不是这样
> ✗ `Tag + 组号 + 块内地址 + 数据`
> 组号、块内地址都来自 CPU 发出的地址，**不需要存进 Cache**。

### ② Tag 位数怎么定

$$
\text{Tag 位}=\underbrace{n}_{\text{物理地址}}-\underbrace{\text{Index 位}}_{\text{定位字段}}-\underbrace{o}_{\text{块内地址}}
$$

Index 位数随映射方式而变（与第 3.5.2 节的地址划分一致）：

| 映射方式 | Index 位数 | Tag 位数 |
|---|---|---|
| 全相联 | 0（无定位字段） | $n-o$ |
| 直接映射 | $\log_2 L$（行号） | $n-\log_2 L-o$ |
| $N$ 路组相联 | $\log_2 (L/N)$（组号） | $n-\log_2(L/N)-o$ |

> [!tip] 记忆
> 映射越"定死"，需要比较的部分越短：全相联 Tag 最长，直接映射 Tag 最短。

### ③ 总容量怎么算（四步）

1. **块内地址位数**：$o=\log_2(\text{块大小（B）})$。
2. **Index 位数**：按映射方式查 ② 的表（全相联为 0）。
3. **Tag 位数**：$n-\text{Index 位}-o$。
4. **套总公式**：

$$
\begin{aligned}
\text{Cache 总容量}
&= \underbrace{(\,1+\text{Tag 位}+\text{脏位}+\text{替换位}+2^{o}\times 8\,)}_{\text{一个 Cache 行的位数}}\times L \\
&\quad+\text{每组控制位（如有，按题意）}
\end{aligned}
$$

> [!warning] 一处最容易漏，一处最容易多
> - **容易漏**：每行控制位。有效位永远要加；**脏位只有写回法才配**；**替换位只有 LRU 才配**（直接映射不需要替换算法，也就没有替换位）。
> - **容易多**：把 Index 位、Offset 位也算进去 —— 它们是选择信号，一行都不存。

### ④ 额外存储开销

"为了能用而多存"的部分 = Tag + 全部控制位：

$$
\begin{aligned}
\text{每行额外开销} &= \text{Tag 位}+\underbrace{1}_{\text{有效位}}+\underbrace{(\text{脏位})}_{\text{写回法才有}}+\underbrace{(\text{替换位})}_{\text{LRU 才有}} \\
\text{额外开销总量} &= \text{每行额外开销}\times L
\end{aligned}
$$

数据本身的容量是 $2^{o}\times 8\times L$ bit。若题目问**开销占比**：

$$
\text{开销占比}=\frac{\text{额外开销总量}}{\text{Cache 总容量}}
$$

### ⑤ 考场记忆版

$$
\boxed{\text{Tag 要存，Index 和 Offset 不存}}
$$

$$
\boxed{\text{总容量}=(\text{数据位}+\text{Tag位}+\text{每行控制位})\times\text{行数}}
$$

> [!tip] 想看带数字的算例
> 见第 3.5.8 节自测第 4 题（28 位地址、32B 块、8 组 → 行容量 278 bit）。

## 3.5.8 自测

1. 4 路组相联 Cache 用 LRU 算法，每行计数器需要几位？
2. 写直达法与写回法各配哪种写不命中策略？
3. L1 局部命中率 95%，L2 局部命中率 90%，全局命中率是多少？
4. 28 位物理地址、块 32B、8 组组相联：一个 Cache 行（含 1 位有效位 + 1 位脏位）共多少 bit？组号位和块内地址位要不要算进去？

<details>
<summary>答案</summary>

1. 计数值最大为 $4-1=3$ → $\lceil\log_2 4\rceil =$ **2 位**。
2. 写直达 + **非写分配**；写回 + **写分配**。
3. $H = 0.95 + 0.05\times0.9 =$ **99.5%**。
4. 按第 3.5.7 节的四步走：
   ① 块内地址 $o=\log_2 32=5$；② 8 组 → Index $=\log_2 8=3$；③ Tag $=28-3-5=$ **20 bit**；
   ④ 数据 $=32\times8=$ **256 bit**，行容量 $=1+20+1+256=$ **278 bit**。
   组号位（3 bit）与块内地址位（5 bit）**都不算** —— 它们是选择信号，Cache 一行都不存。

</details>

## 3.6.1 基本概念

**引入目的**：解决**主存容量不足**的问题（让程序不必全部装入主存就能运行）。

**三种地址**：

| 地址 | 构成 | 空间 |
|---|---|---|
| **虚地址（逻辑地址）** | 虚地址 = **虚页号 + 页内地址** | 虚拟空间 / 程序空间 |
| **实地址（物理地址）** | 实地址 = **实页号（页框号）+ 页内地址** | 主存的地址空间 |
| **辅存地址** | 辅存地址 = **磁盘号 + 盘面号 + 磁道号 + 扇区号** | 辅存（磁盘） |

> [!tip] 关键点：**页内地址完全相同**
> 虚地址与实地址的**页内偏移位数一定相等**，地址变换时这一部分**原样搬过去**，不需要翻译。

**虚拟存储器的四个组成部分**（大纲考点）：

| 组成 | 作用 |
|---|---|
| **页表机制** | 通过查表获取虚页号到实页号的映射信息 |
| **中断机制** | 要访问的页不在内存时产生**缺页中断** |
| **地址变换机构** | 把逻辑地址变换成物理地址（MMU） |
| **内存和外存** | 需要一定容量的内存和外存支持 |

**三种基本分类**（详见 3.6.5 节）：

| | 页式 | 段式 | 段页式 |
|---|---|---|---|
| 划分 | 固定大小的页 | 按逻辑结构分段，长度各异 | 先分段，段内再分页 |
| 虚拟地址 | 虚页号 + 页内地址 | 段号 + 段内地址 | 段号 + 段内页号 + 页内地址 |

## 3.6.2 页式虚拟存储器与页表

**空间划分**：

```
虚拟地址 = 虚页号（VPN）        + 页内地址
实地址   = 实页号（页框号 PPN） + 页内地址     ← 页内地址相同
```

**页表**：实现虚实地址变换的对照表，**存放在主存中**（所以叫"慢表"）。

**页表记录的信息**：
- **虚页号与实页号的对照信息**
- **装入信息（有效位/装入位）**：该页是否已装入主存

**页表项（PTE）的字段**：

| 字段 | 位数 | 作用 |
|---|---|---|
| 虚页号 / 页号 | 隐含，不存 | 页表项顺序存放，**下标就是页号** |
| **有效位（装入位）** | 1 bit | 1 = 已调入主存；0 = 不在主存 → 触发**缺页** |
| **实页号（页框号）** | 取决于物理地址 | 该页在主存中的页框号 |
| 修改位（脏位） | 1 bit | 被写过 → 换出时要写回辅存 |
| 访问位 | 1 bit | 供置换算法使用 |
| 外存地址 | — | 该页在辅存中的位置 |

**优缺点**（教材原文口径）：

| | 页式虚拟存储器 |
|---|---|
| **优点** | **页面长度固定、页表简单、调入方便** |
| **缺点** | **页不是逻辑上独立的实体，处理保护和共享不方便** |

**页表大小公式**：

$$
\text{单级页表项数} = 2^{\text{虚页号位数}},\qquad
\text{单级页表大小} = 2^{\text{虚页号位数}} \times \text{页表项大小}
$$

**页表项地址**：

$$
\text{页表项地址} = \text{页表始址} + \text{页号} \times \text{页表项大小}
$$

**两级页表**：当虚页号位数很大（如 24 bit）时，单级页表需要 $2^{24}\times4\text{B}=64\text{MB}$ 连续空间，太浪费 → 把虚页号再切成两半，**页目录（一级页表）+ 页表（二级页表）**，二级页表可按需建立。

$$
\text{虚页号} = \text{页目录号} \mid \text{页号}
$$

> [!note] 页表始址寄存器
> 页表始址存放在进程 PCB 中；CPU 内有**页表始址寄存器**（在 MMU 内），进程切换时由 PCB 更新。
> 页表项 = 页表始址 + 页号 × 页表项大小 → **一次访存**。

> [!tip] 记忆口诀

### 图 2《完整流程 ①～⑨》

![[02_图2_地址转换完整流程.jpg]]

| 步骤 | 讲义原文 | 说明 |
|---|---|---|
| **①** | 用虚拟页号查快表 | 拿 **虚页号 VPN** 去查 **TLB（快表）** |
| **②** | 若快表命中，则直接得到页框号 | TLB 命中 → **完全跳过页表** |
| **③** | 若快表未命中，用虚拟页号查慢表 | 回落到**主存中的页表**（慢表） |
| **④** | 通过查慢表得到页框号 | 页表里读到页框号 |
| **⑤** | "页框号"拼接"页内偏移量"得到完整的物理地址 | `PA = 页框号 ‖ 页内偏移`，**不是加法** |
| **⑥** | 用物理地址访问 Cache | 切到计组的地盘 |
| **⑦** | 若 Cache 命中，直接得到目标数据 | 结束 |
| **⑧** | 若 Cache 未命中，用物理地址访问主存 | 继续往下 |
| **⑨** | 从主存中得到目标数据 | 结束（同时把该主存块调入 Cache） |

> [!warning] 最容易错的一步：⑤ 是"拼接"不是"相加"
> $$
> \text{物理地址} = (\text{页框号} \ll \text{页内偏移位数}) \mid \text{页内偏移}
> = \text{页框号}\times 2^{\text{偏移位数}} + \text{页内偏移}
> $$
> 讲义示例：`AE866H ‖ 996H = AE866996H`。

### 图 4《全相联 TLB 命中 + 不用查页表》

![[04_图4_全相联TLB命中_不查页表_单级.jpg]]

- **绿色字**：全相联映射 TLB
- **TLB 表项结构**：`TLB 标记 (24bit) | 有效位 (1bit) | 页框号 (20bit)`
- **①.a** 用**虚拟页号**与 TLB 中**每一行**的 TLB 标记比较
- **①.b** 只有虚拟页号与标记**完全一致、且有效位为 1** 才算 TLB 命中
- **②** 命中 → **直接得到页框号**，页表压根不用查
- 讲义原注：**虚拟页号和 TLB 标记的比较速度非常快，由硬件电路实现，全部 TLB 标记同时并行对比**

**访存次数 = 1 次**。这是最快的一条路径。

> [!important] 为什么全相联 TLB 的"标记"就是"虚拟页号"
> 全相联 = 任意一行都能放任意虚页号，所以**整个 24 位虚页号都必须参与比较**，
> **标记位数 = 虚页号位数 = 24 bit**。

### 图 5《全相联 TLB 未命中 + 查一级页表》

![[05_图5_全相联TLB未命中_查一级页表.jpg]]

虚页号 `98521H` 与所有 TLB 标记**都不匹配**（图中打红叉）。

- **①.b** 不匹配 → **TLB 未命中**
- **③** 用虚拟页号查**慢表** → **③.a** 查页表 → `98521H → 有效位 1 → 页框号 AE866H`
- **④ → ⑤ → ⑥ → ⑦/⑧ → ⑨**

**访存次数 = 2 次**。

> [!tip] TLB 未命中之后要**回填 TLB**
> 查到页表项后，通常把它**写入 TLB**（替换掉某个旧表项），下次访问同一页就能命中 TLB。

### 图 6《地址转换：查二级页表》

![[06_图6_查二级页表.jpg]]

**场景**：无 TLB，虚页号 24 bit 被切成 **12 bit 页目录号 + 12 bit 页号**。

- **③.a 查页目录（一级页表）**：用**页目录号 `985H`** 作下标
  → 页目录项 `985H | 1 | 11111H`（`11111H` = 二级页表所在页框号）
- **③.b 查页表（二级页表）**：用**页号 `211H`** 作下标
  → 页表项 `211H | 1 | AE866H`
- **④** 得到页框号 `AE866H` → ⑤ 拼接 → ⑥ …

**访存次数 = 3 次**（页目录 1 次 + 二级页表 1 次 + 取数据 1 次）。

> [!note] 一级页表（页目录）也有有效位
> 页目录项有效位 = 0 表示对应二级页表**还没建立**，同样归入缺页处理。
> 图 6 把一级页表画成"占一整页"（项数 $2^{12}$）。

### 图 7《全相联 TLB 未命中 + 查二级页表》

![[07_图7_全相联TLB未命中_查二级页表.jpg]]

把图 5（TLB 未命中）和图 6（二级页表）**串起来**：

- ①.a / ①.b：虚页号与全相联 TLB 的标记比较 → 不匹配，**TLB 未命中**（红叉）
- ③ 落到慢表 → **③.a 查目录**（985H → 11111H）→ **③.b 查二级页表**（211H → AE866H）
- ④ → ⑤ → ⑥ → ⑦/⑧ → ⑨

**访存次数 = 3 次**。

> [!danger] 这是"最慢的正常路径"
> TLB 未命中 + 二级页表 = 每次访问都要多访存 2 次。
> 所以**加大 TLB 命中率**（增大容量、用组相联、提高局部性）是性能关键。

### 图 8《全相联 TLB 命中 + 不用查页表》（二级页表背景）

![[08_图8_全相联TLB命中_不查页表_二级.jpg]]

和图 4 标题相同，**区别在于背景的页表是二级的**（图里画出了 `页目录号 12bit | 页号 12bit`）。

**它要说明的道理**：只要 TLB 命中，**不管底层是一级、二级还是三级页表，都一律跳过**，直接拿页框号。

> [!tip] 结论（考点）
> TLB 里存的**不是**"页号→页框号"的中转项，而是**页表项本身的副本**（虚页号 + 页框号 + 有效位等）。
> 所以 **TLB 命中就等于"页表命中"，与页表几级无关。**

**访存次数 = 1 次**。

### 一张图理清所有分支

```
CPU 给出虚拟地址 VA
        │
        ├─ 拆成 虚页号 VPN + 页内偏移
        │
        ├─ ① 查 TLB ──── 命中 ──► 直接得页框号 ──┐
        │                                         │
        └─ 未命中                                 │
              │                                   │
              ├─（一级页表）用 VPN 作下标查页表 ──┤  访存 1 次
              │        └ 有效位=0 → 缺页中断 ─────┤
              │                                   │
              └─（二级页表）页目录号 → 目录项     │  访存 2 次
                        → 页号 → 页表项 ──────────┘
                                                  │
                          ⑤ 拼接：页框号 ‖ 页内偏移 → 物理地址 PA
                                                  │
                    ⑥ 用 PA 访问 Cache ── 命中 ─► ⑦ 取数据
                                                  │
                                            未命中
                                                  │
                    ⑧ 用 PA 访问主存 ─────────► ⑨ 取数据（并调块入 Cache）
```

（各分支的访存次数汇总见第 3.7.4 节。）

## 3.6.4 快表 TLB

### 为什么需要快表

查页表要**访存**（页表在主存中），使每次取数至少要访存 **2 次**（查页表 + 取数据）。为减少访存，把**当前最常用的页表项**放到一个小容量的**高速存储器**中，构成**快表（TLB）**。

- **快表 TLB** = **页表的 Cache**，对快表的查找和管理**全部由硬件实现**
- **慢表 Page** = 主存中的页表
- **注**：查找时，**快表和慢表是一起查的**；若快表找到了，慢表查找停止；快表没找到就继续在慢表查；**都没查到则执行页面替换策略**

### TLB 的性质

| 项目 | 说明 |
|---|---|
| 本质 | **页表项的副本**（不是"页号→页框号"的简化表） |
| 位置 | **MMU 内部**，MMU 集成在 **CPU** 中 → **属于 CPU** |
| 组成 | **SRAM**，速度极快 |
| 本质器件 | **相联存储器（CAM）**，**按内容访问** |
| 容量 | 很小（几十~几百项） |
| 依据 | **程序局部性原理** |

### 图 9《4 路组相联 TLB 命中 + 不用查页表》

![[09_图9_4路组相联TLB命中_不查页表.jpg]]

**绿色字 & 注释**：TLB 采用**4 路组相联**映射，**共 8 组，每组 4 行**。

讲义示例虚拟页号：`VPN = 8FFBFDH`（24 bit）

```
8FFBFD H = 1000 1111 1111 1011 1111 1101
组号 = 末 3 位 = 101 B = 5      → 去查第 5 组
标记 = 前 21 位 = 1000 1111 1111 1011 1111 1 = 0x11FF7F
```

| 子步骤 | 讲义原文 | 说明 |
|---|---|---|
| **①.a** | 用虚页号的**后三位**寻找对应的分组 | 组号 = $VPN \bmod 8$ → 第 5 组 |
| **①.b** | 用虚页号的**前 21 bit** 与组内 4 个 TLB 标记**并行**对比 | 组内 4 路同时比 |
| ①.c | 还要比对**有效位**是否为 1 | 标记相同 **且** 有效位 1 才算命中 |
| **②** | 若快表命中，则直接得到页框号 | 命中第 5 组内的某一路 |
| **⑤** | 页框号拼接页内偏移 → 完整物理地址 | 跳过整个页表 |

**访存次数 = 1 次**。

> [!important] 组相联 TLB 的两个位数公式
> $$
> \text{组号位数} = \log_2(\text{组数}),\qquad
> \text{TLB 标记位数} = \text{虚页号位数} - \text{组号位数}
> $$
> 本例：组数 8 → 组号 3 bit；$24 - 3 = 21$ bit 标记。✔

### TLB 命中 / 未命中之后干什么

| 情形 | 硬件动作 | 访存 |
|---|---|---|
| **TLB 命中** | 直接得到页框号 → 拼接得物理地址 | 0 次（地址转换） |
| **TLB 未命中，页表命中** | 按页表（一级/二级）访存查到页框号，**并把该页表项写入 TLB** | 1 次（一级）/ 2 次（二级） |
| **TLB 未命中，页表也缺失** | 触发**缺页中断** → 操作系统调页、改页表 → **重新执行指令** | 更多 |

> [!important] "TLB 未命中" ≠ "缺页"
> - **TLB 未命中**：页在不在主存还不知道，往下查页表；**硬件**可自行处理。
> - **缺页**：页表项有效位 = 0，页**不在主存**，必须由**操作系统**从磁盘调页，代价大。

### 进程切换时的 TLB（高频考点）

| 部件 | 进程切换时 |
|---|---|
| 页表始址寄存器 | **更新**为新进程的页表始址 |
| **TLB** | **全部作废**（所有有效位清 0） |
| Cache | **不需要作废**（不同进程可能共享同一物理页框） |

**原因**：TLB 装的是**当前进程**页表项的副本，换进程后这些映射全部失效。

> [!note] 补充：ASID（地址空间标识符）
> 现代 CPU 给 TLB 表项加一个 ASID 字段，从而切进程时**不必整体清空 TLB**。408 默认按"TLB 全部作废"答题。

## 3.6.5 段式与段页式虚拟存储器

### 段式虚拟存储器

**概念**：段是**按程序的逻辑结构划分**的，**长度各异**。

**虚拟地址划分**：

$$
\text{虚拟地址} = \text{段号} + \text{段内地址}
$$

**段表**：程序的逻辑段与其在主存存放位置的**对照表**，记录：**段号、装入位、段起点（段基址）、段长**。

**虚实地址变换**：

1. 用**段号**查段表 → 得到**段起点**和**段长**（访存 1 次）
2. **检查段内地址 < 段长**，否则越界（保护性异常）
3. 计算实地址 $\text{实地址} = \text{段起始地址} + \text{段内地址}$（**加法**，不是拼接！）
4. 按实地址取数据（访存 1 次）

| | 段式虚拟存储器 |
|---|---|
| **优点** | 段的分界与程序的分界对应、具有**逻辑独立性**；**易于编译、管理、修改、保护、共享** |
| **缺点** | 容易在段间留下**碎片**，造成浪费（**外部碎片**） |

### 段页式虚拟存储器

**概念**：把程序**按逻辑结构划分段，每段再划分固定大小的页**；主存空间也划分为同样大小的页。**段式与页式的结合**。

**虚拟地址划分**：

$$
\text{虚拟地址} = \text{段号} + \text{段内页号} + \text{页内地址}
$$

**虚实地址变换（要经过两级查表，比较费时）**：

1. **段表**：根据段号 → 段表地址，从段表中找到**页表起始地址**
2. **页表**：用段内页号 → 页表地址，在页表中取出**实页号**
3. **实页号 + 页内地址 → 实地址**

$$
\text{访存次数（无快表）} = 3\ \text{次}
$$

> [!important] 三个关键细节
> - 段页式里 **每个段一张页表**（不是整个进程一张），段表项里存的是**页表始址 + 页表长度**，不再存段长。
> - 段页式**每访问一个数据都要查三次表**，开销大 → 必须配**快表（TLB）**。
> - 兼具**分段便于共享保护**与**分页无外部碎片**的优点，代价是软硬件开销最大。

### 三种方式速查

| | 页式 | 段式 | 段页式 |
|---|---|---|---|
| 划分依据 | **物理**等分 | **逻辑**意义 | 先分段、段内再等分页 |
| 大小 | 固定 | 可变 | 段可变、页固定 |
| 地址结构 | 页号 \| 页内偏移 | 段号 \| 段内偏移 | 段号 \| 页号 \| 页内偏移 |
| 地址空间维数 | 一维 | **二维** | 二维 |
| 对用户可见 | 不可见 | **可见** | 可见 |
| 表 | 页表（每进程 1 张） | 段表（每进程 1 张） | 段表 + 页表（**每段 1 张页表**） |
| 表项内容 | 页框号 + 有效位 | **段长 + 段基址** | 段表：页表始址 + 页表长度；页表：页框号 |
| 拼地址 | 页框号 **‖** 偏移 | 段基址 **+** 偏移 | 页框号 **‖** 偏移 |
| 访存（无快表） | 2 次 | 2 次 | **3 次** |
| 碎片 | **内部碎片** | **外部碎片** | 内部碎片 |
| 共享保护 | 不方便 | **方便** | **方便** |

> [!tip] 一句话记忆
> **分页是"为了操作系统方便"，分段是"为了用户方便"。**

## 3.6.6 页面置换算法与缺页

> [!note] 大纲原文
> 置换算法：**OPT、FIFO、LRU、CLOCK、改进型 CLOCK**。

| 算法 | 全称 | 淘汰谁 | 备注 |
|---|---|---|---|
| **OPT** | 最佳置换 | 以后**不再使用**（或最长时间后才用）的页 | 理论最优，**无法实现**，只作基准 |
| **FIFO** | 先进先出 | **最先装入**的页 | 可能出现 **Belady 异常** |
| **LRU** | 最近最少使用 | **最近最长时间未被访问**的页 | 性能接近 OPT，实现开销大 |
| **CLOCK** | 简单时钟 | 环形队列 + **访问位**：转一圈把 1 清 0，遇到 0 就淘汰 | 又称最近未使用（NRU） |
| **改进型 CLOCK** | — | 同时考虑**访问位 a 和修改位 m** | 优先淘汰"**未被访问且未被修改**"的页，减少写回磁盘的开销 |

**改进型 CLOCK 的淘汰优先级**：

```
(a=0, m=0)  ← 最先淘汰（既没访问又没改）
(a=0, m=1)  ← 次之（要写回，代价大）
(a=1, m=0)
(a=1, m=1)  ← 最后考虑
```

### 缺页（Page Fault）与调页

**触发条件**：页表项有效位 = 0（页不在主存）。

**处理流程**：

1. CPU 访问虚拟地址 → MMU 查 TLB → 未命中 → 查页表 → 有效位 = 0
2. 产生**缺页中断（内中断 / 异常）**，CPU 陷入内核态
3. 操作系统从**辅存（磁盘）**把该页调入主存空闲页框；若无空闲页框，按置换算法淘汰一页（**脏页要写回磁盘**）
4. **更新页表项**：填入新页框号，有效位置 1
5. **重新执行**引发缺页的那条指令

> [!warning] 三个易错点
> 1. 缺页是**内中断（异常）**，不是外中断。
> 2. 处理完是**重新执行原指令**，不是接着执行下一条。
> 3. **缺页处理的时间开销远大于 Cache 缺失**：磁盘访问约 $10^5\!\sim\!10^7$ 个时钟周期，主存访问只有 $10^2$ 个数量级。

### 相关寄存器与硬件位置

| 部件 | 位置 | 进程切换时 |
|---|---|---|
| PCB | 主存内核区 | 换出 / 换入 |
| 页表 | 主存内核区 | 不切换 |
| **页表始址寄存器** | **MMU（CPU 内）** | **更新** |
| **TLB（快表）** | **MMU 内，属 CPU，SRAM** | **全部作废** |
| **Cache** | CPU 内，**不属于 MMU** | **不需要作废** |

## 3.6.7 自测

1. 讲义设定下，TLB 采用 **8 组 4 路**组相联，组号几位？标记几位？
2. 某访问 TLB 未命中、页表是二级的、且页表命中。共访存几次？
3. 图 8 和图 4 的标题一样，它到底想强调什么？
4. 段页式中，段表项里存的是什么？为什么不存段长？

<details>
<summary>答案</summary>

1. 组数 $8 = 2^3$ → 组号 **3 bit**；标记 $= 24 - 3 =$**21 bit**。
2. 页目录 1 次 + 二级页表 1 次 + 取数据 1 次 = **3 次**。
3. 强调"**TLB 命中时，页表是几级都无所谓**"——一律跳过页表，直接拿页框号（TLB 存的是页表项的副本）。
4. 存**页表始址**和**页表长度**。因为段长 = 该段页数 × 页大小，由页表长度体现，不需要再单独存段长。

</details>

# 3.7 专题：虚拟存储器 vs Cache 对比

> [!abstract] 一句话贯穿全章
> **虚拟存储器**解决"主存不够用"（虚地址 → 物理地址翻译，由**操作系统 + 硬件**共同管理，缺失代价 = 磁盘 I/O）。
> **Cache**解决"主存太慢"（物理地址 → 数据，**纯硬件**管理，缺失代价 = 一次主存访问）。

## 3.7.1 相同点

| # | 相同点 |
|---|---|
| 1 | 都利用了**程序访问的局部性原理** |
| 2 | 都把**大容量慢速存储**划分成等大的**块**，按块调入小容量快速存储 |
| 3 | 调入后都建立**地址映射**（标记 + 有效位 + 数据），都支持**全相联 / 直接 / 组相联**三类映射 |
| 4 | 都有**映射规则、替换算法、更新（写）策略** 三件套 |
| 5 | 命中/未命中判定都**要检查有效位** |

## 3.7.2 不同点（**可直接作简答题答案**）

| 对比项 | **虚拟存储器** | **Cache** |
|---|---|---|
| **目的** | 解决**主存容量不足**，逻辑上扩大主存 | 解决**主存速度跟不上 CPU** |
| **地址空间** | 虚拟地址空间 → 物理地址空间 | 主存地址 → Cache 地址 |
| **映射对象** | 虚页 → 实页（页框） | 主存块 → Cache 行 |
| **块（页面）大小** | 页，通常**几 KB** | 块，通常**几十 B ~ 几百 B** |
| **数据交换单位** | 页（主存 ↔ 辅存） | 主存块（Cache ↔ 主存） |
| **实现者** | **操作系统 + 硬件**共同实现 | **纯硬件**实现 |
| **透明度** | 对**系统程序员不透明**，对应用程序员透明 | 对**所有程序员都透明** |
| **未命中的名称** | **缺页（Page Fault）** | **Cache 缺失（Cache Miss）** |
| **未命中代价** | 磁盘 I/O，约 $10^5\!\sim\!10^7$ 个时钟周期 | 一次主存访问，约 $10^2$ 个时钟周期 |
| **是否产生中断** | **产生缺页中断**，由 OS 处理 | **不产生中断**，硬件处理 |
| **未命中后的填补** | OS 把页从**磁盘**调入内存并改写页表 | 硬件把块从**主存**调入 Cache |
| **映射表位置** | **页表**在主存（TLB 是其缓存） | **标记**就在 Cache 里 |
| **能否与 CPU 直接通信** | 辅存**不能**与 CPU 直接通信 | Cache **能与 CPU 直接通信** |
| **进程切换** | 页表始址切换，**TLB 全部作废** | **不需要作废** |

> [!danger] 四句必背
> 1. **缺页由操作系统处理（产生中断）；Cache 缺失由硬件处理（不产生中断）。**
> 2. **缺页代价 >> Cache 缺失代价。**
> 3. **页大小 >> Cache 块大小。**
> 4. **虚存不命中对系统性能影响更大**（要访问磁盘）。

## 3.7.3 缺页 与 Cache 缺失 的处理流程对比

**Cache 缺失（纯硬件，几个周期）**

```
查 Cache 未命中
   → 硬件用物理地址访存，取出整个主存块
   → 按替换算法写入 Cache（写回式还要处理脏位）
   → 重新取到数据，程序继续（无中断、无异常）
```

**缺页（陷入内核 + 磁盘 I/O，百万级周期）**

```
查页表发现有效位 = 0
   → 产生缺页中断（内中断 / 异常），CPU 转内核态
   → OS 检查地址合法性（非法 → 段错误 / 保护性异常）
   → 找空闲页框；若无空闲则按置换算法淘汰一页（脏页写回磁盘）
   → 从磁盘把该页读入页框
   → 更新页表项（页框号 + 有效位 = 1），必要时更新 TLB
   → 返回用户态，重新执行原指令
```

## 3.7.4 访存次数总表（考前最后一遍）

> 假设：页表/页目录都放在主存；一次"访存"= 访问一次主存。

| 场景 | 转化地址 | 取数据 | **合计** |
|---|---|---|---|
| TLB 命中（无视页表级数） | 0 | 1 | **1** |
| TLB 未命中 + 单级页表命中 | 1 | 1 | **2** |
| TLB 未命中 + 二级页表命中 | 2 | 1 | **3** |
| 无 TLB + 单级页表命中 | 1 | 1 | **2** |
| 无 TLB + 二级页表命中 | 2 | 1 | **3** |
| 无 TLB + 单级页表**缺页** | 1（未命中）+ 1（重查） | 1 | **3** |
| 无 TLB + **二级页表缺页** | 1 + 2（重查两级） | 1 | **4** |
| 段页式，无快表 | 2（段表 + 页表） | 1 | **3** |
| 段页式，快表命中 | 0 | 1 | **1** |
| 地址转换完成后 Cache 命中 | 0 | 0（数据来自 Cache） | **0 次访存** |

> [!warning] 关于"缺页"的访存次数，说法要跟题干
> 王道常见口径：**无 TLB 时，缺页一共访问内存 3 次**（查页表未命中 1 次 → 缺页处理 → 重新查页表 1 次 → 取数据 1 次）。
> 若题干还要求算"缺页处理程序修改页表"的访存，则再多 1 次（4 次）。
> **答题时先写清假设，再给数字。**

## 3.8.1 公式总表（考前 5 分钟版）

### ① 容量与地址

| 量 | 公式 |
|---|---|
| 存储容量 | 存储单元个数 × 存储字长 |
| $n$ 位地址 | $2^{n}$ 个存储单元 |
| 按某个粒度编址的单元数 | 总容量 ÷ 该粒度字节数 |
| 地址线根数 | $\log_2(\text{存储单元个数})$ |
| DRAM 行列地址复用后外部引脚 | 约 内部地址位数 / 2 |

### ② 主存扩展

| 量 | 公式 |
|---|---|
| 所需芯片数 | $\dfrac{\text{目标字数}}{\text{单片字数}} \times \dfrac{\text{目标字长}}{\text{单片字长}}$ |
| 片内地址位数 | $\log_2(\text{单片字数})$ |
| 片选地址位数 | 总地址位数 − 片内地址位数 |
| 译码器输出（片选）个数 | $2^{\text{片选地址位数}}$（线选法只有 $n$ 个） |

### ③ 磁盘 / SSD

| 量 | 公式 |
|---|---|
| 平均存取时间 | 寻道时间 + 旋转延迟时间 + 传输时间 |
| 平均旋转延迟 | $\dfrac{1}{2r}$（$r$ 为转速，转/秒） |
| 数据传输率 | $D_r = r \times N$（$N$ 为每条磁道容量） |
| 磁盘地址位数 | $\log_2(\text{驱动器数}) + \log_2(\text{柱面数}) + \log_2(\text{盘面数}) + \log_2(\text{每道扇区数})$ |
| 位密度 | 磁道单位长度上的二进制位数（**内圈位密度大**） |
| 面密度 | 位密度 × 道密度 |

### ④ 虚拟存储器

| 量 | 公式 |
|---|---|
| 页内偏移位数 | $\log_2(\text{页面大小})$ |
| 虚页号位数 | 虚拟地址位数 − 页内偏移位数 |
| 实页号（页框号）位数 | 物理地址位数 − 页内偏移位数 |
| 单级页表项数 | $2^{\text{虚页号位数}}$ |
| 单级页表大小 | $2^{\text{虚页号位数}} \times \text{页表项大小}$ |
| 页表项所在地址 | 页表始址 $+$ 页号 × 页表项大小 |
| 实地址 | (实页号 ‖ 页内偏移)，即 实页号 × 页大小 + 页内偏移 |
| 段式实地址 | **段基址 + 段内地址** |
| 二级页表切分 | 虚页号 ÷ 2（前半 = 页目录号，后半 = 页号） |

### ⑤ TLB / Cache

| 量 | 公式 |
|---|---|
| 全相联 TLB 标记 | 虚页号位数 |
| 组相联 TLB 组号 | $\log_2(\text{组数}) = \log_2(\text{TLB行数}/\text{路数})$ |
| 组相联 TLB 标记 | 虚页号位数 − 组号位数 |
| LRU 计数器位数 | $\lceil \log_2 n\rceil$（$n$ 为路数） |
| Cache 块内地址 | $\log_2(\text{块大小})$ |
| 直接映射行号 | $\log_2(\text{Cache 行数})$ |
| 组相联组号 | $\log_2(\text{Cache 块数}/\text{路数})$ |
| 标记位数（通用） | 物理地址位数 − 定位字段位数 − 块内位数 |
| **Cache 行容量**（**不含**组号位/块内地址位） | $\text{Tag位}+\text{数据位}+\text{有效位}+\text{脏位}+\text{其它每行控制位}$ |
| **Cache 总容量** | $\text{行容量}\times\text{行数}+\text{每组控制位}$ |
| 命中率 | $H = \dfrac{\text{命中次数}}{\text{总访问次数}}$ |

### ⑥ 性能

| 量 | 公式 |
|---|---|
| 平均访问时间（先 Cache 后主存） | $T_a = H t_c + (1-H)(t_c+t_m) = t_c + (1-H)t_m$ |
| 平均访问时间（同时访问） | $T_a = H t_c + (1-H)t_m$ |
| 加速比 | $S = t_m / T_a$（或"性能提高多少倍"） |
| 两级 Cache 全局命中率 | $H = H_1 + (1-H_1)H_2$ |
| 主存带宽 | $B_m = \dfrac{\text{数据宽度（存储字长）}}{\text{存取周期}}$ |
| 低位交叉连续读 n 个字 | $t = T + (n-1)r$ |
| 低位交叉流水线不间断条件 | $m \ge T/r$ |

## 3.8.2 六类题的解题模板

### 模板 A｜地址位段划分（最高频）

1. 由页大小求 **页内偏移位数** $o = \log_2(\text{页大小})$。
2. **虚页号位数** $= \text{虚拟地址位数} - o$。
3. **实页号位数** $= \text{物理地址位数} - o$。
4. 若给的是物理空间大小，先求物理地址位数 $= \log_2(\text{空间大小})$（按字节编址）。

### 模板 B｜页表大小 / 级数

1. 页表项数 $= 2^{\text{虚页号位数}}$。
2. 单级页表大小 $= 页表项数 \times 页表项大小$。
3. 若要求"页表恰好占整数页"：**每级切分位数** $= \log_2(\text{页大小}/\text{页表项大小})$。

### 模板 C｜TLB / Cache 标记位数

**口诀：标记 = 总位数 − 定位字段位数 − 块内位数。**

| 对象 | 定位字段 |
|---|---|
| 全相联 TLB | 无 → 标记 = 虚页号位数 |
| 组相联 TLB | 组号 = $\log_2(\text{组数})$ |
| 全相联 Cache | 无 → 标记 = 物理地址位数 − 块内位数 |
| 直接映射 Cache | 行号 = $\log_2(\text{行数})$ |
| 组相联 Cache | 组号 = $\log_2(\text{组数})$ |

### 模板 D｜主存扩展

$片数 = \dfrac{M}{A}\times\dfrac{N}{B}$ → 求片内地址位数、片选位数、译码器输出数 → 画连接 → 写地址范围。

### 模板 E｜平均访问时间 / 命中率

1. 看清题干是"**先查 Cache 未命中再访存**"还是"**同时访问**"。
2. 写公式 → 代入 → 得 $T_a$；加速比 $S = t_m/T_a$。

### 模板 F｜访存次数

1. 画路径：TLB？页表几级？缺页否？Cache 命中否？
2. 逐段累加：**查表次数 + 取数据次数**。
3. 写出结论句，并**声明假设**（是否计入缺页处理程序改页表的访存）。

## 3.8.3 完整示范大题（综合）

> **题干**：某 36 位系统按字节编址，页面大小 4KB，虚拟地址 36 位，物理地址空间 4GB，采用二级页表；
> TLB 采用 8 组 4 路组相联；Cache 块大小 64B，采用 2 路组相联，共 8 组。
> 现有一条指令访问虚拟地址 `98521996H`，查表得到页框号 `AE866H`。求：
> （1）各地址字段位数；（2）TLB 的组号与标记位数；（3）Cache 的组号与标记位数；（4）若 TLB 与 Cache 都命中，共访存几次？

**解**

**(1) 地址字段**

$$
o = \log_2 4\text{KB} = 12\ \text{bit}
$$

- 页内偏移：**12 bit**；虚页号：$36-12=$ **24 bit**
- 物理地址：$\log_2 4\text{GB} =$ **32 bit**；页框号：$32-12=$ **20 bit**

**(2) TLB**（8 组 → 组号 3 bit）

- 组号 $= \log_2 8 =$ **3 bit**；标记 $= 24 - 3 =$ **21 bit**
- 例：若虚页号为 `8FFBFDH`，组号 = 末 3 位 `101B = 5`

**(3) Cache**（8 组 → 组号 3 bit，块 64B → 块内 6 bit）

- 块内地址 $= \log_2 64 =$ **6 bit**；组号 $= \log_2 8 =$ **3 bit**；标记 $= 32-3-6 =$ **23 bit**

验证（`PA = AE866996H`）：

```
1010 1110 1000 0110 0110 1001 1001 0110
标记23 = 10101110100001100110100
组号3  = 110    → 组 6           ← 与讲义图 14 高亮一致
块内6  = 010110 → 块内第 22 字节 ← 与讲义图 10 蓝块一致
```

**(4) 访存次数**

| 阶段 | 访存 |
|---|---|
| TLB 命中 → 地址转换 | 0 次 |
| Cache 命中 → 取数据 | 0 次 |
| **合计** | **0 次访存**（全程不回主存） |

> 若改成"TLB 未命中、页表命中、Cache 未命中"：页目录 1 + 二级页表 1 + 主存取数据 1 = **3 次访存**。

## 3.8.4 易错点清单（考前扫一遍）

| # | 易错点 | 正解 |
|---|---|---|
| 1 | 物理地址 = 页框号 + 页内偏移（加法） | **拼接**：`PA = 页框号 ‖ 页内偏移` |
| 2 | 段式也是拼接 | 段式是 **段基址 + 段内偏移（加法）** |
| 3 | Cache 缺失会产生中断 | **不会**，纯硬件处理 |
| 4 | TLB 未命中就是缺页 | **不一定**，还要看页表项有效位 |
| 5 | 标记匹配就算 Cache 命中 | 还要 **有效位 = 1**（讲义图 11） |
| 6 | 直接映射也要选替换算法 | 直接映射**不需要**替换算法 |
| 7 | 进程切换时 Cache 要作废 | **不需要**；只有 **TLB 要全部作废** |
| 8 | TLB 里存的是"页号→页框号"的简化表 | 存的是**页表项的副本** |
| 9 | 页框大小 = Cache 块大小 | **不同**：页框用于主存↔辅存，块用于主存↔Cache |
| 10 | 一级页表项里没有有效位 | **有**；有效位 0 表示二级页表未建立 |
| 11 | 缺页处理完接着执行下一条指令 | 处理完**重新执行**原指令 |
| 12 | 虚页号位数 = 实页号位数 | 一般**不等**（虚拟空间通常大于物理空间） |
| 13 | 平均访问时间公式随便用 | 先看题干"**串行**"还是"**并行**"，两者差 $(1-H)t_c$ |
| 14 | 多级页表访存次数忘了乘以级数 | **每级都要访存 1 次** |
| 15 | 主存容量扩展时把位扩展和字扩展搞反 | **位扩展**加字长（数据线并分出），**字扩展**加单元数（片选分开） |
| 16 | 线选法地址连续 | **线选法地址不连续**，译码片选法才连续 |
| 17 | 磁盘每条磁道容量不同 / 位密度相同 | **容量相同，位密度不同**（内圈位密度大） |
| 18 | DRAM 刷新由 CPU 控制 | 刷新由**存储器独立完成**，但占用读写周期 |
| 19 | 低位交叉是"扩容" | 低位交叉提高**带宽**；**高位交叉**才是单纯扩容 |
| 20 | 闪存"读比写慢" | **写比读慢**（写入前必须先擦除） |
| 21 | 算 Cache 容量时把组号位、块内地址位也加进去 | **只存 Tag + 数据 + 控制位**；组号/块内地址是 CPU 地址里的选择信号，**一行都不存**（见第 3.5.7 节） |

## 3.8.5 考场 30 秒自检

1. **分清"翻译"还是"取数"**：虚地址→实地址归 OS/TLB/页表；实地址→数据归 Cache/主存。
2. **先画位段**：把虚拟地址、物理地址的位段画成两个格子，一切从这两行格子推出。
3. **数位数**：定位字段（无/行号/组号）+ 块内位数拿走，剩下的就是标记。
4. **数访存**：查表几次 + 取数几次，并声明假设。
5. **查有效位**：命中判定永远要带上有效位。
6. **看措辞**：串行 / 并行；已删除考点（双端口 RAM）不用深究。
7. **算容量只数"存了什么"**：Tag + 数据 + 控制位；**组号位、块内地址位一律不算**（第 3.5.7 节）。
