## Obsidian 字体统一：等宽换衬线等宽 + 整体加粗一档（00:0x）

## 字体方案二次大改：改为 Claude 桌面客户端的字体栈（用户给了 Claude 截图后）

**背景**：用户先抱怨"等宽字体还是很奇怪"，要求"参考苹果的设计方案整体重新调整"，
查完苹果系统字体（SF Mono 步进 0.6182em，会破网格）后，用户直接甩来一张 **Claude 桌面客户端截图**，
说"请你调整成截图的这种字体"。于是方向从"苹果风"改成"照抄 Claude.app 的字体栈"。

- **怎么挖出 Claude 真实字体栈**（关键方法，别只看 `Resources/fonts/`）：
  从前端 CSS/JS 里读设计令牌 —— `--font-ui:var(--font-anthropic-sans)`、
  `--font-mono:var(--font-anthropic-mono,"SF Mono")`，`@font-face` 指向 `assets/v1/*.woff2`。
  即 **Anthropic Sans（正文/界面）+ Anthropic Mono（等宽）**，字重 300–800，都是变量字体。
  woff2 → ttf 用 fontTools（`f.flavor=None` 后 save），实例化时 **pin `opsz=16`**。

- **★ 核心决策：不再"找一款度量完美的字体"，改成"给 Anthropic Mono 补齐字形"**
  - 实测 Anthropic Mono 的 ASCII/框线/运算符步进**恰好 0.6000em**，但缺
    `├ ┤ ┬ ┴ ┼ ↔ ↕ ✔ ‖` 和几乎全部希腊小写字母；一缺字就回退到 Menlo(0.6021)/SF Mono(0.6182)，
    60 列的行能歪出 1.8 列。
  - 先扫真实笔记统计码点（围栏块 + 行内代码，排除 CJK）：**119 种**非 CJK 特殊字符，目标字体缺 **60 种**。
    缺得最狠的是 `├`(290 次)、`α/β/θ/λ/σ`(50–175 次)、`✅`(26 次)。
  - 补法（脚本 `/tmp/claude2/patch_mono.py`，配方已存进 skill 的 `references/glyph-patching.md`）：
    * `├ ┤ ┬ ┴ ┼`：**用本色 `─`/`│` 的矩形直接拼**（同绕向矩形求并，非零环绕自动填实），
      度量与原版逐项一致 —— `├` 实测 `x[+0.2605,+0.6250] y[-0.3200,+1.0200]`。
    * `↔ ↕`：本色 `←`∪`→`、`↑`∪`↓` 求并。
    * 其余 50 个：从 Menlo/Iosevka 借，**按 x 高缩放**（不是 upem），步进单独写成 0.6em，
      水平居中；符号类再把垂直中心对到 **+0.360em**（本色运算符的数学轴线；Menlo 是 +0.314，直接搬会"坐低"）。
    * `⟹ ⟺`：借 Menlo 的 `⇒`/`⇔` 后横向拉伸占满整格。
    * 缺口清单里的 `①-⑨` **故意不给西文层** —— 它们是全角、必须占 2 列，交给中文层。
  - **★★ 最值钱的一步：把竖线拉出行盒**
    朴素做法是量出 `│` 高 1.100em 再把 `line-height` 压到 ≤1.10，但 15px 下 1.10 = 16.5px，
    浏览器把行盒**取整到像素**后可能变 17px → 露 0.5px 白缝，框线又变虚线。
    改为把 `│ ┌┐└┘├┤┬┴┼` 的竖向范围从 asc/desc(1.25em) **拉长到 [-0.32,+1.02]em(1.34em)**，
    相邻行必然重叠 0.09em → `line-height` 取 **1.25**（字体自然行高）即可，容错到 1.30。
    实测：line-height ≤1.30 时竖线**0 空隙**，1.34 才 1px。
    横线不受行高影响 —— 本色已带 0.025em 出血，实测连续 40 个 `─` 在 13–36px 全 0 空隙。
  - 补齐后**逐码点校验：笔记里 118 个特殊字符全部严格 0.6000em**（组合符 0）。
  - 字体改名 **`Quiet Mono West`**（避免与已装的原 Anthropic Mono 撞族），
    同时删掉旧的 `AnthropicMono-{Regular,Bold}.ttf`；**原始实例留在 `/tmp/fonts/`**，重跑从那里出发。

- **中文那侧**：等宽中文用 **Noto Sans SC Wide**（把思源黑体每个字形步进 ×1.2 得到 1.2em = 2 列，
  墨迹重新居中、删 hinting 表）。**不用 CSS `size-adjust:120%`** —— 那会把字号一起放大；
  改步进是"只拉步子，不放字号"。正文中文用普通 **Noto Sans SC**（1.0em，无需加宽）。

## 第二轮（同日稍后）：等宽字体「全量补齐」——把 Menlo 回退彻底关掉

上一轮只补了「笔记里出现过的」缺字（60 个），本轮做了三件事。

### 1) 发现并修掉一个静默 bug：`⟹ ⟺` 从来就没被覆盖过

写脚本时顺手加了 `vault_chars & 声明范围` 求交集。但 `⟹`(U+27F9) `⟺`(U+27FA)
属于 **Supplemental Arrows-A（U+27F0–27FF）**，而 CSS 里只写了 `U+2700-27BF`（Dingbats），
于是这两个字符被**静默滤掉**了 —— 上一轮"补过了"的结论并不成立。
**修复**：脚本改成两边取并集，并主动报警「笔记用到但 CSS 未声明」的码点；
CSS 的 4 处 `U+2700-27BF` 都补成 `U+2700-27BF, U+27F0-27FF`。

### 2) ★ 最大的认知修正：量到 0.6em 不等于字形来自本字体

`--font-monospace` 是 `"Quiet Mono", ui-monospace, "SF Mono", Menlo, monospace`，
而 `ui-monospace` 在 macOS 上解析成 **SF Mono，步进也正好 0.6000em**。
所以某个字符本字体没有字形、回退到 SF Mono 时，`measureText` 量出来**依然是 0.6000em**，
和真命中的结果**完全无法区分**。
→ 结论：**验收必须分两层**。字体层读 ttf 的 `cmap`+`hmtx` 查真值（唯一能证明覆盖的手段），
浏览器层只负责端到端（分流对不对、真实框图排得齐不齐）。
真正会破格的是最后兜底到 Menlo（0.6021em），且误差**沿行累积**：连写 20 个 `═` 就偏 0.6px。

### 3) 按 CSS 声明范围全量补齐（而不是只补用到的）

- 声明范围内应有 **3449** 个码点，原字体只有 617 个 → **补了 2740 个字形**（两字重各一份，字体 60KB → 416KB）。
- 同一批 1520 个美术/框图区段字符，非 0.6em 的从 **1294 个 → 107 个**；
  剩下 107 个全部可解释：23 个彩色 emoji + 14 个零宽格式符(`Cf`) + 10 个空白(`Zs`，故意不补)
  + 60 个任何源字体都没有的冷门装饰符号（`⛰ ⛱ ⛴ ⚳ …`）。
- **字体层自检：步进不合规 0 个**（97.3% 覆盖）。

本轮新学到的三类补法（已写进 `references/glyph-patching.md`）：

- **块元素 `░▒▓▀▄▌▐` 要用「Menlo `█` → 本字体 `█`」的仿射映射**（允许 sx≠sy）。
  普通的"等比缩放+居中"对这类字全错：会把 `▌` 挪到中间、让 `▀▄` 对不齐。
  映射后实测 `▀` y[720,1440] + `▄` y[0,720] 严丝合缝拼成 `█` y[0,1440]，`▌` 守在左半 x[-50,599]。
- **组合符（`Mn`/`Me`）要"步进 0 + 登记 GDEF 的 mark(class 3)"两步**。
  ⚠️ 原字体自带的 `gravecomb`/`acutecomb`/`dotbelowcomb` 等 20 个组合符 `hmtx` **就是 1200**，
  靠 GDEF 归零 —— 这是原字体正当设计，**不要改**；自检判据要写成
  「组合符 `adv ∈ {0,1200}`，且 `adv==1200` 时必须在 GDEF mark 集合里」。
- **新补的符号一律把垂直中心对到 +0.360em**（本字体运算符数学轴线），实测 `⇐⇑⇓⇔↵★☆◆◇○△▽◀▶∧∨∩∪⊂⊃⊕⊗` 全部精确 720。

### 4) 另一个假信号：`ccmp`/`liga` 把连字分解成两个字形

`ŉ`(U+0149) `ﬀﬁﬂ`(U+FB00-02) 量出 **1.2000em**，看着像掉到两格。
实测：只关 `ccmp` 或只关 `liga` 仍是 1.2em，**两个都关才回 0.6em** ——
说明是字体自己的 GSUB 把它们分解成两个字形（0.6×2），**并没有歪**。
验收判据因此要按类别分派（组合符→0；`①-⑳` 与 ccmp 连字→1.2；emoji 豁免），别一律断言 0.6em。

## 10:20–10:40 字号放大 + 修好「公式裸露」

### 起因：用户截图「这里有问题」（公式显示成 `$...$` / `\text{K}` 源码）

排查结论：**不是 CSS 也不是 MathJax 的问题，是笔记里的 Markdown 写法踩了 Obsidian 的硬规则** ——
行内公式 `$...$` 的**定界符内侧不能有空格**（Obsidian 有意这么设计，免得把 "$2.50 … $3.00" 当公式）。
`$ x$` / `$x $` / `$ x $` 一律退化成纯文本原样显示。

写成脚本精确配对后（正则做不到配对，最初两条正则全是假阳性），
在本仓库查出 **8 处**，全部在《第三章 存储系统（完整笔记）》：

| 行 | 原写法 | 修法 |
|---|---|---|
| 518–520 | `$= \log_2 4\text{K} = $ **12 根**`（等 3 条） | 删掉闭 `$` 前的空格 → `$= \log_2 4\text{K} =$ **12 根**` |
| 716 | `$= 1/(2r) = 1/200\text{ s} = $ **5 ms**` | 同上 |
| 1052 / 1054 | `$\lceil\log_2 4\rceil = $`、`$H = … = $` | 同上 |
| 1528 | `$= 24 - 3 = $**21 bit**` | 同上 |
| 1757 | `$\log_2 4\text{GB} = $ **32 bit**` | 同上 |
