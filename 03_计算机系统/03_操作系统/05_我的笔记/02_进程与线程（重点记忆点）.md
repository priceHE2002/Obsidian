# 2.1 进程与线程

## 2.1.1 进程的定义、组成、特征

🔴 **定义**：进程是进程实体的**运行过程**，是系统进行**资源分配和调度**的独立单位。
（进程实体 = PCB + 程序段 + 数据段；进程实体是静态的，进程是动态的。）

🔴 **PCB 是进程存在的唯一标志**，常驻内存。创建进程 = 创建 PCB；撤销进程 = 回收 PCB。

| PCB 四类信息 | 具体内容 |
|---|---|
| 进程描述信息 | PID、UID、进程名、父进程 |
| 进程控制和管理信息 | 状态、优先级、代码入口、程序外存地址、占用 CPU 时间 |
| 资源分配清单 | 内存/虚拟地址空间、打开文件表、I/O 设备 |
| 处理机相关信息 | 通用寄存器、地址寄存器、PSW、栈指针（现场信息） |

🔴 **五大特征**：**动态性（最基本）**、并发性、独立性、异步性、结构性。

> [!warning] 进程 vs 程序
> 程序是**静态**的指令集合，可长期存在；进程是**动态**执行过程，有生命周期。
> 一个程序可对应多个进程；一个进程也可运行多个程序（如 exec）。

## 2.1.2 进程的状态与转换（🔴 高频）

三态：就绪、运行、阻塞　五态：+创建、终止　七态：+就绪挂起、阻塞挂起

| 转换 | 触发事件 | 主动性 |
|---|---|---|
| 创建 → 就绪 | PCB 初始化完成，进入就绪队列 | — |
| 就绪 → 运行 | 被调度程序选中、分配 CPU | 被动 |
| 运行 → 就绪 | **时间片用完** / 被更高优先级抢占 | 被动 |
| 运行 → 阻塞 | 请求 I/O、申请资源失败、P 操作失败 | **主动** |
| 阻塞 → 就绪 | I/O 完成、资源可用、V 操作唤醒 | 被动 |
| 运行 → 终止 | 正常结束 / 异常 / 被杀 | — |
| 就绪 ↔ 就绪挂起 / 阻塞 ↔ 阻塞挂起 | 中级调度（换出/换入内存） | — |

> [!warning] 三个"不存在"的转换
> **阻塞 → 运行**（必须先变就绪）、**就绪 → 阻塞**（没占 CPU 无法发起阻塞）、**阻塞 → 阻塞**（无意义）。
> 记住：**运行→阻塞是进程自己的主动行为，阻塞→就绪只能由别人（OS/其他进程）唤醒。**

## 2.1.3 进程控制

用**原语**实现（关中断 / 开中断保证原子性）。五类原语：创建、终止、阻塞、唤醒、切换。

- 🔴 **创建**：分配 PID → 分配并初始化 PCB → 分配资源 → 插入就绪队列
- **终止**：找到 PCB → 若在运行则剥夺 CPU → 回收资源 → 回收 PCB
- **阻塞**：保存现场 → 状态改为阻塞 → 插入阻塞队列 → **转调度**
- **唤醒**：从阻塞队列移出 → 改为就绪 → 插入就绪队列（不一定马上运行）
- 🟡 **切换**：保存上下文 → 更新 PCB → PCB 移入相应队列 → 选新进程 → 更新其 PCB → 恢复上下文

> [!tip] 记忆
> 阻塞与唤醒**必须成对**出现，且是一对方向相反的原语；阻塞由**自己**调用，唤醒由**别人**调用。

## 2.1.4 进程通信（4 种）

| 方式 | 要点 | 优缺点 |
|---|---|---|
| 共享存储 | 基于**数据结构**（低级，如共享数组）/ 基于**存储区**（高级，共享内存） | 最快，但**必须自己加同步互斥** |
| 消息传递 | 直接（按 PID 发给某进程）/ 间接（信箱）；消息缓冲队列 | 隐藏细节，适合分布式；有拷贝开销 |
| 管道 pipe | **半双工**；固定大小缓冲区；**写满则写进程阻塞、读空则读进程阻塞**；本质是共享文件 | 只能亲缘进程（匿名管道）；读写需互斥同步 |
| 信号 signal | 软中断式的**通知机制**（如 SIGINT） | 只能传"发生了某事"，不能传数据 |

## 2.1.5 线程（🔴 必考选择题）

🔴 **引入线程后：进程是资源分配的基本单位，线程是 CPU 调度的基本单位。**
线程 = 线程 ID + PC + 寄存器组 + 栈；**线程自己基本不拥有资源**，共享所属进程的资源。

| 共享（同进程内所有线程） | 私有（每线程一份） |
|---|---|
| 代码段、数据段、**堆**、全局/静态变量 | 线程 ID、**寄存器组（PC/SP）**、**栈**、局部变量 |
| 打开的文件、当前工作目录、信号处理函数 | errno、**信号屏蔽字**、调度优先级、线程状态 |

| 对比 | 用户级线程 ULT | 内核级线程 KLT |
|---|---|---|
| 内核是否感知 | 否（内核只看到进程） | 是 |
| 切换开销 | 小（不需进内核） | 大（需模式切换） |
| 一个线程阻塞 | **整个进程阻塞** | 仅该线程阻塞 |
| 能否利用多核 | **不能** | 能 |
| 调度者 | 用户空间线程库 | 内核 |

多线程模型：**多对一**（多个 ULT→1 KLT，易阻塞、不能多核）、**一对一**（开销大）、**多对多**（折中）。
🟡 线程只有**就绪/运行/阻塞**三态（没有挂起态）。

# 2.2 处理机调度

## 2.2.1 三级调度（🔴）

| 级别 | 别名 | 做什么 | 频率 | 场景 |
|---|---|---|---|---|
| 高级 | 作业调度 / 长程 | 外存后备队列 → 内存，建进程 | 最低 | 多道批处理 |
| 中级 | 内存调度 / 中程 | **挂起 → 就绪**（换入换出） | 中 | 提高内存利用率、吞吐量 |
| 低级 | 进程调度 / 短程 | 就绪 → 运行，分配 CPU | **最高** | 一切 OS |

🟡 **调度器**决定"选谁"，**分派器（dispatcher）**做上下文切换、模式切换、跳转到用户态入口。
🟡 **闲逛进程 idle**：优先级最低，没有就绪进程时运行，此时 CPU 记为**空闲**。

## 2.2.2 调度时机与方式

**需要调度**：进程创建、进程终止、进程阻塞、I/O 中断、时间片用完。
**不能调度**：① 中断处理过程中；② 进程处于**内核临界区**；③ 需要原子完成的操作中。

- **非抢占（非剥夺）**：进程主动放弃 CPU 才切换 → 实时性差、开销小
- **抢占（剥夺）**：时间片到 / 更高优先级到达 / 中断 → 实时性好、开销大、需硬件支持

## 2.2.3 五个评价指标（🔴 公式必背）

设到达时间 $a$、服务时间 $s$、完成时间 $f$：

- 周转时间 $T = f - a$
- 带权周转时间 $W = \dfrac{T}{s}$（**恒 $W \ge 1$**，越接近 1 越好）
- 等待时间 $W_q = T - s$（作业）；进程则为其在就绪队列中等待时间之和
- 响应时间 $R = t_{\text{响应}} - t_{\text{提交}}$（分时系统最关心）
- CPU 利用率 $U = \dfrac{T_{\text{忙}}}{T_{\text{总}}}$；吞吐量 $\lambda = \dfrac{N}{t}$

## 2.2.4 六类调度算法（🔴 对比表背下来）

| 算法 | 抢占 | 核心规则 | 优点 | 致命缺点 / 陷阱 |
|---|---|---|---|---|
| **FCFS** | 否 | 按到达先后 | 公平、简单 | 短作业等长作业；**利于 CPU 繁忙型，不利于 I/O 繁忙型** |
| **SJF/SPF** | 否 | 服务时间最短优先 | **平均等待/周转时间最短** | 长作业**饥饿**；须预知运行时间 |
| **SRTN** | 是 | 剩余时间最短优先 | 更优的平均周转 | 同样饥饿；切换多 |
| **HRRN** | 否 | 响应比最高优先 | **兼顾长短作业、不会饥饿** | 每次要算响应比 |
| **RR** | 是 | 时间片轮转 | 响应快，适合分时 | 时间片过大→退化为 FCFS；过小→切换开销大 |
| **优先级** | 均可 | 优先级高者先 | 可区分紧急程度 | 低优先级**饥饿**；静态/动态优先级 |
| **多级反馈队列** | 是 | 优先级递减、时间片递增 | 综合最优，通用 | 低优先级长作业可能**饥饿** |
| **多级队列** | — | 进程固定在某队列，队列间固定优先级/轮转 | 实现简单 | 队列间不灵活 |

🔴 **HRRN 响应比** $R = \dfrac{W_q + s}{s} = 1 + \dfrac{W_q}{s}$。

> [!tip] 数字结论
> $n$ 个进程、时间片 $q$、就绪队列满时，一个进程的**响应时间上界** $\approx (n-1)q$；
> 单 CPU 系统中若有 $n$ 个进程，**就绪态最多 $n-1$ 个**。

🟡 **多处理机调度**：公共就绪队列（负载均衡好、争用大）vs 私有队列（缓存友好、可能不均）；**处理器亲和性**；推/拉式迁移。

# 2.3 同步与互斥

## 2.3.1 基本概念与四准则

- **临界资源**：一次仅允许一个进程使用的资源（打印机、共享变量、缓冲区）
- 临界区四段：进入区 → **临界区** → 退出区 → 剩余区
- **同步**（直接制约）：为完成同一任务而协调**先后次序**
- **互斥**（间接制约）：争用临界资源而**互斥进入**

🔴 **四条准则**
1. **空闲让进**（临界区空则允许进）
2. **忙则等待**（有人则等）
3. **有限等待**（不能无限等，防饥饿）
4. **让权等待**（进不去就释放 CPU，不忙等）——**前三条必须，第四条尽量**

## 2.3.2 软件实现（四种，🔴 谁破坏了哪条）

| 方法 | 做法 | 违背的准则 |
|---|---|---|
| 单标志法 | turn 表示"该谁进" | **空闲让进**（对方不来我就进不去） |
| 双标志**先检查** | 先看对方 flag 再置自己 | **忙则等待**（检查与置位之间被切换，可能同时进） |
| 双标志**后检查** | 先置自己 flag 再检查对方 | **空闲让进 + 有限等待**（可能互相谦让，都进不去→饥饿/死锁） |
| **Peterson** | flag + turn 双变量 | 满足互斥、空闲让进、有限等待；**不满足让权等待**（忙等） |

## 2.3.3 硬件实现

| 方法 | 说明 | 局限 |
|---|---|---|
| 中断屏蔽（关中断） | 进入临界区前关中断 | **只适用单处理机**、只适用内核；用户态危险 |
| **TestAndSet（TS）** | 原子地"读旧值并置 true" | 忙等，不满足让权等待 |
| **Swap / XCHG** | 原子交换锁标志 | 同上 |

🟡 **互斥锁 / 自旋锁**：加锁失败就**忙等（自旋）**。适合**多处理机 + 临界区很短**；单处理机上自旋纯浪费 CPU。

## 2.3.4 信号量（🔴 全章最核心）

**整型信号量**：`P: while(S<=0); S--;` → 不满足让权等待（忙等）。

**记录型信号量**（考试默认这种）：

```c
typedef struct { int value; struct process *L; } semaphore;

P(S):  S.value--;                 // 申请一个资源
       if (S.value < 0) block(S.L);   // 没资源就阻塞，进等待队列

V(S):  S.value++;                 // 释放一个资源
       if (S.value <= 0) wakeup(S.L); // 还有人在等，唤醒一个
```

🔴 **$S.value$ 的物理意义**：初值 = 资源数；$S.value > 0$ 表示**剩余可用资源数**；$S.value < 0$ 时 $|S.value|$ = **阻塞队列中的进程数**。

**三类用法（模板）**

```c
/* ① 互斥：初值 1，P/V 在同一进程内成对 */
P(mutex);   临界区;   V(mutex);

/* ② 同步：初值 0，前操作后 V，后操作前 P */
进程A: ...; V(S);        进程B: P(S); ...
// 口诀：前 V 后 P

/* ③ 前驱关系：每条边一个信号量，初值 0 */
S1 → S2：S1 末尾 V(a)；S2 开头 P(a)
```

> [!warning] 死锁陷阱
> 生产者-消费者中若把 `P(mutex)` 写在 `P(empty)/P(full)` 之前：
> 生产者占着 mutex 等 empty、消费者等 mutex 才能 V full → **互相等待，死锁**。
> **铁律：资源信号量的 P 一定在互斥信号量的 P 之前。**

## 2.3.5 四个经典问题（大题原型）

| 问题 | 信号量设置 | 关键点 |
|---|---|---|
| **生产者-消费者** | `empty=n, full=0, mutex=1` | 先 P(empty)/P(full)，再 P(mutex)；V 顺序相反 |
| **多生产者-多消费者**（盘子） | `plate=1, apple=0, orange=0`（或 +mutex） | 每种产品一个同步信号量；盘子互斥 |
| **读者-写者** | `rw=1, mutex=1, count=0` | 第一个读者 P(rw)、最后一个读者 V(rw)；count 需互斥 |
| **哲学家进餐** | `chopstick[5]={1,1,1,1,1}` | 三种解法见下 |

哲学家三种解法：① **最多允许 4 人同时拿筷**（加 `sem=4`）；② **奇偶编号不同顺序**（奇数先左后右，偶数反之）；③ **AND 型信号量**（一次性拿两只）。

> [!warning] 读者-写者三种变体
> **读者优先**：读者源源不断 → 写者**饥饿**；**写者优先**：写者不断 → 读者饥饿；**读写公平**：加一个排队信号量按到达顺序放行。

## 2.3.6 管程

🔴 **管程 = 共享数据结构 + 一组操作 + 初始化代码**，把"临界区"封装起来，**同一时刻只允许一个进程在管程内执行某个过程**（互斥由**编译器**自动保证，不用手写 P/V）。

- 条件变量：`wait`（阻塞并释放管程）、`signal`（唤醒一个等待者）
- 条件变量**没有值**，只表示等待队列；`signal` 空队列时无影响

| | 信号量 | 管程 |
|---|---|---|
| 层次 | OS 原语 | 语言/编译器级 |
| 互斥 | 自己 P/V | 自动保证 |
| 同步 | P/V | 条件变量 wait/signal |
| 风险 | 漏写、顺序错 → 死锁 | 风险低 |

> [!note] Hoare vs Mesa
> Hoare 管程：`signal` 后**立即切换**到被唤醒进程；Mesa（Java synchronized 一类）：`signal` 后**继续执行**。408 一般不深究，知道名字即可。

# 2.4 死锁

## 2.4.1 定义与四个必要条件（🔴）

死锁：多个进程因**竞争资源**而造成的一种**互相等待**的僵局，无外力介入都无法推进。

🔴 **四个必要条件（同时成立才可能死锁，缺一不可）**
1. **互斥**：资源一次只能给一个进程
2. **不可剥夺（不剥夺）**：已获得的资源不能被强行夺走
3. **请求并保持（占有并等待）**：占着资源还去申请新资源
4. **循环等待**：存在进程—资源的环形等待链

## 2.4.2 四种处理策略

| 策略 | 思路 | 时机 | 代价 |
|---|---|---|---|
| **预防** | 破坏四个条件之一 | 运行前（静态） | 资源利用率低 |
| **避免** | 分配前判断是否进入**不安全状态**（银行家算法） | 每次分配时（动态） | 计算开销 |
| **检测与解除** | 允许死锁发生，定期检测再解除 | 事后 | 检测开销 + 解除损失 |
| **鸵鸟策略** | 不理 | — | 通用 OS 常这么做 |

**预防的具体做法**

| 破坏的条件 | 方法 | 缺点 |
|---|---|---|
| 互斥 | 尽量把资源改造成可共享（如 SPOOLing） | 多数临界资源无法改造 |
| 不可剥夺 | 申请不到就**释放已占资源**；或抢占 | 实现复杂、代价大 |
| 请求并保持 | **一次性申请全部资源** / 运行前一次分配 | 资源浪费、可能饥饿 |
| 循环等待 | **资源顺序编号，按递增顺序申请** | 编号难定、限制编程 |

## 2.4.3 银行家算法（🔴 大题）

数据结构（$n$ 个进程、$m$ 类资源）：
$Available[m]$、$Max[n][m]$、$Allocation[n][m]$、$Need[n][m]$，且 $\text{Need}[i][j] = \text{Max}[i][j] - \text{Allocation}[i][j]$。

**安全性算法**（判断当前是否安全）
1. $Work = Available$，$Finish[i] = \mathrm{false}$
2. 找一个 $Finish[i] = \mathrm{false}$ 且 $Need[i] \le Work$ 的进程
3. 令 $Work \leftarrow Work + Allocation[i]$，$Finish[i] = \mathrm{true}$，回到 2
4. 若所有 $Finish$ 为 true → **安全**，否则不安全

**请求算法**（$P_i$ 请求 $Request$）
1. $Request \le Need$？否 → 出错
2. $Request \le Available$？否 → 等待
3. **试探分配**：$Available \leftarrow Available - Request$，$Allocation \leftarrow Allocation + Request$，$Need \leftarrow Need - Request$
4. 做安全性检查：安全 → 正式分配；**不安全 → 回滚，让 $P_i$ 等待**

> [!warning] 三个易错
> ① **安全状态一定无死锁；不安全状态只是"可能"死锁**。
> ② 银行家算法是**避免**（动态），不是预防。
> ③ 安全序列**可能不唯一**，找到一条即可。

## 2.4.4 检测与解除

- **资源分配图**：进程结点（圆）+ 资源结点（方框，内含点数=该类资源数）；请求边、分配边
- 🔴 **死锁定理**：资源分配图**可完全简化** ⇔ 系统**无死锁**；不可完全简化 ⇔ 有死锁
- **解除**：① 资源剥夺（挂起某些进程抢资源）；② 撤销进程；③ 进程回退（需记录检查点）

## 2.4.5 死锁 / 饥饿 / 活锁（🟡 概念辨析）

| | 死锁 | 饥饿 | 活锁 |
|---|---|---|---|
| 状态 | 全部阻塞，**永远**推不动 | 长期得不到资源，但**可能**推进 | 一直在运行/重试，但**无进展** |
| 范围 | 至少 2 个进程 | 可单个进程 | 可单个/多个 |
| 例 | 互相等对方释放 | 低优先级进程总被抢占 | 双方不断退让重试 |

# 附 A · 20 条速记（考前 10 分钟）

1. PCB 是进程存在的唯一标志，常驻内存。
2. 进程五特征：动态（最基本）、并发、独立、异步、结构。
3. 运行→阻塞是主动；阻塞→就绪只能被动唤醒。
4. 阻塞→运行不存在。
5. 引入线程后：进程 = 资源分配单位，线程 = CPU 调度单位。
6. 线程私有：ID、寄存器（PC/SP）、栈、局部变量、errno、信号屏蔽字。
7. 用户级线程一个阻塞 → 整个进程阻塞；不能利用多核。
8. 三级调度频率：低级 > 中级 > 高级。
9. 中断处理中、内核临界区中不能调度。
10. 带权周转时间 ≥ 1。
11. SJF 平均周转最短但长作业饥饿；HRRN 不会饥饿。
12. RR 时间片过大退化为 FCFS，过小切换开销大。
13. 互斥四准则：空闲让进、忙则等待、有限等待、让权等待（前三条必须）。
14. 单标志违背空闲让进；双标志先检查违背忙则等待；后检查违背空闲让进+有限等待。
15. 信号量 $S.value < 0$ 时，$|S.value|$ 就是等待进程数。
16. 资源信号量的 P 必须在 mutex 的 P 之前（否则死锁）。
17. 前驱图：每条边一个信号量，初值 0，前 V 后 P。
18. 死锁四条件：互斥、不可剥夺、请求并保持、循环等待。
19. 安全状态必无死锁；不安全状态可能死锁。
20. 资源分配图可完全简化 ⇔ 无死锁。
