# 4.1 文件系统基础

## 4.1.1 文件、文件系统与基本操作　★★★

🔴 **文件**：以计算机硬盘为载体的、存储在计算机上的相关信息的集合，是文件系统管理的基本对象。
🔴 **目录本身也是文件**（目录文件），只是内容特殊：存放目录项。

**文件属性**（选择题喜欢问「哪个不属于文件属性」）：

| 属性 | 说明 |
|---|---|
| 名称 | 用户可见，同一目录下唯一 |
| 标识符 | 系统内部唯一编号，**用户不可见** |
| 类型 | 普通文件 / 目录文件 / 特殊文件（设备） |
| 位置 | 文件在哪个设备、哪些块 |
| 大小 | 当前长度，可动态增长 |
| 保护 | 读/写/执行权限 |
| 时间戳 | 创建、最后修改、最后访问 |
| 所有者 | 属主、属组 |

**文件系统的七项功能**：文件存储空间管理、文件命名、文件与目录的创建/删除、文件读写管理、文件保护、文件共享、可靠性与安全性保证。

### 六个基本操作（🔴 open 是最大陷阱）

| 操作 | 系统实际做了什么 |
|---|---|
| 创建 create | 找空闲空间 → 建 FCB/inode → 在目录中加目录项 |
| 删除 delete | 删目录项 → 释放 inode 与数据块 |
| **打开 open** | 按路径检索目录 → 找到 FCB/inode → **调入内存打开文件表** → 返回文件描述符 fd |
| 关闭 close | 删进程打开文件表项 → 系统表计数 −1 → 计数为 0 且被修改过则写回 |
| 读 read | 按**读指针**把数据从盘读入内存用户区，读后指针后移 |
| 写 write | 按**写指针**把数据写入，写后指针后移 |
| 定位 seek / lseek | **只改文件指针**，不做任何 I/O |

🔴 **两张打开文件表**：

| | 系统打开文件表 | 进程打开文件表 |
|---|---|---|
| 数量 | 全系统一张 | 每个进程一张 |
| 内容 | 文件 FCB/inode 副本、**打开计数**、读写偏移 | 文件描述符 → 系统表项的指针、本进程读写偏移 |
| 作用 | 多进程共享同一文件时只保留一份 FCB | 记录「这个进程打开了哪些文件」 |

> [!warning] 三个必考陷阱
> ① **open 不等于把文件内容读入内存**，只是把 FCB 调入内存。
> ② 同一文件被两个进程打开，系统表只有**一个表项**（计数为 2），但进程表各有表项。
> ③ inode 里**没有文件名**，文件名只存在于目录项。

### 文件在系统中的四层表示（UNIX 系）

```
目录项 dentry：文件名 + inode 号          ← 用户看到的名字
索引结点 inode：类型、权限、大小、块指针   ← 文件的全部元数据
系统打开文件表 file：读写偏移、打开模式    ← 一次「打开」的实例
超级块 superblock：整个文件系统的元数据    ← inode 总数、空闲块等
```

## 4.1.2 文件的逻辑结构（用户视角）　★★

🔴 **逻辑结构** = 文件内部数据怎么组织给用户看；**物理结构** = 文件在磁盘上怎么放。两者**互相独立**，同一逻辑结构可用不同物理结构实现。

| 类型 | 细分 | 要点 |
|---|---|---|
| **无结构文件**（流式） | 字符流 | 以**字节**为单位，如源程序、目标代码、库函数；长度 = 字节数，靠指针读写 |
| **有结构文件**（记录式） | 定长记录 / 变长记录 | 由记录组成，记录是相关数据项的集合 |

**有结构的四种组织方式**：

| 方式 | 结构 | 查找效率 | 适用 |
|---|---|---|---|
| **顺序文件** | 串结构（按存入时间）/ 顺序结构（按关键字有序） | 串结构平均 $N/2$；顺序结构可折半 $\log_2 N$ | 批量顺序处理 |
| **索引文件** | 为**变长记录**建索引表：每记录一个索引项（关键字 + 长度 + 指针） | 先查索引表，$O(\log N)$ 或 $O(1)$ | 变长记录、要随机访问 |
| **索引顺序文件** | 记录**分组**，每组一个索引项（指向组内第一条） | 组索引 + 组内顺序，约 $O(\sqrt{N})$ | 顺序文件 + 少量随机 |
| **直接文件 / 散列文件** | 关键字经哈希函数直接算出物理地址 | 期望 $O(1)$，冲突时退化 | 按关键字随机存取 |

> [!tip] 数字感
> $N=10000$ 条记录：串结构平均查 $5000$ 次；顺序结构折半约 $14$ 次；
> 索引顺序文件按 $100$ 组 × 每组 $100$ 条，索引表平均 $50$ 次 + 组内平均 $50$ 次 = $100$ 次。
> 这就是「索引顺序文件 ≈ $\sqrt{N}$」的来历。

## 4.1.3 目录　★★★

🔴 **目录 = 目录项的集合**；目录项 = **文件名 + inode 号**（早期是完整 FCB）。

| 结构 | 怎么组织 | 优点 | 缺点 |
|---|---|---|---|
| **单级目录** | 全系统一张目录表 | 简单 | **不允许重名**、查找慢、不便于共享 |
| **两级目录** | 主文件目录 MFD + 每用户一个 UFD | 解决重名、多用户隔离 | 不便于分类与共享 |
| **树形目录** | 多级层次，绝对路径/相对路径 | 层次清晰、易分类、**不同目录可重名** | **不便于文件共享** |
| **无环图目录** | 允许一个文件/目录有多个父目录（共享） | 真正共享、节省空间 | 需**引用计数**，删除要小心 |
| **通用图目录** | 允许成环 | 最灵活 | 需垃圾回收，实现复杂 |

🟡 **路径**：绝对路径从根 `/` 开始；相对路径从**当前目录**开始；`..` 上级目录，`.` 当前目录。
🟡 **目录操作**：搜索、创建、删除、遍历（列目录）、重命名、链接。

### 索引结点 inode（🔴 全章最高频考点之一）

把 FCB 中**除文件名以外**的信息抽出来单独存放，目录项只留「文件名 + inode 号」。

**为什么要拆？** 目录项变小 → 一个盘块能放更多目录项 → 检索同一目录时**磁盘 I/O 次数减少**。

| 磁盘 inode 字段 | 内容 |
|---|---|
| 文件类型与权限 | 普通/目录/设备；`rwx` |
| 属主、属组 | UID、GID |
| 大小 | 字节数 |
| 时间戳 | 创建/修改/访问 |
| **链接计数** | 硬链接数 |
| **数据块指针** | 直接指针 + 一级/二级/三级间接指针 |
| 索引结点号 | 系统内部编号 |

🟡 **内存 inode 额外字段**：引用计数（多少进程在用）、是否被修改（脏位）、是否已调入内存、打开计数。

> [!warning] 两个易错
> ① **inode 不含文件名**，所以改名只改目录项，不动 inode。
> ② 一个文件**只有一个 inode**，但可以有**多个目录项**（硬链接）。

### 目录实现

| 实现 | 查找 | 插入/删除 |
|---|---|---|
| 线性表 | $O(n)$ 顺序扫 | 简单 |
| 哈希表 | 期望 $O(1)$ | 需处理冲突，删除麻烦 |

## 4.1.4 文件共享（硬链接 vs 软链接）　★★★

| | **硬链接**（基于索引结点） | **软链接 / 符号链接** |
|---|---|---|
| 本质 | 新增一个目录项，指向**同一个 inode** | 新建一个 **Link 型文件**，内容是一串路径 |
| inode 计数 | 创建时 count++，删除时 count−− | **不影响**目标 inode 计数 |
| 跨文件系统 | **不能**（inode 号只在单个文件系统内唯一） | **能** |
| 原文件删除后 | 数据仍在，其他目录项照常访问 | 变成**悬空链接**，访问报错 |
| 访问开销 | 与普通文件相同 | 要**逐级解析路径**，多几次 I/O |
| 能否指向目录 | 一般禁止（防止形成环） | 可以 |

🔴 **删除语义**（必考）：`unlink` 一个硬链接 → 目录项删除、count−1；**只有 count = 0 且没有进程打开时才回收 inode 与数据块**。

> [!tip] 一句话记
> 硬链接是「多个名字一个文件」，软链接是「一个文件里写着另一个文件的路」。

🟡 **打开文件共享的偏移语义**：同一进程 `dup` 出的两个 fd 共享偏移；两个进程各自 `open` 同一文件则有各自偏移。

## 4.1.5 文件保护　★★

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 口令保护 | 每个文件设口令，存于系统/FCB | 开销小 | 口令存在系统内，**安全性差** |
| 加密保护 | 用密钥加密文件内容 | 安全性高 | 加解密耗时 |
| **访问控制** | 访问控制表 ACL：每个文件列出「谁能做什么」 | 灵活、最常用 | 表可能很大 |

🟡 **访问矩阵**：行 = 用户，列 = 文件，元素 = 权限集合。
- 按**列**存储 → 访问控制表 ACL（某文件有哪些用户可访问）
- 按**行**存储 → 能力表（某用户能访问哪些文件）

🟡 **UNIX 权限 9 位**：`rwxrwxrwx` = 属主 / 同组 / 其他。目录权限含义不同：

| 目录权限 | 含义 |
|---|---|
| `r` | 可列出目录内容（ls） |
| `w` | 可在目录中创建/删除文件 |
| `x` | 可进入该目录（搜索路径），**访问目录下文件的前提** |

# 4.2 文件系统实现

## 4.2.1 文件系统的层次结构　★★

```
用户接口（系统调用 open/read/write）
   ↓
文件目录系统          按路径逐级解析，找到 inode
   ↓
存取控制验证模块      检查权限（读/写/执行）
   ↓
逻辑文件系统与文件信息缓冲区   逻辑块号、文件信息缓存
   ↓
物理文件系统          逻辑块号 → 物理块号
   ↓
辅助分配模块 ｜ 设备管理模块  分配/回收块、发起磁盘 I/O
```

> [!tip] 记忆
> 上层管「名字与权限」，中层管「逻辑块」，下层管「物理块与设备」。

## 4.2.2 磁盘布局与挂载　★

```
磁盘
├── MBR（主引导记录，第 0 号扇区）
│     ├── 引导代码（446 B）
│     ├── 分区表（64 B，4 个分区项）
│     └── 结束标志 55AA（2 B）
└── 分区 1 / 分区 2 …
      ├── 引导块（引导扇区）：该分区的自举程序
      ├── 超级块：inode 总数、块总数、空闲块指针、文件系统类型
      ├── 空闲空间管理结构（位图 / 成组链接）
      ├── inode 区（索引结点表）
      ├── 根目录
      └── 文件与目录数据
```

🟡 **挂载 mount**：把某分区的文件系统接到目录树的某个挂载点上，超级块读入内存。
🟡 开机流程：BIOS/UEFI → MBR 引导代码 → 活动分区引导块 → 操作系统内核。

## 4.2.3 文件分配方式（物理结构）　★★★

| 方式 | 目录项存什么 | 随机访问 | 优点 | 缺点 |
|---|---|---|---|---|
| **连续分配** | 起始块号 + 长度 | ✔ $O(1)$ | 顺序/随机都快，寻道最少 | **外部碎片**、难扩展、要求连续空间 |
| **隐式链接** | 首块号（+ 尾块号） | ✘ 只能顺序 | 无外部碎片、易扩展 | 指针占空间、**断链丢数据**、I/O 次数多 |
| **显式链接（FAT）** | 首块号 | ✔ 查 FAT | 无外部碎片、可随机、FAT 常驻内存 | FAT 占内存、单点故障 |
| **索引分配** | 索引块号 | ✔ | 支持随机、易扩展 | 索引块占空间、大文件需多级 |
| **混合索引（UNIX）** | inode 号 | ✔ | 小文件省索引块、大文件可扩展 | 计算复杂 |

### ① 连续分配

- 逻辑块号 $k$ → 物理块号 = 起始块 + $k$（块号从 0 计）
- 访问第 $k$ 块：**1 次 I/O**（可预读后续块）
- 碎片：**外部碎片**（块间空隙），可用紧凑（compact）解决，代价大
- 扩展：后面没空位就要整体搬迁

### ② 隐式链接

- 每个数据块尾部存「下一块指针」，目录项只存首块（和尾块）
- 访问第 $k$ 块要读 $k$ 次（顺序），**不支持随机访问**
- 指针占空间：块 512B、指针 4B → 有效数据 508B

### ③ 显式链接 FAT

- 把所有权指针集中到一张 **FAT（文件分配表）**，表项数 = 盘块数
- FAT **常驻内存**，所以「顺着表跳」不产生磁盘 I/O → 支持随机访问
- FAT 表大小 = 盘块数 × 表项字节数。例：$2^{20}$ 块、FAT16（2B/项）→ 2MB

### ④ 索引分配与混合索引（🔴 大题核心）

**单级索引**：每个文件一个索引块，存放该文件所有数据块号。
- 读文件第 $k$ 块：先读索引块（1 次）+ 读数据块（1 次）= **2 次 I/O**

**多级索引**：索引块再指向索引块；二级 2 次索引 I/O，三级 3 次。

**混合索引（UNIX inode）**：10 个直接指针 + 1 个一级 + 1 个二级 + 1 个三级。

> [!important] 计算模板（必背）
> 设块大小 $B$，指针大小 $P$，则每块指针数 $n = B/P$。
>
> | 层次 | 可寻址数据量 | 读一个数据块的 I/O 次数 |
> |---|---|---|
> | 10 个直接块 | $10B$ | 1 |
> | 一级间接 | $nB$ | 2（1 索引 + 1 数据） |
> | 二级间接 | $n^2B$ | 3 |
> | 三级间接 | $n^3B$ | 4 |
>
> 最大文件 $= 10B + nB + n^2B + n^3B$。

> [!tip] 例（$B=4\text{KB}$，$P=4\text{B}$，$n=1024$）
> 直接 $10 \times 4\text{KB} = 40\text{KB}$；一级 $1024 \times 4\text{KB} = 4\text{MB}$；
> 二级 $1024^2 \times 4\text{KB} = 4\text{GB}$；三级 $1024^3 \times 4\text{KB} = 4\text{TB}$。
> 最大文件 ≈ $4.004\text{TB}$。
> **逻辑块号 5000（从 0 计）落在哪？** $5000 - 10 = 4990 > 1024$，减去一级的 1024 → $3966$，落在二级：
> 一级索引项 $= \lfloor 3966/1024 \rfloor = 3$，二级索引项 $= 3966 \bmod 1024 = 894$。
> 读取路径：inode →（读一级索引块）→（读二级索引块）→ 数据块，共 **3 次 I/O**。

🟡 **其他两种索引扩展**：链接方案（索引块串成链表，只适合超大文件）、多层索引（按需增加层数）。

## 4.2.4 文件存储空间管理　★★★

| 方法 | 数据结构 | 分配 | 回收 | 特点 |
|---|---|---|---|---|
| **空闲表法** | 空闲区表（起始块、长度） | 首次/最佳适应 | 合并相邻空闲区 | 适合**连续分配** |
| **空闲链表法** | 空闲盘块链 / 空闲盘区链 | 取链头 | 挂回链头 | 简单；盘块链效率低 |
| **位示图** | 1 位 = 1 块，0 空闲 / 1 占用 | 找 0 位置 1 | 置 0 | 易找连续块；位图占空间 |
| **成组链接法** | 每组 100 个块号，组头存下一组 | 从栈顶取 | 压栈，满则成新组 | UNIX 采用；省空间又高效 |

### 位示图换算（🔴 必考）

设字长 $n$ 位，块号从 0 开始：
$$\text{字号} = \left\lfloor \frac{b}{n} \right\rfloor,\qquad \text{位号} = b \bmod n$$
反向：$b = \text{字号} \times n + \text{位号}$。

若题目中块号、字号、位号**都从 1 开始**：$\text{块号} = (\text{字号}-1)\times n + \text{位号}$，代入前先把块号减 1。

**位图大小**：盘块数 $N$ → $N$ 位 = $N/8$ 字节。
例：$1\text{TB}$ 磁盘、块 $4\text{KB}$ → $2^{40}/2^{12} = 2^{28}$ 块 → $2^{28}/8 = 2^{25}\text{B} = 32\text{MB}$。

> [!tip] 例
> 字长 32 位、块号 130（从 0）：字号 $\lfloor 130/32 \rfloor = 4$，位号 $130 \bmod 32 = 2$。
> 反过来：字号 4、位号 2（均从 0）→ 块号 $4\times 32 + 2 = 130$。

### 成组链接法（🔴 理解过程）

- 把空闲块分成若干组，每组最多 **100** 个块号；**组头**记录本组块数与**下一组首块号**
- 超级块中保存**第一组**（相当于栈底）
- **分配**：从当前组取一个块；若取完，按组头指向读入下一组
- **回收**：把块号压入当前组；若当前组已满 100，则把整组写到新回收的块上，该块成为新组头

> [!warning] 易错
> 成组链接的「组」存在**空闲块自己身上**，超级块只保存第一组；所以文件系统刚挂载时只需读超级块。

## 4.2.5 虚拟文件系统 VFS　★★

🔴 目的：**屏蔽不同文件系统（FAT、NTFS、ext4）的实现差异**，向上提供统一接口。

| 对象 | 对应什么 | 生命周期 |
|---|---|---|
| 超级块对象 superblock | 一个已挂载的文件系统 | 挂载到卸载 |
| 索引结点对象 inode | 一个文件 | 文件被访问期间 |
| 目录项对象 dentry | 路径中的一个分量 | 缓存，可回收 |
| 文件对象 file | 一次「打开」 | open 到 close |

🟡 实现方式：VFS 定义一组统一操作（`open/read/write/close`），各具体文件系统提供**函数指针表**，调用时转向对应实现。
🟡 VFS **只存在于内存**，系统启动时建立，卸载时消失。

# 4.3 磁盘与固态硬盘

## 4.3.1 磁盘结构、地址与容量　★★★

**层次**：盘片 → 盘面（每面一个磁头）→ 磁道（同心圆）→ 扇区（最小读写单位，512B 或 4KB）。
🔴 **柱面** = 所有盘面上半径相同的磁道集合；按柱面访问可减少寻道。

🔴 **磁盘地址 = （柱面号，盘面号，扇区号）**：先定柱面（寻道）、再选盘面（电子切换，几乎无延迟）、最后等扇区转到磁头下（旋转延迟）。

$$\text{容量} = \text{盘面数} \times \text{每面磁道数} \times \text{每道扇区数} \times \text{扇区大小}$$

> [!tip] 例
> 8 盘面、每面 1000 磁道、每道 200 扇区、扇区 512B：
> $8 \times 1000 \times 200 \times 512\text{B} = 819.2\text{MB}$。

## 4.3.2 访问时间　★★★

$$\text{平均访问时间} = \text{平均寻道时间} + \text{平均旋转延迟} + \text{传输时间}$$

- **平均旋转延迟** = 转半圈的时间 $= \dfrac{1}{2}\cdot\dfrac{60}{r}$（$r$ 单位 r/min）
- **传输时间** = $\dfrac{\text{读取字节数}}{\text{传输速率}}$，或 $\dfrac{\text{读取扇区数}}{\text{每道扇区数}} \times$ 一圈时间
- 🟡 **数据传输率** = 每道字节数 × 每秒转数 = 每道字节数 × $r/60$

> [!tip] 例（$r = 7200\text{ r/min}$）
> 一圈 $= 60/7200 = 8.33\text{ms}$ → 平均旋转延迟 $= 4.17\text{ms}$；
> 每道 200 扇区 → 读 1 个扇区约 $8.33/200 = 0.042\text{ms}$；
> 若平均寻道 $5\text{ms}$，平均访问时间 ≈ $5 + 4.17 + 0.04 \approx 9.2\text{ms}$。

## 4.3.3 磁盘调度算法　★★★

| 算法 | 规则 | 优点 | 缺点 |
|---|---|---|---|
| **FCFS** | 按请求到达顺序 | 公平、简单 | 平均寻道长 |
| **SSTF** | 每次选离当前磁头**最近**的 | 平均寻道短 | **远端请求饥饿** |
| **SCAN**（电梯） | 单向扫到**端点**再反向，反向也服务 | 兼顾公平与效率 | 中间磁道占便宜；到端点有空跑 |
| **C-SCAN** | 只单向服务，回程**直接返回不服务** | 各磁道更公平 | 回程空跑 |
| **LOOK** | 扫到**最远请求**就返回 | 比 SCAN 少空跑 | 需知道最远请求 |
| **C-LOOK** | 单向服务，到最远请求即返回，回程不服务 | 公平 + 少空跑 | 同上 |

🟡 **计算模板**：画数轴 → 按算法顺序连线 → 总移动磁道数 = 相邻访问点距离之和 → 平均寻道长度 = 总移动量 ÷ 请求数（看清题目是否含初始磁头位置）。

> [!important] 经典例题：磁头在 53，请求 98, 183, 37, 122, 14, 124, 65, 67（磁道 0—199）
>
> | 算法 | 服务顺序 | 总移动磁道数 |
> |---|---|---|
> | FCFS | 98→183→37→122→14→124→65→67 | **640** |
> | SSTF | 65→67→37→14→98→122→124→183 | **236** |
> | SCAN（先向大） | 65→67→98→122→124→183→37→14 | **299** |
> | C-SCAN（先向大） | …→183→199→0→14→37 | **382** |
> | LOOK（先向大） | 65→67→98→122→124→183→37→14 | **299** |
> | C-LOOK（先向大） | …→183→14→37 | **322** |
>
> 手算校验：SSTF $= 12+2+30+23+84+24+2+59 = 236$ ✔

## 4.3.4 减少延迟时间的方法　★★

| 方法 | 做法 | 解决什么 |
|---|---|---|
| **交替编号** | 逻辑相邻的扇区在物理上隔开（如 1,3,5,…,2,4,6） | 给控制器处理时间，避免「读完处理不及、要等整圈」 |
| **错位命名** | 不同盘面的扇区起始位置错开 | 换盘面读同一柱面时不用等整圈 |
| **按柱面存放** | 同一柱面的数据连续存放 | 减少寻道（柱面内换头几乎无寻道） |

> [!tip] 一句话区分
> 交替编号解决**同一磁道上的处理延迟**；错位命名解决**换盘面的等待**；按柱面存放解决**寻道次数**。

## 4.3.5 磁盘管理　★

| 步骤 | 做什么 |
|---|---|
| **低级格式化**（物理格式化） | 划分磁道与扇区，写头尾标志、ECC 校验；出厂时完成；会标记坏块 |
| **分区** | 把磁盘划成若干逻辑区，写分区表 |
| **高级格式化**（逻辑格式化） | 建立文件系统：初始化 inode 区、根目录、空闲空间管理（位图/成组链接）、超级块 |
| **引导** | MBR 引导代码 → 活动分区引导块 → 装入 OS |
| **坏块处理** | 简单磁盘：在 FAT 中标记坏块，避免分配；复杂磁盘：**扇区备用（滑动替换）**，对 OS 透明 |

## 4.3.6 固态硬盘 SSD　★★

- **介质**：NAND 闪存；**页（page）为读写单位**（常见 4KB），**块（block）为擦除单位**（常见 128—256 页）
- **写前必须擦除整块**：改一个页要先把所在块的有效页搬走、擦块、再写回 → **写放大**
- **性能**：无寻道、无旋转延迟，随机读写远快于 HDD；顺序写不一定占优
- **寿命**：每块擦写次数有限（SLC > MLC > TLC > QLC），靠三件事续命：
  1. **FTL（闪存转换层）**：逻辑地址 → 物理页的映射表
  2. **垃圾回收 GC**：搬移有效页、擦除整块、回收空闲块
  3. **磨损均衡**：动态（只在空闲块间轮换）/ 静态（冷数据也搬走，强制均匀）
- 🟡 **寿命估算**：$\text{TBW} \approx \dfrac{\text{容量} \times \text{擦写次数}}{\text{写放大系数}}$，可再折算成每天可写量（DWPD）

| 对比项 | HDD | SSD |
|---|---|---|
| 寻道/旋转延迟 | 有（ms 级） | 无（μs 级） |
| 随机访问 | 慢 | 快 |
| 最小读写单位 | 扇区 | 页 |
| 最小擦除单位 | — | 块 |
| 寿命限制 | 机械磨损 | 擦写次数 |
| 写放大 | 无 | 有（先擦后写） |

# 附 B · 30 条速记（考前 10 分钟）

1. 目录本身也是文件；目录项 = 文件名 + inode 号。
2. **inode 不含文件名**，改名只改目录项。
3. open 只是把 FCB 调入内存，返回 fd；不读文件内容。
4. 系统打开文件表全局一张，进程打开文件表每进程一张。
5. 文件属性里的「标识符」用户不可见。
6. 串结构只能顺序查；顺序结构（按关键字有序）可折半。
7. 索引文件为**变长记录**服务；索引顺序文件 ≈ $\sqrt{N}$。
8. 树形目录解决重名与分类，**不便于共享**；无环图才共享。
9. 硬链接：同一 inode、count++、不能跨文件系统。
10. 软链接：独立 Link 文件存路径、可跨文件系统、原文件删了会悬空。
11. 删除硬链接 ≠ 删除文件，count 为 0 才回收。
12. inode 拆出来是为了让目录项变小、减少检索 I/O。
13. 文件系统层次：用户接口 → 目录 → 存取控制 → 逻辑文件系统 → 物理文件系统。
14. 超级块存文件系统元数据（inode 数、块数、空闲块指针）。
15. 连续分配：随机访问 $O(1)$、有**外部碎片**、难扩展。
16. 隐式链接只能顺序访问，读第 $k$ 块要 $k$ 次 I/O。
17. FAT 显式链接可随机访问，因为 FAT 常驻内存。
18. 索引分配读一个数据块：单级 2 次 I/O，二级 3 次，三级 4 次。
19. 混合索引最大文件 = 直接 + 一级 + 二级 + 三级之和。
20. 位示图：字号 $\lfloor b/n \rfloor$，位号 $b \bmod n$。
21. 位图大小 = 盘块数 / 8 字节。
22. 成组链接每组 100 块，第一组在超级块。
23. VFS 四对象：超级块、inode、目录项、文件。
24. 磁盘地址 =（柱面号，盘面号，扇区号）。
25. 平均访问时间 = 寻道 + 半圈旋转 + 传输。
26. 转速 $r$ → 一圈 $60/r$ 秒，平均旋转延迟是它的一半。
27. SSTF 会饥饿；SCAN 到端点才返回；C-SCAN 回程不服务；LOOK 到最远请求就返回。
28. 交替编号给处理时间，错位命名给换面时间，按柱面存放减少寻道。
29. 高级格式化 = 建立文件系统；低级格式化 = 划分扇区。
30. SSD：页读写、块擦除，写前先擦，靠 FTL + GC + 磨损均衡续命。

# 附 D · 四个计算模板（照着套）

**① 混合索引**
$n = B/P$；最大文件 $= 10B + nB + n^2B + n^3B$；定位逻辑块号 $k$：$k<10$ 直接；否则 $k-10$，依次与 $n$、$n^2$、$n^3$ 比较。

**② 位示图**
字号 $=\lfloor b/n \rfloor$，位号 $=b \bmod n$；反向 $b=\text{字号}\times n+\text{位号}$；位图大小 $=N/8$ 字节。

**③ 成组链接**
分配：取栈顶；栈空则读下一组。回收：压栈；栈满（100）则整组写入新块，该块当新组头。

**④ 磁盘调度**
总移动磁道数 $=\sum |\text{相邻访问点之差}|$；平均寻道长度 = 总移动量 / 请求数；平均访问时间 = 寻道 + 半圈旋转 + 传输。
