# 简历与面试策略

> [!tip] 一句话定位（简历顶部 3 行）
> **具身基础模型方向的算法候选人：22 篇 VLA 论文精读 + 训练基础设施实战（Megatron/ZeRO/LoRA）+ 持续学习研究（CounterStruct）+ 正在完成端到端 VLA 复现与部署闭环。**
> 目标岗位：具身智能算法工程师（VLA / 大模型训练 / 强化学习后训练）。不写「热爱 AI、学习能力强」这类空话。

## 二、CounterStruct 的三种包装

同一个研究，面向三类岗位换三种讲法。**不要三种都写上去**，按投递岗位选一种。

> [!warning] 下面 bullet 里的 `XX` / `X%` / `X 倍` 都是**模板占位符**
> 面试前必须换成你自己跑出来的真实数字（数据集名、提升幅度、显存、延迟）。**一个编造的数字会毁掉整份简历的可信度**——没有就跑实验补上，或者改成定性描述。

### 包装 A：学术型（投科研机构 / 大厂研究岗 / 论文岗位）

> **CounterStruct: Horizon-Calibrated Structural Action Values for Fixed-Capacity Continual Learning**（第一作者，投稿中/预印本）
> - 提出**积分时域结构动作值**，在固定容量约束下量化「结构选择」的长期收益，解决持续学习中的容量-可塑性权衡问题。
> - 设计 **exact-2:4 拓扑图 + shadow intervention** 机制，实现任务局部的结构搜索与保护，避免灾难遗忘。
> - 在 XX 基准上相较 X 提升 X%，代码开源（GitHub）。

**讲法**：问题（灾难遗忘 vs 容量上限）→ 现有方法为什么不够（只保护参数不保护结构）→ 你的贡献（结构动作值 + shadow intervention）→ 结果。

### 包装 B：应用型（投具身算法岗，主打「能落地」）

> **固定容量下的机器人策略持续学习（研究项目）**
> - 针对「机器人持续接入新任务时策略遗忘」问题，提出结构动作值 + 任务局部记忆的方案，在固定参数预算下容纳 XX 个任务。
> - 与 LoRA/Adapter 类方案对比，验证结构稀疏在持续学习场景下的优势；实验代码可复现。
> - **迁移思考**：同一框架可用于具身策略的多机器人本体适配（不同本体 = 不同任务分布）。

**讲法**：先讲具身场景痛点（新任务/新本体→遗忘/重训），再讲方法，最后讲「为什么这对你们公司有用」。

### 包装 C：系统型（投训练/Infra 岗，主打「懂训练」）

> **受限资源下的持续训练系统（研究 + 工程）**
> - 在 2:4 稀疏结构约束下实现训练-推理一致的模型更新，分析显存/吞吐/精度三角权衡。
> - 结合 ZeRO/梯度检查点/混合精度，将单卡可训练规模提升 X 倍（与 [[03_训练基础设施论文精讲]] 中的技术对应）。

**讲法**：训练成本、显存墙、并行策略、稀疏感知推理的延迟收益。

### 简历 bullet 的量化纪律

| 要写 | 不要写 |
|---|---|
| 「在 XX 数据集上成功率 62% → 78%」 | 「显著提升性能」 |
| 「推理延迟 120ms → 45ms（TensorRT INT8）」 | 「优化了推理速度」 |
| 「单卡显存 80G → 32G（ZeRO-2 + checkpointing）」 | 「降低了显存」 |
| 「精读 22 篇 VLA 论文，输出 22 篇精讲 + 可运行 model.py」 | 「熟悉 VLA」 |

## 三、三个 portfolio 项目

对应 [[04_12周学习路径]] 的 W1–W8，每个项目都能单独讲 5 分钟。

### 项目 1：VLA 复现与微调（核心，W1–W7）

- **内容**：π0 / OpenVLA / ACT / Diffusion Policy 四模型在 LIBERO/SimplerEnv 上的成功率、延迟、显存对比；用 50–100 条自采或开源数据微调，做失败分析。
- **产出**：GitHub 仓库 + 技术报告（2000 字）+ 2 分钟 demo 视频。
- **面试亮点**：「我不只是读论文，我把四个模型都跑了一遍，这是它们的真实开销和失败模式。」
- **追问准备**：为什么 ACT 在小数据上更稳？π0 的 flow matching 采样步数怎么选？你的失败案例里哪类最多？

### 项目 2：训练/部署链路（差异化，W6 + 训练基础设施笔记）

- **内容**：把策略从训练到部署打通——ONNX/TensorRT 导出、量化、延迟测量；训练侧用 ZeRO/混合精度/梯度检查点跑通一次多卡或单卡大 batch。
- **产出**：`docs/deploy.md`（链路图 + 延迟拆解）+ 一个可复现脚本。
- **面试亮点**：「部署延迟预算是这么拆的：视觉编码 X ms + 推理 Y ms + 通信 Z ms + 控制 W ms。」

### 项目 3：持续学习 / 数据引擎（研究延伸，W5–W8）

- **内容**：LIBERO 多任务顺序学习，对比 naive fine-tune vs CounterStruct 思路；或 50–100 条数据的采集-清洗-评测闭环。
- **产出**：对照实验表 + 数据卡片。
- **面试亮点**：「具身策略的持续学习为什么比 CV 难：分布漂移、本体差异、评测昂贵。」

> [!warning] 三个项目的排序随岗位变
> 投 VLA 岗：1 → 2 → 3；投训练/Infra 岗：2 → 1 → 3；投研究岗：3 → 1 → 2。

## 五、面试题库（30 题，按出现频率排）

> 每题写 200 字答案存到 `11_求职/面试答案/`，面试前一周只复习自己的答案。标 ★ 的是 152 条 JD 里明确出现的能力项。

## 七、英文表达（投海外/外企）

- **自我介绍 60 秒**：Who I am → What I built (project 1) → What I know (VLA/infra) → Why this role.
- 高频英文问题见 `Figure / PI / Skild` 类 JD 的 requirements，核心词：manipulation, dexterous, sim2real, VLA, policy learning, evaluation protocol.
- 一句模板：*"I reproduced four VLA policy families and built an end-to-end train-to-deploy pipeline, so I can tell you not just what the papers claim but what the numbers actually look like on a single GPU."*

## 八、常见坑

| 坑 | 纠正 |
|---|---|
| 简历写「熟悉 VLA」 | 改成「复现 4 个 VLA 模型，成功率 XX%，延迟 XXms」 |
| 项目全是课程作业 | 只留项目 1/2/3，课程项目一行带过 |
| 面试被问「你做的和论文有什么区别」答不出 | 准备「复现 → 发现问题 → 改进尝试」三段式 |
| 觉得没实习就没戏 | 用 **开源项目 + 论文 + 复现报告**替代；很多具身初创更看动手 |
| 只投大厂 | T1 里的初创（它石/穹彻/千寻/自变量/星尘）匹配度更高 |
